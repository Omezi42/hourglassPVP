# ui-polish-loop Skill

## Fableへ渡す形(Fableで回すとき)

Fableには判断だけを任せ、状況の把握は先に下位モデルで済ませて渡す(Fableが自分で探すとトークンがかさむ)。

1. **下調べ(Sonnet)**: `scratchpad/fable_briefs/<項目>/` に次を置く。案は出さない
   - `README.md`: 対象の画面・操作 / 仕様の該当段落の写し(9章ほか。段落ごと引用し章・節を添える)/
     触るファイルと、描画・反応を担う関数名・行範囲・いまの定数の値 / UiPolishLog の関連する判定(採用・却下)/
     守ること(`docs/Pitfalls.md` と記憶のうちこの画面に効くものを数行で)
   - 今の縦横のスクショ(下の4.の道具)。動きを見る項目は動画(GIF/MP4)
   - **大きさの上限**: README は15KB以内(冒頭に「事実として気づいたこと」を置き、仕様の写しは判断に効く段落だけ)。
     Fableに見せる画像は `for_fable/` に12枚まで選んで置く(残りは別フォルダに置き、Fableは要るときだけ開く)
   - **動きはコマ割りの1枚で渡す**(Fableは動画を再生できない)。対局の動きは `tools/record_match_motion.sh` で撮り、
     出来事のコマ番号つきで並べたコマ割りを場面×向きごとに1枚作る。GIF/MP4は人へ送る用
2. **判断(Fable)**: 束だけを読む。docs・コードを探しに行かない(足りなければ足りない物を書いて止める)。
   直すことを、値・色・尺・どの関数かまで決めて `decision.md` に書く。見た目が文で伝わらない部分だけ、描画のコード片を添えてよい
3. **実装(Sonnet)**: `decision.md` どおりに直し、下の4.・5.を行う。人の判定で「詰めが足りない」となったときだけ、
   前後の撮影を束へ足してFableへ戻す

目的は「細部の詰めと操作への反応」を強くすること(派手な演出より優先)。1回の呼び出しで1周だけ回す。
同じセッションで周を重ねない(1セッション1テーマ)。

## 0. 始める前に

- `docs/Pitfalls.md` と `docs/design/09_ui.md` を読む。触る画面の `docs/design/` の章と `docs/arch/` の節も読む
- `docs/UiPolishLog.md` を読む。**「判定: 待ち」が3件以上ならコードを触らない。**
  待ちの一覧と前後スクショを撮り直して `SendUserFile` で送り、この周を終える
- 人の判定が付いた項目を処理する
  - 採用: ログの判定を「採用」にする
  - 却下: その変更を revert し、ログの「却下した方向」へ理由を1行足す。同じ方向の案を二度と出さない
- 「画面ごとの最終更新」を更新する

## 1. 画面を1つ選ぶ

ユーザーが画面を指定していればそれを使う。無ければ、ログで最も長く触っていない画面を選ぶ
(対局・ホーム・デッキ一覧・デッキ編集・ショップ・結果・遠征など)。

## 2. スクショとコード・仕様で問題点を洗い出す

縦横のスクショを先に撮って読み、下の観点で見つけたものをコードで裏付ける。

- **反応**: 押せるもの全部に hover・押下・無効の状態があるか。押したら即座に何かが返るか。待ちに表示があるか
- **一貫性**: 色・余白・角丸・文字サイズがテーマや定数から来ているか(ベタ書きの数値が無いか)。
  似た部品が別々の見た目になっていないか
- **縮尺**: 枠線・輪郭・面取りの太さが要素の大きさに合わせて変わるか(固定値で描いていないか)
- **縦横**: 縦(720x1280)と横(1280x720)の両方で、はみ出し・重なり・小さすぎるタップ領域が無いか
- **情報**: 次に何をすればよいか分かるか。最適手の推奨を出していないか。
  英字のサブタイトルや裏方処理の成否表示が無いか。ホバー詳細は操作しないパネルに限っているか
- **DCGの慣習**: ハースストーン等で当たり前の表現から外れた独自表現になっていないか

見つけたものを「影響の大きさ × 直しやすさ」で並べ、上位1〜2件だけを扱う。残りはログの「候補」へ1行ずつ積む。

## 3. 直す(範囲を限る)

- 直接実装するのは小さな磨き込み(状態・余白・反応・一貫性・縮尺)だけ
- 画面の構成を変える案はコードを書かない。Godotでモックを描いてスクショを撮り、ログへ「提案」として積む
- GameDesign.md に無い挙動が要るなら、CLAUDE.md の仕様変更フローに従って提案だけ出す
- `.tscn` はパッチスクリプト経由で触る。1000行に近いファイルは先に切り出す
- 機械的な作業は Sonnet のサブエージェントへ渡してよい

## 4. 検証して撮る

- `bash tools/check.sh` を回して ALL OK を確認する
- 変更前と変更後を縦横とも撮る(`--headless` は付けない。出力はスクラッチパッドへ)
  - 対局画面: `res://tools/capture_match_layout.tscn -- <出力先> [both|overlays|panels]`
  - それ以外: `res://tools/capture_screen_layout.tscn -- <出力先> <portrait|landscape> <画面>...`
  - 変更前は `git stash` で戻して撮り、`git stash pop` で戻す
- 撮った前後を読み、狙いどおり変わったか・崩れが無いかを確かめてから送る
- **採否は人が決める。**`SendUserFile` で「何を・なぜ変えたか1行 + 前後スクショ」を送る

## 5. 記録して commit

- `docs/UiPolishLog.md` の「判定待ち」へ「日付 / 画面 / 変えたこと / コミット」を追記する
- 日本語のメッセージで commit → push する(スクショ・一時ファイルは含めない)
- 完了報告は CLAUDE.md の4項目の順で書く
