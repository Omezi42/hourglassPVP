# 砂時計アリーナ ルール設計書(v5.0)

## コンセプト

砂時計モチーフのターン制対戦カードゲーム。
**砂時計の上の部屋に残った砂が体力、下に落ちた砂が攻撃力**であり、時間が経つほど
強くなると同時に脆くなる。ひっくり返せば体力と攻撃力が入れ替わる——この一点を
ゲームの核に据える。

1戦は5分程度。Godot + unityroom でのオンライン対戦を想定し、
毎日アプデで新しい砂時計を追加し続けられるデータ駆動な拡張性を前提とする。

---

## 1. 砂時計(カード)

カードには**盤面へ出る「砂時計」**と、**出ずに効果だけを起こす「砂術」**の
2種類がある(砂術は6章)。この章が扱うのは砂時計のほうで、
**このゲームの中心は砂時計**であり砂術はそれを助けるものとして数を絞る。

各砂時計は次の3つのパラメータを持つ。

| パラメータ | 意味 |
|---|---|
| **コスト** | 場に出すために支払うマナ |
| **総量** | 体力と攻撃力の合計。そのカードの規模 |
| **キーワード / 効果** | 持たないもの(バニラ)があってよい |

場に出た砂時計は **体力=総量 / 攻撃力=0** で始まる。

- **毎ターン終了時、砂が1粒落ちる**(体力-1 / 攻撃力+1)
- **体力が0になったら破壊される**(砂が落ちきった)
- **反転すると体力と攻撃力が入れ替わる**

出した直後は攻撃力0なので何もできない。これが召喚酔いにあたる。

### 生涯ダメージ

体力h・攻撃力aの砂時計が、反転せず寿命を全うするまでに与える総ダメージは

```
生涯ダメージ = h × a + h(h-1)/2
```

**反転の最適解は「攻撃力が体力を上回ったとき」**である。攻撃力の高い砂時計を
体力の高い状態へ戻すほうが、寿命が伸びて総火力が大きくなる。
「体力を攻撃力に換金する」ために反転するのは短視眼であり、砂時計を使い捨てにしてしまう。

## 2. 対局の構成

- デッキは **30枚**(同名カードは2枚まで)
- 場は各プレイヤー **6枠**
- プレイヤーの初期HPは **30**
- マナは自分のターン開始時に**最大値+1・全回復**(上限10)
- **初期手札は先手3枚・後手4枚。後手は「コイン」を1枚持つ**
- 山札が尽きたら、以降は自分のターン終了ごとに1ダメージ(疲労)

先手・後手の補正は「**後手が1枚多い**」と「**後手はコインを持つ**」の2つだけとする。

**コイン**は、後手が**1対局に1度だけ、自分の手番でマナを+1できる**もの。手札の枚数には
数えず、使うタイミングだけを選ぶ。マナ上限(10)は超えない。

補正の効き幅はどちらも大きく、実測では**コイン単独で先手勝率が約22ポイント動く**。
そのため**複数の補正を重ねてはいけない**。以前あった「先手の1ターン目はドローなし」も
同じく約22ポイントの補正であり、コインと併用すると先手勝率が38%まで落ちるため廃止した
(先手も自分の1ターン目からドローする)。

マナ上限を恒久的に+1する形の補正は、粒度が粗すぎて使えない(先手勝率が64%から26%へ飛ぶ)。

### マリガン(初手の引き直し)

対局開始時、両プレイヤーは配られた初期手札を見て、**任意の枚数を選んで引き直せる**。
選んだカードを一度手札から外し、**同じ枚数を引いてから、外したカードを山札へ混ぜて切り直す**。
この順序により、**引き直したカードがその場で手札へ戻ってくることはない**。
マリガンは1対局に1度だけで、**先手・後手が同時に行う**。相手が何枚交換したかは互いに分からない。

30枚のデッキでコスト1〜2のカードを1枚も引けない事故が構造的に起きるため、
**事故がそのまま敗因になる状態を避けることを目的とする**。交換できる枚数に上限は設けない
(全交換もできる)。上限を設けても事故の型が変わるだけで、覚えることだけが増えるため。

**コインは後手の持ち物であり、マリガンの対象外とする**(手札の枚数に数えないため)。

## 3. ターンの流れ

1. **マナ回復** — 最大マナ+1、全回復
2. **ドロー** — 1枚引く
3. **メインフェイズ** — 以下を好きな順で、何度でも
   - **場に出す**:手札から1枚、マナを支払って空き枠へ置く。
     **空き枠が無い場合は出せない**(既存の砂時計への上書き設置は行わない)
   - **コインを使う**(後手のみ・1対局に1度):マナを+1する
   - **反転する**:自分の砂時計の体力と攻撃力を入れ替える。**マナは不要**。
     ただし**1体につき1ターンに1回まで**、**出したターンは反転できない**
   - **攻撃する**:攻撃力が1以上の砂時計で、相手の砂時計か相手プレイヤーを攻撃する。
     **1体につき1ターンに1回まで**、**出したターンは攻撃できない**
4. **ターン終了** — 自分の砂時計の砂が1粒ずつ落ちる(体力-1 / 攻撃力+1)。
   体力が0になったものは破壊される

## 4. 戦闘

- 相手プレイヤーを攻撃した場合、攻撃力ぶんのダメージがそのままHPに入る
- **相手の砂時計を攻撃した場合、互いに相手の攻撃力ぶんのダメージを受ける**(相打ち)
- **ダメージを受けると、その分の砂は消える**(体力が減り、総量も減る。攻撃力は変わらない)
- 体力が0になった砂時計は破壊される

### なぜ「相打ち」と「砂が消える」の両方が必要か

この2点はどちらもゲームの成立条件であり、片方でも欠けると破綻する。

- **相打ちがないと**、除去がノーリスクの得になり、本体を殴る理由が原理的に消える。
  実測では対局の100%がデッキ切れで決着し、本体ダメージが一度も勝敗を決めなかった
- **ダメージで砂が「落ちる」(総量が保存される)と**、戦闘で価値がほとんど失われないため
  殴り合う意味がなくなる。体力5・攻撃1同士がぶつかると双方が体力4・攻撃2になり、
  生涯ダメージは15から14へ1しか減らない。実測ではユニットへの攻撃が9%まで落ちた

両方を入れたとき、はじめて「盤面を取りつつ本体を削る」という形が成立する。

## 5. 勝利条件

- 相手プレイヤーのHPを先に0にした方が勝利
- 投了は敗北とする(従来どおり)
- **持ち時間は1手番につき60秒とし、手番が移るたびに60秒へ戻す**(総持ち時間は持たない)。
  1手ごとに必ず60秒考えられる状態を保つためで、以前の「1人3分の総量制」は、
  序盤に使いすぎると終盤の1手を考えられなくなり、盤面が複雑になる終盤ほど
  時間が無いという逆の配分になっていた。決着手数は平均22.1手のため、
  1対局におよそ20分を見込む
- **持ち時間が尽きても、それだけでは負けにしない。その手番を強制的に終了して相手へ渡す**。
  1手番60秒は「1手をじっくり考えられる」ための枠であり、考え込んだ結果その1手を落とすのは
  自然でも、**対局そのものを落とすのは罰として重すぎる**。渡した後も盤面は残るため、
  次の手番で挽回できる
- **時間切れを起こすたび、次の自分の手番の持ち時間を半分にする**(60秒 → 30秒 → 15秒)。
  時間切れが続くのは席を外している可能性が高く、**待っている側の拘束時間をそのぶん縮める**ため。
  **1手でも指せば60秒へ戻る**ので、長考して1度落としただけのプレイヤーが不利を持ち越すことはない
- **連続して3回、自分の手番を時間切れで渡し続けたら敗北とする**。何もしない相手を待ち続ける
  状態を終わらせるための線で、これも**1手でも指せば数え直す**。上の半減と合わせて、
  席を外した人は 60+30+15=105秒 で決着し、待つ側はそこで解放される
- **ルームマッチに限り、部屋を作る側が持ち時間を切れる**。持ち時間は切断・放置への対処を
  兼ねるため既定は入だが、**ルームマッチは相手が誰か分かっている友達対戦**であり、
  放置への備えより「じっくり考える」ほうが価値が高い場合がある。決めるのは
  **部屋を作った側だけ**で、参加する側・観戦する側は画面で確認できるが変更できない
  (対局が始まってから食い違わないよう、部屋の設定として1箇所で持つ)。
  **切にすると、放置された相手を時間切れで倒せなくなる**ため、この注意を画面に1行で示す。
  **ランダムマッチとCPU戦では選べない**。ランダムマッチは相手が見知らぬ人であり
  放置への対処を外せず、CPU戦はもともと持ち時間を消費しない(13章)

## 6. キーワード

同じキーワードを**コストと総量だけ変えて複数のカードに載せる**ことを前提とした語彙。

### 語にするのは、複数のカードに載っている能力だけ

**キーワード(語)にしてよいのは、2枚以上のカードに載っている常在能力に限る。**
1枚にしか無い能力を語にすると、その語を覚えても他のカードで使い回せず、
**カードを読むたびに語の意味を思い出す手間だけが増える**。
語にしない能力は、カードに効果の文をそのまま書く。

カードを追加してある能力が2枚目に載った時点で、語へ昇格させてよい。

### キーワード(語にする常在能力)

| キーワード | 効果 | 載っているカード |
|---|---|---|
| **守護** | 相手はこの砂時計を無視して他を攻撃できない | シールド / ガード |
| **硝子(がらす)** | 最初に受けるダメージを1度だけ無効にする | グラス / ミラー |
| **貫通** | 砂時計を攻撃したとき、超過分が相手プレイヤーへ抜ける | ドリル / ランス |
| **速落(そくらく)** | 場に出た瞬間に砂が2粒落ちる(すぐ攻撃できる) | ダッシュ / ランス |

### 語にしない常在能力

いまは1枚にしか載っていないため、語を使わず効果の文で書く。
2枚目のカードに載せるときに語(毒砂・吸命・連撃)へ昇格させる。

| 能力 | カードに書く文 | 載っているカード |
|---|---|---|
| 毒砂 | ダメージを与えた砂時計を破壊する | ポイズン |
| 吸命 | 与えたダメージぶん自分のHPを回復する | ヴァンプ |
| 連撃 | 1ターンに2回攻撃できる | ツイン |

**カードの面には左右の隅を数値バッジが占めるため、収まるのは4文字程度**しかない。
そこには短い言い換え(「破壊」「回復」「2回攻撃」)を出し、
上の文は詳細パネルとデッキ編集の一覧で読ませる。

### トリガーキーワード

| キーワード | 発動 |
|---|---|
| **設置** | 場に出したとき |
| **反転** | 反転したとき(**この作品固有**。毎ターン行えるため常在効果として値付けする) |
| **余砂(よさ)** | 破壊されたとき |
| **落砂(らくさ)** | 自分のターン終了時(砂が1粒落ちる瞬間) |
| **被弾(ひだん)** | ダメージを受けたとき |

トリガーは能力ではなく**分類**のため、載っている枚数に関わらず語のまま使う
(「設置」はどのカードでも「場に出したとき」を意味する)。
ただし現状、反転は1枚しか無い。カードを足して語の使い回しが効く状態にする。

**落砂と被弾は、盤面に居続けることで繰り返し働くトリガーである。**設置・余砂が
1回で終わるのに対し、この2つは駒が生きているあいだ何度でも発動する。どちらも
**このゲームの土台の挙動をそのまま発火点にしている**点が要で、落砂は毎ターン必ず起きる
砂の落下(3章)に、被弾は必ず相打ちになる戦闘(4章)に乗る。**発動する回数を
プレイヤーが動かせる**(殴りに行けば被弾は増え、守れば落砂が伸びる)ため、
値付けは「1回あたりの効果 × 何回起こせるか」で考える。

### 常在能力の値段(総量換算)

語にするかどうかに関わらず、常在能力は「同じコストのバニラと釣り合うために
総量をいくつ削るか」で値付けする。
値段は**実装したエンジンで測った実測値**であり、測り方と生データは
`docs/BalanceReport_v5.md` 2〜4章に置く。

まず基準となるバニラ(効果なし)の総量は、コストに対してほぼ直線に乗る。

> **バニラの基準総量 ≒ 1.9 + 1.33 × コスト**

| コスト | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 基準総量 | 3.2 | 4.5 | 5.9 | 7.2 | 8.6 | 9.9 | 11.2 |

**最小コストは1とする。**マナは1ターン目に1しか無いため、コスト1のカードが1枚も
無いと1ターン目は構造上どちらのプレイヤーも何も出せず、盤面へ触れないまま1手が過ぎる。

この基準からいくつ削るかが、キーワード・効果の値段になる。

| 能力 / 効果 | 値段(総量) | 性質 |
|---|---|---|
| **貫通** | +0 | 実質無料 |
| **守護** | +0〜1 | 大型ほど**安い** |
| **速落** | +0.6 | 一定・安い |
| **硝子** | +1〜2 | 大型ほど高い |
| **吸命** | +1 | ほぼ一定 |
| **連撃** | +1.6 | ─ |
| 余砂:本体へ2ダメージ | +0.1 | 発動が破壊時まで遅れるぶん、設置より1粒安い |
| 余砂:1枚引く | +0.2 | 同上。**設置(+2)より2以上安い** |
| 落砂:本体へ1ダメージ | +0.9 | 場に残るかぎり毎ターン働く |
| 被弾:1枚引く | -0.1 | **総量そのものが「働ける回数」を買っている**(下記) |
| 攻撃できない | **-3〜-5** | 制約なので総量が増える。ワッチャーはコスト2で総量7 |
| 設置:トークンを1体出す | +0.5 | 盤面の枠を1つ使うぶん、総量を足すより安い |
| 設置:味方1体の総量+2 | +1.9 | ─ |
| 設置:味方1体に守護 | +0.1 | ─ |
| 設置:敵1体の効果を消す | -0.1 | ─ |
| 設置:本体へ2ダメージ | +1.1 | ─ |
| 反転:総量+1 | +1.4 | ─ |
| 設置:1枚引く | +2 | 手札1枚がそのまま展開になる |
| 余砂:トークンを1体出す | +0.2 | 設置版(+0.5)より安い。破壊されるまで働かないため |
| 余砂:味方1体の総量+2 | +1.3 | 設置版(+1.9)より安い。同上 |
| 被弾:本体へ1ダメージ | +0.2 | 総量が「働ける回数」を買っている(下記) |
| 反転:本体へ1ダメージ | +0.6 | ─ |
| 設置:味方1体の攻撃力+1 | +1.2 | ─ |
| 落砂:味方1体の攻撃力+1 | +1.6 | **同じ効果でも設置(+1.2)より高い**。毎ターン働くため |
| 設置:味方全体の砂を1粒落とす | **-0.4** | **総量が増える**。体力を削って攻撃力へ回すため、利点だけではない |
| 落砂:相手全体へ1ダメージ | **+6.9** | プールで最も高い。全体除去が毎ターン続くのに等しい |
| **毒砂** | +3.4 | 常に高い |
| 設置:1体を破壊 | +5.6 | 総量では買いきれない(下記) |
| 設置:全体の砂を2粒削る | +6.2 | 同上 |

**繰り返し働くトリガーは、総量そのものが値段になる。**落砂・被弾を持つカードは、
総量を削ると「働ける回数」まで一緒に削れる。クラック(被弾:1枚引く)は総量6で51%だが、
総量2まで下げると36%まで落ちる。**効果の値段がほぼ0に見えるのはこのためで、
実際には総量が効果の一部を買っている。**普通のカードのように「総量をいくつ削るか」で
値付けできない唯一の型として扱う。

**繰り返しトリガーと「攻撃できない」を重ねた場合だけ、コストで買える。**タワー
(攻撃できない / 落砂:本体2)はコスト5では最小の総量でも61%あり、コスト7で釣り合った。
効果が盤面の大きさに比例しないため、除去(下記4)と違ってコストの引き上げが効く。

**設計指針**

1. **貫通・速落・守護は安く、どのコスト帯にも載せられる。**同じキーワードを持つカードを
   軽重さまざまに量産するのに向く
2. **硝子は大型ほど高い。**守護と硝子はどちらも「大型ほど高い」と考えられていたが、
   実測では**守護は逆**だった(コスト2で+0.6、コスト5で+0.1)。盤面6枠に対して守護1体では
   止めきれず、相打ちで自分も削れるため
3. **効果を砂の移動で表現できるキーワードは、値段が自動的に安くなる**
   (速落は体力-2・攻撃力+2 を自分で払っている)
4. **余砂(破壊されたとき)は、同じ効果の設置版よりはるかに安い。**本体2ダメージで
   1.0、ドローで2.5下がる。破壊されるまで待つぶん遅いことに加え、**盤面へ直接効かない
   効果ほど値段が消える**(引いたカードを使うマナが残っていないことが多い)
5. **毒砂・確定破壊・全体除去は高い。**とくに**確定破壊と全体除去はコストを上げても
   釣り合わない**(ハンマーはコスト5で57.1%、6で56.4%、スイープはコスト8で59.5%、9で60.4%と、
   コストを上げてもほとんど下がらない)。総量は下限に達しており、
   **効果そのものを弱める以外に釣り合わせる手段がない**

### 語彙だけでカードを作らない

**キーワードをコストと総量だけ変えて載せ替えたカードばかりにしてはいけない。**
語彙を使い回せることは追加のコストを下げるための性質であって、カードの面白さの
基準ではない。実際、23種の時点で**バニラ4枚とキーワードだけの10枚で全体の6割**を占め、
残りも「設置で1回だけダメージかドロー」に寄っていた。

**1枚ごとの固有効果を積極的に足す。**手本にするのは、初期のハースストーン・
シャドウバース・ドラゴンクエストライバルズにあるような、**1行で読めるのに他の
どのカードとも重ならない**効果である。長い条件文や複数の分岐を持つカードは採らない。

固有効果を作るために新しい `EffectType` やトリガーを足すことは**禁じない**。
既存の語彙で作れるかどうかより、そのカードが盤面で何を起こすかを先に決める。

**自分の砂時計1体を対象に取る効果は、その効果を持つ砂時計自身を選べない。**
自分を強化できると「他の駒を助ける」というカードの読みが崩れ、対象を選ぶ意味も無くなる。

### 攻撃できない砂時計

**「攻撃できない」という制約を持つ砂時計を作ってよい。**その代わり総量を大きく取る。
反転はできるため、**攻撃力の高い状態を体力へ戻す壁**として働き、守護とは違う守り方になる。
制約は語(キーワード)にせず、カードに「攻撃できない」と書く。

### 砂時計を出す効果(トークン)

**効果で場に出る砂時計(トークン)を作ってよい。**空き枠が無い場合は出ない。

- **トークンはデッキに入れられず、砂時計一覧にも出さない。**集めるものではなく、
  効果の結果として現れるものだから。一覧に並べると「持っていないカード」と
  見分けが付かなくなる
- **その代わり、トークンを出すカードの詳細に、出るトークンの中身を1行で添える。**
  一覧にも辞書にも無い以上、**そのカードの側で説明しないと何が場に出るのか調べる
  手段が無い**(「モートを1体出す」とだけ書かれても、モートの総量も効果も分からない)。
  出すのは名前・総量・効果と、デッキには入れられないという断りだけにする
- トークンも通常の砂時計と同じく、毎ターン砂が落ち、反転でき、破壊される

### 1枚だけの固有効果

上の「語にしない常在能力」と同じ考え方で、1枚だけの固有効果は文章のまま持たせる。**盤面の広がりを参照する効果は逆転装置として働く**ため、
プールに2枚程度含める(実測で逆転率が14%から25%へ上がる)。

### 砂術(スペル)

**盤面へ出ず、効果だけを起こして墓地へ行くカードを作ってよい。**呼び名は
**「砂術(さじゅつ)」**とする(「魔法」はこの作品の語彙に無いため)。

- **総量・体力・攻撃力を持たない。**持つのは**コストと効果の文だけ**
- **盤面の枠を使わない。**6枠がすべて埋まっていても撃てる。
  「空き枠が1つも無い間はどのカードも暗くする」(9章)の**唯一の例外**とする
- 撃った砂術はそのまま墓地へ置く。反転も攻撃もせず、盤面に残らない
- トリガーを持たない。**効果は撃った瞬間に1度だけ解決する**
- デッキには通常どおり入り、同名2枚まで。砂時計一覧にも並ぶ
- **砂術は「砂時計」ではない。**以後、カード全体を指すときは「カード」、
  盤面へ出るものを「砂時計」、出ないものを「砂術」と書き分ける

**砂術の値付けは、コストではなく効果そのもので行う。**この章のバニラ基準線
(`1.9 + 1.33 × コスト`)は総量を持つ駒のための式であり、砂術には使えない。
砂時計と同じ方式(そのカード2枚を含むデッキ vs 含まないデッキ)で勝率を測る。

**ただし、砂術はコストを動かしても勝率がほとんど変わらない**
(`docs/BalanceReport_v5.md` 10.2節)。確定破壊・全体除去がコストを上げても
釣り合わないのと同じ壁が、**弱い側にも出る**——最小コストは1であり、
弱すぎる砂術を安くして釣り合わせる余地が無いためである。
実測では、コストを1から3へ動かしたときの差が測定誤差(±5pt)より小さかった。
**したがって砂術を釣り合わせる手段は、効果の数値か効果そのものを書き換えることしかない。**

**測るときは、同じプールで測り直した砂時計と並べること**(同10.3節)。
この方式は釣り合っているカードでも45〜50%に出るため、砂術が43〜48%に出たときに
「弱い」と早合点しない。

**確定破壊と全体除去を砂術にしてはいけない。**総量を持たない砂術はコストでしか
釣り合わせられないが、除去はコストを上げても釣り合わないことが実測で出ている
(`docs/BalanceReport_v5.md` 4.2節)。**釣り合わせる手段が1つも残らない**ため、
砂術の除去は「1体に固定ダメージ」「全体に固定ダメージ」までとする。

**砂術も、語彙の載せ替えだけでプールを埋めない。**砂時計と同じ方針(この章「語彙だけで
カードを作らない」)を適用する。**既存の設置効果を砂術へ移すこと自体は禁じない**——
同じ効果でも「駒を残さない代わりに規模が大きい」という取引になるため、
盤面へ残るカードとは選択が変わる(ソードの「設置:本体へ2ダメージ」と、
同じダメージだけを撃つ砂術は別のカードとして成立する)。

**ただし、そればかりにしてはいけない。**砂術は数を絞る以上、
**少なくとも3分の1は「盤面へ駒を置かないからこそ成立する効果」**にする。
駒には持たせられない効果——1ターンの行動回数の制限を無視する、盤面から駒を取り除いて
手札へ戻す、盤面全体の状態をまとめて裏返す——がここに当たる。

## 7. バランスの目標値

自己対戦シミュレーションで次のレンジに収まることを確認する。
測り方と生データは `docs/BalanceReport_v5.md` にある。

| 指標 | 目標 | 現状(70枚・デッキ30枚) | 参考(砂術を足す前・58種) |
|---|---|---|---|
| 先手勝率 | 45〜55% | **56.1%** | 57.0% |
| 決着手数 | 20〜30手 | 23.2手 | 23.6手 |
| 本体ダメージで決着した割合 | 90%以上 | 99.9% | 99.9% |
| ユニットへの攻撃の割合 | 30〜60% | 50.6% | 54.5% |
| 逆転率(中盤劣勢からの勝率) | 25〜35% | **35.8%** | 35.1% |

現状は**基本セット70枚・デッキ30枚**での実測(800戦×シード42/43 = 1600戦)。
**砂術12種を足しても全体の形は動かなかった**(いずれも1〜4ポイント以内)。

**デッキを20枚から30枚へ増やした時点で、それ以前の実測値はすべて無効になる。**
枚数はマリガンの事故率・疲労・引きの分散のすべてに効くため、2章の枚数を動かしたら
必ず測り直すこと(実際、20枚のときの値を残したまま30枚へ移した回があり、
仕様書だけが古い数字を指していた)。

**30枚化で疲労による決着がほぼ消えた**(97.1% → 99.9%)。山札が1周する前に決着が
つくようになったためで、決着手数はほとんど変わっていない。

**先手勝率が57.0%と、目標(45〜55%)を2ポイント超えている。**30枚にしたぶん軽い受けを
引ける確率が下がり、後手が1手の遅れを取り返しにくくなったと見られる。**手番の補正は
足さない**(下記のとおり効き幅が大きく、重ねると必ず行き過ぎる)。次にプールを触る回に、
まずコストの分布のほうを見て測り直す。

**「本体ダメージで決着した割合」を必ず測ること。**この値が低い場合、対局が
デッキ切れ(疲労)で決まっており、カードゲームとして成立していない。

**先手勝率と逆転率は連動する。**盤面の広がりを参照する逆転カード(スイープ・スウォーム)は
構造的に後手を利するため、片方だけを見て調整すると取り違える。
手番の補正はどれも効き幅が大きい(コイン・1ターン目のドローなしはいずれも約22ポイント、
後手の手札1枚あたり約7ポイント)。**複数を重ねると必ず行き過ぎるため、1つだけ選ぶ**。

**カード1枚の強さを測るときは、混成デッキ同士の平均勝率を使ってはいけない。**
プールから30枚を引くと1デッキに15種前後が入り、1枚の差が勝率へ現れない。
「そのカード2枚を含むデッキ」と「含まないデッキ」を直接ぶつけて測る。

## 9. UI設計メモ

- 画面レイアウトは横長(16:9目安、デスクトップブラウザでのunityroomプレイを主眼)とする。基準解像度は1280x720とし、アスペクト比を維持したまま拡縮する
- **対局画面を除く全ての画面は、共通のレイアウト規約に従う**。画面の外周余白は24px、画面上部に高さ88pxの共通ヘッダーを置き、その下に24pxの余白を取ってコンテンツ領域を始める(コンテンツの開始位置は全画面でy=136に揃う)。ヘッダーの構成は**左=戻るボタン / 中央=画面タイトル / 右=その画面の主アクション(0〜3個)**で固定する。画面ごとにヘッダーの高さ・位置・余白を個別に決めることはしない。これは、画面ごとに絶対座標で個別にヘッダーを組んだ結果、戻るボタンの位置もコンテンツの開始位置も画面ごとにばらついていた状態を解消するための規約である
- **一覧を表示する画面では、1画面に収まる件数を優先して横2列のグリッドを基本とする**。縦1列にすると1画面に2〜3件しか入らず、目的の項目を探すのにスクロールを強いるため。件数が少ないうちに縦へ間延びしないよう、一覧のカード自体も横長・低背にする
### 対局画面

- **対局画面は上から順に「相手の情報帯 / 相手の場(6枠)/ 自分の場(6枠)/ 自分の情報帯 /
  自分の手札」で構成する**。盤面を挟んで対面させる点は従来と同じだが、**手札は情報帯より
  外側(画面最下部)に置く**。手札は最も頻繁に触る領域であり、盤面と混ざらない位置に固定する
- **12枠の盤面は1枚の卓上として描く**。奥へわずかに狭まる石と真鍮のテーブルを置き、その上に
  相手側6枠・自分側6枠を並べ、中央に真鍮の区切り線を通す。枠を宙に浮かせず1つの卓へ載せる
  ことで、盤面が「対面して物を置き合う場」として読める。テーブルの外側は暗く落とした背景と
  し、視線が盤面へ集まるようにする
- **情報帯にはHP・マナ・山札の残り枚数・墓地の枚数を並べる**。相手側は手札の枚数も出す
  (中身は伏せる)。**相手の手札を裏向きカードの列として並べることはせず、数字1つで示す**。
  6枠の盤面と30枚のデッキを同時に置くと画面が狭く、裏向きカードの列に幅を割けないため
- **名前プレートにはアイコン・称号・表示名を並べる**。プレイヤーのアイコンを左端に丸型で置き、
  名前の上に小さな文字で称号を表示する。相手側も相手のアイコンと称号を表示し、
  CPU戦ではCPU専用アイコンと「AI思考体」などの称号を表示する
- **マナは数字とピップ(粒)の併記とする**。「3/7」の数字だけだと、支払える手札を見比べる
  操作が読みにくいため。上限10まで横に並べても情報帯の幅に収まる
- 山札・墓地は枚数のバッジを持つ小さな山として置き、押すと墓地の中身を一覧できる。
  山札の中身は見られない
- **手札のカードと、場に出た砂時計は別の見た目にする**。手札は「まだ手に持っている札」で
  あるためカードの枠を持つが、**場に出た瞬間に枠を捨て、台座の上に立つ砂時計そのものになる**。
  砂時計はそれ自体が状態を表示する器であり(上の砂=体力 / 下の砂=攻撃力)、枠へ閉じ込めると
  絵が小さくなって**砂の量というこの作品で最も重要な情報チャネルが潰れる**。また、中心となる
  行動である反転は「砂時計をひっくり返す」ことであり、枠が固定されたまま中身だけが回ると
  演出が嘘になる。手札はカード・場はミニオンという形は既存のDCGでも標準であり、慣習からも
  外れない
- **数値の配置は既存のDCGの慣習にそのまま合わせる**。手札は**コストが左上・総量が右下**、
  場の砂時計は**攻撃力が左下・体力が右下**で、**場ではコストを表示しない**(既に支払い済みで
  読む必要がないため)。砂時計の上下の部屋(上=体力/下=攻撃力)へ数字の位置を対応させる案は
  採らない。**初見のプレイヤーが他のカードゲームで身につけた読み方をそのまま持ち込めることの
  ほうが、モチーフの一貫性より価値が高い**ためで、慣習から外れた配置は覚え直しのコストを
  全プレイヤーへ課す
- **盤面の6枠は、カード型のスロットではなく丸い台座として描く**。空き枠は台座だけが置かれた
  状態になり、そこへ砂時計が立つ。カード型の枠を並べると、出した後も「カードが置いてある」
  ように見えてしまう
- **イラストは体力と攻撃力の比で3枚を切り替える**。攻撃力が体力より少ないうちは上向き、
  拮抗しているときは落下中、攻撃力が体力を上回ったら落ちきりの絵にする。連続値である
  体力/攻撃力を3段階へ量子化して見せる。**場ではこの絵を大きく表示し、砂の量を数値と並ぶ
  主要な情報として扱う**。**モチーフを生かすのはこの絵と演出の側であり、数値の読み取りには
  持ち込まない**
- **砂時計の絵は1組(3状態)だけを持ち、カードごとの色は数値として持つ**。全58種が同じ絵の
  色違いである以上、色違いを焼いた画像を種類の数だけ配布する理由が無い。**カードが持つのは
  「元にする絵のid」と「色相の回転量・彩度・明度」であり、実際の絵は起動時に1組から作る**。
  これにより、**カードを何種増やしても配布物の大きさは増えない**(色の数値が1行増えるだけ)。
  砂時計の絵は配布物の7割を占めており、毎日カードを足す運用ではここが積み上がり続ける
  - **後から固有の絵を用意したくなった場合は、そのカードぶんの画像を置けばそちらが優先される**。
    色違いで足りないカードだけを個別の絵に差し替えられる状態は維持する
  - **色の数値は、いま配っている絵から逆算したものを初期値とする**。ソード・シールドなど
    9種は作られた経緯の記録が無いため逆算した近似であり、**輪郭のコントラストがごくわずかに
    緩む**。同じカードとして読める範囲であることを、現行の絵と並べて確認したうえで採った
- **カード1枚ごとに固有の紋章(モチーフのアイコン)を添える**。砂時計のイラストは全種で
  **共通の1枚を色違いにしたもの**であり、色相の違いだけでは20種を超えたあたりで見分けが
  つかなくなるため。紋章は**そのカードのモチーフ**(サンド=砂時計 / アイ=目 / ポイズン=髑髏 /
  ウォール=煉瓦の壁)であって、能力の分類ではない。能力の系統を表す共通の紋章を数種類作って
  使い回す案は採らない。カードが増えるほど互いに似通っていき、**1枚ごとの個性を立てるという
  目的と逆に働く**ため
- **50種になった時点で、色相だけでは砂時計を見分けられない。**実測した代表色相の並びでは、
  50種を色相環へ均等に置いても隣との差は 0.02 しかなく、既に swarm と dash は 0.01 差で
  並んでいる。**したがって見分けているのは紋章であり、色は「同じ絵に見えないための下地」に
  過ぎない**。彩度を2段(鮮やか / くすんだ)に分けて実質の置き場を倍にしてあるが、これも
  100種までは保たない。**種類がさらに増えるときは、色ではなく枠の形か装飾を変える手段を
  用意する**(色相をさらに刻む案は採らない。刻んでも人間が見分けられないため)
- **紋章の置き場所は、砂時計そのものの装飾ではなく「砂時計を載せている側」とする**。
  場では**台座の正面に据えた真鍮のメダル**、手札では**カード左下に押した封蝋の印**、
  詳細パネルでは名前の左に大きく出す。手札=紙の札 / 場=台座に立つ物体という二層構成に
  それぞれ馴染む形を選んでいる。**駒の背後に大きな紋章の透かしを敷く案は採らない**。
  場の駒は128x168pxしかなく砂時計の絵がほぼ全面を占めるため、はみ出した縁だけが見えて
  散らかった(実際に描画して確認した)
- 紋章の素材は**商用利用可・クレジット表記不要**の外部アイコンから取る。出所は
  `assets/CREDITS.md` へ必ず記録する
- **キーワードは短いラベルとして並べる**(「守護」「硝子」など)。紋章にはしない。7種あり
  複数持つカードもあるため、絵柄で覚えさせるより語で読ませる。手札はカードの下端、場は
  台座の下に置く
- **守護は形でも示す**。手札ではカードの枠を太くし、**場では台座の輪を太い真鍮にする**。
  **ただしこの強調を出すのは対局画面だけとする**。砂時計一覧やデッキ編集のように
  カードを並べて見比べる画面では、守護のカードだけ枠が太いことが意味の無い強調に見え、
  選択中の枠とも紛らわしい(一覧で読みたいのは能力の欄であり、対象選択は存在しない)。
  攻撃の対象選択に直接効くため、ラベルだけでは足りない。**硝子が残っているものには薄い光の膜を
  重ねる**(1度使うと消える)。場では枠ではなく**砂時計のガラスそのものに膜を掛ける**
- 出したターンのもの(反転も攻撃もできない)は僅かに沈んで見せ、**このターンに攻撃済みの
  ものは彩度を落とす**
- **出す**:手札のカードを押す → 空き枠が光る → 枠を押すと出る。マナが足りないカードは
  手札の時点で暗く表示し、押しても光らせない。**空き枠が1つも無い間は、どのカードも
  暗く表示して出せなくする**(上書き設置は行わないため)
- **設置効果が相手1体を対象に取る場合**、出した直後に相手の場が対象選択の状態になる。
  対象がいない場合は選択を挟まずそのまま出る
- **反転**:自分のカードを押す → その場に「反転」ボタンが出る → 押すと入れ替わる。
  1体につき1ターン1回・出したターンは不可であり、できない場合はボタンを出さない。
  **ボタンは選んだ駒のすぐ下へ出す**。画面右の行動の列へ置くと、盤面から離れていて
  視線とカーソルを往復させることになる。**上ではなく下なのは、自分の場の上が相手の場**
  であり、上へ出すと相手の駒へ重なるため。駒の下端と自分の情報帯のあいだへ収まる高さに
  して、HP・マナ・山札を隠さない
- **攻撃**:自分のカードを押した状態で相手のカードか**相手のHP帯**を押す。ドラッグでも
  同じ操作ができるようにする。攻撃できる対象だけを光らせ、**守護がいる間は守護のカード
  以外が光らない**
- **対局が始まる前にマリガン画面を挟む**(2章)。盤面の上に暗幕を敷き、初期手札を中央へ大きく
  並べて「引き直すカードを選んでください」と示す。カードを押すたびに選択が切り替わり、
  選ばれたものは沈んで暗くなり、**砂時計を裏返した印**を重ねる。右下の確定ボタンは選択が
  0枚なら「このままで開始」、1枚以上なら「n枚を引き直す」と文言が変わる。確定した後は
  相手を待つ状態になり、両者が確定した時点で対局が始まる。**相手が何枚交換したかは出さない**
- **攻撃の対象を選んでいる間、双方の予測後の数値を出す**。攻撃する駒と、光っている
  相手の駒それぞれに「この攻撃の後どうなるか」(体力の減り方・破壊されるかどうか)を
  重ねる。**戦闘は相打ちである以上、攻撃は必ず自分も削る**(4章)ため、
  「この攻撃で自分も死ぬのか」が毎回の判断の中心になる。暗算させない
- **手札のカードはホバーで拡大して見せる**。手札の札は小さく、効果の文が読めない。
  カーソルを乗せている間だけ手前へ大きく浮かせる(押す操作は変わらない)
- **手札からは、押して枠を選ぶ操作に加えてドラッグでも出せる**。攻撃が既に
  ドラッグに対応しているため、盤面へ物を置く操作だけがクリック限定なのは揃わない
- **砂術は砂時計の絵を持たない**(6章)。手札では砂時計の絵の代わりに**紋章を中央へ大きく**
  置き、**総量のバッジを出さない**(コストの左上だけ)。**枠の色を砂時計と変える**ことで、
  手札を見た時点で「これは置くカードではない」と分かるようにする。**盤面には出ないため、
  場での見た目は存在しない**
- **砂術を押すと、空き枠ではなく対象が光る。**対象を取らない砂術はその場で発動する。
  ドラッグでも撃てるが、落とす先は空き枠ではなく対象(対象を取らないものは盤面のどこでもよい)。
  **空き枠が無くても暗くならない**(6章の例外)
- **砂術の効果は、自分の情報帯から対象へ光の筋を伸ばして見せる**(設置効果と同じ語彙)。
  出どころの駒が盤面に無いため、余砂と同じく陣地の側から出す
- **砂術は撃った瞬間に墓地へ置く**。手札から消えただけに見えないよう、
  カードが中央で一度大きくなってから墓地へ吸い込まれる動きを挟む
- **ターン終了は画面右の行動の列の中ほどに置く大きなボタンとし、その下に「ログ」「投了」
  「エモート」を順に並べる**。列の中ほどなのは、盤面(上)と手札(下)のどちらからでも
  同じだけの距離で届くため。**列そのものを画面の中央へ移すことはしない**(盤面の幅が
  そのぶん削れる)。
- **対局中にエモート(短文の意思疎通)を送れる**。画面右の操作列に「エモート」ボタンを置き、押すと4つの選択肢が開く。**このボタンは「ログ」「投了」とまったく同じ寸法・同じ作りにする**(同じ列に並ぶ以上、数pxでも違うと1つだけ別物のボタンに見える。クールダウン中も文言の頭は「エモート」のままにし、残り秒数を後ろへ添える)。選択肢は真鍮枠のパネルに1行ずつ並べ、行頭に菱形の印を置く。選択すると即座に送信され、発言者の名札付近に真鍮枠の吹き出しとして約3.8秒間(完全不透明で3.0秒)表示されたあとフェードアウトする。送信後は吹き出しが完全に消えて余韻を待つ9秒間のクールダウンを設ける。
  - **よろしくお願いします** (挨拶)
  - **見事な一手です** (賞賛)
  - **なんだと…** (驚き)
  - **こちらに傾いているようですね** (挑発・優勢)
  - **マリガン中はエモートを送信できない**(対局開始後に打てるようになる)。**この間はボタン自体を出さない**。押せないボタンは無効の見た目になり、真鍮のまま並ぶ「ログ」「投了」の隣でそこだけ色が違って見えるため。
  - **相手のエモートをミュートする機能**を用意する。エモート選択ポップアップ内で切り替え可能とし、ミュート中は相手から届いたエモートの吹き出しを表示しない。
  - CPU戦でもプレイヤーから送信可能で、CPU側も状況や低確率で返答することがある
- **攻撃は、駒が対象の斜め上まで渡っていき、反動をつけて当てる**。盤面を挟んで対面している
  以上、攻撃は「線を引く」ものではなく「渡っていく」ものであり、場の駒を枠から出して台座に
  立てた構成をもっとも活かせる場面がここになる。動きは4段で構成する。

| 段 | 動き | 尺の目安 |
|---|---|---|
| 寄る | 台座を離れ、対象の**斜め上**まで移動する。等速では機械的に見えるため、出だしを速く終わりを緩める。**駒は上端をつままれてぶら下がっている**ものとして、移動の慣性ぶんだけ下端が遅れて振れる | 0.28秒 |
| 溜める | その場で上端を支点に**振り子のように後ろへ傾く**。ガラスの中の砂も傾きに合わせて寄る | 0.14秒 |
| 当てる | 支点はそのままに振り下ろし、対象へ**コツンと当てる**。叩き潰す動きにはしない。当たった瞬間に接触点で閃光と砂の破片を散らす | 0.10秒 |
| 戻る | 数回小さく揺れながら台座へ戻り、静止する | 0.30秒 |

- **相打ちは、当たった瞬間に防御側も同じだけ砂を散らし、押し返された反動で揺れる**ことで示す。
  攻撃した側も必ずダメージを受けるため、一方的に見える演出にしない。**以前は「双方のカードが
  中央でぶつかる」としていたが、攻撃側だけが渡っていく形へ変更した**。誰が仕掛けたのかが
  明確になり、防御側は迎え撃つのではなく受けるという関係もルールと合うため
- **相手プレイヤーを直接殴る場合も同じ動きとし、対象がHPバーになるだけにする**。
  「守護がいなければ本体を殴れる」という選択が、盤面の駒を殴るときと同じ語彙で見えるようにする
- **貫通は、砕けた対象を通り抜けてそのままHPバーまで届く**。超過分が本体へ抜けるという
  固有の挙動を、動きそのもので示す
- **連撃は、1回目が台座へ戻ってから2回目に入る**。2回目は下記のとおり尺を6割へ詰めるため、
  続けて2回叩いたことは間合いで読める。**動きを重ねる案は採らない**。攻撃の演出中は
  入力とCPUの続きを止めており、重ねるには「戻りの途中から次の攻撃を受け付ける」形へ
  演出の進行を作り替える必要がある。得られるのは0.3秒ほどの短縮でしかない
- **同じターンで2回目以降の攻撃は、尺を6割へ詰める**。1回目で動きは理解されており、
  以降は結果だけ追えればよいため。連撃や6枠が並ぶ中盤で1ターンが冗長になるのを防ぐ
- 攻撃の演出中は盤面の操作を受け付けない
- **消える砂と落ちる砂を、演出で明確に分ける**。被ダメージで消える砂は砕けて散り、ターン
  終了時に落ちる砂は下の部屋へ流れる。この2つを取り違えるとルール(4章)を誤解するため、
  **演出上もっとも重要な区別として扱う**
- ターン終了時、自分の全ユニットの砂は**同時に**1粒落とし、破壊されたものだけを続けて見せる
  (6枠あるため1体ずつ順送りにすると長い)
- **破壊された砂時計は、砕けて台座へ崩れ落ちる**。ガラスが割れ、残っていた砂が
  台座の上へこぼれてから消える。**「破壊されたものだけを続けて見せる」(上記)の
  「見せる」がこれにあたる**。以前は次の描画で駒が黙って消えており、盤面から1体
  減ったことに気づけなかった。ターン終了時に複数が同時に壊れた場合も同時に見せる
- **場に出した砂時計は、台座の少し上から落ちて着地する**。接地の瞬間に足元へ砂が舞う。
  出す操作は1手番のうち最も回数が多いにもかかわらず、駒が音も動きも無く現れていた。
  **落とすのは、盤面が「対面して物を置き合う場」であるという構成に沿うため**
  (9章の卓上・台座の考え方と同じ)
- **設置効果は、出した駒から対象へ光の筋を伸ばし、届いた瞬間に効果を見せる**。
  反転の光の筋(下記)と同じ語彙を使い、**色で区別する**(反転=金 / 効果=対象に応じた色)。
  相手プレイヤーを狙う効果は相手のHPバーへ、砂時計を狙う効果はその駒へ伸ばす。
  全体に効く効果(スイープ)は対象の数だけ同時に伸ばす。数値だけが黙って変わると、
  どのカードが何をしたのかを対局ログを開くまで追えないため
- **硝子が最初のダメージを無効にしたとき、膜が割れる閃光を出す**。硝子は1度きりの
  効果でありながら、膜が音も光も無く消えるだけだった。**割れたことがその場で分からないと、
  次の攻撃が通るかどうかを判断できない**
- **ドローは山札から手札へ札が流れる動きで見せ、疲労は山札そのものを赤く脈打たせる**。
  ダメージの発生源を示す方針(下記)の例外として、疲労だけは発生源が駒ではなく山札に
  あたるため、山札を光らせてからHPバーへ数字を飛ばす
- **手番の切り替わりを画面で示す**。自分の手番になった瞬間、盤面の中央に「あなたの番」を
  一瞬だけ大きく出して消す。相手の手番の間は相手の情報帯を光らせ、自分の情報帯を落とす。
  **手番はゲームでもっとも頻繁に変わる状態でありながら、押せるボタンの有無からしか
  読み取れなかった**ため追加した
- **相手の1手は、1手ずつ見せる**。相手(CPU・オンライン)の手を適用したら、対象の駒へ
  スポットライトを当て、**対局ログと同じ文言**をその駒の近くへ短く浮かせ、間を置いてから
  次の手へ進む。CPUは短い間隔で続けて指すため、まとめて適用すると盤面が一瞬で書き換わり、
  何をされたのかがログを開かないと追えない。文言はログと共通の組み立てを使い、
  実況とログが食い違わないようにする
- **選択は右クリックまたはEscでも取り消せるようにする**。「他を押す」以外に戻る手段が無いと、
  対象選択に入った後の抜け方が分からない
- **まだ攻撃できる自分の駒に控えめな印を出す**。このターンに攻撃済みの駒は彩度を落として
  区別しているが、その逆(まだ動ける)を示していないため、6枠が並ぶと押し忘れる

- **反転は、誰がその駒に手を出したのかが分かる演出にする**。反転を行った側の陣地から対象の駒へ向かって光の筋が伸び、それが届いた瞬間に駒が持ち上がって回転し着地する。相手の駒を反転させた場合、盤面を挟んで手を伸ばしたように見える。反転は駒がその場で回るだけで「自分がやったのか相手にやられたのか」を実況テキスト以外から読み取れなかったため追加した。**反転はゲームの中心となる行動であるため、演出は他より作り込む**。光の筋が届いた瞬間の着弾の衝撃、回転中のガラスと砂の反射、着地時の余韻までを含めた一連の流れとして見せる
- **対局中に何が起きたかのログを確認できるようにする**。各手番で誰がどのアクション(出す/反転/攻撃)を行ったか、ターン終了時の砂の進行で何が起きたかを記録して表示する
- **対局ログには決着そのものも1手として記録する**(「先手の勝利(後手のHPが0)」「先手の勝利(後手の投了)」など)。ログだけを追っても、何が起きて勝負が決したのかが分かる状態にする
- HPは常時バー表示する。**相手のHPは画面上部、自分のHPは画面下部**に配置し、盤面を挟んで対面させる。ダメージ発生時はフローティング数字で演出する。発生源の駒が特定できる場合(砂時計が落ちきったことによるダメージ)は、その駒の位置からHPバーへ向けて数字を飛ばし、原因の駒自体も一瞬光らせることで、1手の中で複数のダメージがほぼ同時に発生した場合でも何が原因か個別に追えるようにする。発生源が特定できない場合はHPバー付近から浮かせるだけに留める
- **対局中の砂時計・手札の効果詳細は、マウスホバーではなくクリックした時のみ表示する**。ホバーで自動ポップアップすると他の砂時計や盤面が覆われて見づらくなるため、プレイヤーが意図してクリックした時だけ詳細パネルを開く。
  - **手札のカード**: クリックで詳細を表示(プレイ可能な場合は従来通り出せる枠も光り、プレイ不可の場合でも詳細が表示される)
  - **自分の場の駒**: クリックで詳細を表示(行動可能な場合は従来通り反転ボタンや攻撃対象選択となり、行動済みや相手番でも詳細が表示される)
  - **相手の場の駒**: 対象選択モードでない通常時や相手手番中にクリックすると詳細を表示する(攻撃・効果の対象選択中は攻撃や効果適用が優先される)
  - **詳細の閉じ方**: 詳細パネルの外側をクリック、右クリック、Escキー、手番進行などで閉じられる。別のカードをクリックした場合はそのカードの詳細に切り替わる
  - ※手札カード自体のホバー時の軽微な手前拡大(`hover_zoom`)は、カード単体の視認性向上のため維持する
- クリックできる要素(駒・カード・各種リストのカード等)は共通の挙動を持つ。ホバーするとわずかに明るく浮き上がりカーソルが指マークに変わり、押し込むとわずかに縮み、**要素の上で離した時のみ**操作が確定する(外へ出して離すとキャンセル)。操作できない状態(相手の手番待ち・観戦・リプレイ再生中など)ではホバー表現・カーソル変更を行わない
- **対局が終了したら、盤面の上に結果パネルを重ねて表示する**。パネルには勝敗・両者の最終HP・その対局の総手数・決着の要因(3章)と、「もう一度」「ログ」「ホームへ」の3つのボタンを置き、背景を暗くして盤面の操作を受け付けなくする。これは対局モード(ローカル/オンライン/CPU戦)と観戦モードで共通とする
- **「もう一度」は同じデッキでもう1局始める**。**連戦の導線が無いと、CPU戦を続けて遊ぶだけで
ホーム→バトル→CPU戦→デッキ選択と4手戻ることになる**。**当面はCPU戦にだけ置く**。
オンライン対戦の再戦は相手の同意を取り交わす仕組みが要り、片方だけが待ち続ける状態を
作りやすいため、別途設計する。観戦・リプレイ再生では出さない。

**対局が終了した後もログを確認できるようにする**。結果パネルの「ログ」ボタンから、対局中と同じログを開く。ログは結果パネルより手前に重ね、閉じると結果パネルへ戻る。終局後は結果パネルが盤面全体の操作を塞ぐため、対局中の導線(画面下部中央のログボタン)からは開けないことを補う
- ただし**リプレイ再生モードでは結果パネルを出さない**。再生中は自由に手を前後できることが目的であり、最後の手まで進めるたびにパネルで操作を塞ぐと再生の妨げになるため。リプレイからは既存の戻るボタンで一覧へ戻る
- **起動して最初に出るのはタイトル画面とする**。ゲーム名は「砂時計アリーナ」。画面のどこか(またはEnter/Space)を押すとホーム画面へ移る。タイトル画面に置くのはこの開始の導線と、アカウントへの入口(14章)だけとし、機能はホーム画面側へ集約する。ホームからタイトルへ戻る導線は設けない(タイトルは起動時の入口であって、行き来する画面ではないため)
- **タイトルロゴは王道クラシカルな路線とする**。金の箔押し文字に濃紺の縁取りを重ね、上に砂時計の紋章、下に飾り罫を通す。**英字のサブタイトルは置かない**(語感が作品の路線に合わないため。ジャンルを伝える必要があるときは、ロゴではなく公開先のサムネイル・説明文で行う)。**ロゴは作品の絵そのものであるため、UIクロームと違い画像アセットとして扱う**(砂時計・背景イラストと同じ分類)。ただし画像の生成はユーザーの手作業で行う運用のため、**画像が未配置の間も同じ構図をコード描画で表示して画面が成立する状態を保つ**。背景も同様にタイトル専用の絵があればそれを使い、無ければホーム画面の背景を流用する
- **タイトルからホームへ移るときだけは、他画面のクロスフェードではなく専用の演出を使う**。画面を上から金色の砂が満たし、覆いきった時点で画面を差し替え、続けて砂が下へ抜けて次の画面が現れる。砂時計というモチーフをそのまま画面の切り替えに使うことで、ゲームの世界に入る瞬間を印象づける。押した瞬間はロゴが一度光って伸び上がり、押したことが分かるようにする
- 起点として**ホーム画面**を用意し、機能を切り替えられる構成とする(大手DCG/ソシャゲに近いUI構成)。タブ切り替えは画面下部の3ボタン(アイコン+ラベル)方式とし、左から「ルール」「デッキ」「バトル」を並べる。選択中のタブのボタンは他より大きく表示し、現在地を視覚的に強調する。将来のタブ追加を見据え、拡張しやすい構造にする
- **初回起動時のみ「ルール」タブを初期選択とし、2回目以降は「デッキ」を初期選択とする**。ルールを読ませることは強制せず、最初に一度だけ目に入る位置へ置くに留める。ブラウザで遊ぶ以上、ルールが分からないまま離脱されることが最大の損失である一方、読了を必須にすると既にルールを知っているプレイヤーへ毎回1手を課すことになるため、その中間を取る。読んだかどうかではなく**一度でもホーム画面を開いたか**で判定する(読了を測ると、ルールを閉じただけの人に何度も出てしまうため)
- 画面遷移はハードカットではなく短い**クロスフェード**(0.2秒未満)でつなぐ。ランダムマッチ・ルーム作成・観戦確認など通信待ちの間は、ステータス文言の末尾に巡回するドット(「.」→「..」→「...」)を添えて、処理が生きていることを示す
- **ルールタブは「遊んで覚える」と「読んで覚える」の2つの枠に分ける**。前者に誘導対局
  (18章)、後者に「遊び方」(16章)・「画面の見かた」(20章)・「キーワード辞書」(17章)を
  横並びで置く。**入口を縦に4つ並べる形は採らない**。タブの高さは下部タブとアカウント帯に
  挟まれた448pxしかなく、4行では収まらない。加えて、**実際に手を動かして覚える道と
  読んで覚える道は性質が違う**ため、同じ列に並べるより枠を分けたほうが選びやすい
- **デッキタブ**:左側に大きな「デッキ編集」ボタン、右側に縦2列で「砂時計一覧」「ショップ」ボタン(アイコン+ラベル)を配置する。**ショップは今回はアイコン配置のみとし、タップ時は「近日公開」等の未実装案内を表示する。通貨(砂金)は15章で定義したが、購入対象が未設計のため引き続き実装しない**
- **ホーム画面のヘッダーに、アカウントのボタンと砂金の残高を並べて置く**(14章・15章)。残高は対局から戻るたびに更新する。アカウントボタンには表示名(未設定なら「ゲスト」)を出し、押すとアカウント画面へ移る
- **対局の結果パネルに、その対局で獲得した砂金を表示する**(15章)。勝敗・最終HP・総手数・決め手と同じパネル内に1行として置く
- **バトルタブ**:「ランダムマッチ」「ルームマッチ」「CPU戦」ボタンを大きく配置する(既存のランダムマッチ/ルームコード導線を大型ボタン化)。**これらのボタンを押すと、マッチングキューへの参加・ルーム作成・CPU戦の開始より先に、使用するデッキを保存済みデッキから選ぶ画面を挟む**。前回選んだデッキが初期選択値として引き継がれるが、対局のたびにここで選び直せる。**デッキを1つも保存していない場合は選択画面を挟まず、プリセットの「基本」で対局へ入る**(18章)。選ぶ対象が存在しない状態でボタンを押せなくすると、初めて遊ぶ人が30枚を組み終えるまで一度も対局できないため。**ただしルームマッチだけは専用の画面(11章)へ入り、使うデッキはその画面の中で選ぶ**。相手を待つ間にも選び直せるほうが自然なため、共通のデッキ選択画面を先に挟まない
- **砂時計一覧画面**:現在定義されている**全種類**の砂時計を表示する。**保有していないものも含めて全種類を表示する**(将来追加予定のショップ・収集要素と連動させる設計の布石)。なお現状は「保有/未保有」を区別する仕組み自体が存在しないため、当面は全砂時計を通常表示とし、未保有の視覚的な区別表現は収集要素の実装時に改めて設計する。一覧から選択すると詳細パネル(イラスト・名前・コスト・総量・キーワード・効果)を表示する。この詳細パネルは共通コンポーネント化し、デッキ編集画面や将来的な対局中の参考表示にも流用する
- **砂時計一覧の並び順を切り替えられる**。既定は**コスト順**(同コストは総量の小さい順 → id順)で、
  もう一方は**追加順**(プールへ加えられた順。新しいカードほど後ろ)。毎日カードが増える運用のため、
  「軽いものから見比べる」ときと「最近増えたものを見に行く」ときで求める並びが違う。切り替えは
  ヘッダー右の主アクションに置いたボタン1つで行い、押すたびに2つを往復する。**選んだ並び順は
  保存しない**(次に開いたときは常にコスト順から始まる)。**id順(ファイル名順)は並びとして
  使わない**。プレイヤーには読めない内部の識別子であり、追加順とも一致しないため
- **デッキ編集画面の空き枠は「ここにドラッグ」といった、ドラッグ操作を誘導する文言・見た目にする**。ドラッグ元となる下部の砂時計カードは、ホバー時に掴めるカーソル(ドラッグ用カーソル)へ変わり、ドラッグ操作が可能であることを示す。同じ`HourglassCard`が使われる他画面(砂時計一覧・デッキ選択の手札)ではドラッグできないため、通常のクリック用カーソルのままとする
- **デッキ管理**:プレイヤーは複数のデッキを保存・管理できる(名前付け可能。デッキ名は表示上の都合により10文字程度までを目安に制限する。保存数の上限は設けない)。デッキ一覧画面では保存済みデッキを横長カード(デッキ名+代表的な砂時計のアイコン)の一覧として**横2列のグリッド**で表示し(件数が増えたら縦スクロール)、各カードに「編集」「削除」ボタンを持つ(「使用中」を示すバッジ表示は行わない。使用するデッキは対局直前のデッキ選択画面で毎回選び直すため、一覧側での常時表示は不要と判断した)。デッキの並び順の入れ替えは、カード個別のボタンではなく、画面右上「新規デッキ作成」ボタンの隣に置く「デッキ入れ替え」ボタンから専用の並び替えモードに入って行う。画面左上に戻るボタンを配置する。バトル開始前のデッキ選択画面(9章のバトルタブ参照)も、このデッキ一覧画面と同じ見た目のカード一覧を流用する(ただし編集・削除ボタンは表示せず、カードをタップして選択するのみ)。**デッキ編集画面は「左=全カードの一覧 / 右=編成中のデッキ」の2カラムとする。**
カードは毎日のアプデで増え続ける(50種を予定)ため、**一覧の探しやすさを最優先する**。
以前は一覧を画面下部の横1行の横スクロールに置いていたが、23種の時点で一度に10種しか
見えず、目的のカードへ届くまで横へ送り続ける状態になっていた

- **左の一覧はグリッドとし、上部の操作行に「絞り込み」ボタンを置く**。絞り込みや検索のチップを常時並べると右側のデッキリスト上部に不自然な隙間ができるため、**コスト・キーワード・名前検索は「絞り込み」ボタンから開くモーダルダイアログへ集約する**。
  - 絞り込み適用中はボタンに条件数バッジを表示し、一括リセットも可能とする
  - これにより左右のカラム開始位置(y=112)を揃え、一覧グリッドの縦幅を広げてカードを探しやすくする
  - 枚数によって行数が変わることは問題にしない(縦スクロールで受ける)
- **右の欄は上から「デッキ名・枚数 / 編成中の一覧 / マナカーブ」**の順とする。
  - **マナカーブはデッキリストの下部に配置し、縦幅を140px確保する**。高さを十分に取ることで、コストごとの山や配分を美しくダイナミックに可視化する
  - **編成中の一覧はスクロール前提とし、カード帯の縦幅を太め(46px)にする**。従来の細い帯(32px)から太くすることで、敷かれたイラストの特徴や文字・ボタンが押しやすく見やすくなる
- **編成中の1枚は、カードの絵を右端へ薄く敷いた横長の帯とする**(30枚をカードの絵で
  並べると画面に入らないが、文字だけの表では何のカードか読み取るのに時間がかかる)。
  左端にコストを菱形で置き、**2枚積みのものだけ枚数のバッジを出す**(1枚のものに
  「×1」を出しても情報にならない)。**絵はバッジ・ボタンに重ならない位置で切り取り、
  帯からはみ出させない**
- **帯からは1枚減らすだけでなく、1枚足すこともできる**。帯の右端に「−」と「+」を並べ、
  一覧まで戻らずに枚数を調整できるようにする。**入れたカードをもう1枚足す操作が
  いちばん多いのに、それが一覧側にしか無いのは遠い**
- **コスト別の枚数(マナカーブ)は常時表示する**。30枚のデッキではコストの配分が
  構築の中心であり、数えなくても分かる状態にする。**目盛りはプールに実在するコストの
  範囲だけを出す**(常に1〜10を並べると、最大コストが6の現状では半分が空欄になる)
- **カードの詳細は、マウスホバーではなく一覧のカードや編成中の帯をクリックした時に表示する**。ホバーで自動的に浮かせると他のカードや編成欄が隠れて探しづらくなるため、クリックした時のみ右上に詳細パネルを出す。
  - **一覧のカード**: クリックで詳細パネルを表示(追加可能なカードなら同時にデッキへ1枚追加し、2枚積んでいて追加不可なカードでもクリックで詳細が表示される)
  - **編成中の帯**: 帯をクリックするとそのカードの詳細パネルを表示する(「+」「-」ボタンは枚数の増減)
  - **詳細の閉じ方**: 詳細パネルの外側をクリックするか右クリック / Escキー等で閉じられる。別のカードをクリックした場合はそのカードの詳細に切り替わる
  - 出す場所は画面の右上に固定し、指しているカードの位置では動かさない。ヘッダーの主アクション(保存・プリセット・コード)や編成中の欄の上端に重なるのは許容する(重なってよい相手は「いま読みたいカード」以外であり、カードに重ならないことを優先する)
- 一覧のカードを押すと編成へ1枚加わる。2枚入っているカードは一覧側で「2/2」と示し、追加はできないが詳細確認のためのクリックは受け付ける。保存ボタン・戻るボタンは共通ヘッダーに置く
- **デッキを短い番号(デッキコード)として書き出し、読み込める**。デッキ編集画面から
  自分のデッキのコードを発行・コピーでき、受け取ったコードを入力すればその構築が入る。
  **ルームマッチで友達と遊べるのに、構築を渡す手段が無いのは片手落ち**であるため。
  読み込めないコードは、その旨を1行で示す
- **デッキコードは8桁の数字とし、中身はサーバーへ預けて番号だけを渡す**。
  以前はカードのidと枚数を圧縮して文字列へ埋め込んでいたが、**30枚の組み合わせは
  1億通りをはるかに超えるため、中身を持ったまま8桁へ収めることは原理的にできない**。
  口頭やメモで渡せる短さを優先し、預ける方式へ変えた
  - **発行はボタンを押したときだけ行う**。画面を開くたびに預けると、使われない
    コードが際限なく増える。**同じ構築を続けて発行しても、同じ番号を返す**
  - **預けたデッキは消さない**。1件はごく小さく、消す仕組みを持つ利点より、
    **渡したコードが後日読めなくなる事故**のほうが損になる
  - **カードが増減しても既存のコードは読める**。預けているのはカードのidと枚数であり、
    一覧の並び順の番号ではない(番号で表すと、カードを1枚足した時点で過去のコードが
    すべて別のデッキになる)。**プールから消えたカードを含むコードだけは読めなくなる**
  - **発行・読み込みには通信が必要**であり、オフラインでは使えない。失敗したときは
    その旨を1行で示す。デッキの編集そのものは従来どおりオフラインでも行える
- **カードの詳細では、能力が実際にどう働くかを小さなアニメーションで実演する**。詳細パネル
  に実演枠を設け、抽象化した砂時計の駒(手前=自分 / 奥=相手)と細いHPバーだけを描いて、
  そのカードの能力が盤面で何を起こすのかを数秒のループで見せる。効果の文だけでは、
  「貫通の超過分がどこへ行くのか」「硝子が何度効くのか」が初見のプレイヤーに伝わらないため。
  **実演はカードごとではなく、キーワード / 効果の種類ごとに1本用意する**。カードは毎日の
  アプデで増え続けるため、1枚ずつ演出を書き起こす形は採らない。既存の語彙の組み合わせで
  新しいカードを足せば、実演も自動的に付いてくる状態を保つ。**効果を持たないカード(バニラ)
  には「基本の砂の動き」の実演を出す**。毎ターン 体力-1 / 攻撃力+1 と進み体力0で砕けるという
  土台は最初に理解すべきもので、実演の価値はむしろここが一番高い。複数の能力を持つカードは、
  能力ごとの実演を順に繰り返す

| 実演 | 見せるもの |
|---|---|
| 基本(全カード共通) | 体力5/攻撃0 が 4/1 → 3/2 → … と進み、体力0で砕ける |
| 守護 | 相手の攻撃が守護の駒へ吸い寄せられ、他の駒を狙えない |
| 硝子 | 一撃目が薄い膜に弾かれて膜が割れ、二撃目は通る |
| 貫通 | 攻撃力5が体力2の駒を貫き、超過3が相手のHPバーへ抜ける |
| 速落 | 出した瞬間に砂が2粒落ち、そのまま攻撃する |
| 毒砂 | 1ダメージを当てた相手の駒が、体力を残したまま砕ける |
| 吸命 | 与えたダメージと同じだけ自分のHPバーが伸びる |
| 連撃 | 同じ駒が続けて2回攻撃する |
| 反転(トリガー) | 駒が裏返り、体力と攻撃力が入れ替わる |
| 設置の各効果 | 置いた瞬間に対象へ効果が飛ぶ(ダメージ・破壊・砂削り・ドロー・強制反転) |
| 攻撃力を足す | 下の部屋へ砂が足され、攻撃力だけが増える(体力は変わらない) |
| 砂時計を出す | 空き枠に小さな砂時計が現れる |
| キーワードを与える | 対象の駒に守護の輪が付く |
| 効果を消す | 対象の駒からキーワードのラベルと膜が剥がれ落ちる |

**実演の文は「何が起きるか」だけを持ち、「いつ起きるか」はトリガーから組み立てる。**
同じ効果が設置・反転・余砂・落砂・被弾のどれに載っても、台本を作り直さずに
正しい文が出る状態を保つ。

- **デッキ編集画面のマナカーブは、デッキリスト下部に高さ140pxで配置する**。棒グラフの山や数値が潰れず、コスト配分を一目で美しく把握できるようにする。詳細パネル(実演枠つき)は
  常時表示ではなく、**一覧のカードや編成中の帯をクリックした時のみ画面右上へ表示する**
  (一覧のカードクリックは従来どおり編成へ1枚加える処理も兼ねる)
- **効果音を鳴らす**。対象は「カードを出す」「反転」「攻撃(相打ち)」「被弾」「決着」「ボタン押下」の6種とする。音源は**CC0(パブリックドメイン)ライセンスの外部フリー素材**を用いる。以前は完全無料運用を維持するため、プロジェクト内で手続き的に生成した短いWAVを使っていたが、用途に対して音質が不十分だったため方針転換した。**採用する素材はCC0に限る**。クレジット表記の義務なくunityroomへ公開でき、公開後にライセンス表記を管理し続けるコストを負わずに済むため(CC BY等、帰属表示が必要なライセンスは採用しない)。効果音はすべてユーザー操作か盤面の変化を起点に鳴るため、ブラウザの自動再生制限には抵触しない
- **BGMを鳴らす**。タイトル画面・ホーム画面系(ホーム・デッキ・一覧・リプレイ等)・対局画面の3曲をループ再生し、画面が切り替わったらクロスフェードで繋ぐ。**タイトル画面には厳かで壮大な曲を充てる**(ゲームの第一印象を決める画面であり、ホーム・対局の落ち着いた曲とは役割が異なるため)。曲は**パブリックドメインのクラシック音楽(ピアノソロ)**とする。砂時計の「時の流れ・時計仕掛け」というモチーフに合い、コード描画で作った真鍮・琥珀・石のアンティークな質感とも揃うため。オーケストラ曲(交響曲・協奏曲)は強弱の幅が大きく、BGMとして一定音量で流すのに向かないため採らない。クラシックは楽曲として完結しておりシームレスにループしないため、曲の終わりでフェードアウトし、短い間を置いて頭から再生する「アルバム再生」方式で繰り返す。**曲の途中を切り出した音源でも切れ目が唐突に聞こえないよう、フェードアウトは曲の終端の数秒前から始める**
- **対局の結果画面ではBGMを止め、短い勝利/敗北ジングルを鳴らす**。結果パネルは数秒から数十秒しか表示されず、数分あるクラシックの曲を割り当てても冒頭しか聞かれないため。ジングルも効果音と同じくCC0素材とし、弦楽器のピチカートなど、BGMのピアノと調和する音色を選ぶ
- **BGMはブラウザの自動再生制限を受ける**。効果音と違いユーザー操作を起点に鳴るとは限らないため、**最初のクリック/タップを検知してから再生を開始する**
- **音量は「効果音」「BGM」の2系統を独立して調整できるようにする**。ホーム画面の右上に小さな**ハンバーガーメニュー**のボタンを置き、押すとメニュー(モーダル)が開いてスライダー2本(いずれも0〜100%、0で実質ミュート)を操作できる。BGMだけ切って効果音は残す、という遊び方ができるようにするため1本にまとめない。設定は `user://` へ永続化して次回起動時も引き継ぐ。ブラウザで遊ぶ以上、音をすぐ止められることは必須要件として扱う
- **ホーム画面のメニューには、音量の下に公式Discordサーバーへの導線を置く**。**Discord公式のマークだけを載せた正方形のボタン**とし、押すとブラウザの別タブで招待リンクを開く。マークは公式のものをそのまま使い、他のUIに合わせて真鍮へ塗り替えることはしない(ブランドの規定に従うため)。ランダムマッチの募集はDiscordへ流している(11章)ため、**その通知を受け取る場所への行き方がゲーム側に無いと、待っても人が来ない状態を自分で解消できない**。導線をホーム画面のヘッダーへ直接並べず、メニューの中へ入れるのは、ヘッダーの主アクションを増やさないため(共通のレイアウト規約)。**ボタンを「設定」からハンバーガーへ変えたのは、中身が音量だけではなくなったため**であり、今後この引き出しへ項目が増えても文言を書き換えずに済む
- 全画面について、大手ソシャゲ/DCGのUIを参考に作り込む。開発初期の仮配置(単純な絶対座標配置など)から、実際に配布・公開して恥ずかしくない見た目へ強化する
- **UIの外枠・装飾(ボタン、パネル枠、入力欄、棚板、名札など、いわゆるUIクローム)は、AI生成画像ではなくコード描画で作る**。品質管理のしやすさを理由に、画像生成による運用から方針転換した。コード描画は無地の図形を並べるだけでは平坦でチープに見えるため、多段階のグラデーション・面取り・内側の落ち込み影・手続き的なノイズ(グレイン)・金属の照り返しといった質感表現を伴わせることを前提とする。色とパーツの描画は共通のライブラリへ集約し、画面ごとに個別実装しない
- ただし**砂時計そのもののイラストと画面の背景イラストは引き続き画像アセットとして扱う**。これらはUIの枠組みではなく作品の絵そのものであり、コード描画で置き換える対象ではない(生成手順は従来どおり `docs/AssetPromptTemplate.md` に従い、生成自体はユーザーが手動で行う)

## 10. 技術設計方針(毎日アプデ運用のための骨格)

- 砂時計は `Resource`(.tres)としてデータ駆動で管理し、コード変更なしで新規追加できる形にする
- 効果は「トリガー×ターゲット×エフェクト」の組み合わせで表現し、エフェクトの種類ごとにハンドラを用意する
- 既存のエフェクト種別の組み合わせだけで新しい砂時計を作れる状態を維持し、「新効果そのものの追加」と「既存効果の組み合わせによる新駒追加」を分けて運用する
- オンライン対戦はターン制の特性を活かし、非同期(手番ごとにサーバーへ送信→相手に反映)の通信方式を基本とする

## 11. オンライン対戦

- マッチング方式は**2種類**を用意する
  1. **ランダムマッチ**:待合室(マッチングキュー)に入り、他の待機プレイヤーと自動的に対戦成立させる。複数人が同時にキューへ入っても、二重マッチや取りこぼしが起きないようにする
  2. **ルームコード対戦**:片方がルームを作成しコードを発行、もう片方がコードを入力して参加する(友達対戦向け)
- **ルームコードは4桁の数字とする**。口頭で伝えられる短さを優先する。桁数が少ない以上
  同じコードが同時に生きることは避けねばならないため、**使われていない番号を選んで作る**。
  **一定時間より古い部屋の番号は再び使ってよい**(対局は20分ほどで終わるため、
  それより十分に長い時間を置く)
- 対局中の通信は、指した手(場に出す/反転/攻撃/コイン/ターン終了)を送信→相手が受信して反映する非同期方式とする
- サーバー側での正当性検証は行わず、クライアントの操作をそのまま信頼する(不正対策は将来検討)
- 持ち時間切れの扱いは5章の通り(切断・放置時の敗北条件を兼ねる)
- **対局が始まる前(相手のデッキ・配置を待っている間)は、いつでも中断してホームへ戻れる**。
  待たされている側が抜ける手段を持たないと、相手がブラウザを閉じただけで長時間画面に
  縛り付けられるため。中断したことは相手にも伝え、相手側は「対戦相手が対局を取りやめました」
  として同じくホームへ戻れる状態にする。中断は対局が始まる前にしか行えず、対局開始後に
  抜けたい場合は投了する(3章)
- **通信の状態を対局画面に表示する**。手を送っている間は「送信中」、送信・受信が続けて
  失敗している間は「相手と接続できません(再試行中)」を出す。通信は数秒で完了することも
  失敗することもあるが、何も出さないと「相手が長考している」のか「自分の手が届いていない」
  のかを区別できないため。接続が回復したら表示を消す
- **持ち時間はオンラインでは各手に添えて送り、受け取った側は相手の残り時間をその値で
  上書きする**。相手の手が届くまでに通信の遅延があるぶん、自分の画面だけで相手の時計を
  減らし続けると実際より早く時間切れと判定してしまうため。**上書きが効くのは相手の
  手番が続いている間だけ**で、手番が移った時点では受け取った値ではなく60秒へ戻す
- **対局の途中で切断しても、同じ対局へ復帰できる**。ブラウザを閉じた・再読み込みした・
  通信が切れたまま画面を離れた場合でも、次に起動したときに「前回の対局へ戻る」導線を出す。
  **対局の内容はサーバー側に「両者のデッキ・山札の種・指した手の並び」として残っており、
  そこから同じ局面を作り直せる**(リプレイと同じ仕組み)。復帰できるのは終わっていない
  対局に限り、終局済み・相手が対局を取りやめた場合は導線を出さない
- **復帰しないまま持ち時間が尽きれば、通常どおり時間切れで負ける**。復帰の導線があることは、
  放置した側が守られることを意味しない
- **時間切れは、切れた本人が申告する**。自分の持ち時間が0になったプレイヤーは、投了と同じく
  1手として「時間切れ」を送信し、**その手番を強制的に終了する**(5章)。連続3回に達した場合は
  その時点で敗北となる。相手が切断していて申告そのものが来ない場合に備え、相手の残り時間が
  0になってから短い猶予を置いても何も届かなければ、**切断とみなして**待っている側の勝利として
  終局させる。**申告が届いている限り敗北にはしない**——届いているならその相手は生きており、
  切断への保険を働かせる理由がないため

### ルームマッチ画面

**ルームマッチは専用の画面を持つ**。バトルタブの「ルームマッチ」を押すとこの画面へ入り、
**部屋を作る・コードで参加する・観戦する**の3つをここで完結させる。以前はバトルタブに
コード入力欄と参加/観戦ボタンを並べ、部屋を作った後の待機はラベル1行だけだったため、
**待っている間に確認したいこと(参加コード・使うデッキ・持ち時間)がどこにも出ていなかった**。

画面は次のものを持つ。共通のレイアウト規約(9章)に従い、ヘッダーは
左=戻る / 中央=「ルームマッチ」/ 右=なし とする。

- **参加コード**:部屋を作った後に大きく表示し、隣に**コピーボタン**を置く。友達へ渡すことが
  目的の値であり、読み上げて手入力させる前提にしない。コピーできなかった場合でも
  コード自体は大きく出ているため、その旨を画面に出さない(手入力で足りる)
- **使用デッキ**:デッキ名を表示し、「変更」から選び直せる。相手を待っている間も変更できる
- **持ち時間の入/切**(5章)。**部屋を作る前にだけ変更でき**、作った後と、コードで参加した側は
  表示だけになる。切にしてあるときは、放置された相手を時間切れで倒せない旨を1行で添える
- **待機の状態**:「相手の参加を待っています」「対局の開始を待っています」などを、
  他の画面と同じ巡回するドットで示す。待機は中断でき、中断すると部屋も消える
- **参加と観戦**:コードの入力欄と2つのボタンを同じ画面に置く

**観戦も同じ画面で待てる**。これまでは対局がまだ始まっていないコードを入れると
「対局がまだ始まっていません」で弾いていたが、**2人が集まる前にコードを共有された
観戦者には、弾かれる以外にできることが無かった**。始まっていない場合はその部屋の待機に入り、
対局が始まった時点で観戦へ移る。

### 対戦相手の募集をDiscordへ通知する

ランダムマッチは同時に遊んでいる人がいなければ成立しない。人が少ないうちは
「待っても誰も来ない」ことが最大の離脱要因になるため、**キューに入ったことを
コミュニティのDiscordへ知らせ、いま遊べる人を呼べるようにする**。

- **キューに入った時点で待機中の相手がいなかった場合にだけ通知する。**即座にマッチが
  成立した場合は送らない(呼ぶ必要がないため)
- **通知は毎回送る。**回数を絞ることはしない。1行で済む知らせであり、間引いて
  「いま人がいる」という情報の鮮度を落とすほうが損になる。**短い間に同じプレイヤーが
  何度も入り直した場合も、そのつど送る**(以前は2分だけまとめていたが、まとめる意味より
  鮮度を落とす損のほうが大きい)
- **メンションは飛ばさない。**気づきたい人はDiscord側のチャンネルごとの通知設定で
  受け取る。**毎回全員へメンションすると通知そのものを切られ、機能しなくなる**
- 通知に載せるのは**時刻とゲームのバージョン**だけとし、プレイヤーを特定できる情報
  (表示名・ID)は送らない
- **送信に失敗しても、マッチングは通常どおり続ける。**Discordが落ちていてもゲームは成立させる
- **成否を文言として出さない。**通知はプレイヤーの操作ではなく裏方の処理であり、
  届いた・届かなかったを待機中の文言へ混ぜても、待っている人にできることは無い。
  待機中は「マッチング中」だけを出す
- **ただし、知らせたこと自体は引ける状態にする。**待機中の文言の右へ丸い印(「!」)を
  添え、**カーソルを乗せたときにだけ**「公式Discordサーバーへ通知を送りました」と出す。
  印は押すものではなく読むためのものとして扱う。届かなかった場合は印も出さない
- **届くまで、間を置いて試し直す。**待っている間に1度だけ試して終わりにしない。
  ただし届いた後は、待ち続けていても送り直さない(同じ募集を繰り返し流すと
  通知そのものを切られる)

### バージョン

ゲームは**日付方式のバージョン**を持つ(`2026.08.29`。同じ日に複数回出す場合は `-2`)。
上の通知に添えるほか、不具合の報告と突き合わせるために使う。
**この値は書き出しの手順が自動で書き込む**(ビルドIDと同じ)。手で更新する値として
残していたときは、書き出しを重ねても日付が古いままで、募集の通知に何日も同じ数字が
出ていた。

### バージョンが違う相手とはマッチングしない

毎日更新する以上、ブラウザに古い版が残ったまま新しい版と同じ対局へ入りうる。
オンライン対戦は**山札の種を共有して両者が同じ対局を再現する**方式のため、カードの
総量が1でも違えば**盤面が静かに食い違ったまま進行する**。落ちないぶん質が悪い。

- **突き合わせるのは「ビルドした時刻」とする**。日付方式のバージョンは人が読むための
  ものとして残し、マッチングの可否は**書き出しのたびに自動で切り替わるビルドID**で
  判定する。ルールに影響する変更があった回だけ上げる番号を別に持つ案は、
  **上げ忘れた回に盤面が食い違う**——守るべき一点をちょうど守れないため採らない
- **ビルドIDは書き出しの手順が自動で書き込む**。手で更新する値を増やさない
- **違う相手は掴まない**。ランダムマッチは待機者のうち自分と同じビルドの人だけを掴み、
  ルームマッチは参加しようとした側が弾く。観戦も同じ扱いとする
- **古い版で待っている人を追い出さない**。掴まないだけで、その人のキューは消さない
- **弾いたときは画面に理由を出す**。黙って待ち続けると「マッチングしない不具合」に
  しか見えない。ビルドIDは時刻順に比較できるため、**自分が古い場合は「新しい版が
  公開されています。再読み込みしてください」**、自分が新しい場合は「相手が古い版で
  待っています」と書き分ける
- **対局画面にバージョンを出す**。不具合の報告と突き合わせるため

## 12. リプレイ・観戦

- 対局終了後、その対局の手順(棋譜)をリプレイとして保存する。**オンライン対戦・CPU戦の両方が対象**とする
- リプレイを閲覧できるのは、その対局を実際にプレイした本人(CPU戦の場合は自分)のみとする
- 保存件数は、オンライン対戦・CPU戦それぞれ直近30件とし、それを超えたら古いものから自動的に削除する。**この30件はアカウントごとに数える**(以前はアプリ全体で30件としていたが、プレイヤーが増えると互いの記録を消し合うため変更した)
- **リプレイはアカウントに紐づく**(14章)。別の端末からログインしても同じ記録を続けて閲覧できる。CPU戦のリプレイは通信を必要としない利点を保つためローカル保存のままとし、レコードに所有者を記録して一覧では自分のものだけを表示する
- リプレイは1手ずつコマ送りで再生できる形式とする
- パスは棋譜に1手(`pass`)として記録され、リプレイでも1手として数える
- **リプレイ一覧画面**:`バトルタブ`に「リプレイ」ボタンを追加し、そこから遷移する。オンライン対戦・CPU戦を問わず、保存済みリプレイを横長カードの一覧として新しい順に縦スクロール表示する(両者は保存先が異なるため、一覧表示の時点でマージして日時順に並べる)。各カードには対局日時・勝敗・先手/後手・対戦種別(オンライン/CPU戦)に加えて、**両者のデッキを代表する数枚のアイコン**を表示する(デッキは30枚あり、そのまま並べるとカードに収まらないため)。対局履歴が無い場合は「まだ対局履歴がありません」等の案内を表示する。カードをタップすると再生画面へ遷移する
- **リプレイ再生画面**:対局画面の盤面・情報帯をそのまま流用し、盤面のクリック操作を無効化した「再生モード」として動作させる。画面右の行動の列には、対局中のボタンの代わりに、先頭へ/1手戻る/再生・一時停止/1手進む/最後へ、の5つの再生コントロールと「n / 全手数」の手数表示を置く。**再生モードには結果パネルを出さない**ため、一覧へ戻る導線もこの列に置く。「再生」中は一定間隔(0.8秒/手を目安)で自動的にコマを進める
- **観戦機能**:進行中の対局を第三者がリアルタイムで見られる機能。**ルームコード対戦限定**とし、ランダムマッチには観戦導線を用意しない(共有できるコードが存在しないため)。`バトルタブ`のルームコード入力欄に「観戦する」ボタンを追加し、対局中の2人が使ったものと同じコードを入力すると観戦できる。観戦中は盤面・HPが対局の進行に合わせてリアルタイムに更新されるが、一切操作はできない。対局が終了した場合は通常の勝敗演出をそのまま表示する

## 13. CPU戦

- オンライン通信を必要としない、CPU(コンピューター)を相手にしたローカル対局。`バトルタブ`に「CPU戦」ボタンを追加する。他のバトル導線と同様、ボタンを押すと先に使用デッキを選ぶ画面を挟んでから開始する
- CPUのデッキは、現在定義されている全砂時計を各2枚ずつ入れた山からランダムに30枚を引いて組む(CPU専用のカードは用意しない)
- 先手/後手は常に**プレイヤーが先手**に固定する
- CPUもマリガン(2章)を行う。相手が何枚引き直したかは、対人戦と同じく分からない
- CPUは1手番の中で「場に出す → 攻撃する → 反転する → 終える」の順に選ぶ。**攻撃してから反転する**のが要点で、逆にすると攻撃力の高い状態を捨ててしまう。価値の物差しは生涯ダメージ(1章)を使う。**1手ずつ間合いを置いて指す**(まとめて適用すると盤面が一瞬で書き換わり、何をされたのか追えないため)
- 5章の持ち時間は、**オンライン対戦の切断・放置対策を目的とした仕組み**であり、CPU戦はローカル対局でその懸念が存在しないため、持ち時間の消費・時間切れ判定を行わない(プレイヤー・CPUともに考慮時間は無制限)
- CPU戦の対局終了後、その対局の棋譜は12章の通り**ローカルにリプレイとして保存する**(Firestoreへは書き込まない)。観戦はオンライン対戦のルームコード対戦限定のまま、CPU戦は対象外とする

---

## 14. アカウント

対局の記録(リプレイ)と通貨(15章)をプレイヤー個人に紐づけて保存するための仕組み。

- **アカウントを作らなくても遊べる**。起動した時点で匿名のアカウントが自動的に用意され、
  そのまま全ての機能を利用できる。ただし匿名のままだとブラウザのデータを消した時点で
  記録と通貨が失われるため、その旨をアカウント画面に明示する
- **IDとパスワードを自分で決めて登録できる**。登録するとその2つでログインでき、
  別の端末・別のブラウザからでも同じ記録の続きを遊べる。メールアドレスは取得しない
- **IDは他のプレイヤーと重複できない**。既に使われているIDで登録しようとした場合は
  その旨を表示して登録を拒否する
- **パスワードを忘れた場合、そのアカウントは復旧できない**。メールアドレスを取得しない以上、
  再設定の案内を送る手段が存在しないため。登録画面にこの注意を明記する
  (将来メールアドレスを任意項目として追加すれば解決できるが、現時点では扱わない)
- **匿名で遊んでいた記録は、登録した時点でそのまま引き継がれる**。登録は新しいアカウントを
  作る操作ではなく、いま遊んでいる匿名アカウントにIDとパスワードを結びつける操作として扱う
- **自動ログイン**:一度ログインすれば、次に起動したときは自動的に同じアカウントへ復帰する。
  匿名アカウントもこの対象とし、起動のたびに別人になることがないようにする
- **ログアウトできる**。ログアウトすると新しい匿名アカウントで遊ぶ状態に戻る。登録済みの
  アカウントの記録は消えず、同じIDとパスワードで再びログインすれば戻れる
- **表示名を持つ**(10文字程度まで)。対局中の「先手/後手」の表示と、リプレイ一覧の
  対戦相手の表示に使う。未設定の場合は従来どおり「あなた/相手」と表示する。表示名は
  いつでも変更でき、ID(ログインに使う文字列)とは別物として扱う
- **表示名に使えるのは、同梱フォントが字形を持つ文字だけとする**。絵文字・ハングル・
  アクセント付きのラテン文字・大半の記号は字形が無く、そのまま出すと豆腐(□)になる。
  **フォールバック用のフォントを同梱して対応する案は採らない**。絵文字だけで約10MBあり、
  pck全体(約4MB)の何倍にもなってブラウザでの起動待ちがそのぶん延びるため、
  日本語圏向けの作品として釣り合わない。入力欄では使えない文字を受け付けず、
  「この文字は使えません」と1行で示す。**相手から届いた表示名も同じ基準で通し**、
  使えない文字は「?」へ置き換えて表示する(自分が我慢しても、相手のクライアントが
  送ってきた名前で自分の画面が化けるため)
- **対局画面の名前欄は、自分側には常に自分の表示名を出す**(オンライン対戦・CPU戦のいずれも)。
  相手側は、オンライン対戦では相手の表示名、**CPU戦では「CPU」**とする。誰と戦っているのかが
  一目で分かる状態にするため
- **アカウント画面**を用意し、タイトル画面とホーム画面の両方から開けるようにする。
  画面には現在のアカウントの状態(匿名か登録済みか)・表示名・通貨の残高を表示し、
  未登録なら「登録」、登録済みなら「ログアウト」の導線を置く。ログイン導線も同じ画面に置く
- サーバー側での正当性検証を行わない方針(11章)はアカウントにも適用する。認証そのものは
  認証サービスに任せるが、通貨や記録の内容はクライアントの申告をそのまま信頼する

### アイコンと称号
プレイヤーの個性を表現するため、アイコンと称号を設定できる。

- **アイコン**:
  - アカウント画面で一覧から好きなアイコンを選択・変更できる。
  - 初期状態で選択可能なアイコンは砂時計の紋章(流砂、時計、王冠、大盾、宝剣、真眼、光輪、閃光など)とする。**すなえるアイコンは初期配布せず、将来のショップ等の解放要素とする**。
  - 未設定時の既定値は「流砂(`sand`)」。
  - ホーム画面ヘッダー、アカウント画面、対局画面(PlayerInfoBar)に表示される。
  - CPU戦でのCPUのアイコンは専用アイコン(`cpu`)とする。
- **称号**:
  - アカウント画面で一覧から好きな称号を選択・変更できる。
  - 称号が増えても一覧しやすいスクロール可能なリスト形式で表示する。
  - 初期状態では「駆け出し決闘者(`novice`)」(ゲーム起動で自動獲得)と「称号なし(`none`)」から選べるようにする。
  - 未設定時の既定値は「駆け出し決闘者(`novice`)」。
  - 対局画面の名前プレート上部に小さく表示される。
- **アカウント画面のレイアウト**:
  - 画面の高さいっぱいに収まる**2カラム構成**(幅1060px)とする。
    - **左カラム(プロフィール設定)**: 名札見本(リアルタイムプレビュー)、表示名変更、アイコン一覧グリッド、スクロール対応の称号リスト、「プロフィールを保存」ボタン。
    - **右カラム(アカウント登録・ログイン)**: 登録・ログイン・ログアウトの操作および注意事項。
  - ボタンは全てゲーム世界観に統一された真鍮スタイルのボタン(`CodedButton`)を使用する。
- **保存と同期**:
  - 表示名と同様に `players/{uid}` に保存され、ログインした全端末で同期される。
  - オンライン対戦時、相手のアイコンと称号も取得して対局画面に表示する。

## 15. 通貨

- 通貨の名称は**「砂金(さきん)」**とする。対局を終えるたびに獲得し、アカウント(14章)に貯まる
- **用途は現時点では定義しない**。ショップ(9章)を実装する際に改めて設計する。今回は
  「貯まっていく」ところまでを対象とし、消費する手段は用意しない

### 獲得量

| 対局種別 | 勝利 | 敗北 |
|---|---|---|
| ランダムマッチ | 30 | 10 |
| ルームマッチ | 10 | 5 |
| CPU戦 | 5 | 2 |

負けても獲得できるのは、勝てないプレイヤーが一切貯められない状態を避けるため。
ランダムマッチを厚くしているのは、相手が必要で自分の都合だけでは回せないため。

### 不正な稼ぎ方への線引き

サーバー側で対局内容を検証しない方針(11章)のため、**自分ひとりで繰り返せる対局ほど
報酬を低くする**ことで釣り合いを取る。加えて次の2つの条件を設ける。

- **総手数が10手に満たない対局は報酬の対象外とする**。開始直後に投了して短時間で
  繰り返すことを防ぐため
- **CPU戦は1日10戦までを報酬の対象とする**。上限に達した後もCPU戦自体は遊べるが、
  砂金は入らない

### 表示

- ホーム画面に残高を常時表示する
- 対局の結果パネルに、その対局で獲得した額を「+30 砂金」として表示する。報酬の対象外
  だった場合(手数が足りない・CPU戦の1日の上限に達している)は、その理由を1行で示す
- 通信に失敗して残高を更新できなかった場合でも、獲得した額は失わない。未反映分を
  手元に控えておき、次に通信が成功した時点でまとめて加算する(CPU戦はオフラインでも
  遊べるため、この扱いが必要になる)

## 16. ルール画面(遊び方)

ルールを知らないまま対局へ入って離脱されることを防ぐための画面。ホーム画面の
「ルール」タブから入る。

- **テキストと、実際にレンダリングされた盤面を並べた「紙芝居」形式とする**。1ページは
  見出し1行・本文2〜4行・その内容を実演する盤面の3つで構成する。読み物だけでも、
  動く絵だけでも足りないため、必ず両方を対にする
- **盤面は挿絵ではなく、対局画面と同じ描画コンポーネントを同じデータで描いたものとする**。
  ルール画面専用の簡易イラストを別に用意すると、実際の対局画面と見た目がずれた時点で
  誤った予習になるため
- **ページに入った瞬間に、そのページの演出が1度だけ自動再生される**(砂が1粒落ちる /
  反転する / 相打ちで砂が砕ける)。「もう一度見る」で再生し直せる。**演出も対局画面と
  同じものを使う**。消える砂と落ちる砂の違い(4章)は文章より演出のほうが伝わるため、
  ここが本画面の中心になる
- **章を選んで飛べる目次を左に置く**。順に読ませる導線(次へ)と、あとから1点だけ調べに
  戻る導線(目次)の両方を持たせる。チュートリアルではなくリファレンスとしても使える
  ようにするため
- 操作はページ送り(前へ / 次へ)と目次のみ。**盤面はクリックを受け付けない**。
  対局と同じ見た目である以上、押せそうに見えるものが押せないことを避けるため、
  ホバーの反応も出さない
- 進捗は保存しない。次に開いたときは常に先頭のページから始める

### 章立て

| 章 | 見せること | 盤面 |
|---|---|---|
| 1 | 上の砂=体力 / 下の砂=攻撃力、合計が総量 | 砂時計1体を大きく |
| 2 | 毎ターン終了時に砂が1粒落ちる。体力0で破壊 | 1体が落ちきるまで |
| 3 | 反転。攻撃力が体力を上回ったら返す | 1体が反転する |
| 4 | 場に出す。マナ・コスト・6枠・出したターンは動けない | 手札から台座へ |
| 5 | 攻撃は相打ち。**受けた砂は消え、落ちた砂は消えない** | 2体がぶつかる |
| 6 | キーワード(守護 / 硝子 / 貫通 / 速落) | 該当カードを並べる |
| 7 | 対局の流れ・勝利条件・コイン | 6枠の盤面と情報帯 |

## 17. キーワード辞書

ルール画面(16章)が「順に読ませる紙芝居」であるのに対し、こちらは**語を1つだけ
引きに来るためのリファレンス**とする。ホーム画面の「ルール」タブから、ルール画面と
並べて入口を置く。

- 収録するのは**現在定義されている語すべて**。常在の能力7種(守護 / 硝子 / 貫通 /
  速落 / 毒砂 / 吸命 / 連撃)とトリガー5種(設置 / 反転 / 余砂 / 落砂 / 被弾)。
  **6章で「語にしない」と決めた毒砂・吸命・連撃も辞書には載せる。**カードの面へ語を
  出さないことと、用語を引けることは別の話であり、盤面で「破壊」とだけ書かれた能力の
  正確な挙動を確かめる場所が無いと困るため
- 1件は「語 / 一文の説明 / 実演 / その語を持つ砂時計の一覧」の4つで構成する
- **語にしない能力(毒砂・吸命・連撃)は、カードの面と同じ短い言い換え**(「破壊」
  「回復」「2回攻撃」)**を見出しに出す。**盤面に出ていない語を辞書だけで見せると、
  同じ能力の呼び名が2つになるため(6章)
- **実演は9章のカード詳細と同じものを使う**。辞書専用の絵は作らない。実演はキーワード /
  効果の種類ごとに1本用意する方針(9章)であり、辞書はその単位とそのまま一致する
- **その語を持つ砂時計を並べることを、説明文と同じだけ重要な要素として扱う。**
  「守護はどの砂時計にあるのか」を引けることが辞書の価値の半分を占める。一覧は
  全砂時計から実行時に集めるため、砂時計を追加したときに辞書側へ書き足す作業は発生しない
- **該当する砂時計が1枚も無い語も項目を消さない。**「まだこの能力を持つ
  砂時計はありません」と示し、語彙として定義済みであることを隠さない
- 左に語の一覧、右に選んだ語の詳細、の2カラムとする。共通のレイアウト規約(9章)に従う

### 詳細パネルからの用語ポップ

- **砂時計の詳細に出ている語(「守護」など)を押すと、その語の説明と実演を小さな
  パネルとして重ねる。**辞書画面と同じ内容を出す
- **押せるのは効果欄に並ぶ語のボタン**(語にしない能力は短い言い換え、設置などの
  トリガーはその語)。効果の文そのものは押させない。押せるものと読むものを見た目で
  分けるため
- **対局中に駒をクリックして開いた詳細からも、同じ操作で引ける。**効果を覚えていないと
  戦えない状態を避けるという9章の方針の延長で、「効果の文は読めたが語の意味が分からない」
  という一段深いつまずきをその場で解消する
- ポップは押した語1件だけを出す。ここから辞書の全一覧へ移る導線は置かない
  (対局中に画面を離れさせないため)

## 18. はじめてのプレイ

ルール画面(16章)と辞書(17章)は**読みに行く**ものであり、読まずに対局へ入った
プレイヤーには何も届かない。ここでは**遊びながら覚える**導線と、**構築せずに遊べる**
状態を用意する。ブラウザゲームである以上、最初の数分で離脱されることが最大の損失にあたる。

### 誘導対局(チュートリアル)

- **実際の対局画面で、実際に手を指させる**。読み物や紙芝居ではなく、CPU戦をそのまま使う
- 進行は**段階ごとの短い指示**として画面上部に出す。「手札のカードを空き枠へ出してみましょう」
  のように**1度に1つだけ**を求め、その操作が行われたら次へ進む
- 段階は次の6つとする。**いずれもこの作品でしか通用しない部分**であり、
  他のカードゲームの経験だけでは埋まらない

| 段階 | 求める操作 | 覚えること |
|---|---|---|
| 0 | マリガンを確定する | 初手は引き直せる。引き直さなくてよい |
| 1 | 手札のカードを空き枠へ出す | マナを払って場に出す。出した直後は攻撃できない |
| 2 | ターンを終える | ターン終了時に砂が1粒落ちる(体力-1 / 攻撃力+1) |
| 3 | 攻撃する | 攻撃は相打ちで、**自分も相手の攻撃力ぶん削れる** |
| 4 | 反転する | 体力と攻撃力が入れ替わる。**攻撃力が体力を上回ったら返す** |
| 5 | ─ | 以降は自由に続ける(通常のCPU戦として最後まで遊べる) |

- **誘導対局はマリガン画面から始まる**(2章)。ここに案内が無いと、初めて遊ぶ人は最初の画面で
  何を求められているのか分からないまま止まる。**すなえるの指示はマリガンの暗幕より手前へ出し**、
  引き直しの意味と「選ばなくてよい」ことを伝える。**マリガンを誘導対局だけ省く案は採らない**。
  実際の対局では必ず通る画面であり、省くと初回の壁が後ろへ移るだけのため
- **段階を1つ終えたときの説明は、時間で消さず「つぎへ」を押すまで残す**。読む速さは人により、
  1秒足らずでは読み切れない。**指示の文が自動で切り替わることが、案内が1度しか出なかったように
  見せていた**。手を塞がない方針は変えないため、押さずに指し続けることもでき、
  次の操作を行った時点で先へ進む
- **段階をすべて終えたら、締めのひと言を出してから帯を閉じる**。勝利条件と、
  困ったら駒を押せば効果を読めることだけを伝える。何の区切りも無く案内が消えると、
  続きを投げ出されたように読める。**それ以上は喋らせない**。対局中ずっと話しかけるのは、
  長い語りがルールの読解を妨げるという本節の方針に反する
- **いま触るものを盤面の上で光らせる**。「空いている台座へ出してみてね」と言われても、
  初見のプレイヤーには**どれが空き枠なのかが分からない**。段階ごとに対象(手札 / 空き枠 /
  ターン終了ボタン / 攻撃できる駒 / 反転できる駒)を脈打つ輪郭で囲む。**手は塞がないまま
  視線だけを誘導する**ため、下記の「従わない操作も禁止しない」と両立する
- **求めた操作が今できない場合は、そのための手を代わりに示す**。1ターン目はマナが1しか
  無いため、手札によっては**「出してみてね」と言われても1枚も出せない**。この状態を放置
  すると、初めて遊ぶ人には指示に従えない理由が分からない。出せる札が1枚も無い間は
  「ターン終了を押すとマナが増える」ことを伝え、そちらを光らせる
- **何段階のうちのどこにいるかを出す**。すなえるの下へ段の数だけ点を並べ、済んだものを
  塗る。**終わりが見えないと、いつまで案内が続くのか分からない**。閉じる導線を置かない
  (下記)以上、残りが読めることは必要になる
- **段階を終えたときの一言には、いま自分の盤面で起きた実際の数値を差し込む**。
  「砂が1粒落ちたよ」ではなく「サンドの体力が5から4に、攻撃力が0から1になったよ」と書く。
  **一般論の説明より、目の前の駒と結びついた説明のほうが速く入る**
- **指示に従わない操作も禁止しない**。手を塞ぐと「言われた通りにしか動かせない」体験になり、
  自分で考える余地が消える。指示は**次に何をすれば良いか分からない状態を埋めるためだけ**に置く
- **途中で閉じる導線は置かない**。一度閉じると以降の段階の案内が二度と読めなくなり、
  誤って押した人は残りを教われないまま対局だけが続く。指示は手を塞がない(上記)ため、
  邪魔なら無視してそのまま指してよく、締めのひと言まで進めば自分で閉じられる
- 誘導対局は**何度でも遊べる**が、一度終えたら入口の扱いを控えめにする(下記)
- 誘導対局のデッキは**プリセットの「基本」を使う**。保存済みのデッキがあっても、
  そちらを使わない。覚えてほしい動きが出ないデッキで始まると成立しないため

### 案内役「すなえる」

誘導対局の指示は、**マスコットの「すなえる」が話しかける形にする**。指示だけが
帯に出ている状態には話者がおらず、画面が一方的に命令しているように読めるため。

- **すなえるは、砂時計に天使の輪と羽と目を足したもの**とする。**新しく絵を起こさず、
  ゲーム内の砂時計そのものへ描き足す**。盤面に立っている駒と見た目が必ず一致し、
  「この子はこのゲームの砂時計なんだ」と分かる状態を保つため
- **口は描かない。**表情が固定されず、砂時計という物体のままでいられる
- 一人称は「ぼく」、語尾は「〜だよ」「〜してみてね」程度。**指示の文は短く保つ**。
  このゲームは覚えることが多く、長い語りはルールの読解を妨げる
- 立ち絵は**指示の帯の左端に小さく置く**だけとし、盤面を新たに隠さない。
  すなえるのために画面の場所を作らない
- **出るのは誘導対局の間だけ**とする。ルール画面(16章)・タイトル・ホームには
  出さない。**常時いると案内役ではなく飾りになる**ため、
  「初めて遊ぶ人に付き添う」という役割が薄れる

### プリセットデッキ

- **30枚を自分で組まずに遊べる状態を用意する**。デッキ構築は面白さの中心だが、
  **始める前に30枚を選ばせるのは最初の壁として重すぎる**
- プリセットは**3つ**とし、それぞれ狙いを1行で示す

| 名前 | 狙い |
|---|---|
| **基本** | 軽いカードを中心に、砂の進み方と相打ちを素直に体験する |
| **速攻** | 速落・貫通で早く殴りきる |
| **重厚** | 守護と大型で受け止め、盤面を残して勝つ |

- デッキ編集画面から**プリセットを選んで読み込める**。読み込んだ後は普通に編集でき、
  保存すれば自分のデッキになる(プリセット自体は上書きされない)
- **デッキを保存していないプレイヤーは、プリセットの「基本」で対局へ入れる**
  (これまでも既定のデッキで入れていたが、その中身が画面に出ていなかった)

### 初回の導線

- **初めてホーム画面を開いたときは「ルール」タブを初期選択とする**(9章、実装済み)。
  そのタブの先頭へ**「1局遊んで覚える」**を置き、読み物より前に出す
- **一度でも誘導対局を終えたら、その入口は他の項目と同じ大きさへ下げる**。
  終えた人に毎回いちばん目立つ位置で勧め続けない

## 19. 戦績

**勝っても何も残らない状態を避けるための記録**。ランク戦(順位付け)は行わないと決めて
いるため、通算の成績を見返せることが「勝つ理由」の中心になる。

- 記録するのは**対局種別ごとの対局数・勝率・平均手数**、**カード別の勝率**、
  **デッキ別(構築ごと)の勝率**の3つ
- **リプレイから集計しない**。リプレイは直近30件しか残らないため(12章)、
  古い対局が消えるたびに通算の勝率が変わってしまう。終局のたびに1件足す積み上げ方式とし、
  リプレイの保持件数とは切り離す
- **アカウントごとに数える**(14章)。ログアウトして別のアカウントで遊んだぶんは混ざらない
- **カード別は「そのカードを入れたデッキで戦った勝率」**であり、そのカードの強さそのもの
  ではない。同じカードを2枚積んでいても1局は1局として数える。**この値でカードの強弱を
  判断してはいけない**(強さの測り方は7章のとおり、含むデッキと含まないデッキを直接
  ぶつける方式による)
- デッキ別は構築を**その内容から作った指紋**で見分ける。1枚でも違えば別の構築として数える。
  9章のデッキコードは番号を預ける仕組みであり、記録のたびに通信することになるため使わない。
  覚えておく構築は多くならないよう上限を設け、超えたら対局数の少ないものから落とす
- 表示は専用の画面とし、バトルタブから入る。**対局数が0のうちは、その旨を1行で示す**

## 20. 画面の見かた

ルール画面(16章)がルールを**順に読ませる**場所、キーワード辞書(17章)が語を**引く**場所で
あるのに対し、ここは**画面に出ているものの意味を引く**場所とする。

9章で決めた表示の約束——数値の位置・台座の輪・光の膜・彩度・印——は、**どこにも説明が
無いまま盤面に出ている**。守護のカードが1枚も手元に無ければ辞書を引く動機も生まれず、
「台座の輪が太いのは何なのか」を調べる手段が存在しなかった。

- **実際の対局画面と同じ描画で組んだ1枚の盤面を中央に出し、左に項目の一覧を置く**。
  項目を選ぶと盤面の該当箇所が光り、その意味が説明として出る
- **専用の説明図は作らない**。16章と同じ理由で、対局画面と食い違った時点で誤った予習になる
- **盤面はクリックを受け付けない**(16章と同じ)。ホバーの反応も出さない
- 進捗は保存しない。次に開いたときは常に先頭の項目から始める

### 収録する項目

| 項目 | 説明すること |
|---|---|
| 情報帯 | HP・マナ(数字とピップ)・山札・墓地の枚数。相手側は手札の枚数とコインの有無 |
| 盤面と台座 | 各プレイヤー6枠。空き枠は丸い台座だけが置かれた状態になる |
| 手札のカード | **コスト=左上 / 総量=右下**。マナが足りないものは暗くなる |
| 場の砂時計 | **攻撃力=左下 / 体力=右下**。場ではコストを出さない(支払い済みのため) |
| 砂時計の絵 | 体力と攻撃力の比で3状態に変わる(上向き / 落下中 / 落ちきり) |
| 守護と硝子 | 守護=台座の輪が太い真鍮 / 硝子=ガラスに掛かった光の膜(1度使うと消える) |
| 駒の状態 | 出したターン=沈んでいる / 攻撃済み=彩度が落ちる / まだ動ける=控えめな印 |
| 攻撃の予測 | 対象を選んでいる間、双方に「この攻撃の後どうなるか」が出る |
| 行動の列 | 画面右にコイン・ターン終了・ログ・投了。**反転だけは選んだ駒のすぐ下**に出る |

### 砂時計の数値バランスについての方針

**個々のカードの数値調整は、いったんここで打ち切る。**現行21種の勝率は 44.7〜55.0% まで
収束しており、800戦での測定誤差(±3.5pt程度)とほぼ同じ幅しかない。**これ以上の調整は
誤差を追いかけるだけになる**(`docs/BalanceReport_v5.md` 5.2節)。

次に測り直すのは、**新しいカードを追加してメタが動いたとき**とする。カードを増やせば
値付けの基準そのものが動くため、いま21種だけを見て詰めても作業が無駄になる。

- **先手勝率が55.5%と目標をわずかに超えている。**原因はマリガンではなく
  「上書き設置の廃止」以降のテンポの価値の上昇。**手番の補正は重ねない**(7章)ため、
  カードの値付けを見直す回に併せて測り直す。単独で補正を足さない
- 実際のプレイテストによる、決着までの手数・時間の確認(自己対戦では平均22.1手)
- 21種以降、カードを追加していく際のバランス指針の継続的な更新
