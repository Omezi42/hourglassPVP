# 砂時計アリーナ ルール設計書(v5.0)

## コンセプト

砂時計モチーフのターン制対戦カードゲーム。
**砂時計の上の部屋に残った砂が体力、下に落ちた砂が攻撃力**であり、時間が経つほど
強くなると同時に脆くなる。ひっくり返せば体力と攻撃力が入れ替わる——この一点を
ゲームの核に据える。

1戦は5分程度。Godot + unityroom でのオンライン対戦を想定し、
毎日アプデで新しい砂時計を追加し続けられるデータ駆動な拡張性を前提とする。

---

## 1. 砂時計(カード)

カードには**盤面へ出る「砂時計」**と、**出ずに効果だけを起こす「砂術」**の
2種類がある(砂術は6章)。この章が扱うのは砂時計のほうで、
**このゲームの中心は砂時計**であり砂術はそれを助けるものとして数を絞る。

各砂時計は次の3つのパラメータを持つ。

| パラメータ | 意味 |
|---|---|
| **コスト** | 場に出すために支払うマナ |
| **総量** | 体力と攻撃力の合計。そのカードの規模 |
| **キーワード / 効果** | 持たないもの(バニラ)があってよい |

場に出た砂時計は **体力=総量 / 攻撃力=0** で始まる。

- **毎ターン終了時、砂が1粒落ちる**(体力-1 / 攻撃力+1)
- **体力が0になったら破壊される**(砂が落ちきった)
- **反転すると体力と攻撃力が入れ替わる**

出した直後は攻撃力0なので何もできない。これが召喚酔いにあたる。

### 生涯ダメージ

体力h・攻撃力aの砂時計が、反転せず寿命を全うするまでに与える総ダメージは

```
生涯ダメージ = h × a + h(h-1)/2
```

**反転の最適解は「攻撃力が体力を上回ったとき」**である。攻撃力の高い砂時計を
体力の高い状態へ戻すほうが、寿命が伸びて総火力が大きくなる。
「体力を攻撃力に換金する」ために反転するのは短視眼であり、砂時計を使い捨てにしてしまう。

## 2. 対局の構成

- デッキは **30枚**(同名カードは2枚まで)
- 場は各プレイヤー **6枠**
- プレイヤーの初期HPは **24**(時計の文字盤にちなむ数)
- マナは自分のターン開始時に**最大値+1・全回復**(上限10)
- **初期手札は先手3枚・後手4枚。後手は「コイン」を1枚持つ**
- 山札が尽きたら、以降は自分のターン終了ごとに1ダメージ(疲労)

先手・後手の補正は「**後手が1枚多い**」と「**後手はコインを持つ**」の2つだけとする。

**コイン**は、後手が**1対局に1度だけ、自分の手番でマナを+1できる**もの。手札の枚数には
数えず、使うタイミングだけを選ぶ。マナ上限(10)は超えない。

補正の効き幅はどちらも大きく、実測では**コイン単独で先手勝率が約22ポイント動く**。
そのため**複数の補正を重ねてはいけない**。以前あった「先手の1ターン目はドローなし」も
同じく約22ポイントの補正であり、コインと併用すると先手勝率が38%まで落ちるため廃止した
(先手も自分の1ターン目からドローする)。

マナ上限を恒久的に+1する形の補正は、粒度が粗すぎて使えない(先手勝率が64%から26%へ飛ぶ)。

### マリガン(初手の引き直し)

対局開始時、両プレイヤーは配られた初期手札を見て、**任意の枚数を選んで引き直せる**。
選んだカードを一度手札から外し、**同じ枚数を引いてから、外したカードを山札へ混ぜて切り直す**。
この順序により、**引き直したカードがその場で手札へ戻ってくることはない**。
マリガンは1対局に1度だけで、**先手・後手が同時に行う**。相手が何枚交換したかは互いに分からない。

30枚のデッキでコスト1〜2のカードを1枚も引けない事故が構造的に起きるため、
**事故がそのまま敗因になる状態を避けることを目的とする**。交換できる枚数に上限は設けない
(全交換もできる)。上限を設けても事故の型が変わるだけで、覚えることだけが増えるため。

**コインは後手の持ち物であり、マリガンの対象外とする**(手札の枚数に数えないため)。

### 反転権

**反転権**は、場に出ている砂時計を**敵味方問わず**反転させられる特殊な行動回数。
通常の反転(3章)とは別枠で管理し、**「1体につき1ターン1回まで」「出したターンは
反転できない」という制限を受けない**。マナは不要。

先手・後手ともに持つが、**対局中に使える総回数が異なる**(後手を多くすることで
手番差を補正する)。使わなかった回数はターンをまたいで持ち越せる。1度使うと、
場のどちらの陣営でもよいので1体を選んで反転させ、残り回数が1減る。

自分の砂時計を反転権で有利な状態(攻撃力が体力を上回ったとき)へ戻すのはもちろん、
**相手の砂時計を反転させることにも使える。**相手の駒(体力が攻撃力より多い、
まだ若い駒)を反転させると、体力と引き換えに攻撃力が跳ね上がる。**この一撃だけでは
相手を弱めたことにならず、むしろ次の相手の手番で使える攻撃力を渡すだけになる**ため、
同じ手番のうちに自分の攻撃でその駒を仕留めるか、確実に破壊できる(体力が0になる)
場合に限って使うのが定石になる。「反転」トリガー(6章)を持つ砂時計は、
誰が反転させても、**持ち主を利する形で**効果が発動する(グロウなら持ち主の総量が
増え、ホイールなら持ち主の相手がダメージを受ける)。

先手・後手それぞれの総回数は **先手2回・後手3回**とする。CPU自己対戦(800戦×2シード)で
5指標すべてが目標圏に収まることを確認済み(先手勝率51.0〜51.5%・決着手数20.1〜20.2手・
ユニットへの攻撃47.5〜47.9%・逆転率32.1〜33.3%・本体ダメージで決着100%。
`docs/BalanceReport_v5.md` 12章)。**コインとの併用も確認済みで、コインを外すと
先手勝率が60〜69%まで跳ね上がるため、コインは維持する**(7章「手番補正は複数重ねては
いけない」の例外ではなく、反転権はコインの代わりにはならないという結論)。

**反転権の値打ちは「弱めてから同じ手番で仕留める」使い方に集約される。**この使い方を
教えないと、単に強い駒への反撃としてしか見えず宝の持ち腐れになる(実際、この使い方を
知らないCPUで測ると反転権はほぼ使われず何も変えなかった。同12章)。ルール画面
(16章)・誘導対局(18章)のいずれかで、この使い方を伝える案内を用意すること
(現状は未着手)。

## 3. ターンの流れ

1. **マナ回復** — 最大マナ+1、全回復
2. **ドロー** — 1枚引く
3. **メインフェイズ** — 以下を好きな順で、何度でも
   - **場に出す**:手札から1枚、マナを支払って空き枠へ置く。
     **空き枠が無い場合は出せない**(既存の砂時計への上書き設置は行わない)
   - **コインを使う**(後手のみ・1対局に1度):マナを+1する
   - **反転する**:自分の砂時計の体力と攻撃力を入れ替える。**マナは不要**。
     ただし**1体につき1ターンに1回まで**、**出したターンは反転できない**
   - **反転権を使う**(残り回数があるとき):敵味方問わず場の砂時計1体を選んで
     反転させる。マナは不要。**通常の反転の制限(1体1ターン1回・出したターンは不可)を
     受けない**ため、すでに反転済みの駒や出したばかりの駒にも使える(2章)
   - **攻撃する**:攻撃力が1以上の砂時計で、相手の砂時計か相手プレイヤーを攻撃する。
     **1体につき1ターンに1回まで**、**出したターンは攻撃できない**
4. **ターン終了** — 自分の砂時計の砂が1粒ずつ落ちる(体力-1 / 攻撃力+1)。
   体力が0になったものは破壊される

## 4. 戦闘

- 相手プレイヤーを攻撃した場合、攻撃力ぶんのダメージがそのままHPに入る
- **相手の砂時計を攻撃した場合、互いに相手の攻撃力ぶんのダメージを受ける**(相打ち)
- **ダメージを受けると、その分の砂は消える**(体力が減り、総量も減る。攻撃力は変わらない)
- 体力が0になった砂時計は破壊される

### なぜ「相打ち」と「砂が消える」の両方が必要か

この2点はどちらもゲームの成立条件であり、片方でも欠けると破綻する。

- **相打ちがないと**、除去がノーリスクの得になり、本体を殴る理由が原理的に消える。
  実測では対局の100%がデッキ切れで決着し、本体ダメージが一度も勝敗を決めなかった
- **ダメージで砂が「落ちる」(総量が保存される)と**、戦闘で価値がほとんど失われないため
  殴り合う意味がなくなる。体力5・攻撃1同士がぶつかると双方が体力4・攻撃2になり、
  生涯ダメージは15から14へ1しか減らない。実測ではユニットへの攻撃が9%まで落ちた

両方を入れたとき、はじめて「盤面を取りつつ本体を削る」という形が成立する。

## 5. 勝利条件

- 相手プレイヤーのHPを先に0にした方が勝利
- 投了は敗北とする(従来どおり)
- **持ち時間は1手番につき60秒とし、手番が移るたびに60秒へ戻す**(総持ち時間は持たない)。
  1手ごとに必ず60秒考えられる状態を保つためで、以前の「1人3分の総量制」は、
  序盤に使いすぎると終盤の1手を考えられなくなり、盤面が複雑になる終盤ほど
  時間が無いという逆の配分になっていた。決着手数は平均22.1手のため、
  1対局におよそ20分を見込む
- **持ち時間が尽きても、それだけでは負けにしない。その手番を強制的に終了して相手へ渡す**。
  1手番60秒は「1手をじっくり考えられる」ための枠であり、考え込んだ結果その1手を落とすのは
  自然でも、**対局そのものを落とすのは罰として重すぎる**。渡した後も盤面は残るため、
  次の手番で挽回できる
- **時間切れを起こしても、次の手番の持ち時間は60秒のままとする**。以前は時間切れのたびに
  半分にしていた(60秒 → 30秒 → 15秒)が、**1度目の長考と「席を外した」は見分けがつかない**。
  盤面が複雑になる終盤ほど長考は起きやすく、そこで次の手番が30秒になるのは、
  **1手ごとに必ず60秒考えられる状態を保つ**という上の方針と正面から食い違う。
  待っている側を解放する役目は、下の「連続3回で敗北」がすでに単独で果たしている
- **連続して3回、自分の手番を時間切れで渡し続けたら敗北とする**。何もしない相手を待ち続ける
  状態を終わらせるための線で、これも**1手でも指せば数え直す**。席を外した人は
  60×3=180秒 で決着し、待つ側はそこで解放される
- **ルームマッチに限り、部屋を作る側が持ち時間を切れる**。持ち時間は切断・放置への対処を
  兼ねるため既定は入だが、**ルームマッチは相手が誰か分かっている友達対戦**であり、
  放置への備えより「じっくり考える」ほうが価値が高い場合がある。決めるのは
  **部屋を作った側だけ**で、参加する側・観戦する側は画面で確認できるが変更できない
  (対局が始まってから食い違わないよう、部屋の設定として1箇所で持つ)。
  **切にすると、放置された相手を時間切れで倒せなくなる**ため、この注意を画面に1行で示す。
  **ランダムマッチとCPU戦では選べない**。ランダムマッチは相手が見知らぬ人であり
  放置への対処を外せず、CPU戦はもともと持ち時間を消費しない(13章)

## 6. キーワード

同じキーワードを**コストと総量だけ変えて複数のカードに載せる**ことを前提とした語彙。

### 語にするのは、複数のカードに載っている能力だけ

**キーワード(語)にしてよいのは、2枚以上のカードに載っている常在能力に限る。**
1枚にしか無い能力を語にすると、その語を覚えても他のカードで使い回せず、
**カードを読むたびに語の意味を思い出す手間だけが増える**。
語にしない能力は、カードに効果の文をそのまま書く。

カードを追加してある能力が2枚目に載った時点で、語へ昇格させてよい。

### キーワード(語にする常在能力)

| キーワード | 効果 | 載っているカード |
|---|---|---|
| **守護** | 相手はこの砂時計を無視して他を攻撃できない | シールド / ガード |
| **硝子(がらす)** | 最初に受けるダメージを1度だけ無効にする | グラス / ミラー |
| **貫通** | 砂時計を攻撃したとき、超過分が相手プレイヤーへ抜ける | ドリル / ランス |
| **速落(そくらく)** | 場に出た瞬間に砂が2粒落ちる(すぐ攻撃できる) | ダッシュ / ランス |
| **静止(せいし)** | ターン終了時に砂が落ちない(老いない代わりに攻撃力も伸びない) | フリーズ / スプリング(静止の刻) |

### 語にしない常在能力

いまは1枚にしか載っていないため、語を使わず効果の文で書く。
2枚目のカードに載せるときに語(毒砂・吸命・連撃)へ昇格させる。

| 能力 | カードに書く文 | 載っているカード |
|---|---|---|
| 毒砂 | ダメージを与えた砂時計を破壊する | ポイズン |
| 吸命 | 与えたダメージぶん自分のHPを回復する | ヴァンプ |
| 連撃 | 1ターンに2回攻撃できる | ツイン |

**カードの面には左右の隅を数値バッジが占めるため、収まるのは4文字程度**しかない。
そこには短い言い換え(「破壊」「回復」「2回攻撃」)を出し、
上の文は詳細パネルとデッキ編集の一覧で読ませる。

### トリガーキーワード

| キーワード | 発動 |
|---|---|
| **設置** | 場に出したとき |
| **反転** | 反転したとき(**この作品固有**。毎ターン行えるため常在効果として値付けする) |
| **余砂(よさ)** | 破壊されたとき |
| **落砂(らくさ)** | 自分のターン終了時(砂が1粒落ちる瞬間) |
| **被弾(ひだん)** | ダメージを受けたとき |

トリガーは能力ではなく**分類**のため、載っている枚数に関わらず語のまま使う
(「設置」はどのカードでも「場に出したとき」を意味する)。
ただし現状、反転は1枚しか無い。カードを足して語の使い回しが効く状態にする。

**落砂と被弾は、盤面に居続けることで繰り返し働くトリガーである。**設置・余砂が
1回で終わるのに対し、この2つは駒が生きているあいだ何度でも発動する。どちらも
**このゲームの土台の挙動をそのまま発火点にしている**点が要で、落砂は毎ターン必ず起きる
砂の落下(3章)に、被弾は必ず相打ちになる戦闘(4章)に乗る。**発動する回数を
プレイヤーが動かせる**(殴りに行けば被弾は増え、守れば落砂が伸びる)ため、
値付けは「1回あたりの効果 × 何回起こせるか」で考える。

### 常在能力の値段(総量換算)

語にするかどうかに関わらず、常在能力は「同じコストのバニラと釣り合うために
総量をいくつ削るか」で値付けする。
値段は**実装したエンジンで測った実測値**であり、測り方と生データは
`docs/BalanceReport_v5.md` 2〜4章に置く。

まず基準となるバニラ(効果なし)の総量は、コストに対してほぼ直線に乗る。

> **バニラの基準総量 ≒ 1.9 + 1.33 × コスト**

| コスト | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 基準総量 | 3.2 | 4.5 | 5.9 | 7.2 | 8.6 | 9.9 | 11.2 |

**最小コストは1とする。**マナは1ターン目に1しか無いため、コスト1のカードが1枚も
無いと1ターン目は構造上どちらのプレイヤーも何も出せず、盤面へ触れないまま1手が過ぎる。

この基準からいくつ削るかが、キーワード・効果の値段になる。

| 能力 / 効果 | 値段(総量) | 性質 |
|---|---|---|
| **貫通** | +0 | 実質無料 |
| **守護** | +0〜1 | 大型ほど**安い** |
| **速落** | +0.6 | 一定・安い |
| **硝子** | +1〜2 | 大型ほど高い |
| **吸命** | +1 | ほぼ一定 |
| **連撃** | +1.6 | ─ |
| 余砂:本体へ2ダメージ | +0.1 | 発動が破壊時まで遅れるぶん、設置より1粒安い |
| 余砂:1枚引く | +0.2 | 同上。**設置(+2)より2以上安い** |
| 落砂:本体へ1ダメージ | +0.9 | 場に残るかぎり毎ターン働く |
| 被弾:1枚引く | -0.1 | **総量そのものが「働ける回数」を買っている**(下記) |
| 攻撃できない | **-3〜-5** | 制約なので総量が増える。ワッチャーはコスト2で総量7 |
| 設置:トークンを1体出す | +0.5 | 盤面の枠を1つ使うぶん、総量を足すより安い |
| 設置:味方1体の総量+2 | +1.9 | ─ |
| 設置:味方1体に守護 | +0.1 | ─ |
| 設置:敵1体の効果を消す | -0.1 | ─ |
| 設置:本体へ2ダメージ | +1.1 | ─ |
| 反転:総量+1 | +1.4 | ─ |
| 設置:1枚引く | +2 | 手札1枚がそのまま展開になる |
| 余砂:トークンを1体出す | +0.2 | 設置版(+0.5)より安い。破壊されるまで働かないため |
| 余砂:味方1体の総量+2 | +1.3 | 設置版(+1.9)より安い。同上 |
| 被弾:本体へ1ダメージ | +0.2 | 総量が「働ける回数」を買っている(下記) |
| 反転:本体へ1ダメージ | +0.6 | ─ |
| 設置:味方1体の攻撃力+1 | +1.2 | ─ |
| 落砂:味方1体の攻撃力+1 | +1.6 | **同じ効果でも設置(+1.2)より高い**。毎ターン働くため |
| 設置:味方全体の砂を1粒落とす | **-0.4** | **総量が増える**。体力を削って攻撃力へ回すため、利点だけではない |
| 落砂:相手全体へ1ダメージ | **+6.9** | プールで最も高い。全体除去が毎ターン続くのに等しい |
| **毒砂** | +3.4 | 常に高い |
| 設置:1体を破壊 | +5.6 | 総量では買いきれない(下記) |
| 設置:全体の砂を2粒削る | +6.2 | 同上 |
| **静止** | 未測定 | 静止の刻(8章)で初出。壁としては自壊しない利点、攻め手としては攻撃力が伸びない欠点。総量が丸ごと体力として残るため、守護と重ねると高く出る見込み |
| 反転できない | 未測定(**制約**なので総量が増える) | 静止の刻で初出。クロノスはコスト7で総量12 |
| 砂を上へ戻す(1粒) | 未測定(安い) | 総量を変えない砂の移動であり、落砂(前借り)の逆の後払い。速落・ひとつまみと同じく低く見積もる |

**繰り返し働くトリガーは、総量そのものが値段になる。**落砂・被弾を持つカードは、
総量を削ると「働ける回数」まで一緒に削れる。クラック(被弾:1枚引く)は総量6で51%だが、
総量2まで下げると36%まで落ちる。**効果の値段がほぼ0に見えるのはこのためで、
実際には総量が効果の一部を買っている。**普通のカードのように「総量をいくつ削るか」で
値付けできない唯一の型として扱う。

**繰り返しトリガーと「攻撃できない」を重ねた場合だけ、コストで買える。**タワー
(攻撃できない / 落砂:本体2)はコスト5では最小の総量でも61%あり、コスト7で釣り合った。
効果が盤面の大きさに比例しないため、除去(下記4)と違ってコストの引き上げが効く。

**設計指針**

1. **貫通・速落・守護は安く、どのコスト帯にも載せられる。**同じキーワードを持つカードを
   軽重さまざまに量産するのに向く
2. **硝子は大型ほど高い。**守護と硝子はどちらも「大型ほど高い」と考えられていたが、
   実測では**守護は逆**だった(コスト2で+0.6、コスト5で+0.1)。盤面6枠に対して守護1体では
   止めきれず、相打ちで自分も削れるため
3. **効果を砂の移動で表現できるキーワードは、値段が自動的に安くなる**
   (速落は体力-2・攻撃力+2 を自分で払っている)
4. **余砂(破壊されたとき)は、同じ効果の設置版よりはるかに安い。**本体2ダメージで
   1.0、ドローで2.5下がる。破壊されるまで待つぶん遅いことに加え、**盤面へ直接効かない
   効果ほど値段が消える**(引いたカードを使うマナが残っていないことが多い)
5. **毒砂・確定破壊・全体除去は高い。**とくに**確定破壊と全体除去はコストを上げても
   釣り合わない**(ハンマーはコスト5で57.1%、6で56.4%、スイープはコスト8で59.5%、9で60.4%と、
   コストを上げてもほとんど下がらない)。総量は下限に達しており、
   **効果そのものを弱める以外に釣り合わせる手段がない**

### 語彙だけでカードを作らない

**キーワードをコストと総量だけ変えて載せ替えたカードばかりにしてはいけない。**
語彙を使い回せることは追加のコストを下げるための性質であって、カードの面白さの
基準ではない。実際、23種の時点で**バニラ4枚とキーワードだけの10枚で全体の6割**を占め、
残りも「設置で1回だけダメージかドロー」に寄っていた。

**1枚ごとの固有効果を積極的に足す。**手本にするのは、初期のハースストーン・
シャドウバース・ドラゴンクエストライバルズにあるような、**1行で読めるのに他の
どのカードとも重ならない**効果である。長い条件文や複数の分岐を持つカードは採らない。

固有効果を作るために新しい `EffectType` やトリガーを足すことは**禁じない**。
既存の語彙で作れるかどうかより、そのカードが盤面で何を起こすかを先に決める。

**自分の砂時計1体を対象に取る効果は、その効果を持つ砂時計自身を選べない。**
自分を強化できると「他の駒を助ける」というカードの読みが崩れ、対象を選ぶ意味も無くなる。

### 攻撃できない砂時計

**「攻撃できない」という制約を持つ砂時計を作ってよい。**その代わり総量を大きく取る。
反転はできるため、**攻撃力の高い状態を体力へ戻す壁**として働き、守護とは違う守り方になる。
制約は語(キーワード)にせず、カードに「攻撃できない」と書く。

### 反転できない砂時計

**「反転できない」という制約を持つ砂時計を作ってよい**(「攻撃できない」の鏡像)。
砂が落ちるほど攻撃力が伸びて体力が減る、というこのゲームの土台の挙動から逃げられない駒であり、
**放置すれば攻撃力が総量-1まで伸びる時限爆弾**として働く。相手は殴って壊すか、
砂を上へ戻して遅らせるかを迫られる。その代わり総量を大きく取る。

**この制約は反転権(2章)にも効く。**反転権は「1体1ターン1回・出したターンは不可」という
**回数と時期の制限**を無視するものであって、駒の性質を書き換えるものではない。
反転権で反転できてしまうと、出した直後(攻撃力0)に反転させるだけで無償の除去になり、
制約の対価として取った総量が丸ごと相手の得になる。
制約は語(キーワード)にせず、カードに「反転できない」と書く。

### 砂を上へ戻す効果

**「砂が上へ戻る」(攻撃力-n / 体力+n)という、落砂の逆向きの砂の移動を効果として持ってよい。**
総量は変わらない。落砂が「体力を攻撃力へ前借りする」動きなら、これは「攻撃力を体力へ
後払いで戻す」動きで、**駒の寿命を伸ばし、火力を削る**。自分の駒に使えば壁が長持ちし、
相手の駒に使えば攻撃力を落として時間を稼ぐ——どちらも受けに回る側の道具になる。

**総量を変えない砂の移動は、総量を増やす効果より低く値付けする**(6章の値段表)。
攻撃力が0の駒には効かない(0未満にはならない)。

**静止(上記)は落砂の発火を止めない。**静止が止めるのは砂が落ちることだけで、
「自分のターン終了時」というトリガーはそのまま発火する(スプリングの落砂効果は毎ターン働く)。

### 砂時計を出す効果(トークン)

**効果で場に出る砂時計(トークン)を作ってよい。**空き枠が無い場合は出ない。

- **トークンはデッキに入れられず、砂時計一覧にも出さない。**集めるものではなく、
  効果の結果として現れるものだから。一覧に並べると「持っていないカード」と
  見分けが付かなくなる
- **その代わり、トークンを出すカードの詳細に、出るトークンの中身を1行で添える。**
  一覧にも辞書にも無い以上、**そのカードの側で説明しないと何が場に出るのか調べる
  手段が無い**(「モートを1体出す」とだけ書かれても、モートの総量も効果も分からない)。
  出すのは名前・総量・効果と、デッキには入れられないという断りだけにする
- トークンも通常の砂時計と同じく、毎ターン砂が落ち、反転でき、破壊される

### 1枚だけの固有効果

上の「語にしない常在能力」と同じ考え方で、1枚だけの固有効果は文章のまま持たせる。**盤面の広がりを参照する効果は逆転装置として働く**ため、
プールに2枚程度含める(実測で逆転率が14%から25%へ上がる)。

### 砂術(スペル)

**盤面へ出ず、効果だけを起こして墓地へ行くカードを作ってよい。**呼び名は
**「砂術(さじゅつ)」**とする(「魔法」はこの作品の語彙に無いため)。

- **総量・体力・攻撃力を持たない。**持つのは**コストと効果の文だけ**
- **盤面の枠を使わない。**6枠がすべて埋まっていても撃てる。
  「空き枠が1つも無い間はどのカードも暗くする」(9章)の**唯一の例外**とする
- 撃った砂術はそのまま墓地へ置く。反転も攻撃もせず、盤面に残らない
- トリガーを持たない。**効果は撃った瞬間に1度だけ解決する**
- デッキには通常どおり入り、同名2枚まで。砂時計一覧にも並ぶ
- **砂術は「砂時計」ではない。**以後、カード全体を指すときは「カード」、
  盤面へ出るものを「砂時計」、出ないものを「砂術」と書き分ける

**砂術の値付けは、コストではなく効果そのもので行う。**この章のバニラ基準線
(`1.9 + 1.33 × コスト`)は総量を持つ駒のための式であり、砂術には使えない。
砂時計と同じ方式(そのカード2枚を含むデッキ vs 含まないデッキ)で勝率を測る。

**ただし、砂術はコストを動かしても勝率がほとんど変わらない**
(`docs/BalanceReport_v5.md` 10.2節)。確定破壊・全体除去がコストを上げても
釣り合わないのと同じ壁が、**弱い側にも出る**——最小コストは1であり、
弱すぎる砂術を安くして釣り合わせる余地が無いためである。
実測では、コストを1から3へ動かしたときの差が測定誤差(±5pt)より小さかった。
**したがって砂術を釣り合わせる手段は、効果の数値か効果そのものを書き換えることしかない。**

**測るときは、同じプールで測り直した砂時計と並べること**(同10.3節)。
この方式は釣り合っているカードでも45〜50%に出るため、砂術が43〜48%に出たときに
「弱い」と早合点しない。

**確定破壊と全体除去を砂術にしてはいけない。**総量を持たない砂術はコストでしか
釣り合わせられないが、除去はコストを上げても釣り合わないことが実測で出ている
(`docs/BalanceReport_v5.md` 4.2節)。**釣り合わせる手段が1つも残らない**ため、
砂術の除去は「1体に固定ダメージ」「全体に固定ダメージ」までとする。

**砂術も、語彙の載せ替えだけでプールを埋めない。**砂時計と同じ方針(この章「語彙だけで
カードを作らない」)を適用する。**既存の設置効果を砂術へ移すこと自体は禁じない**——
同じ効果でも「駒を残さない代わりに規模が大きい」という取引になるため、
盤面へ残るカードとは選択が変わる(ソードの「設置:本体へ2ダメージ」と、
同じダメージだけを撃つ砂術は別のカードとして成立する)。

**ただし、そればかりにしてはいけない。**砂術は数を絞る以上、
**少なくとも3分の1は「盤面へ駒を置かないからこそ成立する効果」**にする。
駒には持たせられない効果——1ターンの行動回数の制限を無視する、盤面から駒を取り除いて
手札へ戻す、盤面全体の状態をまとめて裏返す——がここに当たる。

### コンボ系カード(条件付き効果)

**「総量(体力+攻撃力)がちょうど5のとき」を条件に発動する効果**を持つカードを作ってよい。
総量はダメージを受けることでしか減らない(3章)ため、この条件は「基本の総量が5より大きい
カードが、狙って(あるいは巻き込まれて)ダメージを受け、ちょうど5まで削れた」ときに初めて
満たされる、**盤面の履歴を読む条件**になる。語(キーワード)にはしない。個々のカードが条件と
効果の組を1枚ずつ独自の文として持つ(前節「語彙だけでカードを作らない」と同じ考え方)。

条件の確認範囲は3通りある。

- **自分自身の総量を見る**(常在):そのカード自身のいまの総量が5の間だけ、別の能力を持つ
- **選んだ対象の総量を見る**(設置などの対象選択):総量5の味方・相手しか対象に選べない
- **盤面に総量5の駒がいるかどうかを見る**(トリガー):選ぶ対象そのものの総量は問わず、
  自分の場のどこかに総量5の駒がいれば発動する

**この条件を満たしていない間、効果は静かに不発になる**(対象がいなければ何も起きず、
使ったカードやマナが無駄になる)。条件を満たさない可能性がある以上、**同じ効果の常時発動版
より数値・効果そのものを強くしてよい**が、既存カードの完全な下位互換(同じコスト・同じ総量で
条件だけが足された劣化版)を作ってはいけない。

初のカードセット「五砂の刻」(8章・21章)5枚が、この仕組みで作られた最初の例。
個別のカードは `docs/Hourglasses.md` を参照。

## 7. バランスの目標値

自己対戦シミュレーション(CPUは中級)で次のレンジに収まることを確認する。
測り方・生データ・調整の経緯はすべて `docs/BalanceReport_v5.md` にある。

| 指標 | 目標 | 現状(70枚・デッキ30枚・HP24・反転権2/3) |
|---|---|---|
| 先手勝率 | 45〜55% | 51.0〜51.5% |
| 決着手数 | 20〜30手 | 20.1〜20.2手 |
| 本体ダメージで決着した割合 | 90%以上 | 100% |
| ユニットへの攻撃の割合 | 30〜60% | 47.5〜47.9% |
| 逆転率(中盤劣勢からの勝率) | 25〜35% | 32.1〜33.3% |

(800戦×シード42/43。BalanceReport_v5.md 12.4節)

**測るときの原則**

- **「本体ダメージで決着した割合」を必ず測る。**低いと対局がデッキ切れで決まっており、
  カードゲームとして成立していない
- **先手勝率と逆転率は連動する。**盤面の広がりを参照する逆転カード(スイープ・スウォーム)は
  構造的に後手を利する。片方だけ見て調整しない
- **手番の補正は1つだけ選び、重ねない。**コイン・1ターン目ドローなしは各約22pt、
  後手の手札1枚は約7pt動く。先手勝率が上振れしたらまずコストの分布を疑う
  (58種化ではコスト1〜2を足しただけで5.5pt戻った)
- **カード1枚の強さは混成デッキの平均勝率では測れない。**「そのカード2枚を含むデッキ」と
  「含まないデッキ」を直接ぶつける
- **デッキ枚数・初期HPを動かしたら、それ以前の実測値はすべて無効。**必ず測り直す
- **初期HP24(2026-09-05)**は時計の文字盤にちなむ数。HPを下げることは、クラス制の無いこの
  ゲームでは「対局の短縮 = 先行者有利の強化」にしか効かない(逆転率↓・先手勝率↑)。
  単独でこれ以上のHP調整は行わない。時の逆流の損益分岐点はHP12

## 8. 基本セット(現行のカード一覧)

砂時計58種 + 砂術12種 = **70枚を「基本セット」とし、ここで出そろったものとする**。
以後に追加するカードは基本セットへ混ぜず、**別のセットとして数える**。
レアリティ・クラス制・カードセットはいずれもこの70枚を土台として設計する。

**「出そろった」とは、追加を止めるという意味ではなく、値付けの基準をここで固定する
という意味である。**58種の時点までは1枚足すたびに基準そのものが動いていたが、
以後は基本セットの70枚を動かさずに、新しいセットの側をこれへ合わせて測る。

カードの個別データ(名前・コスト・総量・キーワード・効果)は `docs/Hourglasses.md` を参照。

### 基本セット以後の追加:カードセット(2026-09-09〜)

基本セット以後に追加するカードは、**「カードセット」**としてコンセプトごとに3〜15枚程度を
まとめ、ショップ(21章)で砂金と引き換えに**買い切り**で解放する形を主軸とする。
1セットの規模はコンセプトの大きさに応じて選ぶ——数枚の強化パッケージのこともあれば、
1つのプレイスタイルを一通り揃えられる15枚規模のこともある。

**ガチャ(確率による排出)は採らない。**欲しいセットをそのまま買う。重複という概念が
発生しないため、重複を別のカードへ変える「錬金」のような仕組みも持たない。

**基本セット70枚は、カードセットを1つも持たなくても通常に遊べる状態を維持する。**
カードセットは対局の土台ではなく、そこへ足す広がりとして位置づける。

**未購入のカードセットのカードは、デッキ編成へ入れられない。**カードセットの購入が
そのままカードの入手経路になる(21章)。

**買い切りのカードセット以外の追加手段も、状況に応じて別途検討してよい**
(記念・イベント等の無料追加など)。カードセットだけに追加手段を限定しない。

**1セットが単一のキーワードの使い回しだけで埋まることは避ける。**「語彙だけでカードを
作らない」方針(6章)はセット単位でも守る。

**セットは「足りない要素の詰め合わせ」ではなく、1つの枠(世界観・狙うデッキタイプ)で
まとめる**(2026-09-22、ユーザー判断)。プールに欠けている要素(墓地参照・反転への反応・
マナ操作など)は、それぞれが自然に収まる枠へ振り分けて、別々の回のセットとして出す。
**枠を選ぶときは、まずメタゲームでどのデッキタイプが組めていないかを見る。**

#### 第2弾「静止の刻」(2026-09-22〜)

**枠は「時を止める・巻き戻す」。狙うのはコントロールデッキの成立。**

基本セットの時点で、アグロ(速落・貫通・本体火力・コスト1〜2が10枚)とミッドレンジ
(コスト3〜4が31枚)は組めるが、**コントロールは組めない**。カードが足りないからではなく、
**駒が毎ターン老いて必ず死ぬ**という骨格が受けを許していないためである。守護の壁を立てても
数ターンで自壊し、回復はフラスコ・バームの2枚しか無く、相手の駒の成長に触る手段が1枚も無く、
「耐えていれば勝つ」形になる勝ち筋も無い。

このセットは、そこへ**老いない駒(静止)**・**砂を上へ戻す**・**回復**・**条件付きの除去**・
**大型の時限爆弾**を足して、盤面を維持しながら長期戦へ持ち込む道を作る。
9枚・900砂金。個別のカードは `docs/Hourglasses.md`「カードセット: 静止の刻」を参照。

**値付けの物差し**(このセットの数値を詰める際にユーザーが示したもの。以後も使う):
**総量を増やす効果は「使いやすく強い」と高く見積もる**——攻撃力へ足しても反転すれば体力に
なるため、体力・攻撃力のどちらへ足しても実質は総量の増加である。
**総量を変えずに砂を動かすだけの効果(落とす・上へ戻す)は低く見積もる**——前借りか後払いで
あって、それ自体は得にならない。

**今後のセットの枠(案・未確定)**:反転が反転を呼ぶ「反響の刻」(反転コンボ・相手の反転や
反転権への反応・召喚酔い解除)/ 墓地を積もった砂として参照する「遺砂の刻」(墓地参照・回収・
余砂の連鎖)/ アグロを更新する砂嵐の枠(マナ操作・速落付与)。採用が決まった回にここへ足す。

## 9. UI設計メモ

### 対局画面

見た目の現行仕様は下の「対局画面の再構築(2026-09-21)」が上書きしている。ここは構成・操作・演出の約束。

#### 構成

- 上から順に「相手の情報帯 / 相手の場(6枠)/ 自分の場(6枠)/ 自分の情報帯 / 自分の手札」。
  手札は最も頻繁に触るため、情報帯より外側(画面最下部)に固定する
- **12枠の盤面は1枚の卓上として描く**(木の額 / プレイマット / 中央の真鍮のレール)。卓の外は暗く落とし、
  卓の後ろにだけ淡い光を置いて浮かせる。卓の面は濃紺のフェルトで四隅に金の唐草(木地のままだと駒の砂の琥珀色と近く駒が沈む)
- **台座は空き枠にも必ず描く**(どこへ置けるかを盤面から読めるように)。6枠はカード型のスロットではなく丸い台座
- **プレイマットは自分と相手で別々に敷く**。ショップ(21章)で買う見た目の品で、**既定は「なし」**(額・フェルト・レールだけ)。
  相手のマットは相手の設定を表示名等と同じ経路で受け取る。CPU戦はCPU専用、リプレイと観戦は既定(棋譜はマットを記録しない)。
  地は暗く模様は薄く、駒・台座・バッジのコントラストを落とさないことを見た目より優先する。**画像ではなくコード描画**で、
  持つのは地の色・模様の種類・縁の色だけ
- **情報帯**: HP・マナ・山札の残り・墓地の枚数。相手側は手札の枚数も(裏向きカードの列にはせず数字1つ)。
  名前プレートにはアイコン・称号・表示名(CPU戦はCPU専用アイコンと「AI思考体」等の称号)。
  **マナは数字とピップの併記**で、粒はいまの最大マナのぶんだけ並べる。**HPは真鍮の器に入った琥珀の砂**として見せ、数字は必ず読める色で置く
- **手札は革の「手元の面」の上に置く**。札が宙に浮いている状態にしない
- **画面左の余白(卓の左)は「直前の手」の列**。直近3〜4件を上から積む
- 山札・墓地は枚数バッジを持つ小さな山。押すと墓地の中身を一覧できる。山札の中身は見られない
- **画面右の行動の列**: 反転権 / コイン / 持ち時間の時計 / ターン終了(大きなボタン・列の中ほど)/ ログ / 投了 / エモート。
  列を画面中央へ移すことはしない(盤面の幅が削れる)。「反転」はこの列に置かない(下記)
- **対局画面にバージョンを出す**(不具合の報告と突き合わせるため。11章)

#### 手札と場の見た目

- **手札のカードと場の砂時計は別の見た目にする**。手札はカードの枠を持つが、**場に出た瞬間に枠を捨て、台座の上に立つ
  砂時計そのものになる**。砂時計はそれ自体が状態を表示する器(上の砂=体力 / 下の砂=攻撃力)であり、枠へ閉じ込めると
  最重要の情報チャネルが潰れ、反転の演出も嘘になる。手札=カード / 場=ミニオンは既存DCGの標準でもある
- **数値の配置は既存DCGの慣習に合わせる**。手札は**コスト=左上 / 総量=右下**、場は**攻撃力=左下 / 体力=右下**、
  **場ではコストを出さない**。砂時計の上下の部屋へ数字を対応させる案は採らない(慣習から外れた配置は覚え直しを全員へ課す)
- 手札の名前とキーワードの行は、下の隅のバッジと封蝋が占める帯より上へ置く。**名前の高さはキーワードの有無に関わらず揃える**
- **イラストは体力と攻撃力の比で3枚を切り替える**(攻撃力<体力=上向き / 拮抗=落下中 / 攻撃力>体力=落ちきり)。
  場ではこの絵を大きく出し、砂の量を数値と並ぶ主要な情報として扱う。モチーフを生かすのは絵と演出の側で、数値の読み取りには持ち込まない
- **砂時計の絵は1組(3状態)だけを持ち、カードごとの色は数値(元の絵のid + 色相の回転量・彩度・明度)として持つ**。
  起動時に1組から作るため、カードを何種増やしても配布物は増えない。固有の絵を置けばそちらが優先される
  (基本の絵を品として売るのがカードスキン。31章)。色の数値は現行の絵から逆算した近似で、輪郭のコントラストがごくわずかに緩む
- **カード1枚ごとに固有の紋章(モチーフのアイコン)を添える**。全種が同じ絵の色違いである以上、
  **実際に見分けているのは紋章であり、色は「同じ絵に見えないための下地」に過ぎない**(50種で色相環の隣との差は0.02しか無い。
  彩度を2段に分けても100種までは保たない。さらに増やすときは色ではなく枠の形か装飾を変える)。
  紋章はカードのモチーフ(サンド=砂時計 / アイ=目 …)であって能力の分類ではない。能力系統の共通紋章を使い回す案は採らない
  - **カードを並べるすべての画面へ必ず添える**。図鑑・工房の在庫棚・編成中の棚はいずれも「絵の隅へ押した真鍮の印」で形を1つに揃える
  - **置き場は砂時計そのものではなく「載せている側」**: 場=台座正面の真鍮のメダル / 手札=左下の封蝋 / 詳細パネル=名前の左。
    駒の背後へ大きな透かしを敷く案は採らない(駒が128x168pxしかなく、はみ出した縁だけが見えて散らかる)
  - 素材は商用利用可・クレジット表記不要の外部アイコンから取り、出所を `assets/CREDITS.md` へ記録する
- **キーワードは短いラベルとして並べる**(紋章にしない。7種あり複数持つカードもあるため語で読ませる)
- **守護は対局画面の場でだけ形でも示す**(台座の輪を太い真鍮に)。攻撃の対象選択に直接効くため。手札・一覧・デッキ編集では
  ラベルだけ(枠を太くする強調は2026-09-14に廃止。意味の無い強調で選択中の枠とも紛れる)。
  **硝子が残っているものはガラスに薄い光の膜**を重ね、1度使うと消える
- 出したターンのもの(動けない)は僅かに沈め、**攻撃済みは彩度を落とし**、**まだ攻撃できる自分の駒には控えめな印**を出す
- **砂術は砂時計の絵を持たず、紋章を中央へ大きく置き、総量のバッジを出さず、枠の色を変える**。場での見た目は存在しない

#### 操作

- **出す**: 手札を押す → 空き枠が光る → 枠を押す。ドラッグでも出せる。マナが足りない札・**空き枠が無い間はどの札も暗くして出せなくする**
  (上書き設置は行わない)。設置効果が相手1体を対象に取る場合は出した直後に対象選択へ入る(対象がいなければそのまま出る)
- **反転**: 自分の駒を押す → **その駒のすぐ下に「反転」ボタン**が出る → 押す。できない場合はボタンを出さない。
  右の列へ置くと視線とカーソルの往復が遠く、上へ出すと相手の駒へ重なる。駒の下端と自分の情報帯のあいだへ収まる高さにする
- **反転権**(2章): 行動の列のボタン。残り0または自分の手番でないときは押せない。**残り回数は数字ではなく粒で示し、自分と相手の
  両方を並べる**(相手の残りが見えないと、相手の駒を弱めるか守るかの判断が立たない)。押すと**敵味方どちらの場も光り**、
  選んだ駒を反転させて残りが1減る
- **攻撃**: 自分の駒を押した状態で相手の駒か**相手のHP帯**を押す。ドラッグでも同じ。攻撃できる対象だけを光らせ、
  **守護がいる間は守護以外が光らない**
- **砂術**: 押すと空き枠ではなく対象が光る。対象を取らないものはその場で発動。ドラッグの落とし先は対象(取らないものは盤面のどこでも)。
  **空き枠が無くても暗くならない**(6章の例外)
- **攻撃の対象を選んでいる間、双方の予測後の数値を出す**(体力の減り方・破壊されるか)。戦闘は相打ちである以上
  「この攻撃で自分も死ぬのか」が毎回の判断の中心で、暗算させない。狙う相手にカーソルがある間はその1組の結果に置き換え、
  離れたら**最も自分が削られる組**(最悪の場合)へ戻す。HP帯を指しているときは本体を殴る場合の予測
- **選択は右クリックまたはEscでも取り消せる**
- **手札はホバーで手前へ大きく浮かせる**(押す操作は変わらない)
- **コイン**(後手のみ・1対局1度): 行動の列から押してマナ+1
- **マリガン画面**を対局前に挟む(2章)。暗幕の上に初期手札を大きく並べ、押すたびに選択が切り替わり、選ばれたものは沈んで
  砂時計を裏返した印を重ねる。確定ボタンは0枚なら「このままで開始」、n枚なら「n枚を引き直す」。相手が何枚交換したかは出さない
- **クリックできる要素は共通の挙動**: ホバーで明るく浮きカーソルが指に、押し込むと縮み、**要素の上で離した時のみ確定**。
  操作できない状態(相手の手番・観戦・再生中)ではホバー表現もカーソル変更もしない
- タッチ: タップ判定に許容マージンを持たせる。頻繁に押すボタン(反転等)は指でも押せる寸法を確保する

#### 詳細パネル(ホバー)

- **対局中のカード・駒の効果詳細は、カーソルを乗せている間だけ表示する**。クリックで開く形は、自分の駒を読むだけで攻撃・反転の
  選択に入ってしまうため採らない
- **その代わりパネルに操作を要する要素を置かない**(語のボタンも実演も出さず、語と説明を文として並べる)。
  パネルへカーソルを動かす理由が無い状態にして初めて、外れたら消える形が成立する。語の意味と実演は砂時計図鑑に集約する
- 手札・自分の駒・相手の駒のいずれもホバーで出す。空き枠では出さない
- **中身の高さぴったりまで縮め、カーソルのすぐ近く(右下を既定、はみ出す側だけ折り返す)へ出す**。置き場の規則は1箇所で決め、画面ごとに持たない
- **上下の情報帯には掛けない**(HP・マナ・山札は読みながら判断するもの)。パネルは卓の範囲へ収める
- **出さない間**: 攻撃・設置効果・砂術の対象選択中 / マリガン中 / 演出の再生中
- カードから外れたら短い間を置いて消す(隣へ移る途中で点滅させない)。手札のホバー拡大(`hover_zoom`)は別に維持する

#### エモート

- 行動の列の「エモート」ボタンは「ログ」「投了」と**まったく同じ寸法・作り**(クールダウン中も文言の頭は「エモート」のまま、残り秒数を後ろへ)。
  押すと4つの選択肢が真鍮枠のパネルに1行ずつ並ぶ(行頭に菱形)。選ぶと即送信、発言者の名札付近に吹き出しとして約3.8秒(完全不透明3.0秒)表示後フェード。送信後9秒のクールダウン
- **対局中に使えるのは4つまで**で、所有分からアカウント画面でセットする。ショップで増えても選択肢は常に4行(盤面を覆う面積のほうが損)
- 既定の4つ: 「よろしくお願いします」「見事な一手です」「なんだと…」「こちらに傾いているようですね」
- **マリガン中は送信できず、ボタン自体を出さない**(無効の見た目が隣の真鍮のボタンと並ぶと色が違って見える)
- 相手のエモートをミュートできる(ポップアップ内で切り替え)。CPU戦でも送れ、CPUも低確率で返す

#### 演出

**原則**: ロジックは演出を待たず即座に解決し、演出は結果を後から見せる。演出中は盤面の操作を受け付けない。
**消える砂(被ダメージ・砕けて散る)と落ちる砂(ターン終了・下の部屋へ流れる)を演出で明確に分ける**——取り違えると4章のルールを誤解するため、
演出上もっとも重要な区別として扱う。

- **攻撃は、駒が対象の斜め上まで渡っていき、反動をつけて当てる**(線を引くのではなく「渡っていく」)。4段構成:

| 段 | 動き | 尺 |
|---|---|---|
| 寄る | 台座を離れ対象の斜め上へ。出だしを速く終わりを緩め、**上端をつままれてぶら下がった駒**として下端が遅れて振れる | 0.28秒 |
| 溜める | 上端を支点に振り子のように後ろへ傾く。砂も傾きに合わせて寄る | 0.14秒 |
| 当てる | 振り下ろしてコツンと当てる(叩き潰さない)。接触点で閃光と砂の破片 | 0.10秒 |
| 戻る | 小さく揺れながら台座へ戻る | 0.30秒 |

  - **相打ち**: 当たった瞬間に防御側も同じだけ砂を散らし、押し返されて揺れる。加えて**防御側の攻撃力が1以上なら、台座正面の
    紋章を攻撃側へ短く突き出してすぐ戻す**(砂が散るだけでは反撃に見えなかった。2026-09-13)。攻撃力0の駒は突き出さない。
    誰が仕掛けたかは攻撃側の動きだけで示す
  - 相手プレイヤーを殴る場合も同じ動きで対象がHPバーになるだけ。**貫通は砕けた対象を通り抜けてHPバーまで届く**
  - **連撃は1回目が台座へ戻ってから2回目**(重ねる案は採らない。0.3秒の短縮にしかならず演出の進行を作り替える必要がある)
  - **同じターンで2回目以降の攻撃は尺を6割へ詰める**
  - **当たった瞬間、卓と駒だけをごく短く揺らす**(情報帯と行動の列は動かさない)。ダメージが大きいほど強く、上限あり。
    揺れている最中に次が当たったら足さずに大きいほうで上書きする
- **ターン終了の砂落ちは全ユニット同時**に1粒落とし、破壊されたものだけ続けて見せる
- **破壊は砕けて台座へ崩れ落ちる**。割れた瞬間にガラスの破片を砂より速く散らし(器が壊れたことを伝える)、砂は放物線を描いて台座へ溜まってから消える。
  同時に複数壊れた場合も同時に見せる
- **場に出した砂時計は台座の少し上から落ちて着地し、足元に砂が舞う**。着地と通常の反転では台座の銘板を短く光らせる(ドローの合図と同じ光の輪)
- **設置効果・トリガーは「そのカード自身の紋章が対象へ飛んで働きかける」**。光の筋だけでは何かが光っただけにしか見えなかった(2026-09-13)。
  単体・全体・敵味方を問わずすべて紋章で見せ、**光の筋が残るのは通常の反転だけ**。全体を狙う効果は対象の数だけ同時に飛ばす
  - **型**(効果の性質で動き方を変える): **打撃**(ダメージ・破壊・本体への直接ダメージ)=弧を描いて飛び当たると膨らみ盤面を揺らす /
    **恵与**(味方の強化・キーワード付与・回復)=低い山なりで舞い降り金色の輪が広がる、揺らさない / **払拭**(効果を消す)=直進して
    くすんだ輪へ収縮 / **反転**(体力と攻撃力の入れ替え)=回転しながら飛び、届くと対象が通常の反転と同じ演出で裏返る
  - **出どころ**: 駒=駒の中心から即座に / **砂術**=自分の情報帯の上で紋章が大きく浮き上がってから飛ぶ(対象を取らないものはその場で弾けて光の輪だけ)/
    **余砂**=砕けた台座に銘板だけが残り、それが飛ぶ(飛ぶ先が無い効果は銘板がその場で光って消える)
  - **砂へ還す**は紋章が対象を包み、駒が縮んで持ち主の手札の方向へ吸い込まれる(壊れたのではなく戻ったと読めるように)。
    **時の逆流**は自分のHPバーの上で紋章が一回転し、届いた瞬間に数値が入れ替わる
  - **ドローを起こす効果**は山札の脈打ちに加えて、その駒の紋章の周りへ短い光の輪(どのカードが引かせたかを示す)
- **砂術は撃った瞬間に墓地へ置く**。上の浮上が「手札から消えただけ」に見えないための代わりを務める
- **反転は誰が手を出したかが分かる演出にする**: 反転した側の陣地から対象へ光の筋が伸び、届いた瞬間に駒が持ち上がって回転し着地する。
  **中心となる行動のため他より作り込む**——筋の後ろに金の砂粒が尾を引き、着弾で放射状の光条、回転はわずかに行き過ぎてから戻す(手でひっくり返した手応え)
- **硝子が無効化したとき、膜が割れる閃光を出す**(次の攻撃が通るかを判断できるように)
- **ドローは山札から手札へ札が流れる動き、疲労は山札を赤く脈打たせてからHPバーへ数字を飛ばす**
- **ダメージはフローティング数字**。発生源の駒が特定できればその駒からHPバーへ飛ばし原因の駒を光らせる。
  **大きいダメージほど文字を大きく強い色にし、高く浮かせる**。回復は緑で大きさを変えない
- **手番の切り替わり**: 自分の手番になった瞬間、盤面中央に「あなたの番」を一瞬大きく出す。相手の手番の間は相手の情報帯を光らせ自分を落とす
- **相手の1手は1手ずつ見せる**: 対象の駒へスポットライトを当て、**対局ログと同じ文言**をその駒の近くへ浮かせ、間を置いてから次へ
- **効果音**: 出す / 反転 / 攻撃(相打ち)/ 被弾 / 決着 / ボタン押下 の6種。**CC0素材に限る**(クレジット管理のコストを負わないため。CC BY等は不採用)。
  **同じ音源を高さで鳴き分ける**(破壊は被弾より低く、硝子の膜割れは高く。同じ出来事は必ず同じ高さ)。砂時計が壊れた音は被弾と別に鳴らす
- **BGM**: タイトル(厳かで壮大)/ ホーム系 / 対局 の3曲をクロスフェードで繋ぐ。**パブリックドメインのクラシック(ピアノソロ)**。
  オーケストラは強弱の幅が大きくBGMに向かない。楽曲として完結するためループせず、終端の数秒前からフェードして間を置いて頭から鳴らす「アルバム再生」。
  結果画面ではBGMを止め勝敗別の短いジングル(CC0・ピチカート等)。ブラウザの自動再生制限のため最初のクリックを検知してから再生する
- **音量は「効果音」「BGM」の2系統**をホーム右上のハンバーガーメニューのスライダーで独立に調整し `user://` へ永続化。
  メニューには音量の下に**公式Discordサーバーへの導線**(公式マークだけの正方形ボタン、真鍮へ塗り替えない。別タブで招待リンク)

#### 結果とログ

- **対局ログ**: 各手番で誰が何をしたか、砂の進行で何が起きたかを記録して表示する。**決着そのものも1手として記録**(「先手の勝利(後手のHPが0)」等)
- **結果パネル**: 勝敗・両者の最終HP・総手数・決着の要因・獲得した砂金(15章)・「もう一度」「ログ」「ホームへ」。背景を暗くして盤面を塞ぐ。
  対局・観戦で共通。**「もう一度」は同じデッキでもう1局で、当面CPU戦にだけ置く**(オンラインの再戦は同意の仕組みが要る)。
  終局後も「ログ」からログを開け、閉じると結果パネルへ戻る。**リプレイ再生モードでは結果パネルを出さない**(手を前後させる妨げになる)
- **QOL**: 残り15秒以下で時計周辺に緊迫感の演出(脈動・砂粒・警告色)/ **打点アシスト**(いま直接攻撃できる総攻撃力。守護がいればその旨)を控えめに表示 /
  卓のメダリオン等を押すと歯車が回る・砂埃が舞う軽い反応(相手の長考中の手持ち無沙汰)

#### 対局以外の画面

- **起動して最初に出るのはタイトル画面**。ゲーム名「砂時計アリーナ」。どこか(またはEnter/Space)を押すとホームへ。
  置くのは開始の導線とアカウントへの入口だけ。ホームからタイトルへ戻る導線は設けない
- **タイトルロゴは王道クラシカル**(金の箔押し文字に濃紺の縁取り、上に砂時計の紋章、下に飾り罫)。**英字のサブタイトルは置かない**。
  ロゴは作品の絵として画像アセット扱いだが、未配置の間もコード描画で同じ構図を出す。背景もタイトル専用が無ければホームを流用
- **タイトル→ホームだけは専用の演出**: 押すとロゴが光って伸び上がり、金色の砂が上から画面を満たし、覆いきったら差し替えて砂が下へ抜ける
- **ホーム画面**は画面下部5タブ(アイコン+ラベル)「たたかう / そろえる / きろく / おぼえる / つくる」。
  **タブは行いで分ける**(以前は対局の入口が4タブに散っていた)。**選択中はせり出させ文字を大きく、非選択は沈めて彩度と明るさを落とす**
- **入口の強弱は3段に固定**: 塗りつぶした真鍮の面(そのタブでいちばんやってほしいこと1つだけ)/ 暗く凹んだパネル(同格の選択肢)/ 文字だけ(補助情報)
- **ホームの札は「見出し + いまの状態を1行」**(デッキ編集=選択中のデッキ名・枚数・数、図鑑=収集数、ショップ=砂金)。
  中身そのものは見せず、右に紋章の透かしを額縁の内側に収めて敷く(上限あり)。砂時計の絵を大きく透かす案は採らない。
  札はタブの領域を使いきる高さにするが行は増やさない
- **初回起動時のみ「おぼえる」を初期選択、2回目以降は「たたかう」**(一度でもホームを開いたかで判定)
- 画面遷移は0.2秒未満のクロスフェード。通信待ちは文言の末尾に巡回するドット
- **たたかう**: 上の枠「だれかと」(ランダムマッチ / ルームマッチ / ランクマッチ)・下の枠「ひとりで」(CPU戦「好きなデッキで1局」/ ソロモード
  「決まった条件の関門に挑む」/ リーサルパズル「1手番で仕留める」)。固定の数を副題に書かない。
  **「前回の対局へ戻る」は最上段の帯**(戻れるときだけ・急ぐ用件を上へ)。対局前に**デッキ選択画面**を挟む(前回の選択が初期値。
  保存デッキが無ければプリセット「基本」で入る)。**ルームマッチだけは専用画面の中でデッキを選ぶ**
- **おぼえる**: 「遊んで覚える」(誘導対局)と「読んで覚える」(遊び方・画面の見かた・キーワード辞書)の2枠
- **そろえる**: 左に大きな「デッキ編集」、右に縦2列で「砂時計図鑑」「ショップ」。ショップをヘッダーの砂金チップへ移す案は採らない
- **きろく**: 上の枠「ミッション」(**今日の3つと進み具合を札に並べ、受け取れるものがあれば下部タブと札の両方に印**)、下の枠「戦績」「リプレイ」
- **砂金の残高は真鍮の小さなチップ**。文言は「砂金 1,500」に統一し3桁区切り。増えたときだけ脈打たせて数え上げる。
  ホームのヘッダーにアカウントボタン(表示名、未設定なら「ゲスト」)と並べて置き、対局から戻るたびに更新する

#### 砂時計図鑑・デッキ編集

- **砂時計図鑑は机に開いた見開きの本**(左=一覧 / 右=選んだ1枚の解説)。全種を保有の有無に関わらず並べ、未保有は輪郭と「?」
  (砂時計と砂術で形を分ける)。**収集済みの印は置かない**(同じことを2度言うことになる)。全体の進捗は「収集 9 / 70」の1行
  - 1件ごとにコスト(左上の菱形)と総量(右下の丸。砂術は「術」)。砂術は絵の代わりに紋章
  - **右のページの砂時計は押すとひっくり返せる**(操作を促す表示は置かない。砂術は裏返らない)
  - 右ページ下部に「あなたの記録」(共に戦った対局数・勝率。19章の数字を引くだけ)
  - 戻ると並び替えは紙面の外へ。**並び順はコスト順(既定。同コストは砂時計が先・砂術が後 → 総量の小さい順 → id順)と追加順**
    をボタン1つで往復し、保存しない。**id順は並びとして使わない**(内部の識別子で追加順とも一致しない)
  - **能力の実演**: カード詳細に実演枠を設け、そのカードの能力が盤面で何を起こすかを数秒のループで見せる。
    **カードごとではなくキーワード / 効果の種類ごとに1本**(カードが増えても自動で付く)。バニラには「基本の砂の動き」。
    **紙に刷った図版(インクの線画)**で描き、部品(砂時計・HPバー・矢印・守護の輪・硝子の膜・砕けた印)の組み合わせで組む。
    基本の砂は1粒ずつ落とし、省略は「…」で。**文は「何が起きるか」だけを持ち、「いつ」はトリガーから組み立てる**。
    実演を出すのは図鑑と辞書だけ(対局中・デッキ編集の詳細は持たない)
- **デッキ編集は「左=全カードの一覧(グリッド)/ 右=編成中のデッキ」の2カラム**。一覧の探しやすさを最優先(横1行の横スクロールは23種で破綻した)
  - 左の操作行に**「絞り込み」ボタン**(コスト・キーワード・名前検索をモーダルへ集約。適用中は条件数バッジ、一括リセット)
  - 右は「デッキ名・枚数 / **30枠の棚(横6×縦5)**」。編成中のデッキは棚に並べた砂時計そのものとして見せる。
    枠の数はデッキ枚数と一致させ、**空き枠がそのまま「あと何枚」を示す**(帯もマナカーブの棒グラフも置かない。並びがコスト順固定のため)。
    空き枠は棚に彫った受け皿に薄い砂時計の影。**同名2枚は隣り合う2枠**(「×2」にまとめない)。駒にはコスト・総量・紋章・名前
  - 一覧の札を押すと1枚加わる(「2/2」なら暗くするが詳細確認のクリックは受ける)。**棚の枠を押すとその1枚が在庫へ戻る**(増減ボタンは持たない)
  - 一覧の札は**ホバーで掴めるカーソル**へ変わりドラッグで棚へ入れられる(他画面の `HourglassCard` は通常カーソル)
  - **詳細はホバーで出し、操作を要する要素を置かない**(対局画面と同じ規則・同じ置き場)
  - **保存は30枚ちょうどのときだけ通す**。名前は10文字程度まで。プリセットを読み込める(18章)
- **デッキ一覧**: 横長カード(デッキ名 + 代表的な砂時計のアイコン)の**横2列グリッド**、編集・削除ボタン、「使用中」バッジは出さない。
  並び替えはヘッダーの「デッキ入れ替え」から専用モードへ。対局前のデッキ選択も同じ一覧を流用(選ぶだけ)
- **共有**はデッキ編集のヘッダーから開く1パネルに**デッキ表(画像)とデッキコード**を並べる(渡す方法が2つあることに気づけるように)
  - **デッキコードは8桁の数字。中身はサーバーへ預けて番号だけを渡す**(30枚の組み合わせは8桁へ収まらない)。
    発行はボタンを押したときだけ、同じ構築には同じ番号、預けたデッキは消さない、カードのidと枚数で持つため増減しても読める
    (プールから消えたカードを含むものだけ読めない)。通信が要り、失敗はその旨を1行で
  - **デッキ表は1280×720の画像**。上から「デッキ名と枚数 / 30枠の棚(横10×縦3)」で、**編成中の棚と同じもの**を使う。
    隅に作品名とバージョン、コードを発行済みならその番号(画像のために発行しない)。共有パネルにはその画像をそのまま映す。
    **「画像をコピー」と「画像を保存」**。コピーはクリップボードAPIを試み、iframe等で拒否されたら画像をオーバーレイ表示して
    右クリックからコピーできるようにする。ブラウザ以外は保存のみ

#### 共通のレイアウト規約

- 基準解像度1280x720・16:9。アスペクト比を維持し、縦横比の異なる端末では黒帯で16:9を崩さない。PCのホバー操作を最優先
- **対局画面を除く全画面**: 外周余白24px、上部に高さ88pxの共通ヘッダー(左=戻る / 中央=画面タイトル / 右=主アクション0〜3個)、
  その下24pxの余白、コンテンツは y=136 から。画面ごとに個別に決めない
- **一覧が空のときは領域中央に「砂時計の印 / 見出し / 次にすることの1行」**だけを出す(押せるものは置かない)。
  通信待ちも同じ形で見出しの末尾へ巡回ドット(見出しの位置は動かさない)
- **「戻る」はヘッダーを持たない画面(図鑑・工房)でも同じ形(左向きの五角形)**。位置と形だけ共通で大きさは画面に合わせてよい
- **一覧は横2列のグリッドを基本**とし、カードは横長・低背にする(縦1列は1画面に2〜3件しか入らない)
- **UIクローム(ボタン・パネル枠・入力欄・棚板・名札)はコード描画**。無地の図形では平坦でチープに見えるため、多段グラデーション・
  面取り・内側の落ち込み影・グレイン・金属の照り返しを伴わせる。描画は共通ライブラリへ集約し画面ごとに個別実装しない。
  **砂時計のイラストと背景イラストは画像のまま**(作品の絵そのもの)
- **背景イラストを持たない画面は「場所」として描く**: 書庫(ルール・辞書・画面の見かた)/ 記録室(戦績)/ 控えの間(デッキ一覧・
  ルーム・パズル選択)/ 帳場(ショップ)/ 無地(対局)。部品(板壁・棚・引き出し・作業灯・吊り看板)は共通に持ち、画面は組み合わせを選ぶだけ。
  壁は奥にあるものとして扱い、中身の乗る帯は「板目が見えていて文字も読める」ところまで落とす
- 全画面について、大手DCG/ソシャゲのUIを参考に、公開して恥ずかしくない見た目へ作り込む

### 対局画面の再構築(2026-09-21)

対局画面だけが「真っ黒な虚空に卓が浮いている」状態で、場所として読める他の画面より
群を抜いて弱かったため、**操作・演出・ロジックの層は変えず、座標と描き方だけを差し替えた**。
方向はモック3案(`scratchpad/audit/mock_A〜C.jpg`)から **Cの濃紺ベルベットの卓 + Bの吊りランプの
一点光源**を採った(ユーザー判断)。UIは従来どおりコードで描く。

| 要素 | 決めたこと |
|---|---|
| 場所 | 暗い石の広間。卓の真上の真鍮の吊りランプが唯一の光源で、卓・情報帯・手札・行動の列はすべて真下へ落ち影を持つ |
| 卓 | 額と面を台形に描き(手前が広く奥が狭い)、**相手の列の駒を0.92倍**にして奥行きを出す。フル3Dにはしない。面は濃紺のフェルト |
| 台座 | 平たい円ではなく、上面の楕円と側面の帯を持つ真鍮の器。守護の太い輪・選択の水色の輪は上面の縁に掛ける |
| 情報帯 | **1枚の板で囲わず、真鍮の器具を横に並べる**(板を囲う額を太くしても「UIの矩形」のままで卓に負けた)。左から 肖像のメダル / 名札(称号を上・表示名を下)/ HPの器(右端に赤い丸で現在HP)/ マナの計器(青い丸に現在値・右へ最大値ぶんの粒・コインは肩の金貨)/ 山札・墓地・手札の札。**色の語彙は盤面と揃える(青=コスト/マナ、赤=体力/HP)**。手番の側はメダルの外の琥珀の輪が脈打ち、攻撃の的の間はHPの器の縁が赤く脈打つ |
| 行動の列 | 右端の縦1列を1枚の濃紺のパネルとして描き、丸い真鍮のボタンを収める。ターン終了は大きな丸。反転権は紋章を彫った一回り大きいメダル + 自分/相手の残り回数の粒の札。**持ち時間の時計はここ**(コインとターン終了のあいだ)に置き、いま手番の側の残りだけを懐中時計の面に出す。時計を持たない対局は「∞」で、時計そのものは消さない |
| 手札 | 革の面の上、札の上端を卓の額の下端へわずかに重ねる。札の面は「絵の窓 / 名前の帯 / キーワードの行」の3段。地は羊皮紙寄りの明るい紙、真鍮の額(砂術は青系)。**絵の窓の奥にそのカードの砂の色の光だまり**を敷いて色違いの1枚ずつを立たせる(色は色相表から求める)。四隅は 左上=コスト / 右下=総量 / 左下=封蝋 のまま、コストと総量は真鍮の縁で嵌めた宝石として描く |

変えないもの: 画面の構成、数値の位置、砂時計の絵、演出、直前の手の列、詳細のホバー、対象選択・ドラッグ。

### 操作への反応(手触り)(2026-09-15)

演出の派手さではなく、**押した・掴んだ・置いた・取り消したという操作のひとつひとつに画面が
返事をする**ことで手触りを作る。いずれも既存の要素の反応を細かくするもので、新しい画面要素は
増やさない。実装済み。細部の尺・振れ幅は実機で詰める(TODO.md)。

**対局画面**

- 手札: ホバー中の札の両隣が外へ避ける / ドラッグ中の札は動く方向と逆へ遅れて傾く(攻撃の
  「上端をつままれた駒」と同じ物理)/ 空き枠へ放したら指の位置から台座の中心へ滑ってから着地 /
  引いた札が入るとき他の札がスライドして場所を空ける / 相手の手番の間は手札を少し沈める
- マナと数字: 札にホバー中はそのコストぶんのピップが光る / 支払ったピップは札の方向へ吸われて
  消える / 駒の体力・攻撃力のバッジは値が変わった瞬間に小さく跳ねる
- 対象選択: 狙える相手にホバーすると駒がわずかに縮んで輪郭が脈打つ(身構え)/ 攻撃のドラッグ
  中は駒から指先へ矢印を引く / 右クリック・Escの取り消しで光っていた枠は短く縮んで「戻る」
- 音: ボタン・手札・駒にカーソルが乗ったとき、押下音を高く小さく鳴らす(音源は増やさない)。
  ターン終了の砂落ちの音はCC0素材が揃うまで保留

**メニュー画面群**(ホーム・デッキ編集・図鑑・ショップ・アカウント・各一覧)

- 全画面: ボタンの押し込みをもう一段深く(ハイライトが沈み影が薄くなる)/ クロスフェードに
  進む方向の横移動を足す(進むときは右から、戻るときは左へ)/ Esc・右クリックで戻る /
  共通ヘッダーのタイトルは着地でごく短く浮いてから止まる
- ホーム: タブ切り替えで中身が横へ滑る / `HomeTile` のホバーで紋章の透かしが浮く / 副題が
  外部要因(砂金・ミッション)で変わった瞬間に光る / 砂金チップへ獲得ぶんの粒が飛んでから数え上げる
- デッキ編集: 一覧の札を棚へ入れるとき札の位置から枠へ飛び、戻すときは逆向き / 2枚目で
  「2/2」バッジが跳ねる / 30枚ちょうどで棚全体が一度淡く光る / 絞り込みモーダルは押した
  ボタンの位置から膨らんで開く
- 図鑑: 1件を押すと右ページの紙がめくれて次の解説が現れる / 右ページの砂時計はホバーで
  わずかに傾く(押せば裏返ることの誘い。案内文は置かない)/ 並び替えで札が新しい位置へ滑る
- ショップ・アカウント: 「買う」で品の絵が砂金チップへ飛んでから残高が減る / アイコン・称号・
  マットを選ぶと名札見本が跳ねる / 残高不足で暗い品はホバーしても反応しない
- 一覧系: 札は上から順に0.03秒刻みでずれて現れる(上限8件、以降は同時)/ 削除した札は
  縮んで消え、残りが詰まる

## 10. 技術設計方針(毎日アプデ運用のための骨格)

- 砂時計は `Resource`(.tres)としてデータ駆動で管理し、コード変更なしで新規追加できる形にする
- 効果は「トリガー×ターゲット×エフェクト」の組み合わせで表現し、エフェクトの種類ごとにハンドラを用意する
- 既存のエフェクト種別の組み合わせだけで新しい砂時計を作れる状態を維持し、「新効果そのものの追加」と「既存効果の組み合わせによる新駒追加」を分けて運用する
- オンライン対戦はターン制の特性を活かし、非同期(手番ごとにサーバーへ送信→相手に反映)の通信方式を基本とする

## 11. オンライン対戦

- マッチング方式は**2種類**を用意する
  1. **ランダムマッチ**:待合室(マッチングキュー)に入り、他の待機プレイヤーと自動的に対戦成立させる。複数人が同時にキューへ入っても、二重マッチや取りこぼしが起きないようにする
  2. **ルームコード対戦**:片方がルームを作成しコードを発行、もう片方がコードを入力して参加する(友達対戦向け)
- **ルームコードは4桁の数字とする**。口頭で伝えられる短さを優先する。桁数が少ない以上
  同じコードが同時に生きることは避けねばならないため、**使われていない番号を選んで作る**。
  **一定時間より古い部屋の番号は再び使ってよい**(対局は20分ほどで終わるため、
  それより十分に長い時間を置く)
- **先手・後手はランダムに決める**。ランダムマッチ・ルームマッチのいずれも、対局が成立した
  瞬間に五分五分で振り分ける。**先に待っていた側・部屋を作った側が先手になる形は採らない**——
  先手勝率は目標を45〜55%に置いているとおり五分ではなく(7章)、とくに同じ相手と続けて遊ぶ
  ルームマッチでは、部屋を作った側だけが有利を取り続けることになるため。**振り分けは対局を
  成立させた側が1度だけ行い、両者はその結果を読む**(双方が別々に振ると食い違う)。
  **CPU戦・ソロモード・誘導対局は従来どおりプレイヤーの先手で固定する**(13章・27章)
- 対局中の通信は、指した手(場に出す/反転/攻撃/コイン/ターン終了)を送信→相手が受信して反映する非同期方式とする
- サーバー側での正当性検証は行わず、クライアントの操作をそのまま信頼する(不正対策は将来検討)
- 持ち時間切れの扱いは5章の通り(切断・放置時の敗北条件を兼ねる)
- **対局が始まる前(相手のデッキ・配置を待っている間)は、いつでも中断してホームへ戻れる**。
  待たされている側が抜ける手段を持たないと、相手がブラウザを閉じただけで長時間画面に
  縛り付けられるため。中断したことは相手にも伝え、相手側は「対戦相手が対局を取りやめました」
  として同じくホームへ戻れる状態にする。中断は対局が始まる前にしか行えず、対局開始後に
  抜けたい場合は投了する(3章)
- **通信の状態を対局画面に表示する**。手を送っている間は「送信中」、送信・受信が続けて
  失敗している間は「相手と接続できません(再試行中)」を出す。通信は数秒で完了することも
  失敗することもあるが、何も出さないと「相手が長考している」のか「自分の手が届いていない」
  のかを区別できないため。接続が回復したら表示を消す
- **持ち時間はオンラインでは各手に添えて送り、受け取った側は相手の残り時間をその値で
  上書きする**。相手の手が届くまでに通信の遅延があるぶん、自分の画面だけで相手の時計を
  減らし続けると実際より早く時間切れと判定してしまうため。**上書きが効くのは相手の
  手番が続いている間だけ**で、手番が移った時点では受け取った値ではなく60秒へ戻す
- **対局の途中で切断しても、同じ対局へ復帰できる**。ブラウザを閉じた・再読み込みした・
  通信が切れたまま画面を離れた場合でも、次に起動したときに「前回の対局へ戻る」導線を出す。
  **対局の内容はサーバー側に「両者のデッキ・山札の種・指した手の並び」として残っており、
  そこから同じ局面を作り直せる**(リプレイと同じ仕組み)。復帰できるのは終わっていない
  対局に限り、終局済み・相手が対局を取りやめた場合は導線を出さない
- **復帰しないまま持ち時間が尽きれば、通常どおり時間切れで負ける**。復帰の導線があることは、
  放置した側が守られることを意味しない
- **時間切れは、切れた本人が申告する**。自分の持ち時間が0になったプレイヤーは、投了と同じく
  1手として「時間切れ」を送信し、**その手番を強制的に終了する**(5章)。連続3回に達した場合は
  その時点で敗北となる。相手が切断していて申告そのものが来ない場合に備え、相手の残り時間が
  0になってから短い猶予を置いても何も届かなければ、**切断とみなして**待っている側の勝利として
  終局させる。**申告が届いている限り敗北にはしない**——届いているならその相手は生きており、
  切断への保険を働かせる理由がないため

### ランダムマッチ画面

**ランダムマッチの待機は、たたかうタブの上に文言を重ねる形をやめ、専用の画面で行う**
(ルームマッチ画面と同じ考え方)。以前はたたかうタブの「だれかと」の枠の見出し行に
待機中の文言・巡回ドット・キャンセル・Discordへ知らせた印を重ねており、たたかうタブが
「入口」と「待機画面」を兼ねていた。デッキ選択画面でデッキを確定した時点でこの専用画面へ
入り、たたかうタブへは戻らない。

共通のレイアウト規約(9章)に従い、ヘッダーは 左=戻る / 中央=「ランダムマッチ」/ 右=なし
とする。画面を開くと同時にマッチングキューへ参加し、待っている間は「一覧に並べるものが
無いときの見せ方」(9章)と同じ形——砂時計の印・見出し・巡回ドット——で待機を示す。

- **戻るボタンを押すと、待機を取りやめてたたかうタブへ戻る**。ルームマッチ画面の
  キャンセルと同じく、押した瞬間に効かせ、後片付け(通信)の完了は待たない
- **募集をDiscordへ知らせたことを示す丸い印**(下記)は、この画面でも待機中の文言へ
  添える。押すものではなく読むためのものという性質は変えない
- **対戦相手が見つかったら、そのまま対局画面へ遷移する**。ランダムマッチはたたかうタブへ
  戻らないため、この画面に「対局を開始」のような追加の確認は挟まない(ルームマッチの
  ロビーと違い、マッチング成立の時点で両者ともすぐ対局へ入る)

### ルームマッチ画面

**ルームマッチは専用の画面を持つ**。たたかうタブの「ルームマッチ」を押すとこの画面へ入り、
**部屋を作る・コードで参加する・観戦する**の3つをここで完結させる。以前はホーム画面に
コード入力欄と参加/観戦ボタンを並べ、部屋を作った後の待機はラベル1行だけだったため、
**待っている間に確認したいこと(参加コード・使うデッキ・持ち時間)がどこにも出ていなかった**。

画面は次のものを持つ。共通のレイアウト規約(9章)に従い、ヘッダーは
左=戻る / 中央=「ルームマッチ」/ 右=なし とする。

- **参加コード**:部屋を作った後に大きく表示し、隣に**コピーボタン**を置く。友達へ渡すことが
  目的の値であり、読み上げて手入力させる前提にしない。コピーできなかった場合でも
  コード自体は大きく出ているため、その旨を画面に出さない(手入力で足りる)
- **使用デッキ**:デッキ名を表示し、「変更」から選び直せる。相手を待っている間も変更できる
- **持ち時間の入/切**(5章)。**部屋を作る前にだけ変更でき**、作った後と、コードで参加した側は
  表示だけになる。切にしてあるときは、放置された相手を時間切れで倒せない旨を1行で添える
- **待機の状態**:「相手の参加を待っています」「対局の開始を待っています」などを、
  他の画面と同じ巡回するドットで示す。待機は中断でき、中断すると部屋も消える
- **参加と観戦**:コードの入力欄と2つのボタンを同じ画面に置く

**観戦も同じ画面で待てる**。これまでは対局がまだ始まっていないコードを入れると
「対局がまだ始まっていません」で弾いていたが、**2人が集まる前にコードを共有された
観戦者には、弾かれる以外にできることが無かった**。始まっていない場合はその部屋の待機に入り、
対局が始まった時点で観戦へ移る。

### 対戦相手の募集をDiscordへ通知する

ランダムマッチは同時に遊んでいる人がいなければ成立しない。人が少ないうちは
「待っても誰も来ない」ことが最大の離脱要因になるため、**キューに入ったことを
コミュニティのDiscordへ知らせ、いま遊べる人を呼べるようにする**。

- **キューに入った時点で待機中の相手がいなかった場合にだけ通知する。**即座にマッチが
  成立した場合は送らない(呼ぶ必要がないため)
- **通知は毎回送る。**回数を絞ることはしない。1行で済む知らせであり、間引いて
  「いま人がいる」という情報の鮮度を落とすほうが損になる。**短い間に同じプレイヤーが
  何度も入り直した場合も、そのつど送る**(以前は2分だけまとめていたが、まとめる意味より
  鮮度を落とす損のほうが大きい)
- **メンションは飛ばさない。**気づきたい人はDiscord側のチャンネルごとの通知設定で
  受け取る。**毎回全員へメンションすると通知そのものを切られ、機能しなくなる**
- 通知に載せるのは**時刻とゲームのバージョン**だけとし、プレイヤーを特定できる情報
  (表示名・ID)は送らない
- **送信に失敗しても、マッチングは通常どおり続ける。**Discordが落ちていてもゲームは成立させる
- **成否を文言として出さない。**通知はプレイヤーの操作ではなく裏方の処理であり、
  届いた・届かなかったを待機中の文言へ混ぜても、待っている人にできることは無い。
  待機中は「マッチング中」だけを出す
- **ただし、知らせたこと自体は引ける状態にする。**待機中の文言の右へ丸い印(「!」)を
  添え、**カーソルを乗せたときにだけ**「公式Discordサーバーへ通知を送りました」と出す。
  印は押すものではなく読むためのものとして扱う。届かなかった場合は印も出さない
- **届くまで、間を置いて試し直す。**待っている間に1度だけ試して終わりにしない。
  ただし届いた後は、待ち続けていても送り直さない(同じ募集を繰り返し流すと
  通知そのものを切られる)

### バージョン

ゲームは**日付方式のバージョン**を持つ(`2026.08.29`。同じ日に複数回出す場合は `-2`)。
上の通知に添えるほか、不具合の報告と突き合わせるために使う。
**この値は書き出しの手順が自動で書き込む**(ビルドIDと同じ)。手で更新する値として
残していたときは、書き出しを重ねても日付が古いままで、募集の通知に何日も同じ数字が
出ていた。

### バージョンが違う相手とはマッチングしない

毎日更新する以上、ブラウザに古い版が残ったまま新しい版と同じ対局へ入りうる。
オンライン対戦は**山札の種を共有して両者が同じ対局を再現する**方式のため、カードの
総量が1でも違えば**盤面が静かに食い違ったまま進行する**。落ちないぶん質が悪い。

- **突き合わせるのは「ビルドした時刻」とする**。日付方式のバージョンは人が読むための
  ものとして残し、マッチングの可否は**書き出しのたびに自動で切り替わるビルドID**で
  判定する。ルールに影響する変更があった回だけ上げる番号を別に持つ案は、
  **上げ忘れた回に盤面が食い違う**——守るべき一点をちょうど守れないため採らない
- **ビルドIDは書き出しの手順が自動で書き込む**。手で更新する値を増やさない
- **違う相手は掴まない**。ランダムマッチは待機者のうち自分と同じビルドの人だけを掴み、
  ルームマッチは参加しようとした側が弾く。観戦も同じ扱いとする
- **古い版で待っている人を追い出さない**。掴まないだけで、その人のキューは消さない
- **弾いたときは画面に理由を出す**。黙って待ち続けると「マッチングしない不具合」に
  しか見えない。ビルドIDは時刻順に比較できるため、**自分が古い場合は「新しい版が
  公開されています。再読み込みしてください」**、自分が新しい場合は「相手が古い版で
  待っています」と書き分ける
- **対局画面にバージョンを出す**。不具合の報告と突き合わせるため

## 12. リプレイ・観戦

- 対局終了後、その対局の手順(棋譜)をリプレイとして保存する。**オンライン対戦・CPU戦の両方が対象**とする
- リプレイを閲覧できるのは、その対局を実際にプレイした本人(CPU戦の場合は自分)のみとする
- 保存件数は、オンライン対戦・CPU戦それぞれ直近30件とし、それを超えたら古いものから自動的に削除する。**この30件はアカウントごとに数える**(以前はアプリ全体で30件としていたが、プレイヤーが増えると互いの記録を消し合うため変更した)
- **リプレイはアカウントに紐づく**(14章)。別の端末からログインしても同じ記録を続けて閲覧できる。CPU戦のリプレイは通信を必要としない利点を保つためローカル保存のままとし、レコードに所有者を記録して一覧では自分のものだけを表示する
- リプレイは1手ずつコマ送りで再生できる形式とする
- パスは棋譜に1手(`pass`)として記録され、リプレイでも1手として数える
- **リプレイ一覧画面**:`きろくタブ`の「リプレイ」から遷移する。オンライン対戦・CPU戦を問わず、保存済みリプレイを横長カードの一覧として新しい順に縦スクロール表示する(両者は保存先が異なるため、一覧表示の時点でマージして日時順に並べる)。各カードには対局日時・勝敗・先手/後手・対戦種別(オンライン/CPU戦)に加えて、**両者のデッキを代表する数枚のアイコン**を表示する(デッキは30枚あり、そのまま並べるとカードに収まらないため)。対局履歴が無い場合は「まだ対局履歴がありません」等の案内を表示する。カードをタップすると再生画面へ遷移する
- **リプレイ再生画面**:対局画面の盤面・情報帯をそのまま流用し、盤面のクリック操作を無効化した「再生モード」として動作させる。画面右の行動の列には、対局中のボタンの代わりに、先頭へ/1手戻る/再生・一時停止/1手進む/最後へ、の5つの再生コントロールと「n / 全手数」の手数表示を置く。**再生モードには結果パネルを出さない**ため、一覧へ戻る導線もこの列に置く。「再生」中は一定間隔(0.8秒/手を目安)で自動的にコマを進める
- **観戦機能**:進行中の対局を第三者がリアルタイムで見られる機能。**ルームコード対戦限定**とし、ランダムマッチには観戦導線を用意しない(共有できるコードが存在しないため)。ルームマッチ画面(11章)のコード入力欄から「観戦する」を押し、対局中の2人が使ったものと同じコードを入力すると観戦できる。観戦中は盤面・HPが対局の進行に合わせてリアルタイムに更新されるが、一切操作はできない。対局が終了した場合は通常の勝敗演出をそのまま表示する

## 13. CPU戦

- オンライン通信を必要としない、CPU(コンピューター)を相手にしたローカル対局。`たたかうタブ`の「ひとりで」の枠に「CPU戦」を置く(9章)。他の対局と同様、押すと先に使用デッキを選ぶ画面を挟んでから開始する
- CPUのデッキは、現在定義されている全砂時計を各2枚ずつ入れた山からランダムに30枚を引いて組む(CPU専用のカードは用意しない)。**この「全砂時計」には、プレイヤー本人が未購入のカードセット(21章)も含む**——CPUが使うカードをプレイヤーの所有状況で絞らないことで、対局中に「このカードが欲しい」と思わせる出会いの場にする(ユーザー判断)。**ただしソロモード限定のカードセット(価格0・ショップに並ばない。27章)は除く**——通貨で買えない以上、CPUに見せても購入へつながらないため
- 先手/後手は常に**プレイヤーが先手**に固定する
- CPUもマリガン(2章)を行う。相手が何枚引き直したかは、対人戦と同じく分からない
- CPUは1手番の中で「場に出す → 攻撃する → 反転する → 終える」の順に選ぶ。**攻撃してから反転する**のが要点で、逆にすると攻撃力の高い状態を捨ててしまう。価値の物差しは生涯ダメージ(1章)を使う。**1手ずつ間合いを置いて指す**(まとめて適用すると盤面が一瞬で書き換わり、何をされたのか追えないため)
- 5章の持ち時間は、**オンライン対戦の切断・放置対策を目的とした仕組み**であり、CPU戦はローカル対局でその懸念が存在しないため、持ち時間の消費・時間切れ判定を行わない(プレイヤー・CPUともに考慮時間は無制限)
- CPU戦の対局終了後、その対局の棋譜は12章の通り**ローカルにリプレイとして保存する**(Firestoreへは書き込まない)。観戦はオンライン対戦のルームコード対戦限定のまま、CPU戦は対象外とする

### CPU戦の思考レベル

CPU戦のデッキ選択のあとに、思考レベルを選ぶ画面を挟む。**初級 / 中級 / 上級**の3段階とし、
既定(選び直さなかった場合)は**中級**とする。

| レベル | 攻撃 | 反転・反転権 | 設置効果・砂術の対象 | 場に出す判断 |
|---|---|---|---|---|
| **初級** | 攻撃できる駒・狙える相手をランダムに選ぶ(守護がいれば無視できないのは通常のルールどおり) | 使わない | ランダムに選ぶ | 出せるカードがあれば出す(効率・組み合わせは見ない) |
| **中級** | 生涯ダメージ(1章)を物差しに、最も得な相手を狙う | 「攻撃してから反転する」「弱めてから同じ手番で仕留める」を使う(2章) | 最も効果が活きる1体を選ぶ | 生涯ダメージが最大になる1枚を優先して出す |
| **上級** | 中級の判断に加え、**次の相手の手番で受け返す被害**も見て無理に本体を削らず安全な順を選び、**相打ちで自分の守護持ちを失うと後続の被弾が増える**ことも割り引く | 中級と同じ(2章の判断はこの戦闘システム上すでに尽くされている) | 中級より対象を絞る。**ダメージを与える効果は硝子が残っている相手を避け、実際に通る中で最善を選ぶ**(確定破壊は硝子を無視して通るため対象外) | 中級の判断に加え、**その手番で使い切れないマナを残さない**出し方をわずかに優先し、**コインは使った場合に出せる組み合わせが実際に上回るときだけ**切る |

**マリガン(2章)も上級では引き直す枚数の判断を精密にする**。中級以下はコストの
上限だけで戻すが、上級は**手札に残るコスト1〜2のカードが少ないほど、重いカードを
より積極的に戻す**。事故を避けるという狙い(2章)そのものを、より丁寧に実現する。

**上級は評価軸を足すだけに留め、複数手先の探索は行わない。**貪欲法という
CPUの骨格(13章)そのものは変えない。

**誘導対局(18章)は中級固定とする。**教える操作の手順が難易度によって変わってはいけないため、
思考レベルの選択画面を挟まない。

**思考レベルは対局のたびに選び直せる**(前回選んだ値を初期値として引き継ぐ)。

## 14. アカウント

対局の記録(リプレイ)と通貨(15章)をプレイヤー個人に紐づけて保存するための仕組み。

- **アカウントを作らなくても遊べる**。起動した時点で匿名のアカウントが自動的に用意され、
  そのまま全ての機能を利用できる(**掲示板〈ラボ〉への投稿・投票を除く**。29章)。
  ただし匿名のままだとブラウザのデータを消した時点で記録と通貨が失われるため、
  その旨をアカウント画面に明示する
- **IDとパスワードを自分で決めて登録できる**。登録するとその2つでログインでき、
  別の端末・別のブラウザからでも同じ記録の続きを遊べる。メールアドレスは取得しない
- **IDは他のプレイヤーと重複できない**。既に使われているIDで登録しようとした場合は
  その旨を表示して登録を拒否する
- **パスワードを忘れた場合、そのアカウントは復旧できない**。メールアドレスを取得しない以上、
  再設定の案内を送る手段が存在しないため。登録画面にこの注意を明記する
  (将来メールアドレスを任意項目として追加すれば解決できるが、現時点では扱わない)
- **匿名で遊んでいた記録は、登録した時点でそのまま引き継がれる**。登録は新しいアカウントを
  作る操作ではなく、いま遊んでいる匿名アカウントにIDとパスワードを結びつける操作として扱う
- **自動ログイン**:一度ログインすれば、次に起動したときは自動的に同じアカウントへ復帰する。
  匿名アカウントもこの対象とし、起動のたびに別人になることがないようにする
- **ログアウトできる**。ログアウトすると新しい匿名アカウントで遊ぶ状態に戻る。登録済みの
  アカウントの記録は消えず、同じIDとパスワードで再びログインすれば戻れる
- **表示名を持つ**(10文字程度まで)。対局中の「先手/後手」の表示と、リプレイ一覧の
  対戦相手の表示に使う。未設定の場合は従来どおり「あなた/相手」と表示する。表示名は
  いつでも変更でき、ID(ログインに使う文字列)とは別物として扱う
- **表示名に使えるのは、同梱フォントが字形を持つ文字だけとする**。絵文字・ハングル・
  アクセント付きのラテン文字・大半の記号は字形が無く、そのまま出すと豆腐(□)になる。
  **フォールバック用のフォントを同梱して対応する案は採らない**。絵文字だけで約10MBあり、
  pck全体(約4MB)の何倍にもなってブラウザでの起動待ちがそのぶん延びるため、
  日本語圏向けの作品として釣り合わない。入力欄では使えない文字を受け付けず、
  「この文字は使えません」と1行で示す。**相手から届いた表示名も同じ基準で通し**、
  使えない文字は「?」へ置き換えて表示する(自分が我慢しても、相手のクライアントが
  送ってきた名前で自分の画面が化けるため)
- **対局画面の名前欄は、自分側には常に自分の表示名を出す**(オンライン対戦・CPU戦のいずれも)。
  相手側は、オンライン対戦では相手の表示名、**CPU戦では「CPU」**とする。誰と戦っているのかが
  一目で分かる状態にするため
- **アカウント画面**を用意し、タイトル画面とホーム画面の両方から開けるようにする。
  画面には現在のアカウントの状態(匿名か登録済みか)・表示名・通貨の残高を表示し、
  未登録なら「登録」、登録済みなら「ログアウト」の導線を置く。ログイン導線も同じ画面に置く
- サーバー側での正当性検証を行わない方針(11章)はアカウントにも適用する。認証そのものは
  認証サービスに任せるが、通貨や記録の内容はクライアントの申告をそのまま信頼する

### アイコンと称号
プレイヤーの個性を表現するため、アイコンと称号を設定できる。

- **アイコン**:
  - アカウント画面で一覧から好きなアイコンを選択・変更できる。
  - 初期状態で選択可能なアイコンは砂時計の紋章(流砂、時計、王冠、大盾、宝剣、真眼、光輪、閃光)の8種とする。
  - **アイコン・エモート・プレイマット・カードスキン(31章)は「所有」を持つ**。初期から持っているのは上の8種と
    エモート4種、プレイマット「なし」(卓に何も敷かない既定の状態)で、それ以外は
    ショップ(21章)で砂金と引き換えに解放する。**すなえるアイコンもショップの品とする**。
    **ただしカードスキンの設定場所はアカウント画面ではなく砂時計図鑑**とする
    (カードの数だけ行が要り、アカウント画面には並べる場所が無いため。31章)。
  - **プレイマットもアカウント画面で設定する**(ショップは買う場所であって、設定する場所を
    兼ねない)。所有しているものだけを一覧に出すのはアイコンと同じ。
  - **所有しているものだけをアカウント画面の一覧に出す**。持っていないものを暗く並べて
    「買えばここに増える」と示す案は採らない。**その役目はショップの側が果たしており**、
    設定する場所に買えないものが混ざると、選ぶための一覧が品書きを兼ねてしまう。
  - 所有しているアイコンが増えても縦に伸びないよう、一覧はスクロールできるようにする。
  - 未設定時の既定値は「流砂(`sand`)」。
  - ホーム画面ヘッダー、アカウント画面、対局画面(PlayerInfoBar)に表示される。
  - CPU戦でのCPUのアイコンは専用アイコン(`cpu`)とする。
- **称号**:
  - アカウント画面で一覧から好きな称号を選択・変更できる。
  - 称号が増えても一覧しやすいスクロール可能なリスト形式で表示する。
  - 初期状態では「駆け出し決闘者(`novice`)」(ゲーム起動で自動獲得)と「称号なし(`none`)」から選べるようにする。
  - **これ以外の称号は、獲得した人だけが選べる**(例:掲示板〈ラボ〉で採用された投稿者だけが選べる「発案者」。29章)。
  - 未設定時の既定値は「駆け出し決闘者(`novice`)」。
  - 対局画面の名前プレート上部に小さく表示される。
- **アカウント画面のレイアウト**:
  - 画面の高さいっぱいに収まる**2カラム構成**(幅1060px)とする。
    - **左カラム(プロフィール設定)**: 名札見本(リアルタイムプレビュー)、表示名変更、アイコン一覧グリッド、スクロール対応の称号リスト、「プロフィールを保存」ボタン。
    - **右カラム(アカウント登録・ログイン)**: 登録・ログイン・ログアウトの操作および注意事項。
  - ボタンは全てゲーム世界観に統一された真鍮スタイルのボタン(`CodedButton`)を使用する。
- **保存と同期**:
  - 表示名と同様に `players/{uid}` に保存され、ログインした全端末で同期される。
  - オンライン対戦時、相手のアイコンと称号も取得して対局画面に表示する。

## 15. 通貨

- 通貨の名称は**「砂金(さきん)」**とする。対局を終えるたびに獲得し、アカウント(14章)に貯まる
- **用途はショップ(21章)での解放**。見た目に関するもの(アイコン(14章)・エモート(9章)・
  プレイマット・カードスキン(31章))に加えて、**基本セット以後のカードセット(8章)もここに含む**。
  構築に関わるものを砂金で解放すると、貯めた量がそのまま対局の強さになる懸念はあるが、
  **基本セット70枚だけで通常に遊べる状態を維持し、カードセットは対局の土台ではなく
  広がりとして位置づけることでこの懸念に応える**(8章)。カードセットの入手は
  買い切りのみとし、ガチャ(確率による排出)・錬金(重複からの生成)は採らない

### 獲得量

| 対局種別 | 勝利 | 敗北 |
|---|---|---|
| ランダムマッチ | 30 | 10 |
| ルームマッチ | 10 | 5 |
| CPU戦 | 5 | 2 |

負けても獲得できるのは、勝てないプレイヤーが一切貯められない状態を避けるため。
ランダムマッチを厚くしているのは、相手が必要で自分の都合だけでは回せないため。

### 日曜イベント(砂金2倍)

**毎週日曜日(JST)は、ランダムマッチの獲得量が2倍になる。**

| 対局種別 | 勝利 | 敗北 |
|---|---|---|
| ランダムマッチ(日曜) | 60 | 20 |

**ランダムマッチだけを対象とする。**相手が必要で自分の都合だけでは回せない対局を
後押しする狙いは通常時と同じ(上記の獲得量の表でランダムマッチを最も厚くしている
理由と同じ)。**ルームマッチ・CPU戦は対象外**(据え置き)。

判定は「対局が終局した瞬間のクライアントのローカル時刻を日本時間へ換算し、
日曜日かどうか」で行う。サーバー側で正当性検証を行わない既存方針(11章)に揃える。

告知については25章を参照。

### 不正な稼ぎ方への線引き

サーバー側で対局内容を検証しない方針(11章)のため、**自分ひとりで繰り返せる対局ほど
報酬を低くする**ことで釣り合いを取る。加えて次の2つの条件を設ける。

- **総手数が10手に満たない対局は報酬の対象外とする**。開始直後に投了して短時間で
  繰り返すことを防ぐため
- **CPU戦は1日10戦までを報酬の対象とする**。上限に達した後もCPU戦自体は遊べるが、
  砂金は入らない

### 表示

- ホーム画面に残高を常時表示する
- 対局の結果パネルに、その対局で獲得した額を「+30 砂金」として表示する。報酬の対象外
  だった場合(手数が足りない・CPU戦の1日の上限に達している)は、その理由を1行で示す
- 通信に失敗して残高を更新できなかった場合でも、獲得した額は失わない。未反映分を
  手元に控えておき、次に通信が成功した時点でまとめて加算する(CPU戦はオフラインでも
  遊べるため、この扱いが必要になる)

## 16. ルール画面(遊び方)

ルールを知らないまま対局へ入って離脱されることを防ぐための画面。ホーム画面の
「ルール」タブから入る。

- **テキストと、実際にレンダリングされた盤面を並べた「紙芝居」形式とする**。1ページは
  見出し1行・本文2〜4行・その内容を実演する盤面の3つで構成する。読み物だけでも、
  動く絵だけでも足りないため、必ず両方を対にする
- **盤面は挿絵ではなく、対局画面と同じ描画コンポーネントを同じデータで描いたものとする**。
  ルール画面専用の簡易イラストを別に用意すると、実際の対局画面と見た目がずれた時点で
  誤った予習になるため
- **ページに入った瞬間に、そのページの演出が1度だけ自動再生される**(砂が1粒落ちる /
  反転する / 相打ちで砂が砕ける)。「もう一度見る」で再生し直せる。**演出も対局画面と
  同じものを使う**。消える砂と落ちる砂の違い(4章)は文章より演出のほうが伝わるため、
  ここが本画面の中心になる
- **章を選んで飛べる目次を左に置く**。順に読ませる導線(次へ)と、あとから1点だけ調べに
  戻る導線(目次)の両方を持たせる。チュートリアルではなくリファレンスとしても使える
  ようにするため
- 操作はページ送り(前へ / 次へ)と目次のみ。**盤面はクリックを受け付けない**。
  対局と同じ見た目である以上、押せそうに見えるものが押せないことを避けるため、
  ホバーの反応も出さない
- 進捗は保存しない。次に開いたときは常に先頭のページから始める

### 章立て

| 章 | 見せること | 盤面 |
|---|---|---|
| 1 | 上の砂=体力 / 下の砂=攻撃力、合計が総量 | 砂時計1体を大きく |
| 2 | 毎ターン終了時に砂が1粒落ちる。体力0で破壊 | 1体が落ちきるまで |
| 3 | 反転。攻撃力が体力を上回ったら返す。**反転権は敵味方どちらの駒も反転でき、
  「1体1ターン1回・出したターンは不可」の制限を受けない。弱めてから同じ手番で
  仕留めるのが定石** | 1体が反転する |
| 4 | 場に出す。マナ・コスト・6枠・出したターンは動けない | 手札から台座へ |
| 5 | 攻撃は相打ち。**受けた砂は消え、落ちた砂は消えない** | 2体がぶつかる |
| 6 | キーワード(守護 / 硝子 / 貫通 / 速落) | 該当カードを並べる |
| 7 | 対局の流れ・勝利条件・**マリガン**・コイン | 6枠の盤面と情報帯 |

**3章と7章はそれぞれ2ページ・3ページ構成とする**(反転権・マリガンのぶんが1ページずつ
増える)。反転権の「弱めてから同じ手番で仕留める」という使い方は、この使い方を
教えないと宝の持ち腐れになる(2章)ため、ここで初めて案内する。

## 17. キーワード辞書

ルール画面(16章)が「順に読ませる紙芝居」であるのに対し、こちらは**語を1つだけ
引きに来るためのリファレンス**とする。ホーム画面の「ルール」タブから、ルール画面と
並べて入口を置く。

- 収録するのは**現在定義されている語すべて**。常在の能力7種(守護 / 硝子 / 貫通 /
  速落 / 毒砂 / 吸命 / 連撃)とトリガー5種(設置 / 反転 / 余砂 / 落砂 / 被弾)。
  **6章で「語にしない」と決めた毒砂・吸命・連撃も辞書には載せる。**カードの面へ語を
  出さないことと、用語を引けることは別の話であり、盤面で「破壊」とだけ書かれた能力の
  正確な挙動を確かめる場所が無いと困るため
- 1件は「語 / 一文の説明 / 実演 / その語を持つ砂時計の一覧」の4つで構成する
- **語にしない能力(毒砂・吸命・連撃)は、カードの面と同じ短い言い換え**(「破壊」
  「回復」「2回攻撃」)**を見出しに出す。**盤面に出ていない語を辞書だけで見せると、
  同じ能力の呼び名が2つになるため(6章)
- **実演は9章のカード詳細と同じものを使う**。辞書専用の絵は作らない。実演はキーワード /
  効果の種類ごとに1本用意する方針(9章)であり、辞書はその単位とそのまま一致する
- **その語を持つ砂時計を並べることを、説明文と同じだけ重要な要素として扱う。**
  「守護はどの砂時計にあるのか」を引けることが辞書の価値の半分を占める。一覧は
  全砂時計から実行時に集めるため、砂時計を追加したときに辞書側へ書き足す作業は発生しない
- **該当する砂時計が1枚も無い語も項目を消さない。**「まだこの能力を持つ
  砂時計はありません」と示し、語彙として定義済みであることを隠さない
- 左に語の一覧、右に選んだ語の詳細、の2カラムとする。共通のレイアウト規約(9章)に従う

### 詳細パネルからの用語ポップ

- **砂時計の詳細に出ている語(「守護」など)を押すと、その語の説明と実演を小さな
  パネルとして重ねる。**辞書画面と同じ内容を出す
- **押せるのは効果欄に並ぶ語のボタン**(語にしない能力は短い言い換え、設置などの
  トリガーはその語)。効果の文そのものは押させない。押せるものと読むものを見た目で
  分けるため
- **用語ポップと実演を持つのは砂時計一覧の詳細だけとする。**デッキ編集と対局画面の詳細は
  ホバーで出して外れたら消えるため(9章)、**パネルの中の語を押しに行った時点で消えてしまう**。
  操作を要する要素は、パネルが留まる画面にしか置けない
- ポップは押した語1件だけを出す。ここから辞書の全一覧へ移る導線は置かない

## 18. はじめてのプレイ

ルール画面(16章)と辞書(17章)は**読みに行く**ものであり、読まずに対局へ入った
プレイヤーには何も届かない。ここでは**遊びながら覚える**導線と、**構築せずに遊べる**
状態を用意する。ブラウザゲームである以上、最初の数分で離脱されることが最大の損失にあたる。

### 誘導対局(チュートリアル)

- **実際の対局画面で、実際に手を指させる**。読み物や紙芝居ではなく、CPU戦をそのまま使う
- 進行は**段階ごとの短い指示**として画面上部に出す。「手札のカードを空き枠へ出してみましょう」
  のように**1度に1つだけ**を求め、その操作が行われたら次へ進む
- 段階は次の6つとする。**いずれもこの作品でしか通用しない部分**であり、
  他のカードゲームの経験だけでは埋まらない

| 段階 | 求める操作 | 覚えること |
|---|---|---|
| 0 | マリガンを確定する | 初手は引き直せる。引き直さなくてよい |
| 1 | 手札のカードを空き枠へ出す | マナを払って場に出す。出した直後は攻撃できない |
| 2 | ターンを終える | ターン終了時に砂が1粒落ちる(体力-1 / 攻撃力+1) |
| 3 | 攻撃する | 攻撃は相打ちで、**自分も相手の攻撃力ぶん削れる** |
| 4 | 反転する | 体力と攻撃力が入れ替わる。**攻撃力が体力を上回ったら返す** |
| 5 | ─ | 以降は自由に続ける(通常のCPU戦として最後まで遊べる) |

- **誘導対局はマリガン画面から始まる**(2章)。ここに案内が無いと、初めて遊ぶ人は最初の画面で
  何を求められているのか分からないまま止まる。**すなえるの指示はマリガンの暗幕より手前へ出し**、
  引き直しの意味と「選ばなくてよい」ことを伝える。**マリガンを誘導対局だけ省く案は採らない**。
  実際の対局では必ず通る画面であり、省くと初回の壁が後ろへ移るだけのため
- **段階を1つ終えたときの説明は、時間で消さず「つぎへ」を押すまで残す**。読む速さは人により、
  1秒足らずでは読み切れない。**指示の文が自動で切り替わることが、案内が1度しか出なかったように
  見せていた**。手を塞がない方針は変えないため、押さずに指し続けることもでき、
  次の操作を行った時点で先へ進む
- **段階をすべて終えたら、締めのひと言を出してから帯を閉じる**。勝利条件と、
  困ったら駒を押せば効果を読めることだけを伝える。何の区切りも無く案内が消えると、
  続きを投げ出されたように読める。**それ以上は喋らせない**。対局中ずっと話しかけるのは、
  長い語りがルールの読解を妨げるという本節の方針に反する
- **いま触るものを盤面の上で光らせる**。「空いている台座へ出してみてね」と言われても、
  初見のプレイヤーには**どれが空き枠なのかが分からない**。段階ごとに対象(手札 / 空き枠 /
  ターン終了ボタン / 攻撃できる駒 / 反転できる駒)を脈打つ輪郭で囲む。**手は塞がないまま
  視線だけを誘導する**ため、下記の「従わない操作も禁止しない」と両立する
- **求めた操作が今できない場合は、そのための手を代わりに示す**。1ターン目はマナが1しか
  無いため、手札によっては**「出してみてね」と言われても1枚も出せない**。この状態を放置
  すると、初めて遊ぶ人には指示に従えない理由が分からない。出せる札が1枚も無い間は
  「ターン終了を押すとマナが増える」ことを伝え、そちらを光らせる
- **何段階のうちのどこにいるかを出す**。すなえるの下へ段の数だけ点を並べ、済んだものを
  塗る。**終わりが見えないと、いつまで案内が続くのか分からない**。閉じる導線を置かない
  (下記)以上、残りが読めることは必要になる
- **段階を終えたときの一言には、いま自分の盤面で起きた実際の数値を差し込む**。
  「砂が1粒落ちたよ」ではなく「サンドの体力が5から4に、攻撃力が0から1になったよ」と書く。
  **一般論の説明より、目の前の駒と結びついた説明のほうが速く入る**
- **指示に従わない操作も禁止しない**。手を塞ぐと「言われた通りにしか動かせない」体験になり、
  自分で考える余地が消える。指示は**次に何をすれば良いか分からない状態を埋めるためだけ**に置く
- **途中で閉じる導線は置かない**。一度閉じると以降の段階の案内が二度と読めなくなり、
  誤って押した人は残りを教われないまま対局だけが続く。指示は手を塞がない(上記)ため、
  邪魔なら無視してそのまま指してよく、締めのひと言まで進めば自分で閉じられる
- 誘導対局は**何度でも遊べる**が、一度終えたら入口の扱いを控えめにする(下記)
- 誘導対局のデッキは**プリセットの「基本」を使う**。保存済みのデッキがあっても、
  そちらを使わない。覚えてほしい動きが出ないデッキで始まると成立しないため

### 案内役「すなえる」

誘導対局の指示は、**マスコットの「すなえる」が話しかける形にする**。指示だけが
帯に出ている状態には話者がおらず、画面が一方的に命令しているように読めるため。

- **すなえるは、砂時計に天使の輪と羽と目を足したもの**とする。**新しく絵を起こさず、
  ゲーム内の砂時計そのものへ描き足す**。盤面に立っている駒と見た目が必ず一致し、
  「この子はこのゲームの砂時計なんだ」と分かる状態を保つため
- **口は描かない。**表情が固定されず、砂時計という物体のままでいられる
- 一人称は「ぼく」、語尾は「〜だよ」「〜してみてね」程度。**指示の文は短く保つ**。
  このゲームは覚えることが多く、長い語りはルールの読解を妨げる
- 立ち絵は**指示の帯の左端に小さく置く**だけとし、盤面を新たに隠さない。
  すなえるのために画面の場所を作らない
- **出るのは誘導対局の間だけ**とする。ルール画面(16章)・タイトル・ホームには
  出さない。**常時いると案内役ではなく飾りになる**ため、
  「初めて遊ぶ人に付き添う」という役割が薄れる

### プリセットデッキ

- **30枚を自分で組まずに遊べる状態を用意する**。デッキ構築は面白さの中心だが、
  **始める前に30枚を選ばせるのは最初の壁として重すぎる**
- プリセットは**3つ**とし、それぞれ狙いを1行で示す

| 名前 | 狙い |
|---|---|
| **基本** | 軽いカードを中心に、砂の進み方と相打ちを素直に体験する |
| **速攻** | 速落・貫通で早く殴りきる |
| **重厚** | 守護と大型で受け止め、盤面を残して勝つ |

- デッキ編集画面から**プリセットを選んで読み込める**。読み込んだ後は普通に編集でき、
  保存すれば自分のデッキになる(プリセット自体は上書きされない)
- **デッキを保存していないプレイヤーは、プリセットの「基本」で対局へ入れる**
  (これまでも既定のデッキで入れていたが、その中身が画面に出ていなかった)

### 初回の導線

- **初めてホーム画面を開いたときは「ルール」タブを初期選択とする**(9章、実装済み)。
  そのタブの先頭へ**「1局遊んで覚える」**を置き、読み物より前に出す
- **一度でも誘導対局を終えたら、その入口は他の項目と同じ大きさへ下げる**。
  終えた人に毎回いちばん目立つ位置で勧め続けない

## 19. 戦績

**勝っても何も残らない状態を避けるための記録**。ランクマッチ(28章)が段位という
「勝つ理由」を別に持つ一方、フリーマッチ・CPU戦を含めた通算の成績を見返せることも
引き続き「勝つ理由」の1つとして残す。

- 記録するのは**対局種別ごとの対局数・勝率・平均手数**、**カード別の勝率**、
  **デッキ別(構築ごと)の勝率**の3つ
- **リプレイから集計しない**。リプレイは直近30件しか残らないため(12章)、
  古い対局が消えるたびに通算の勝率が変わってしまう。終局のたびに1件足す積み上げ方式とし、
  リプレイの保持件数とは切り離す
- **アカウントごとに数える**(14章)。ログアウトして別のアカウントで遊んだぶんは混ざらない
- **戦績はFirestoreへ同期し、別端末からログインしても同じ記録を続けて見られる**
  (リプレイ・通貨と同じ扱い)。サーバー側の正当性検証は行わない既存方針のまま、
  クライアントの申告をそのまま信頼する。**通信に失敗した対局の記録は端末へ控えておき、
  次に成功した時点でまとめて反映する**(CPU戦はオフラインでも遊べるため)
- **カード別は「そのカードを入れたデッキで戦った勝率」**であり、そのカードの強さそのもの
  ではない。同じカードを2枚積んでいても1局は1局として数える。**この値でカードの強弱を
  判断してはいけない**(強さの測り方は7章のとおり、含むデッキと含まないデッキを直接
  ぶつける方式による)
- デッキ別は構築を**その内容から作った指紋**で見分ける。1枚でも違えば別の構築として数える。
  9章のデッキコードは番号を預ける仕組みであり、記録のたびに通信することになるため使わない。
  覚えておく構築は多くならないよう上限を設け、超えたら対局数の少ないものから落とす
- **数値は右揃えの列にそろえる**。戦績は数字を見比べる画面であり、「20戦 勝率60.0% 平均9.9手」
  のように1本の文へ流し込むと、名前の長さで桁の位置が行ごとにずれて縦に読み比べられない。
  1つの値しか持たない行も、同じ幅の列へ収める
- **デッキ別は、いま保存しているデッキ・プリセットの名前で出す**。見分けに使う指紋は
  プレイヤーには読めない内部の識別子であり、そのまま画面へ出してはいけない
  (9章の「id順は並びとして使わない」と同じ理由)。名前を引けない構築
  (消したデッキ・受け取った構築)は「いま保存していない構築」として出す
- 表示は専用の画面とし、きろくタブから入る。**対局数が0のうちは、その旨を1行で示す**

## 20. 画面の見かた

ルール画面(16章)がルールを**順に読ませる**場所、キーワード辞書(17章)が語を**引く**場所で
あるのに対し、ここは**画面に出ているものの意味を引く**場所とする。

9章で決めた表示の約束——数値の位置・台座の輪・光の膜・彩度・印——は、**どこにも説明が
無いまま盤面に出ている**。守護のカードが1枚も手元に無ければ辞書を引く動機も生まれず、
「台座の輪が太いのは何なのか」を調べる手段が存在しなかった。

- **実際の対局画面と同じ描画で組んだ1枚の盤面を中央に出し、左に項目の一覧を置く**。
  項目を選ぶと盤面の該当箇所が光り、その意味が説明として出る
- **専用の説明図は作らない**。16章と同じ理由で、対局画面と食い違った時点で誤った予習になる
- **盤面はクリックを受け付けない**(16章と同じ)。ホバーの反応も出さない
- 進捗は保存しない。次に開いたときは常に先頭の項目から始める

### 収録する項目

| 項目 | 説明すること |
|---|---|
| 情報帯 | HP・マナ(数字とピップ)・山札・墓地の枚数。相手側は手札の枚数とコインの有無。持ち時間は右の行動の列の時計に出る(時計を持たない対局は∞) |
| 盤面と台座 | 各プレイヤー6枠。空き枠は丸い台座だけが置かれた状態になる |
| 手札のカード | **コスト=左上 / 総量=右下**。マナが足りないものは暗くなる |
| 場の砂時計 | **攻撃力=左下 / 体力=右下**。場ではコストを出さない(支払い済みのため) |
| 砂時計の絵 | 体力と攻撃力の比で3状態に変わる(上向き / 落下中 / 落ちきり) |
| 守護と硝子 | 守護=台座の輪が太い真鍮 / 硝子=ガラスに掛かった光の膜(1度使うと消える) |
| 駒の状態 | 出したターン=沈んでいる / 攻撃済み=彩度が落ちる / まだ動ける=控えめな印 |
| 攻撃の予測 | 対象を選んでいる間、双方に「この攻撃の後どうなるか」が出る |
| 行動の列 | 画面右にコイン・反転権(自分と相手の残り回数の粒)・ターン終了・ログ・投了・エモートが並ぶ。**反転だけは選んだ駒のすぐ下**に出る |

## 21. ショップ

砂金(15章)を使う唯一の場所。ホーム画面のそろえるタブの「ショップ」から入る。

- **売るのはアイコン・エモート・プレイマット・カードセット(8章)・カードスキン(31章)**とする(15章)。称号は
  売らない——名札の上に出る短い文字列であり、買ったことが見た目にほとんど現れないため、
  同じ額を払う品としてアイコン・エモートと並べられない
- **「砂の海」はプレイマットの標準的な1枚としてショップに並べる**(価格は下記の標準1500)。
  既定は「なし」であり、この砂紋の布も他のマットと同じく買って設定する対象とする
- **品揃えは固定とする**。日替わりにも、ランダムにもしない。**欲しいものが今日並んで
  いるかどうかを運に任せると、貯めた砂金の使い道を自分で決められなくなる**
- **価格はアイコン100・エモート200・プレイマット1500(標準)/ 3000(豪華)**。
  プレイマットが桁違いに高いのは、**対局中ずっと目に入り、画面で最も面積が大きい**ため。
  同じ品種の中に価格の段を設け、模様と縁飾りの作り込みで段を分ける。
  **既に並んでいるアイコン・エモートの価格は遡って上げない**——今後足す品の側で
  釣り合わせる(砂金の入手経路が増えるたび、既存の価格は相対的に安くなる)
- **一度買ったものは消えない**。同じものは2度買えず、購入済みの品は「所有済み」と示す
- **残高が足りない品は暗くし、押しても買えない**(手札のマナ不足と同じ扱い)。
  **買えないことは行を暗くすることだけで示し、価格を赤で書かない**——残高が0のうちは
  品書きが一面の赤字になり、品が並んでいるというより不具合が並んでいるように見える
- **買う前に確認を挟む**。押し間違いで砂金が減ると、取り返す手段が対局しかない
- 買ったものは**アカウント画面**で設定する。ショップは買う場所であり、設定する場所を
  兼ねない(**カードセットは例外**。買った時点でそのままデッキ編成に使えるようになり、
  アカウント画面での設定操作を挟まない)

### 画面

共通のレイアウト規約(9章)に従い、ヘッダーは **左=戻る / 中央=「ショップ」/ 右=砂金の残高**とする。
残高はここでの購入で必ず動くため、ヘッダーへ常時出す。

一覧は**横2列のグリッド**(9章)。1件は「品の絵 / 名前 / 価格または『所有済み』」で構成し、
アイコンはその絵を、エモートは実際に出る文言をそのまま出す。**エモートは文言が品そのもの**
であり、名前だけを並べると何を買うのか分からない。**プレイマットは実際に敷いた縮小見本**を
出す——色の名前だけでは何を買うのか分からず、これも文言と同じく品そのものにあたる。

**通信できないときは買えない**。残高はアカウント(14章)にあり、手元だけで減らすと
次に通信した時点で復活してしまう。その場合はその旨を1行で示す。

### カードセット

- **カードセットだけは、他の3種(アイコン・エモート・プレイマット)と価格の決め方が違う**。
  対局の中身に関わる以上、品種一律の価格では釣り合わない。**セットごとに個別に価格を決める**。
  **目安は「1枚100砂金 × 枚数」とする**が固定式ではなく、そのセットの強さに応じて
  個別に増減してよい(6章の効果の値段表と同じ、目安であって固定式ではない扱い)
- 品目には、そのセットの狙い(1行)とセット内のカード数を添える。ショップの一覧そのものには
  1枚ずつの詳細までは並べない
- **購入すると、そのセットのカードがデッキ編成へ入れられるようになる**。買い切りであり、
  ガチャ(確率による排出)は無い(15章)
- **未購入のカードセットのカードは、デッキ編集の一覧でロック表示にする**。押すと
  ショップの該当セットへの導線を出す
- **砂時計一覧(図鑑)は、保有していないカードをシルエットで示す**(9章に既にある
  「未収集はシルエットと『?』で示す」を、カードセットの導入をもってはじめて使う。
  基本セット70枚は常に保有済み扱いとする)
- **買う前に中身を確認できる場所は、ショップの品目そのものが持つ。**デッキ編集・砂時計一覧が
  未所有のカードをロック/シルエットで隠す(上記)以上、**それ以外のどこかで確認できることを
  前提にしてはいけない**。カードセットの品目に「内容を見る」を置き、押すとそのセットの
  全カードをコスト・総量・キーワード・効果つきで見られるプレビューを開く。**図鑑・デッキ編集の
  シルエット/ロックは収集要素としての演出のまま変えず、確認する手段だけをショップ側へ持たせる**
  (見た目を隠す場所と、買う判断のために中身を確認できる場所を分ける)

## 22. 対局の記録と分析

いまバランスの数値は**すべて自己対戦シミュレーションで測っている**(7章)。CPUは1手ごとの
貪欲法であり、**砂術を持て余す**ことが実測で分かっている(`docs/BalanceReport_v5.md` 10.6節)
ように、機械の数字は人の対局とずれる。**人が指した対局を残し、シミュレーションの値と
突き合わせられるようにする。**

### 記録する対象

- **オンライン対戦(ランダムマッチ・ルームマッチ)だけを記録する**。CPU戦は記録しない。
  CPUの癖がそのまま混ざり、「人の対局を測る」という目的と食い違うため。観戦者と
  リプレイの再生も記録しない
- **ルームマッチも記録するが、ランダムマッチとは区別して持つ**。友達対戦は真剣勝負とは
  限らないため、分析のときに外せるようにする

### リプレイとは別に持ち、消さない

対局そのもの(デッキ・種・手順)は既にオンライン対戦の仕組みが持っているが、**それは
リプレイのための置き場であり、アカウントごとに直近30件で消える**(12章)。同じ場所に
「消える」と「消さない」という相反する要件を負わせられないため、**分析用の記録は別に
1件だけ書き、消さない**。中身が重複するが、消えるものと残るものを分けることのほうを採る。

### 記録する中身(要約 + 棋譜)

| 内容 | 理由 |
|---|---|
| ビルドID・バージョン | **カードが変われば混ぜて数えられない**。版をまたいだ集計を防ぐ唯一の手段 |
| 対局の種別(ランダム / ルーム) | 上記のとおり分けて数えるため |
| 勝者・決着の要因・総手数・両者の最終HP | 7章の5指標をそのまま出せる |
| 両者のデッキ30枚のid | カード別・デッキ別の勝率 |
| 山札の種・指した手の並び | **後から再生できる**。「人がどう指したか」はここにしか無い |
| 両者のプレイヤーID | 同じ人どうしの連戦を除いて数えるため。**表示名は記録しない** |

### 誰が書くか

**両者が書きにいき、先着1件だけが通る**。片方が切断していても記録が残り、
二重には数えられない。観戦者は書かない。

**書き込みに失敗しても対局には何も起こさない。**分析のための記録であり、落ちて失われるのは
サンプル1件だけである。**画面にも何も出さない**(裏方の処理の成否をプレイヤーへ見せない。
11章の募集通知と同じ扱い)。

### ゲーム内で見る

全件をクライアントが読むのは重すぎるため、**集計を1つだけ持ち、終局のたびに増分で
更新する**。持つのは総対局数・先手の勝利数・手数の合計・決着の要因ごとの数と、
カードごとの「採用した局数 / そのうち勝った数」。**更新するのは記録を書けた側だけ**とし、
二重に数えないようにする。

戦績画面(19章)へ**「みんなの戦績」**を足し、自分の戦績と切り替えて見られるようにする。
**カード別の勝率はカードの強さそのものではない**という但し書きは、自分の戦績と同じものを
出す(強さの測り方は7章の方式による)。

**集計は版で分けず、通算として貯める。**カードは毎日増えるため版ごとに分けると
画面に出る数字が毎日0に戻る。版ごとの分析は下記の道具が記録そのものを読んで行う。

### Discordで見る

**自動投稿はしない。**1局ごとに流せばうるさく、日次でまとめるにはサーバー側の定期実行が
要るが、この作品はサーバーを持たない(10章)。代わりに**求めたときに記録を読んで集計し、
Discordへ投稿する道具**を用意する。集計の範囲(ビルドID・期間・対局の種別)を指定できる。

## 23. デイリーミッション

毎日更新される課題を達成することで、通貨「砂金」を獲得できる継続プレイ用の仕組み。

- **仕様概要**:
  - 毎日午前0:00(JST)に**3つのミッション**が提示される。**選び方は日付から決める**
    (乱数で選ぶと、起動し直すたびに違う課題が並び、狙って進められない)。
  - 候補は次の7つで、ここから3つが出る。

| 課題 | 報酬 |
|---|---|
| 落砂を10回発動する | 50 |
| 反転を8回行う | 50 |
| 砂術を3回撃つ | 50 |
| 砂時計を20体場に出す | 50 |
| 15回攻撃する | 50 |
| 1勝する | 100 |
| 3回対局する | 50 |

  **3つすべてを達成しても1日150〜200**にあたる。砂金の使い道はショップ(21章)だけであり、
  日課で入る量を厚くすると、そこに並ぶ品が相対的に安くなって買う判断そのものが消える。
  **入手を増やすときは、ショップの価格の側も併せて見直す。**

  - **進捗の記録**: 対局終了時(CPU戦・オンライン問わず、10手以上)に対局中のアクションが集計され、自動的に進捗が進む。**数えるのは自分の行動だけ**で、相手の反転や砂術は進まない。10手に満たない対局を数えないのは、開始直後に投げ捨てて回すのを防ぐため(15章の砂金と同じ線)。
  - **ミッション画面**: きろくタブの「ミッション」から開くモーダルで、達成したものは「受取」ボタンで砂金を獲得する。**通信できないときは受け取れない**(残高はアカウントにあり、手元で受取済みにすると権利だけが消えるため。21章のショップと同じ扱い)。
  - **課題は日をまたぐと入れ替わり、進捗も消える**。貯めておくものではない。

## 24. リーサルパズル(詰将棋モード)

あらかじめ配置された固定の盤面・手札・マナから、**「そのターン中に相手HPを0にする」**手順を見つけ出す一人用パズルモード。

- **仕様概要**:
  - ホーム画面の**「たたかう」タブ**の「ひとりで」の枠から「リーサルパズル」を選んで入場する(9章)。
  - 各問題はステージ形式(Stage 1〜10など難易度順)で構成。
  - **パズルのルール**:
    - ターン開始時のマナ、手札、自陣・敵陣の砂時計の状態(残り砂・攻撃力・キーワード)が固定されている。
    - プレイヤーが「ターン終了」を押すか、マナ・行動権を使い切った時点で相手HPが0にならなければ「失敗(リトライ)」。
    - 相手HPを0にできれば「正解(クリア)」となり、**初回クリアのときだけ50砂金**を得る。
      解き直しはできるが報酬は出ない(「この問題は解決済み」と示す)。
    - **手が尽きたことをゲーム側から宣告しない。**マナも行動権も残っている限り何も言わず、
      失敗になるのは「ターン終了を押した」ときだけとする。詰みかどうかを機械が決めると、
      プレイヤーがまだ気づいていない手順まで断じてしまうため。
  - **相手は指してこない。**パズルは自分の1手番だけで完結するため、CPUも持ち時間も置かない。
    エモートも出さない(送る相手がいないため)。
  - **一覧の札の高さは全問そろえる**。ヒントが2行になる問題だけ背が高いと、横2列の
    グリッドで行ごとに段差が出て並びが落ち着かない。2行が収まる高さを最初から取り、
    1行の問題は下が空くに任せる
  - **目的**: 砂の反転タイミング、相打ちによる砂の消滅、速落や貫通・毒砂の挙動など、対局で勝つための基本〜高度なテクニックを楽しく学べる。

### エンドレスモード

Stage1〜10は「決まった手順を覚えて卒業する」導入教材として固定のまま残す。
これとは別に、**無限に出題され続ける「エンドレス」**を用意する。

- **問題選択画面に「エンドレス」の入口を1つ追加する。**Stage1〜10の一覧とは別枠で、
  押すたびにその場で新しい問題が1つ生成されて始まる。**同じ問題が保存されることはなく、
  一覧にも並ばない**(そもそも一覧に並べる「1件」という概念を持たない)
- **出題する問題は、必ず解答手順が存在することを機械が確かめてから出す。**
  存在しない詰みを出してしまうことがそのまま「壊れたパズル」になるため、
  出題前に**その場でシミュレーションを行い、実際にその手順で相手のHPが0になることを
  確認できたものだけ**を見せる
- **択が多く、正解の手順はごくわずかになるよう作る。**盤面には「攻撃しても得にならない
  駒」「使うとマナが足りなくなるだけの砂術」のような、**一見有効に見えるが実際には
  たどり着けない選択肢**を混ぜる。1手・2手で偶然クリアできてしまう問題は出さない
  (最低でも3手前後の組み立てを要する規模で作る)
- **エンドレスに初回クリア報酬(50砂金)は無い。**同じ問題が二度と出ない以上
  「初回」という区切りが成立せず、際限なく遊べる対局に報酬を出すと他の対局種別
  (15章)に対して際限なく稼げてしまう。**エンドレスは純粋な腕試しとして扱う**
- **クリア記録も残さない。**Stage1〜10の「★」のような達成の印は、二度と出ない問題には
  意味を持たないため付けない
- 結果パネルには**「もう一度」(いまの問題を再挑戦)・「次の問題へ」(新しい問題を
  生成してすぐ続ける)・「一覧へ」**の3つを並べる。失敗したときも「次の問題へ」を
  押せば別の問題へ移れる(1問に詰まって遊べなくなる状態を避けるため)

- **ホーム画面と対局結果パネルにも「日曜イベント中」の表示を添える。**Discordを
  見ていないプレイヤーにも伝わるようにするため。文言は1行に留め、通常時は何も出さない
- **将来、Discord Botのスラッシュコマンドを足す土台としても、同じFirebaseプロジェクトへ
  Cloud Functionsを1本追加する形にする。**常駐するBotプロセス(Gateway接続)は
  現時点では持たず、Discordの「Interactions Endpoint URL」(HTTPS方式)で受ける。
  リアルタイムなメッセージ監視・オンライン表示のようにGateway接続でしか実現できない
  要件が具体的に出た時点で、常駐サーバーの導入を改めて検討する

## 26. Discordスラッシュコマンド

11章の募集通知・25章の日曜イベント告知が**ゲームからDiscordへ知らせる**ものであるのに
対し、こちらは**Discordから情報を取りに行く・見せ合う**向きの機能。公式Discordサーバーで、
ゲームを開かなくてもカードを調べたり、自分の構築やアカウントの状態を確認できるようにする。

### `/card <名前>`

- カードの表示名を部分一致で検索する。1件に絞れない場合は候補を一覧で示し、
  絞り込みを促す(実在する名前を入れたのに無反応に見える状態を避けるため)
- **表示名が完全に一致するカードがあれば、それを最優先で1件だけ返す。**部分一致だけで
  判定すると、「サンド」で調べたつもりが「サンドショット」も一致してしまい、
  1文字も略さず正確に打ち込んだのに候補選びを挟まれる(実際にユーザーがこれで
  詳細を見られなかった)。名前をそのまま正確に入力した人を最短で応答させるため、
  部分一致の絞り込みより完全一致を先に見る
- **結果は砂時計図鑑の詳細パネルを元に、Discord表示用へ最適化した1枚の画像として返す。**
  コスト・総量(砂術は「術」)・キーワード・効果の文・紋章を画像に収める
- **そのカードが持つ効果の実演(9章「能力の実演」・`CardEffectPreview`の台本)を
  GIFアニメーションとして添える。**9章の実演そのものはキーワード/効果の種類ごとに
  1本の台本を持つ設計だが、**Discordへ渡すGIFはカード単位で1本にする**(複数の
  能力を持つカードは、その台本を通しで繋げた1周ぶんを1本のGIFにする)。1枚のカードが
  何をするかを1本で見せられるほうが`/card`の目的に合うため。**都度その場で描画せず、
  カードを追加・変更したときに全カードぶんを静的な画像・GIFとして生成しておき、
  `/card`はそれを配るだけにする**
- 収録するのはプールにある全カード(トークンは除く。6章の「トークンはデッキに入れられず、
  一覧にも出さない」方針をそのまま引き継ぐ)

### `/deck <8桁のコード>`

- 9章のデッキコードをそのまま使う。コードを引き、**デッキの中身(30枚・コスト順)を
  画像として返す**
- **ゲーム内のデッキ表(9章)と全く同じ見た目の再現は求めない。**デッキ表はGodotの
  `SubViewport`描画に依存しており、Discord Bot側でその都度Godotを起動して再現するのは
  常駐サーバーを持たない方針(10章)と相性が悪い。**Discord Bot側(Node.js)で、
  コスト順に30枚のカード名・コスト・総量を並べた簡易な画像を独自に描画する。**
  真鍮の質感などの作り込みは持たず、中身が読めることを優先する
- 存在しないコードは「見つかりませんでした」とだけ返す(9章の共有パネルと同じ扱い)

### `/link <連携コード>` と `/profile`

- ゲーム内のアカウント画面に「Discord連携コード」を発行するボタンを追加する。
  9章のデッキコードと同じ方式で、8桁の数字をFirestoreへ預けて番号だけを渡す
- Discordで `/link <コード>` を打つと、そのDiscordアカウントとゲーム内のuidを結びつける。
  **1つのDiscordアカウントにつき1つのuidだけを保持し、結び直すと前の紐付けを上書きする**
- `/profile`(引数なし)を打つと、結び付いているuidの表示名・アイコン・称号・**砂金の
  残高**・オンライン対戦の通算成績を返す。**19章の戦績(CPU戦を含む通算)はローカル
  保存のためサーバー側から見えず、ここで返せるのは22章の`match_records`から集計できる
  範囲(オンライン対戦だけ)に限られる**。連携していない場合は`/link`を促す文言を返す

### カードスポットライト

- 毎日正午(12:00 JST)に、その日のカードを1枚紹介する投稿を自動で行う(#お知らせ)。
  日曜イベント告知・募集通知が深夜0時台に集中しているため、時間帯をずらしている
- **選び方は完全ランダムとし、直近30日以内に紹介したカードは候補から外す。**
  70枚(今後さらに増える)のプールであれば、1ヶ月ほどで自然と一巡する計算になり、
  特定のカードだけ繰り返し紹介される偏りを防げる。**候補が尽きた場合(直近30日で
  大半を紹介し終えた場合)は、その回だけ除外条件を外して全カードから選び直す**
- 25章の日曜イベント告知と同じCloud Schedulerの仕組みに乗せる

### 応答の公開範囲

- **`/card` `/deck` `/link` `/profile` はいずれも、コマンドを打った本人にだけ見える
  応答(ephemeral)として返す。**チャット欄が埋まっていくのを避けるためで、
  とくに`/profile`は自分のアカウントの状態を返すため、他人に見える必要が無い
- **カードスポットライトはこの対象外**とし、通常のメッセージとして全員に見える形で
  投稿する。コマンドの応答ではなく、コミュニティ全体へ向けた投稿であるため

### 実装方針(概要)

- カードデータは現状Godot専用の`.tres`にしかないため、書き出しの手順
  (`tools/export_web.sh`)にカードデータをJSON化して書き出す工程を足し、
  Cloud Functionsからも同じデータを読めるようにする
- **`/card`の画像・実演GIFは、カードを追加・変更したときにまとめて生成しておく。**
  静止画・GIFの撮影はいずれも実際にレンダリングしたピクセルを読む必要があり
  `--headless`実行では動かないため、`tools/export_web.sh`(全工程が`--headless`)には
  組み込まず、別のツールとして持つ。都度その場で描画する仕組みは持たない
- **`/deck`の画像だけは都度Discord Bot側(Node.js)で描画する。**組み合わせが
  無数にあり事前生成できないため、ここだけ動的生成が必要になる
- Discordの操作(スラッシュコマンド応答・自動投稿)はいずれも25章で導入した
  `discordInteractions`(HTTPS)・Cloud Schedulerの枠組みに追記する形で足し、
  **常駐するBotプロセス(Gateway接続)は導入しない**という既存方針は変えない

## 27. ソロモード

一人用の、腕試し向けチャレンジコンテンツ。ツリー状(見た目は蛇行する1本道)に並んだ
ステージを、上から順にクリアしていく。**チュートリアルではない。**初めて遊ぶ人への
導線は誘導対局(18章)が既に持っており、ソロモードはそれとは別に、**ある程度ルールを
覚えたプレイヤーが歯ごたえのある一人用コンテンツで遊ぶ場所**として作る。誘導対局の
ような操作の説明・案内役(すなえる)は一切出さない。

ホーム画面の**「たたかう」タブ**の「ひとりで」の枠から入る(9章)。**副題は「決まった条件の
関門に挑む」**とし、隣に並ぶCPU戦(「好きなデッキで1局」)との違いが押す前に読めるようにする。
**「10の課題」のように固定の数を副題へ書かない**——ステージを足したときに嘘になるため。

### ステージの構成

**v1はステージが枝分かれしない1本道とする。**見た目はツリー状の道として描くが、
実際に分岐して複数の道から選べる構成は当面採らない。**データ構造上は1つのステージが
複数の前提ステージを持てるようにしておき**、将来分岐を導入する際にステージ側の定義
だけで対応できるようにする。

ステージは次の5種のいずれかを持つ。**種類は今後も増やしてよい**(下記「拡張性」)。

| 種別 | 内容 |
|---|---|
| **パズル型** | リーサルパズル(24章)と同じ仕組み。固定の盤面・手札・マナから、そのターン中に相手HPを0にする手順を見つける |
| **CPU対戦型** | ステージ専用の固定デッキで、思考レベル「上級」固定のCPUと通常ルールで対局する |
| **特殊ルール型** | CPU対戦型に、初期盤面の上書き・勝利条件の変更・ルール改変(下記)のいずれか、または複数を組み合わせる |
| **連戦(サバイバル)型** | HPを持ち越したまま、複数のCPUと連続で対局する。合間の回復は無い |
| **縛り型** | 特定の要素を封じたデッキ・ルールで対局する(例:通常の反転を禁止し反転権のみ使用可) |

**パズル型は、既存のリーサルパズル(24章)の5問より明確に難しくする。**複数の砂時計・
手札を絡めた手順の読み合いを要求し、操作の順序を誤ると倒しきれない構成にする。
CPU対戦型・特殊ルール型・連戦型・縛り型は**思考レベルの選択画面を挟まず、常に上級で
固定する**(13章)。ソロモードは歯ごたえを主眼にしたコンテンツであり、緩める理由がない。

### 特殊ルールのバリエーション

特殊ルール型・縛り型のステージが選べる改変は、次のようにステージのデータが持つ
フラグ・数値として表す(**新しいステージを追加するとき、コード変更なしで組み合わせを
選べる状態を保つ**)。

| 改変 | 内容 |
|---|---|
| 初期盤面の上書き | 自分・相手の場に、あらかじめ指定した砂時計を配置した状態で開始する |
| 勝利条件の変更 | 相手HPを0にする(既定)以外に、**指定ターン数生き残る**・**相手の場の砂時計をすべて破壊する**を選べる |
| 毎ターン落ちる砂の数 | 既定の1粒ではなく、**2粒**にする(高速ルール) |
| HPの上書き | プレイヤーの初期HPを既定(24)より低く(例:半分)して開始する |
| マナの上書き | 自分のターン開始時にマナが増えない(常に1のまま)状態にする |
| 通常の反転の禁止 | 3章の通常の反転(1体1ターン1回)を使えなくする。**反転権(2章)は影響を受けない** |
| 相打ちダメージの倍化 | 4章の相打ちで受けるダメージを2倍にする |

**これらはいずれもソロモード専用の対局にだけ適用される。**オンライン対戦・通常のCPU戦・
リーサルパズル(24章)・誘導対局(18章)には一切影響しない。

### デッキ

**CPU対戦型・特殊ルール型・連戦型・縛り型は、いずれもステージごとに固定されたデッキを
使う。**プレイヤー自身が保存した構築デッキは使わない。パズル型が固定の手札・盤面から
始まるのと同じ考え方で、そのステージで見せたい展開・組み合わせを毎回同じ形で体験させる
ため。縛り型で「反転禁止」を課す場合も、固定デッキ自体を「反転で強くなるカードを持たない
デッキ」として用意すればよく、ルール側の禁止処理と噛み合わせる必要はない
(通常の反転の禁止は「相手も反転できない」場合にだけ、ルール側の制限として効く)。

### 報酬

ステージをクリアすると、初回クリアのときだけ次を得られる(リーサルパズル・24章と
同じ考え方。解き直しでは出ない)。

- **砂金**(必須。額はステージごとに定める)
- **アイコン**(任意。ショップ・21章と同じ所有の仕組みへ追加する)
- **カード**(任意。下記「ソロモード限定カード」の3枚に限る)

### ソロモード限定カード(カードセットとして解放)

**8章で新設した「カードセット」の仕組みをそのまま使う。**ソロモードのためだけに
別の所有の仕組みを作らない——8章は「買い切りのカードセット以外の追加手段も、
状況に応じて別途検討してよい」としており、**ステージのクリアはその追加手段の1つ**
に当たる。

- 新カード3枚は、**1枚ずつを別々のカードセットとして**登録する(8章)。
  ステージごとに違うカードを解放する設計のため、3枚をまとめて1セットにはしない
  (まとめると1回のクリアで3枚とも渡ってしまう)
- **通常のカードセットと違い、ショップでは売らない。**対応するステージをクリアした
  時点で、その1枚ぶんのセットがそのまま所有済みになる(所有への追加は購入と同じ経路だが、
  砂金は減らない)
- 所有・未所有の扱いは8章・21章のカードセットの規則にそのまま従う。未所有の間は
  デッキ編集でロック表示、砂時計一覧(図鑑)ではシルエット表示になる
- **基本セット70枚には一切影響しない**(無変更)
- 所有後は他のカードセットと同じ扱いになる(通常のデッキ構築に使える)。
  **ソロモード限定カードは、通常のCPU戦・オンライン対戦のCPU側デッキ生成(13章)には
  混ぜない**。プレイヤーが未所有の可能性があるカードをCPUだけが使う状態を避けるため

**新カード3種**

| 名前 | 種別 | コスト | 総量 | 効果 |
|---|---|---|---|---|
| **チャイム** | 砂時計 | 2 | 4 | 反転:カードを1枚引く |
| **ウォード** | 砂時計 | 3 | 4 | 守護 + 設置:自分の他の砂時計1体の総量+1 |
| **揺さぶりの一手** | 砂術 | 2 | ─ | 相手の砂時計1体を反転させる |

**「揺さぶりの一手」は、2章の反転権に残っている宿題(「弱めてから同じ手番で仕留める」
使い方を案内する場所が無い。同章・`docs/BalanceReport_v5.md` 12章)と同じ動きを、
カード1枚の効果として持たせたもの**であり、ソロモードの終盤ステージ(下記)で
この使い方が活きる場面を用意する。ただし**教える演出は付けない**(この章の冒頭のとおり)。
これらの数値は初期案であり、他の新規カードと同じく実測で調整する可能性がある
(`docs/Hourglasses.md`)。

### 拡張性

ステージは `.tres` の Resource として持ち(リーサルパズルの `PuzzleStageData` と同じ

## 28. ランクマッチ

**2026-09-15追記。**19章にあった「ランク戦(順位付け)は行わない」という方針を撤回し、
第3のマッチングモードとして追加する。11章のランダムマッチ・ルームコード対戦とは
別のマッチングプールを持ち、フリーマッチ(レート変動なし。中身はランダムマッチと同じ
仕組みを使うが、ランクマッチとはプールを分ける)と対になる。

### 段位構成

| 帯 | 段階 | 昇格条件 |
|---|---|---|
| ブロンズ | 1〜3 | ★2個で昇格 |
| シルバー | 1〜4 | ★3個で昇格 |
| ゴールド | 1〜5 | ★4個で昇格 |
| プラチナ以上 | レート制(1000開始) | 下記の表 |

ブロンズ〜ゴールドは**星取り制**とする。勝利で★+1、敗北で★-1(0未満にはならない)。
既定の★数に達したら次の段位・階級(無ければ次の帯)へ昇格する。ゴールド5から
★4個でプラチナへ上がると、以後は星取りをやめてレート制に切り替わる。

**プラチナへ到達した後は、レートが1000を下回っても星取り制へは戻らない(降格なし)。**
一度プラチナへ上がった実績はシーズン終了まで保持され、下がったレートのまま
プラチナ内に留まり続ける。

### 連勝ボーナス(2026-09-16追記)

**ゴールド以下(星取り制の帯)で3連勝以上しているとき、その回の勝利で得る★が+1される**
(通常の+1に加えて、連勝ボーナスの+1で計+2)。3連勝目・4連勝目・…と、連勝が続く限り
毎勝利で効く。1度でも負けると連勝は0に戻り、ボーナスも外れる。

**プラチナには適用しない。**プラチナは★ではなくレートで進むため、この節はブロンズ〜
ゴールドの間だけを対象とする。連勝の記録そのもの(3連勝したかどうか)はシーズンが
切り替わるとリセットされる(他の段位の値と同じ扱い)。

### プラチナのレート変動

| レート帯 | 勝利 | 敗北 |
|---|---|---|
| 1000〜1099 | +16 | -8 |
| 1100〜1199 | +14 | -10 |
| 1200〜1299 | +12 | -12 |
| 1300〜1399 | +10 | -14 |
| 1400〜1499 | +8 | -16 |
| 1500〜1599 | +6 | -18 |
| 1600以上 | +4 | -20(以降は固定) |

**レートが100上がるごとに勝利側を-2・敗北側を-2(絶対値では+2)ずつ動かし、
1600以上で打ち止めにする。**上位ほど1勝の価値を下げ1敗の重みを上げることで、
実力が拮抗する高レート帯で数値が行き来しにくくする。**この表は初期案であり、
運用しながら調整する。**レートは1000を下回っても(降格しない代わりに)下がり続け、
同じ表の対応するレート帯の値をそのまま使う(1000未満は1000〜1099と同じ +16/-8)。

### シーズン

**1シーズン=1か月。**月初(JST 00:00)に、**全プレイヤーを一律ブロンズ1・★0へ
リセットする**(前シーズンの到達段位に関わらず、全員が同じ位置から再スタートする)。
前シーズンの最高到達段位は月末報酬の判定にのみ使い、新シーズンの開始位置には影響しない。

### 月末報酬・ランキング

- **そのシーズン中に到達した最高段位に応じて、月末(または翌月頭)に砂金を付与する**
  (2026-09-15、ユーザー判断で確定)。**ブロンズ100 / シルバー300 / ゴールド800 /
  プラチナ3000砂金**
- **ゲーム内にランキング画面を新設する。**現在シーズンの参加者を、帯・階級・★・レートを
  貫く単一の順序(進行度)で一覧できるようにする。**プラチナだけに絞らず、ブロンズから
  参加していてもランキングに載る**(2026-09-16、ユーザー判断「プラチナだけじゃなくて
  進行度でもランクに残ったら嬉しそう」)。並び順の合成の仕方は Architecture.md 10.16節
  `RankRules.progress_score()` を参照
- **unityroomのランキング機能との連携(2026-09-15調査済み)。**unityroomのAPIは
  「そのボードへ今回のスコアを送る」だけの一方向の仕組みで、読み出し(ランキングを
  取得する)口は公開されていない。**したがってゲーム内の「ランク」画面
  (ランキング一覧)をunityroom側の値で置き換えることはできず、ゲーム内ランキングを
  主としたまま、unityroom側へはプラチナのレートが動くたびに追加で送る**(そのゲーム
  ページへ来た人が見る、公開された副次的なランキングという位置づけ)。実装は
  `scripts/net/unityroom_ranking_client.gd`。**unityroom側のゲーム管理画面で、
  対応するボードの記録方式を「常に記録」にしておく必要がある**(「ハイスコア」の
  ままだと、シーズンが変わってレートが下がったときに古い最高値が残り続けるため)
- **月初にシーズンが切り替わったプレイヤーへ、モーダルの「表彰式」を1度だけ見せる**
  (2026-09-15、ユーザー判断)。前シーズンの最高到達段位と、それに応じた月末報酬を
  添えて表示する。初めてランクマッチへ触れるプレイヤー(前のシーズンが存在しない)には
  出さない。実装は `CardSeasonCeremonyPanel`(Architecture.md 10.16節)

### 経済(通貨)への影響

ランクマッチの1局ごとの砂金報酬は、当面**ランダムマッチと同額**(勝利30・敗北10。
GameDesign.md 15章)とし、**日曜イベント(15章)の対象にも含める**。段位到達による
月末報酬は、この1局ごとの報酬とは別枠で加算する。

### サーバー側の正当性検証について

**サーバー側での正当性検証を行わない既存方針(11章)により、レートもクライアントの
申告をそのまま信頼する。**意図的なレートの吊り上げ(自己対戦の繰り返し等)への対策は、
15章「不正な稼ぎ方への線引き」と同じ考え方(総手数が少ない対局・同一相手との連戦を
対象外にする等)を流用する想定とし、詳細はArchitecture.mdで詰める。

## 29. 掲示板(ラボ)

**ユーザー投稿によって新しいカードの種を集める仕組み。**プレイヤーが「こんなカードが
欲しい」を投稿し、他のプレイヤーの投票で人気を計り、最も支持された1件を次のカードセット
(8章)へ取り込むかどうか開発側が検討する。ホーム画面に5つ目のタブ**「つくる」**を
新設し(9章)、その中に置く。

### 投稿できるもの

**投稿種別は「新規カード案」の1つだけとする。**フレーバーテキストのような、
この作品にいま存在しない概念を新たに持ち込むことはしない。

投稿は次の3項目からなる自由記述とする。

| 項目 | 内容 |
|---|---|
| カード名(案) | 表示名の案。**そのまま採用されるとは限らない** |
| モチーフ・効果の説明 | 「こういう見た目で、こういう効果」という自由記述(上限文字数を設ける) |
| 砂時計 / 砂術のどちらか | 6章の分類にそのまま従う |

**コスト・総量・キーワードの数値は投稿者が決めない。**採用が決まった後、6章の値段表・
実測(`docs/BalanceReport_v5.md`)に従って開発側が値付けする、通常のカード追加フロー
(`.claude/skills/add-hourglass/SKILL.md`)にそのまま乗せる。掲示板が担うのは
「どんなカードが欲しいか」というモチーフ・アイデアの部分だけであり、**カードは
1枚ずつ固有の効果を持つべき**という6章の方針・値付けの厳密さを、投稿を受け付ける
ことによって緩めない。

### 投稿のコスト

**1件につき300砂金。**通常のオンライン対戦10回前後で届く額とし、あえて安く設定する
(2026-09-15、ユーザー判断)。**最終的に採用されるのは投票で最も支持された1件だけ**
であり、質を絞る役目はコストではなく投票のほうが担う。コストを高くして投稿数を
絞るより、**低コストで気軽に投稿できる状態にして掲示板そのものを賑わわせ**、
数の中から人気作を拾い上げるほうが狙いに合う。**この金額は初期案であり、
投稿数を見ながら調整する。**

**低コスト化で審査(NGチェック・承認)の対象が増えることは織り込み済みとする。**
下記「管理ツール」で1件あたりの確認作業を素早く済ませられるようにすることで、
コストの低さと運用の手間を両立させる。

### ワークフロー

1. **投稿**:プレイヤーがカード名・モチーフの説明・種別を書いて送信する。この時点で
   300砂金を消費する(21章のショップの購入と同じ、`updateTime`前提の`commit()`で
   残高を確認しつつ減算する)
2. **審査中**:投稿は**この時点では他のプレイヤーに見えない**。自動のNGワードチェック
   (差別的表現・実在の商標・過度に露骨な表現など)と、開発側による目視確認を経る。
   **確認は下記「管理ツール」を使って行う**
3. **却下された場合、支払った300砂金は全額返金する。**NG判定は投稿者の落ち度とは
   限らない(単に趣旨が合わない・既存カードと酷似している等も却下の対象になる)ため、
   罰金のようには扱わない
4. **承認された投稿は掲示板へ掲載され、他のプレイヤーが投票できるようになる**
5. **投票はGoodボタンを押すだけの単純な賛成表明とし、1人1投稿につき1回まで、
   取り消しはできない。**反対票・コメント機能は持たない
6. **月末、その月に投稿されたものの中で最も得票が多い1件を、開発側が次のカードセットへ
   取り込むかどうか検討する。**「上位案をゲーム内実装」は約束ではなく検討の対象であり、
   このゲームの設計方針(6章「語彙だけでカードを作らない」等)と噛み合わない場合は
   見送ることもある。採用しない場合も、その旨を投稿へ表示する

### 管理ツール

**承認・却下・月末の採用判断はゲーム内の画面では行わず、開発側だけが開くHTMLの
管理ツールから行う。**ゲーム本体(Godot)へ管理画面を作り込まない代わりに、
**審査待ちの一覧・内容の確認・承認/却下ボタン・今月の得票ランキング・採用の確定を
1画面でまとめて行える**専用のツールを別に用意する(実装方針は`Architecture.md`)。
低コスト化(上記)で件数が増えることを見込み、**1件あたりの確認をボタン1つで
済ませられること**を優先して作る。却下時の返金・採用時の称号付与も、このツール側の
操作にまとめて含める(プレイヤー側の画面で個別に処理を待たせない)。

### 登録済みアカウント限定(14章の例外)

**掲示板への投稿・投票は、登録済みアカウント(14章)に限る。**匿名アカウントは
閲覧だけできる。14章は「アカウントを作らなくても...全ての機能を利用できる」としているが、
**掲示板はこの1点だけ例外とする**。匿名アカウントはブラウザのデータを消せば何度でも
作り直せるため、間口を絞らないと連続投稿・多重投票の温床になる(11章のとおりサーバー側の
正当性検証は行わない方針のため、この種の不正は技術的には防げず、間口を絞ることでしか
対策できない)。

### 一覧の見せ方

- **既定は「今月」の投稿を得票数の多い順に並べる。**ヘッダーの主アクションのボタン1つで
  「今月」と「過去ログ」を往復する(9章の砂時計一覧の並び替えと同じ語彙)
- **過去ログでは、採用された投稿に印を付ける。**却下された投稿は一覧に出さない
  (却下は投稿者への通知だけで足り、他のプレイヤーに見せる理由がない)
- 一覧に1件も無いときは「一覧に並べるものが無いときの見せ方」(9章・`EmptyState`)を使う

### 採用された投稿者への報酬

**採用されたら、投稿者に称号「発案者」を付与する。**14章の称号システムにそのまま
1件追加する形とし、専用の報酬の仕組みを新設しない。

## 30. 公式大会「箱庭杯」

**プレイヤー同士の腕試しの場として、毎月1回、公式大会を開催する。**進行はすべて
公式Discordサーバー上で運営(開発側)が手動で行う。専用の自動進行システムは
作らない(小規模な運営規模に見合わせるため)。

**大会名・優勝称号は開発側から出た仮称であり、他作品の呼び名を流用している
可能性がある。**「砂時計アリーナ」の世界観(砂・時計・刻)に合わせた名前へ
差し替えてもよい(例:「砂時計杯」等)。ここでは一旦この名前のまま進める。

### 開催サイクル

1シーズン=1か月とし、ランクマッチ(28章)と同じ月次サイクルに揃える。

| 週 | 内容 |
|---|---|
| 第1〜4週 | 予選(週1回、計4回) |
| 月末 | 決勝トーナメント(8名) |

### 予選

- **予選は指定日時に一斉開催するライブイベントとする。**参加希望者はDiscordで
  事前に集合し、運営がその場でルームマッチ(11章)のコードを使って対戦カードを組む
- **各回の予選は、その週の参加者によるシングルエリミネーション方式のミニトーナメント
  とし、上位2名が決勝トーナメントへの出場権を得る。**4週間で計8名が出そろい、
  決勝トーナメントの出場者が確定する
- **既に出場権を得たプレイヤーは、以降の週の予選には出場できない**(毎週異なる
  8名が積み上がっていく)。ある週で敗退しても、翌週以降の予選に出場し直せる
- 参加人数が少ない週は、通過人数を運営の判断で調整してよい(例:2名しか
  集まらなかった週は、その2名がそのまま通過する)。**厳密な人数調整の
  アルゴリズムは持たない**(この規模の運営で機械的に処理する必要は無いため)

### 決勝トーナメント

- 出そろった8名で、単一敗退方式のトーナメントを1日で行う
- 対局の設定(先手・後手、持ち時間、使用デッキ)は5章・11章の通常のルームマッチと
  同じとする。**大会専用のルール改変は行わない**

### 参加条件

- **登録済みアカウント(14章)であること**。掲示板(29章)と同じ理由(進行と結果の
  紐付けに、消えない識別子が要るため)
- **公式Discordサーバーへの参加。**進行がDiscord上で行われるため

### 優勝賞品

優勝者には次の2つを贈る。

- **実装権**:自分のカード案を1件、**掲示板(29章)の投票を経ずに**次のカードセットへ
  実装してもらえる権利。**投稿フォーム(カード名案・モチーフの説明・砂時計/砂術の
  区分)は掲示板と同じものを使う。**コストの支払いは不要で、NGチェック(29章)だけを
  通過すれば採用が確定する。**値付け(コスト・総量・キーワードの数値)は開発側が
  通常のカード追加フローに従って行う**(29章と同じく、6章の値付けの厳密さを
  この権利によって緩めない)
- **称号「箱庭王」**:14章の称号システムへ1件追加する(29章の「発案者」と同じ、
  所有を絞る称号)

準優勝以下への副賞は今回は設けない。**大会そのものの盛り上がりと実装権が
主な狙いであり、参加賞のような形の報酬は当面用意しない。**

## 31. カードスキン

**特定のカード1枚の見た目(砂時計のイラスト)を、自分だけ別の絵へ差し替えられる品。**
ショップ(21章)で砂金と引き換えに買い切りで解放する。

9章のとおり、砂時計の絵は全種が共通の1枚の色違いであり、固有の絵を1枚ずつ描き起こす
運用は量産に向かないため採らなかった。**スキンはその裏返しで、「量産しない代わりに
1枚ずつ固有の絵を用意する」ための置き場**とする。カードを見分ける役目は引き続き
紋章が担う(9章)ため、スキンで変わるのは砂時計の絵だけで、**紋章・名前・数値・
キーワードの表示は一切変えない**。

### スキンが持つもの

- 対象のカード1枚のid、表示名、そのカードだけの固有イラスト(上向き / 落下中 /
  落ちきりの3状態)。**トークンと砂術は対象にしない**(絵を持たないため)
- 絵は `docs/AssetPromptTemplate.md` の砂時計テンプレートに従って生成し、
  **本体のガラス玉がキャンバス高さの70%を占める制約をそのまま守る**。スキンだけ
  砂時計が大きく・小さく見えると、盤面で駒の大きさが揃わない
- 3状態は必ず「上の砂が多い / 落下中 / 下の砂が多い」と読める形にする。
  絵を差し替えても、**砂の量というこの作品で最も重要な情報チャネル(9章)を潰さない**
- **手札の絵の窓の光だまりの色(9章「手札」)は、スキンごとに1色持つ。**共通の絵の
  色相表から求められないため

### 売り方と価格

- **1品=カード1枚のスキン**とする。コンセプトで揃えた数枚を1つの品(スキンセット)に
  まとめて売ってもよいが、その場合も中身は1枚ずつ独立したスキンとして扱う(ON/OFFは
  1枚ずつ切り替えられる)
- **価格はスキン1枚500砂金を目安とする。**アイコン(100)・エモート(200)より高く、
  プレイマット(1500)より安い。対局中に目に入るのはそのカードを引いて出したときだけ
  であり、常に画面の大半を占めるマットほどは見えないため。**セットは合計より少し
  安くしてよい。**いずれも初期案であり、砂金の入手経路が増えたら見直す
  (「今後足す品ほど高くする」という21章の方針は同じ)
- 品揃えは固定(21章)。**買う前にショップの品目で3状態の絵をそのまま見られる**
  ようにする(見た目が品そのものであり、名前だけでは何を買うのか分からない。
  プレイマットの縮小見本と同じ考え方)
- 一度買ったものは消えない。同じものは2度買えない

### ON/OFF

- **買った時点でONになる。**買ったのに何も変わらない、という状態を作らない
- **切り替えは砂時計図鑑(9章)の右のページで、カード1枚ずつ行う。**そのカードの
  スキンを所有しているときだけ、絵の下に「スキン:ON / OFF」の切り替えを出す。
  所有していないカードには何も出さない(ショップの役目を図鑑が兼ねない。14章の
  「設定する場所に買えないものを混ぜない」と同じ)
- 図鑑の右のページの絵は、**ONのときスキンの絵で表示し、押して裏返す操作もそのまま
  効く**(3状態を持つため)
- **デッキ単位でまとめて切り替える仕組みは持たない。**構築ごとに見た目を変えたい
  場面はあるが、デッキごとにスキンの状態を持つとデッキの保存形式・共有(デッキ表・
  デッキコード)・対局前の受け渡しのすべてへ手を入れることになり、見た目の品1種の
  ために釣り合わない。**アカウントに対して1枚ずつ、が唯一の設定単位**
- 設定はアカウント(14章)に紐づき、別の端末からログインしても引き継がれる

### どこで見えるか

- **ONのスキンは、そのカードの絵を出すすべての場所で使う**:手札・場の駒・
  ドラッグ中のプレビュー・図鑑・デッキ編集の一覧と棚・墓地の中身・デッキ表(9章)・
  デッキ一覧やリプレイ一覧の代表アイコン。**画面ごとに出す/出さないを分けない**
  (分けると「買ったのにここでは元の絵」という不揃いになる)
- **対局では相手にも見える。**表示名・アイコン・称号・プレイマットと同じ経路で
  相手の設定を受け取り、相手の場と手札から出た駒をその絵で描く。見た目の品は
  相手に見えて初めて値打ちになる(プレイマットと同じ)
- **CPUの駒にはスキンを当てない。リプレイと観戦は元の絵で再生する**(棋譜はスキンを
  記録しない。マットと同じ扱い)
- ルール画面(16章)・画面の見かた(20章)・キーワード辞書(17章)の実演と教材の
  盤面は**常に元の絵**を使う。教材の絵がプレイヤーごとに変わると説明と食い違う

### 絵の用意

- スキンの絵は**固有イラストであり、色違いでは作らない**。生成はユーザーが
  `docs/AssetPromptTemplate.md` のテンプレートで行い(`{{MOTIF}}` にそのスキンの
  意匠を入れる)、透過処理までを手作業で済ませたうえで取り込む。1枚ずつクオリティを
  保つことを優先し、**1度に多くを足す運用にはしない**(数枚ずつ)
- **スキンは配布物(pck)を増やす。**基本の絵は1組で済んでいるが(9章)、スキンは1枚
  ごとに3状態の絵がpckへ入る。非可逆(WebP)で取り込んでも1枚あたり数十KBかかる
  ため、Web版の起動待ちを守るには**足す枚数に上限を意識する**(目安として当面は
  合計20枚程度まで。超えるならBGMと同じく実行時に取りに行く方式を検討する)
- 新しいスキンを足したら、Discordの#お知らせへ紹介する(新カードと同じ扱い)
