# 砂時計PvPゲーム ルール設計書(v1.0)

## コンセプト

砂時計モチーフの、アクション性のない純ターン制対戦ゲーム。
「ひっくり返す」「時間経過で状態が変わる」という砂時計の物理的本質をルールの核に据える。
5分程度で1戦が終わる軽量設計で、Godot + unityroomでのオンライン対戦を想定。
毎日アプデで新しい砂時計を追加し続けられる、データ駆動な拡張性を前提とする。

---

## 1. 基本コンポーネント

- 各プレイヤーは対局前に **5種類の砂時計をデッキとして選ぶ**
- そのうち **3個を場に出し、2個を控えとして持つ**
- 場は **左・中央・右** の3マス固定
- 場に出す3個を**どの位置(左・中央・右)に配置するかはプレイヤー自身が選択する**。控えの2個の順序にルール上の意味はなく、選択順で自動決定する
- 配置フェーズでは、相手が選んだ**5種類のデッキ内容・先手/後手は公開情報**として見える(お互いに見える)。ただし**その3個をどの位置に配置したかは非公開**とし、両者が配置を確定した時点で対局開始とともに同時公開する(いわゆる「チームプレビュー」方式)

```
[相手] 左　中央　右
[自分] 左　中央　右
```

## 2. 砂時計の状態

各砂時計は常に以下いずれかの状態を持つ。

| 状態 | 意味 |
|---|---|
| 上向き | セットした直後。砂は全部上にある |
| 落下中 | 砂が流れている最中 |
| 落ちきり | 砂が全部下に落ちた状態 |

**状態遷移:**
- **自分の手番が終わるとき、自分陣営の場の3マスが左→中央→右の順に1マスずつ解決される**。何が起きるかは、そのマスにその手番で設定された行動によって決まる

| そのマスの設定 | 解決内容 |
|---|---|
| なし(既定) | 何も起きない |
| 反転 | 上向きに戻る |
| 移動 | 自分の場のもう一方のマスと位置が入れ替わる |
| 交代 | 控えと入れ替わる(出てきた駒は上向き) |

**上記の解決に続けて、そのマスの砂が必ず1段階進行する**(上向き→落下中→落ちきり。既に落ちきりなら何も起きない)。移動で入れ替わった2マスも、交代で出てきた駒も同様に進行する。**行動を設定したかどうかで進行の有無は変わらない。**

- 相手陣営の砂時計は、相手の手番が終わるときにのみ解決される
- **相手の駒を反転させる設定をした場合は、自分の3マスの解決をすべて終えた後に、相手の該当マスを反転する**。これは相手陣営の解決ではないため、相手の砂は進行しない
- 行動を設定せずに手番を終える(パス)こともできる。進行の有無は行動の有無に左右されないため、パスは「何も操作しない」ことのみを意味する
- 「反転」させると、どの状態からでも即座に「上向き」に戻る
- **対局開始直後の初期状態は、場の位置によって異なる**。左マスは「上向き」、中央マスは「落下中」、右マスは「落ちきり」から始まる。これにより、開始から2手の間は1手に1駒ずつ順番に落ちきり、何が起きたのかを追いやすくなる。また右マスの駒は最初から落ちきっているため、反転させて起こさない限り働かず、対局開始の1手目から「どの駒に手を入れるか」という判断が発生する。以前は全ての砂時計が「上向き」から始まっていたが、(1)開始2手目に3駒が同時に落ちきってHPの半分近いダメージが一度に入り原因を追えない、(2)序盤は何もしなくてもダメージが入るため反転が損になり手に意味が生まれない、(3)位置ボーナス廃止以降どのマスに置いても差がなく配置フェーズが形骸化していた、という3点を解消するために変更した

以前は「砂時計を移動もしくは反転させたときは砂が落ちないようにしてほしい」というフィードバックを
受け、**行動を設定したマスはその手番の進行を行わない**方式を採っていた。しかし自己対戦による
バランス検証の結果、この方式が**反転にだけ非対称なコストを生んでいる**ことが判明した。自分の駒を
反転すると自陣1マスの進行を失うのに対し、相手の駒を反転するコストはゼロだったため、思考ロジックは
反転の83.6%を相手陣へ集中させ、どちらも自分の砂時計を起こし直さないまま盤面が全て落ちきりで枯れ、
対局の12.8%が膠着した。これを受けて、**行動は進行を止めない**方式へ改めた。自分の駒の再稼働
(反転した駒は同じ手番で落下中になり、次の手番終了で落ちきる)と、相手への妨害(落ちきりを1手番
遅らせる)が、どちらも「1手番ぶん」の取引として釣り合う。あわせて、出した駒が落ちきるまで3手番
かかっていた交代のテンポロスも解消される。この変更により、行動の選択は「進行を止められるかどうか」
ではなく「その効果がどれだけ得か」だけで決まる。

## 3. 勝利条件

- 各プレイヤーの初期HPは30
- 相手のHPを先に0にした方が勝利
- 砂時計自体はHPを持たない。ダメージは常にプレイヤーのHPに入る
- 勝敗が決まった時点で対局は即座に終了する。以降は盤面を操作できず、結果表示からホーム画面へ戻る。ただしこの「即座に終了する」は**以降盤面を操作できないことを指し、決着に至った出来事の演出まで省略することを意味しない**。決着を生んだ手番の解決(砂の進行・ダメージ)は、通常のターン終了時と同じ順序・同じ演出で最後まで見せ切ってから結果を表示する(以前は決着した瞬間に演出を打ち切って即座に結果パネルを出していたが、「何が起きて勝負が決したのか分からない」というフィードバックを受けて変更した)
- **決着を生んだ最後の出来事は、通常のターン進行より強調して見せる**。原因となった駒にスポットライトを当てたまま「決着」を示す表示を重ね、短い間を置いてから結果パネルへ移る。決着した瞬間より後のマスの解決は、勝敗に影響しないため演出しない
- **結果パネルには、勝敗・両者の最終HP・総手数に加えて「何で決着したか」を1行で明示する**。決着の要因は「落ちきりによるダメージ(原因となった駒名を含む)」「効果によるダメージ」「持ち時間切れ」「投了」のいずれかとして表示する
- **投了(サレンダー)**:対局中はいつでも投了でき、投了した側の敗北として即座に対局を終了する。誤操作を防ぐため確認を挟む
- **オンライン対戦での投了は、指し手(反転/移動/交代)と同じ経路で相手へ送信する**。投了した側だけが終局し、相手が持ち時間切れまで待たされる状態にはしない。投了は棋譜にも1手として記録され、リプレイでも「投了で終わった対局」として再現される

初期HPは当初20だったが、「行動は進行を止めない」方式へ改めて対局のペースが上がった結果、
自己対戦での決着が平均21.8手・中央値15手と短くなりすぎたため30へ引き上げた。30では平均27.1手・
中央値22手となり、1手番あたりの解決演出(4〜5秒)と思考時間を合わせて「5分程度で1戦」という
コンセプトに収まる。副次的に、手数が伸びて先制の価値が相対的に下がるため、**先手勝率が
59.5%から52.0%へ緩和される**(後手補正ルールを別途設けずに済む見込み)。

## 4. ターンとアクション

### 4.1 進行方式

- 純粋な交互ターン制(アクション性なし)
- 時間制は**1人あたり持ち時間3分の固定制**(加算なし)とする。フィッシャールール(基礎時間+1手ごとの加算)は分かりにくいため採用しない
- オンライン対戦時、この持ち時間は**切断・放置への対処を兼ねる**。自分の持ち時間が0になった場合、行動していなくても即座にそのプレイヤーの敗北とする。これにより、相手の手を無期限に待つ実装で成立させ、別途タイムアウト処理を持つ必要をなくす

### 4.2 操作フロー(UI想定)

1. 場の砂時計(自分・相手どちらでも)をタップして選択
2. 選択に応じて、選べる行動が表示される
   - 自分の駒を選んだ場合:「反転」と、その駒がスキルを持っていればそのスキル名のボタン
   - 相手の駒を選んだ場合:「反転」のみ
3. 「反転」を選ぶと、その駒に「反転」が設定される(この時点では盤面は動かない)
4. スキルを選ぶと、その駒に「スキル」が設定される。対象を選ぶ必要があるスキル(交代)は、
   続けて対象(控えの砂時計)を選ぶ
5. 行動を設定しても手番はまだ終わらない。設定内容は予約マークとして盤面に表示され、押す前なら別の行動へ設定し直せる
6. 「ターン終了」を押すと4.4の解決へ進む(何も設定していなければパスとして解決する)

### 4.3 行動の種類(1手につき1つ)

| 行動 | 内容 |
|---|---|
| **反転** | 場のどの砂時計でも(自分・相手問わず)選び、そのマスに「反転」を設定する |
| **スキル** | 自分の場の砂時計を選び、その駒が持つスキルを設定する。**反転の代わりに行う** |
| **パス** | 何も設定せずに手番を終える |

反転・スキルはいずれも**その場で盤面を動かすのではなく、そのマスに行動を設定する操作**で
あり、実際の効果はターン終了時の解決で発生する。**反転時に発動する追加効果も、この解決の
タイミングで発動する**。1手番につき設定できる行動は1つまで。

スキルは**1つの駒につき1つまで**とし、持たない駒(バニラ)があってよい。相手の駒のスキルは
使えない。**スキルを使ったマスも、他の行動と同じく解決後に砂が1段階進行する**。つまりスキルを
使うことは「その手番にその駒を起こし直さない」ことと引き換えであり、**落下ダメージが高い駒ほど
スキルの機会費用が高くなる**。この関係が、追加のコストルールを設けずにスキルの強さを釣り合わせる
仕組みになっている(7章の設計指針8を参照)。

以前は「移動」(自分の場の2マスを入れ替える)と「交代」(控えと入れ替える)を全ての駒が使える
基本行動として持っていたが、自己対戦での選択率がそれぞれ1.8%と、1手番を費やす価値がないことが
判明した。原因は、位置ボーナス廃止以降どのマスに置いても差がなく、移動・交代そのものに価値が
なかったことにある。そこで**両者を駒ごとのスキルへ移し、基本行動を「反転」だけに絞った**。
これにより毎手番の判断が「どの駒を選ぶか」に加えて「起こすか、能力を使うか」の2軸になり、
新しい駒を追加する際の設計の幅も広がる。

### 4.4 ターン終了時の解決順序

1. 自分の場の左マスを解決する
2. 中央マスを解決する
3. 右マスを解決する
4. 相手の駒に反転を設定していた場合、そのマスを反転する
5. ターンチック効果(落ちきり中の継続効果など)を解決する
6. 手番を相手へ渡す

スキルのうち位置交換は2マスに関わるため、**入れ替え自体は関与する2マスのうち番号の若い方の
解決時に1度だけ実行する**。その後、関与した2マスはそれぞれの解決の順番で通常どおり進行する。

## 5. 盤面の位置ルール

位置による特性は**「対局開始時の初期状態」のみ**とする。

| 位置 | 特性 |
|---|---|
| **左** | **開始時の初期状態は「上向き」** |
| **中央** | **開始時の初期状態は「落下中」**(そのマスに行動を設定しなければ、最初の1手を終えた時点で落ちきる) |
| **右** | **開始時の初期状態は「落ちきり」**(反転させるまで働かない) |

以前は「左マス=交代の入口」(控えの砂時計はここに出てくる)という特性があったが、交代を
基本行動から駒のスキルへ移した際に廃止した(4.3)。交代スキルを持つ駒は、**自分がいるマスで
そのまま控えと入れ替わる**。

位置による恒常的なダメージ補正は設けない。以前は中央=落下ダメージ+1、右=落ちきり中の
被ダメージ-1という位置ボーナスを設けていたが、**盤面が見づらくルールが複雑になりすぎたため
廃止した**。移動アクションに意味を持たせる意図があったが、その役割は砂時計の種類ごとの効果側で
担保する。

位置の差は**対局開始時の初期状態のみ**であり、対局が進めば位置そのものに有利不利はない。
この差は、位置ボーナス廃止以降どのマスに置いても同じになっていた配置フェーズに、編成判断を
取り戻すために存在する(2章の初期状態を参照)。

## 6. ダメージの基本構造

- **全ての砂時計は「落下ダメージ」という基礎パラメータを持つ**(0の場合もある)
- 落下ダメージは、その砂時計が「落ちきり」状態に到達した瞬間、相手プレイヤーのHPに入る
- 一部の砂時計は、それとは別に「反転時」「落下中」「落ちきり中」に発動する追加効果(受動)や、
  手番の行動として発動する**スキル**(4.3)を持つ

### ダメージのグラデーション方針

落下ダメージは打点であると同時に、**スキルを使うときの機会費用**でもある(4.3)。したがって
強いスキルを持つ駒ほど落下ダメージを低くする。

| 分類 | 目安 | 割合の目安 |
|---|---|---|
| バニラ(効果もスキルも無し) | 4 | 強さの基準となる駒として少数 |
| 受動効果のみ | 2〜3 | 一定数 |
| スキル持ち | 1〜3 | 主力。強いスキルほど低くする |
| 0(特殊枠) | 0 | 全体の1割程度。機会費用が無いため毎手番スキルを撃てる駒として設計する |

## 7. キーワード効果の語彙(拡張用フレームワーク)

新しい砂時計を追加する際は、以下の要素の組み合わせで設計する。

### トリガー(いつ発動するか)
- **起動時(スキル)**:プレイヤーがその駒を選び、手番の行動として発動したとき(4.3)。
  反転の代わりに行うため、1手番に1回だけ。これだけが能動的なトリガーで、他はすべて受動
- **反転時**:反転させた、まさにその瞬間
- **落下中**:「落下中」状態である間、常に条件を満たす
- **落ちきり時 / 落ちきり中**:落ちきった瞬間、またはその状態が続いている間

### ターゲット(何に影響するか)
- **自分自身**(その砂時計自体)
- **隣接**(同じ場の左右どちらか、方向は駒ごとに固定)
- **相手プレイヤー**(直接ダメージなど、位置を問わない効果)
- **自分プレイヤー**(自分自身へのダメージなど、位置を問わない効果)
- **正面**(同じマス列にある、相手側の砂時計)
- **味方ランダム**(自分の場にある砂時計からランダムに1個)

### エフェクト(何をするか)
- ダメージ(相手プレイヤーへの直接ダメージ)
- 被ダメージ軽減(自分の防御)
- 状態操作(ロック/強制進行/状態同期など)
- リカバリー(他の砂時計を上向きに戻す)
- カウンター(反転させられた時に反撃する)
- **控えと交代**(自分自身を控えの1個と入れ替える)
- **位置交換**(隣接する自分の駒と位置を入れ替える)

### スキルの語彙(初期セット)

| スキル | 効果 | 対象の選択 |
|---|---|---|
| **交代** | 自分自身を控えの1個と入れ替える(出てきた駒は上向き) | 控え2個から選ぶ |
| **位置交換** | 隣接する自分の駒と位置を入れ替える(方向は駒ごとに固定) | 不要 |
| **加速** | 自分自身を1段階進める | 不要 |
| **目覚め / 号令** | 落ちきっている味方を、指定の個数まで上向きに戻す | 不要 |
| **一撃** | 相手プレイヤーに直接ダメージ | 不要 |
| **治癒** | 自分プレイヤーのHPを回復する(初期HPを超えては回復しない) | 不要 |
| **同調** | 隣接する自分の駒の状態を、自分と同じ状態に揃える | 不要 |

**回復量は1に抑える**。自己対戦で1手番あたりの平均ダメージが2〜3程度であるため、回復が
それを上回ると双方が回復し合って対局が終わらなくなる。実測では回復1で膠着3.0%・P90が37手
なのに対し、回復2で膠着8.8%・P90が112手、回復3で膠着12.0%・P90が上限の200手に達した。

**対象を選ばせるスキルは「交代」のみとする**。選択の段数が増えるほど操作が重くなるため、
それ以外は対象を自動で決められる形(自分自身・隣接・正面・味方ランダム・相手プレイヤー)に限る。

**交代は強いスキルとして設計しない**。初期配置を自分で自由に選べる以上、単に控えと入れ替える
だけの行動には1手番ぶんの価値が生まれにくい(自己対戦でも採用率はほぼ0だった)。それでも
語彙として残すのは、**「盤面の駒を入れ替えるという行動も存在する」ことをプレイヤーへ示す
役割**があるためで、性能ではなく選択肢の幅として置いている。将来この枠を強くする場合は、
入れ替えそのものに付加価値を持たせるか、控えを配置時に選べなくするなど、前提のほうを変える。

### 設計指針(運用ルール)
1. **プレイヤーへの直接ダメージ効果には位置参照(隣接など)を使わない**。自分・相手いずれのプレイヤーへの効果もシンプルに「自分プレイヤー」「相手プレイヤー」でよい。位置参照は駒同士の状態操作に限定する
2. バニラ(無効果)駒を一定数保ち、強さの基準にする
3. 妨害・防御系の「反転させられ続けると無限に得をする」効果は避ける。カウンター等で釣り合いを取る
4. コピー・同期系の効果は駒プール全体の1〜2割以下に抑える
5. 移動・妨害系のキーワードは、対になる駒(例:時間を止める駒と早める駒)をセットで用意する
6. 0ダメージ枠は全体の1割程度に絞り、意図的にレアな尖った駒として扱う
7. **味方を上向きに戻す効果は、落ちきった駒だけを対象にする**。落下中の駒を戻すと、その駒が
   落ちきるのを自分で遅らせることになり、起こす側の得にならないため
8. **スキルの強さは落下ダメージで釣り合わせる**。スキルを使う手番はその駒を起こし直せないため、
   落下ダメージが高い駒ほどスキルを撃ちにくい。強いスキルには低い落下ダメージを与える。
   コストルールを追加せずに済むのがこの設計の要点であり、スキルごとに個別の制限を付けない
9. **新しい駒は原則としてスキル持ちとして設計する**。スキルを持たないのは、強さの基準となる
   バニラ駒だけとする
10. **受動効果は一部の駒だけに持たせる**。全ての駒が受動効果を持つと、駒の違いが読み取りにくく
   なり、スキルという主軸もぼやける。受動は「その駒の正体」を決める1つだけに絞り、
   持たない駒を多数派に保つ(現行10種のうち受動を持つのは4種)

## 9. UI設計メモ

- 画面レイアウトは横長(16:9目安、デスクトップブラウザでのunityroomプレイを主眼)とする。基準解像度は1280x720とし、アスペクト比を維持したまま拡縮する
- **対局画面を除く全ての画面は、共通のレイアウト規約に従う**。画面の外周余白は24px、画面上部に高さ88pxの共通ヘッダーを置き、その下に24pxの余白を取ってコンテンツ領域を始める(コンテンツの開始位置は全画面でy=136に揃う)。ヘッダーの構成は**左=戻るボタン / 中央=画面タイトル / 右=その画面の主アクション(0〜2個)**で固定する。画面ごとにヘッダーの高さ・位置・余白を個別に決めることはしない。これは、画面ごとに絶対座標で個別にヘッダーを組んだ結果、戻るボタンの位置もコンテンツの開始位置も画面ごとにばらついていた状態を解消するための規約である
- **一覧を表示する画面では、1画面に収まる件数を優先して横2列のグリッドを基本とする**。縦1列にすると1画面に2〜3件しか入らず、目的の項目を探すのにスクロールを強いるため。件数が少ないうちに縦へ間延びしないよう、一覧のカード自体も横長・低背にする
- 状態(上向き/落下中/落ちきり)は、砂時計のイラストそのもの(3パターンの静止画差し替え)で直感的に表現する
- **行動を選んだ瞬間は盤面を動かさず、対象の駒に予約マーク(反転/スキルを示すアイコン)を表示する**。実際に駒が動くのはターン終了時の解決演出の中であり、「行動を設定して手番を終える」というルール(4.3)と画面の見え方を一致させる
- **次の解決で落ちきる駒を、脈動するリングで予告する**。自分の駒(相手にダメージを与える)と相手の駒(自分がダメージを受ける)は色で描き分ける。予告は**その手番に設定された行動を織り込んで判定する**(反転を設定したマスは上向きに戻ってから進行するため落ちきらず、予告を出さない)。行動が進行を止めなくなった(2章)ことで、予告と実際に起きることが常に一致する
- **ターン終了時の解決は、盤面へのカメラのズームで1マスずつ見せる**。自分の場の3マスを左から順にズームして解決内容(砂の進行/反転/スキル)を見せ、**砂が落ちきっていて何も起きないマスも同様にズームして「何も起きなかったこと」を見せる**。相手の駒に反転を設定していた場合は、自分の3マスを終えた後に相手のマスへズームして反転させる。その都度どの駒が進み・どんな効果が発動し・誰が何点のダメージを受けたのかを見せる。この解決演出の間は持ち時間を消費しない(演出待ちで時間が減るのは理不尽なため)。演出中は盤面を操作できない
- **ズームするのは盤面領域のみとし、上下のHP・砂時計スロットのバーはズームの影響を受けず固定する**。画面全体を拡大すると自分と相手のHPが画面外へ出てしまい、ダメージの発生を見失うため
- **プレイヤーの行動(反転/スキル)も、ターン終了時の砂の進行と同様に「何が起きたか」を見せる**。行動が確定した瞬間、対象の駒にスポットライトを当て、その駒の近くへ「先手が後手の『ソード』を反転」といった実況テキストをフロート表示する。文言は対局ログと同一のものを使う。相手(オンライン対戦の相手・CPU)の行動も同じ経路で表示し、自分が待っている間に何をされたのかが分かるようにする
- **行動の演出と、その後のターン終了時の解決演出の間には短い間を置く**。両者が続けて起きると1つの出来事に見え、「相手が指した手」と「その結果として砂が進んだこと」を区別できないため。行動の演出中も、砂の進行の解決演出と同様に持ち時間を消費せず、盤面を操作できない
- **スキルは反転と見た目で区別できるようにする**。行動を選ぶボタンには**スキルごとに異なる紋章**を出し(交代=控えの台、位置交換=交換の矢印、加速=下向きの二重シェブロン、目覚め=光の閃光)、反転の砂時計の紋章と並べても取り違えないようにする。予約マークにも「スキル」ではなく**そのスキルの名前**を出す
- **スキルの発動は「その駒自身が沈み込んでから真上へ弾ける」動きで見せる**。反転が「相手へ手を伸ばして持ち上げる」動きなのに対し、スキルは自分の駒から効果が放たれることを示す。足元へ衝撃波を2回(放つ瞬間と着地)出し、放つ瞬間に駒を発光させる。盤面の別のマスへ届くスキル(位置交換・目覚め)は、**発動元の駒から対象の駒へ反転と同じ光の筋を伸ばす**
- **そのマスで発動しても何も起きないスキルは、行動として選べないようにする**(右隣が無いマスでの位置交換など)。押せてしまうと手番を無駄にするため、ボタン自体を出さない
- **位置交換・交代のスキルは、駒が瞬間的に入れ替わるのではなく動いて見えるようにする**。位置交換は入れ替わる2つの駒が互いの元の位置から滑り込む動き、交代は控えのスロットからその駒のマスへ入ってくる動きで表現する
- **反転は、誰がその駒に手を出したのかが分かる演出にする**。反転を行った側の陣地から対象の駒へ向かって光の筋が伸び、それが届いた瞬間に駒が持ち上がって回転し着地する。相手の駒を反転させた場合、盤面を挟んで手を伸ばしたように見える。位置交換・交代のスキルには駒が動く表現があるのに対し、反転は駒がその場で回るだけで「自分がやったのか相手にやられたのか」を実況テキスト以外から読み取れなかったため追加した。**反転はゲームの中心となる行動であるため、演出は他より作り込む**。光の筋が届いた瞬間の着弾の衝撃、回転中のガラスと砂の反射、着地時の余韻までを含めた一連の流れとして見せる
- **対局中に何が起きたかのログを確認できるようにする**。各手番で誰がどのアクション(反転/スキル)を行ったか、ターン終了時の砂の進行で何が起きたかを記録して表示する
- **対局ログには決着そのものも1手として記録する**(「先手の勝利(後手のHPが0)」「先手の勝利(後手の投了)」など)。ログだけを追っても、何が起きて勝負が決したのかが分かる状態にする
- **画面下部中央には「ログ」「投了」と並べて「ターン終了」ボタンを置く**。自分の手番中に押すと、行動を設定していなければパス(3マスとも進行)、設定済みならそのまま解決へ進む
- **対局中の「ログ」「投了」の導線は、画面下部中央にまとめる**。以前は画面左上に縦に並べていたが、そこは相手の砂時計スロットの表示領域と重なって駒が隠れてしまうため。画面下部中央は、リプレイ再生の操作ボタン・配置フェーズの「対局開始」ボタンと排他で使う領域であり、対局中は常に空いている
- ロック等の状態異常は、専用アイコンをオーバーレイして表示する
- HPは常時バー表示する。**相手のHPは画面上部、自分のHPは画面下部**に配置し、盤面を挟んで対面させる。ダメージ発生時はフローティング数字で演出する。発生源の駒が特定できる場合(砂時計が落ちきったことによるダメージ)は、その駒の位置からHPバーへ向けて数字を飛ばし、原因の駒自体も一瞬光らせることで、1手の中で複数のダメージがほぼ同時に発生した場合でも何が原因か個別に追えるようにする。発生源が特定できない場合はHPバー付近から浮かせるだけに留める
- **HPバーの色は残量に応じて変える**(十分なうちは琥珀系、危険域まで減ったら赤)。赤は「危険」を意味する色として残量表現に使い、相手と自分の区別には使わない。どちらのHPかは配置(上部=相手/下部=自分)と名前ラベルで示す
- 盤面に左・中央・右の位置を示す常時表示のラベルは置かない(位置ボーナス廃止に伴い、常時表示するほどの情報ではないと判断した)
- 盤面上の各駒には、その駒の**落下ダメージを数値バッジ**として表示する。駒の足元には状態が分かる台座を敷き、選択中の駒は枠を強調する
- **盤面では「場」の3マスと「控え」の2マスを視覚的に区切る**。控えは場より控えめな表示(小さめ・彩度低め)とし、交代スキルでしか場に出せない待機状態であることが見た目から分かるようにする。**控えの駒は直接クリックしても行動を選べない**(交代スキルを選んだ直後の対象選択としてのみ押せる)
- **手番は、右上のテキストだけでなく手番側の盤面の列を強調して示す**。オンライン対戦・CPU戦のように自視点が固定される対局では、自分の手番でない間は「相手の手を待っています」と明示する
- **対局中も、駒をクリックすればその駒の効果詳細を確認できる**。効果を覚えていないと戦えない状態を避けるため、いつでも参照できるようにする(以前は「対局中は効果説明を出さずスピード感を優先する」方針だったが、初見プレイヤーが効果を追えないため変更した)。この確認方法は**配置フェーズでも同一の操作(駒をクリック)に統一する**。配置フェーズ専用の効果一覧テキスト表示は置かない。自分の手札だけでなく、配置フェーズ中に公開されている相手の5枚についても同様にクリックで詳細を確認できる
- 操作は「砂時計を選択→**選択した駒の直下**にアクションを横並び表示→選択」の2ステップで統一する。アクションメニューは画面下部固定ではなく、選択した駒の近くにポップアップさせ、どの駒を操作しているのかを視線移動なしで分かるようにする
- クリックできる要素(駒・カード・各種リストのカード等)は共通の挙動を持つ。ホバーするとわずかに明るく浮き上がりカーソルが指マークに変わり、押し込むとわずかに縮み、**要素の上で離した時のみ**操作が確定する(外へ出して離すとキャンセル)。操作できない状態(相手の手番待ち・観戦・リプレイ再生中など)ではホバー表現・カーソル変更を行わない
- **交代スキルを選んだ直後は、対象になれる控えの2マスを選択中の枠とは別の色で点滅ハイライトし**、次に何を押せばよいか示す。対局中に自分の手番でない状態(オンライン対戦・CPU戦で相手を待っている間)で駒を押した場合は、その駒がわずかに左右へ揺れて操作を拒否したことを示す(観戦・リプレイ再生中は対象外)
- **対局が終了したら、盤面の上に結果パネルを重ねて表示する**。パネルには勝敗・両者の最終HP・その対局の総手数・決着の要因(3章)と、「ログ」「ホームへ」の2つのボタンを置き、背景を暗くして盤面の操作を受け付けなくする。これは対局モード(ローカル/オンライン/CPU戦)と観戦モードで共通とする
- **対局が終了した後もログを確認できるようにする**。結果パネルの「ログ」ボタンから、対局中と同じログを開く。ログは結果パネルより手前に重ね、閉じると結果パネルへ戻る。終局後は結果パネルが盤面全体の操作を塞ぐため、対局中の導線(画面下部中央のログボタン)からは開けないことを補う
- ただし**リプレイ再生モードでは結果パネルを出さない**。再生中は自由に手を前後できることが目的であり、最後の手まで進めるたびにパネルで操作を塞ぐと再生の妨げになるため。リプレイからは既存の戻るボタンで一覧へ戻る
- 起点として**ホーム画面**を用意し、機能を切り替えられる構成とする(大手DCG/ソシャゲに近いUI構成)。タブ切り替えは画面下部の2ボタン(アイコン+ラベル)方式とし、「デッキ」「バトル」の2つを用意する。選択中のタブのボタンは他方より大きく表示し、現在地を視覚的に強調する。将来のタブ追加を見据え、拡張しやすい構造にする
- 画面遷移はハードカットではなく短い**クロスフェード**(0.2秒未満)でつなぐ。ランダムマッチ・ルーム作成・観戦確認など通信待ちの間は、ステータス文言の末尾に巡回するドット(「.」→「..」→「...」)を添えて、処理が生きていることを示す
- **デッキタブ**:左側に大きな「デッキ編集」ボタン、右側に縦2列で「砂時計一覧」「ショップ」ボタン(アイコン+ラベル)を配置する。**ショップは今回はアイコン配置のみとし、タップ時は「近日公開」等の未実装案内を表示する。経済要素(通貨・購入対象)は未設計のため実装しない**
- **バトルタブ**:「ランダムマッチ」「ルームマッチ」「CPU戦」ボタンを大きく配置する(既存のランダムマッチ/ルームコード導線を大型ボタン化)。**これらのボタンを押すと、マッチングキューへの参加・ルーム作成・CPU戦の開始より先に、使用するデッキを保存済みデッキから選ぶ画面を挟む**。デッキタブでの「使用中」指定は初期選択値として引き継がれるが、対局のたびにここで選び直せる。デッキを1つも保存していない場合はボタンを押せず、先にデッキタブでの作成を促す
- **砂時計一覧画面**:現在定義されている**全種類**の砂時計を表示する。**保有していないものも含めて全種類を表示する**(将来追加予定のショップ・収集要素と連動させる設計の布石)。なお現状は「保有/未保有」を区別する仕組み自体が存在しないため、当面は全砂時計を通常表示とし、未保有の視覚的な区別表現は収集要素の実装時に改めて設計する。一覧から選択すると詳細パネル(イラスト・名前・落下ダメージ・追加効果)を表示する。この詳細パネルは共通コンポーネント化し、デッキ編集画面や将来的な対局中の参考表示にも流用する
- **配置フェーズでは、各マスに置いた駒がどの状態から始まるのかを表示する**。配置先の3マスには、そのマスの初期状態(上向き/落下中/落ちきり)の砂時計イラストと状態名を示し、駒を置いた後もその状態のイラストで表示する。どこに置くかが初期状態の選択そのものであるため(5章)、対局が始まってから気づくことのないようにする
- **配置フェーズは専用画面を設けず、対局画面の中で行う**。対局画面のスロット(下記)に自分の5個が並んでおり、そこから場の3マスへ配置して確定すると、そのまま対局が始まる。相手の5枚・先手/後手も同じ画面で確認できる。配置内容は対局開始まで相手に非公開とする
- **対局画面ではHPバーの横に5個分のスロットを設け、そこに自分の砂時計5個を置く**。配置フェーズではここから盤面へ配置し、対局中は控えの置き場も兼ねる。相手側も同様に5個が見える。これにより盤面から控えエリアを撤去し、盤面を広く使う
- **対局画面のレイアウトは盤面を挟んだ点対称**とする。上段(相手)は左に砂時計スロット・右にHPバー、下段(自分)は左にHPバー・右に砂時計スロットを置く
- **デッキ編集画面の空き枠は「ここにドラッグ」といった、ドラッグ操作を誘導する文言・見た目にする**。ドラッグ元となる下部の砂時計カードは、ホバー時に掴めるカーソル(ドラッグ用カーソル)へ変わり、ドラッグ操作が可能であることを示す。同じ`HourglassCard`が使われる他画面(砂時計一覧・デッキ選択の手札)ではドラッグできないため、通常のクリック用カーソルのままとする
- **デッキ管理**:プレイヤーは複数のデッキを保存・管理できる(名前付け可能。デッキ名は表示上の都合により10文字程度までを目安に制限する。保存数の上限は設けない)。デッキ一覧画面では保存済みデッキを横長カード(デッキ名+5砂時計アイコン)の一覧として**横2列のグリッド**で表示し(件数が増えたら縦スクロール)、各カードに「編集」「削除」ボタンを持つ(「使用中」を示すバッジ表示は行わない。使用するデッキは対局直前のデッキ選択画面で毎回選び直すため、一覧側での常時表示は不要と判断した)。デッキの並び順の入れ替えは、カード個別のボタンではなく、画面右上「新規デッキ作成」ボタンの隣に置く「デッキ入れ替え」ボタンから専用の並び替えモードに入って行う。画面左上に戻るボタンを配置する。バトル開始前のデッキ選択画面(9章のバトルタブ参照)も、このデッキ一覧画面と同じ見た目のカード一覧を流用する(ただし編集・削除ボタンは表示せず、カードをタップして選択するのみ)。デッキ編集画面は、編集の主要部(左)と詳細パネル(右)の2カラムとする。左には上からデッキ名の入力欄・編成の進捗(n/5枚)、編成中の5枠、全砂時計の一覧を縦に積む。**編成中の5枠は横一列に並べる**(2段へ折り返すと「デッキ5枚の並び」として読めなくなるため)。右には詳細パネル(上記共通コンポーネント)を縦長のまま常設する。砂時計は下の一覧から上の枠へドラッグ&ドロップして配置し、クリックすると詳細パネルに内容を表示する。**全砂時計の一覧は常に1行の横スクロールとする**。砂時計は毎日アプデで増え続けるため、枚数によって行数が変わるグリッドにすると、あるとき突然最終行が中途半端に切れる。1行に固定すれば枚数に関わらずレイアウトが変わらない。続きがあることは横スクロールバーで示す。この一覧だけは詳細パネルの下も使い、画面幅いっぱいに置いて一度に見える枚数を稼ぐ。保存ボタン・戻るボタンは共通ヘッダーに置く
- **効果音を鳴らす**。対象は「反転」「スキル(位置交換系)」「スキル(交代)」「被弾」「決着」「ボタン押下」の6種とする。音源は**CC0(パブリックドメイン)ライセンスの外部フリー素材**を用いる。以前は完全無料運用を維持するため、プロジェクト内で手続き的に生成した短いWAVを使っていたが、用途に対して音質が不十分だったため方針転換した。**採用する素材はCC0に限る**。クレジット表記の義務なくunityroomへ公開でき、公開後にライセンス表記を管理し続けるコストを負わずに済むため(CC BY等、帰属表示が必要なライセンスは採用しない)。効果音はすべてユーザー操作か盤面の変化を起点に鳴るため、ブラウザの自動再生制限には抵触しない
- **BGMを鳴らす**。ホーム画面系(ホーム・デッキ・一覧・リプレイ等)と対局画面の2曲をループ再生し、画面が切り替わったらクロスフェードで繋ぐ。曲は**パブリックドメインのクラシック音楽(ピアノソロ)**とする。砂時計の「時の流れ・時計仕掛け」というモチーフに合い、コード描画で作った真鍮・琥珀・石のアンティークな質感とも揃うため。オーケストラ曲(交響曲・協奏曲)は強弱の幅が大きく、BGMとして一定音量で流すのに向かないため採らない。クラシックは楽曲として完結しておりシームレスにループしないため、曲の終わりでフェードアウトし、短い間を置いて頭から再生する「アルバム再生」方式で繰り返す
- **対局の結果画面ではBGMを止め、短い勝利/敗北ジングルを鳴らす**。結果パネルは数秒から数十秒しか表示されず、数分あるクラシックの曲を割り当てても冒頭しか聞かれないため。ジングルも効果音と同じくCC0素材とし、弦楽器のピチカートなど、BGMのピアノと調和する音色を選ぶ
- **BGMはブラウザの自動再生制限を受ける**。効果音と違いユーザー操作を起点に鳴るとは限らないため、**最初のクリック/タップを検知してから再生を開始する**
- **音量は「効果音」「BGM」の2系統を独立して調整できるようにする**。ホーム画面に小さな設定ボタンを置き、押すと設定パネル(モーダル)が開いてスライダー2本(いずれも0〜100%、0で実質ミュート)を操作できる。BGMだけ切って効果音は残す、という遊び方ができるようにするため1本にまとめない。設定は `user://` へ永続化して次回起動時も引き継ぐ。ブラウザで遊ぶ以上、音をすぐ止められることは必須要件として扱う
- 全画面について、大手ソシャゲ/DCGのUIを参考に作り込む。開発初期の仮配置(単純な絶対座標配置など)から、実際に配布・公開して恥ずかしくない見た目へ強化する
- **UIの外枠・装飾(ボタン、パネル枠、入力欄、棚板、名札など、いわゆるUIクローム)は、AI生成画像ではなくコード描画で作る**。品質管理のしやすさを理由に、画像生成による運用から方針転換した。コード描画は無地の図形を並べるだけでは平坦でチープに見えるため、多段階のグラデーション・面取り・内側の落ち込み影・手続き的なノイズ(グレイン)・金属の照り返しといった質感表現を伴わせることを前提とする。色とパーツの描画は共通のライブラリへ集約し、画面ごとに個別実装しない
- ただし**砂時計そのもののイラストと画面の背景イラストは引き続き画像アセットとして扱う**。これらはUIの枠組みではなく作品の絵そのものであり、コード描画で置き換える対象ではない(生成手順は従来どおり `docs/AssetPromptTemplate.md` に従い、生成自体はユーザーが手動で行う)

## 10. 技術設計方針(毎日アプデ運用のための骨格)

- 砂時計は `Resource`(.tres)としてデータ駆動で管理し、コード変更なしで新規追加できる形にする
- 効果は「トリガー×ターゲット×エフェクト」の組み合わせで表現し、エフェクトの種類ごとにハンドラを用意する
- 既存のエフェクト種別の組み合わせだけで新しい砂時計を作れる状態を維持し、「新効果そのものの追加」と「既存効果の組み合わせによる新駒追加」を分けて運用する
- オンライン対戦はターン制の特性を活かし、非同期(手番ごとにサーバーへ送信→相手に反映)の通信方式を基本とする

## 11. オンライン対戦

- マッチング方式は**2種類**を用意する
  1. **ランダムマッチ**:待合室(マッチングキュー)に入り、他の待機プレイヤーと自動的に対戦成立させる。複数人が同時にキューへ入っても、二重マッチや取りこぼしが起きないようにする
  2. **ルームコード対戦**:片方がルームを作成しコードを発行、もう片方がコードを入力して参加する(友達対戦向け)
- 対局中の通信は、指した手(反転/スキル)を送信→相手が受信して反映する非同期方式とする
- サーバー側での正当性検証は行わず、クライアントの操作をそのまま信頼する(不正対策は将来検討)
- 持ち時間切れの扱いは4.1節の通り(切断・放置時の敗北条件を兼ねる)

---

## 12. リプレイ・観戦

- 対局終了後、その対局の手順(棋譜)をリプレイとして保存する。**オンライン対戦・CPU戦の両方が対象**とする
- リプレイを閲覧できるのは、その対局を実際にプレイした本人(CPU戦の場合は自分)のみとする
- 保存件数は、オンライン対戦・CPU戦それぞれ直近30件とし、それを超えたら古いものから自動的に削除する
- リプレイは1手ずつコマ送りで再生できる形式とする
- パスは棋譜に1手(`pass`)として記録され、リプレイでも1手として数える
- **リプレイ一覧画面**:`バトルタブ`に「リプレイ」ボタンを追加し、そこから遷移する。オンライン対戦・CPU戦を問わず、保存済みリプレイを横長カードの一覧として新しい順に縦スクロール表示する(両者は保存先が異なるため、一覧表示の時点でマージして日時順に並べる)。各カードには対局日時・勝敗・先手/後手・対戦種別(オンライン/CPU戦)に加えて、**自分と相手両方の初期デッキ5枚のアイコン**を表示する。対局履歴が無い場合は「まだ対局履歴がありません」等の案内を表示する。カードをタップすると再生画面へ遷移する
- **リプレイ再生画面**:`MatchScreen`の盤面・HUD表示をそのまま流用し、対局中の駒クリック操作を無効化した「再生モード」として動作させる。画面下部の操作エリアには反転/スキルボタンの代わりに、先頭へ/1手戻る/再生・一時停止/1手進む/最後へ、の5つの再生コントロールと「n / 全手数」の手数表示を配置する。「再生」中は一定間隔(0.8秒/手を目安)で自動的にコマを進める
- **観戦機能**:進行中の対局を第三者がリアルタイムで見られる機能。**ルームコード対戦限定**とし、ランダムマッチには観戦導線を用意しない(共有できるコードが存在しないため)。`バトルタブ`のルームコード入力欄に「観戦する」ボタンを追加し、対局中の2人が使ったものと同じコードを入力すると観戦できる。観戦中は盤面・HPが対局の進行に合わせてリアルタイムに更新されるが、一切操作はできない。対局が終了した場合は通常の勝敗演出をそのまま表示する

---

## 13. CPU戦

- オンライン通信を必要としない、CPU(コンピューター)を相手にしたローカル対局。`バトルタブ`に「CPU戦」ボタンを追加する。他のバトル導線と同様、ボタンを押すと先に使用デッキを選ぶ画面を挟んでから開始する
- CPUのデッキは、現在定義されている全砂時計からランダムに5種類選出する(CPU専用のデッキは用意しない)。場に出す3個・控え2個への振り分けは、マスの初期状態(左=上向き、中央=落下中、右=落ちきり)と駒特性を考慮したCPU配置ロジックによって決定する
- 先手/後手は常に**プレイヤーが先手**に固定する
- 配置フェーズは対局画面上で行い(9章参照)、CPUの5枚(公開情報)を確認しながら自分の配置を決める。対局開始と同時にCPUの配置も公開される
- CPUの思考ロジックは、局面評価と合法手探索を行うロジック(`SmartCpuStrategy`)を標準とする。合法手(反転・移動・交代・パス)の中から盤面とHP状況を評価して有利な手を選択し、CPUの手番では思考している間合いとして0.6秒程度の間を置いてから着手する。なお、合法手からランダムに選ぶ簡易ロジック(`RandomCpuStrategy`)も検証・テスト用として保持する
- 4.1節の持ち時間は、**オンライン対戦の切断・放置対策を目的とした仕組み**であり、CPU戦はローカル対局でその懸念が存在しないため、持ち時間の消費・時間切れ判定を行わない(プレイヤー・CPUともに考慮時間は無制限)
- CPU戦の対局終了後、その対局の棋譜は12章の通り**ローカルにリプレイとして保存する**(Firestoreへは書き込まない)。観戦はオンライン対戦のルームコード対戦限定のまま、CPU戦は対象外とする

## 未検証・今後の検討事項

### 砂時計の数値バランスについての方針

**個々の砂時計の数値調整は、いったんここで打ち切る。** 自己対戦による検証で、ルールの土台
(行動が進行を止めないこと・初期HP30・基本行動を反転に絞ったこと)は決着手数・膠着率・
メタの多様性のいずれも目標レンジへ入った。一方で駒ごとの勝率は、**今後スキル持ちの砂時計を
追加していけばメタ自体が変わる**ため、現時点の10種だけを見て詰めても作業が無駄になる。

したがって当面は、数値の微調整ではなく**スキル制になったゲームをより面白くすること**を優先する。
駒の数値は、新しい駒が一定数たまってメタの形が見えてきた時点で改めて測り直す。

- **決着手数を優先し、先手勝率は後回しにする**。両者は連動しており(自己対戦では25.0手で
  先手55.4%、32.7手で先手49.8%)、片方だけを見て調整すると取り違える。「5分程度で1戦」という
  コンセプトを満たすことを先に確定させ、先手有利の補正は必要になった時点で検討する
- 実際のプレイテストによる、決着までの手数・時間の確認(自己対戦では平均25.0手・中央値22手)
- 10種類以降、砂時計を追加していく際のバランス指針の継続的な更新
- デッキ構築時の「どのスキルを組み合わせるか」という戦略の深掘り
