# 10.8 ショップと所有・弾とパック(GameDesign.md 8章・21章)

| クラス | 責務 |
|---|---|
| `ShopCatalog`(`scripts/data/shop_catalog.gd`, static) | 品揃えと価格。**中身そのものは持たない**——アイコンは `UserProfileLibrary`、エモートは `EmoteLibrary` が持ち、ここは「初期解放に含まれないものが並ぶ」という規則と値段だけを持つ |
| `CardShopScreen`(`scripts/ui/card_shop_screen.gd`) | ショップ画面。共通の `ScreenHeader` を使い、右の主アクションへ残高を出す。左の品種タブ・中央のタイル・右の詳細を並べ、選択中の品と購入の流れを持つ |
| `ShopKindTab`(`scripts/ui/shop_kind_tab.gd`) | 左の品種タブ1つ(品種名 +「所持 n / m」) |
| `ShopItemTile`(`scripts/ui/shop_item_tile.gd`) | 中央のタイル1件。品種ごとの絵・名前・価格または「✓ 所持」。名前と価格を横に並べる幅が無い紋章のタイルは2行に積む。押すと選ぶだけで、買わない |
| `ShopDetailPane`(`scripts/ui/shop_detail_pane.gd`) | 右の詳細。見本・説明・価格と購入後の残高・「購入する」(パックは確率と天井までの残り・「収録カードを見る」も) |
| `EmoteSlotPage`(`scripts/ui/emote_slot_page.gd`) | 所有しているエモートから4つを選ぶ。アカウント画面の「エモート」タブの中身 |

**品揃えを表として別に持たない。**`ShopCatalog.items()` は
「全アイコン − 初期解放のアイコン」と「全エモート − 初期解放のエモート」を並べるだけにする。
表を別に持つと、アイコンを1つ足したときに**ショップへ並べ忘れた品**と
**初期解放でも購入品でもない、どこにも出ないid**が生まれる。

**所有と枠は `AccountService` が持つ**(`players/{uid}` の3フィールド)。
- `owned_icon_ids()` / `owned_emote_ids()` は**初期解放を必ず先頭に含めて返す**。
  呼ぶ側が「初期の8種 + 買った分」を自分で足す形にすると、足し忘れた画面で
  既定のアイコンすら選べなくなる
- `emote_slots()` は保存済みが空なら `EmoteLibrary.DEFAULT_EMOTE_IDS` を返す。
  **所有しなくなったidは起こり得ない**(買ったものは消えないため)が、
  プールから消えた場合に備えて所有していないidは落とす
- `purchase()` は `grant()` と同じ流儀で、`updateTime` を前提条件にした `commit()` で
  **残高の確認と減算と所有への追加を1回の書き込みで行う**。残高を読んでから別に書くと、
  2つのタブで同時に押したときに2つとも買えてしまう
- **未サインインでは買えない**。`AccountStore` へ退避して後から反映する形(`grant()` の
  経路)は使わない。**砂金の獲得は取りこぼすと失われるが、購入は取りこぼしても
  何も失われない**ため、退避する理由がない

**対局中に出すエモートは `AccountService.emote_slots()` から引く**
(`CardMatchEmote` が `EmoteLibrary.get_emote_ids()` を直に読まないようにする)。
**CPUの返答も同じ4つから選ぶ**——プレイヤーが持っていないエモートをCPUだけが喋ると、
どこで手に入るのか分からない品が対局中に現れることになる。

**購入の確認はダイアログではなく、タイルで選ぶ → 詳細の「購入する」の2段階で行う**(GameDesign.md 21章)。
タイルは `pressed` で選ぶだけにし、買う入口は `ShopDetailPane.buy_requested` の1本に絞る。
**詳細の見本は `AccountTablePreview` を使う**(アイコン・プレイマット・エモート)。アカウント画面と同じ部品にして、
「ショップで見た姿」と「設定した後の姿」が食い違わないようにする。エモートは `show_emote()` で名札の吹き出しを出す。
残高が足りない品のタイルも押せる(選んで見本を見られる)。暗くするのは `modulate`、ホバーの発光だけを止める。

**アカウント画面の一覧(アイコン・称号・マット)はタブごとに `ScrollContainer` へ入れる**(GameDesign.md 14章)。
タブの高さは決まっており、買って増えたぶんはスクロールで受ける。

## 10.8.1 弾とパック(GameDesign.md 8章・15章・21章)

**基本セット以後のカードは、`ShopCatalog` へ「パック」という4つ目の品種として乗せる。**
アイコン・エモート・プレイマットが「初期解放に含まれないものが並ぶ」という規則だけを
持つのに対し、パックは**対局の中身そのもの**を左右するため、既存の3種と同じ扱いにしない(GameDesign.md 21章)。
確率・天井・レートは**すべてResource(.tres)に置き、コードに書かない**。

| クラス/フィールド | 責務 |
|---|---|
| `CardData.rarity`(enum: コモン/レア/エピック/レジェンド) | カードのレアリティ。`.tres` のフィールドで持つ。基本セット70枚は対象外(常に2枚持つ) |
| `CardData.set_id`(String) | そのカードが属するテーマのid。空文字は基本セット |
| `CardSetLibrary`(`scripts/data/card_set_library.gd`, static) | **テーマ**の定義(id・表示名・狙いの一文・カードidの並び・予定枚数)。価格は持たない(価格は `PackDefinition`)。**どの `PackDefinition` にも含まれないテーマ(ソロモード限定・プレゼント)は、ガチャに入らない**。`UserProfileLibrary` / `ShopCatalog` と同じ流儀 |
| `PackDefinition`(`data/packs/*.tres`) | 弾1つぶん。id・名前・価格・1パックの枚数・各枠のレアリティ別確率・天井のパック数・含めるテーマ(`CardSetLibrary` のid)。確率と天井はここだけに置く |
| `RarityTable`(`data/rarity_table.tres`) | レアリティごとの「変わる砂粒」と「生成に要る砂粒」(GameDesign.md 15章) |

**実装の置き場所**: 所持数・上限の計算は `CardOwnership`(`scripts/logic/card_ownership.gd`。`players/{uid}` のフィールドを受ける純関数)、
抽選は `PackDraw`(`scripts/logic/pack_draw.gd`。乱数は呼び出し側から渡す純関数)、購入と生成の書き込みは `PackService`(`scripts/net/pack_service.gd`。
`open_packs()` は1回の `commit()` で残高・所持数・砂粒・天井(無料なら `free_pack_date`)を書く。`craft()` は砂粒の減算と所持数の加算)。
`AccountService` は `card_count(id)` / `deck_limit(card)` / `card_counts()` / `sand_dust()` / `pack_pity(pack_id)` / `free_pack_available()` の読み口を持つ。
図鑑のシルエット(`AlmanacEntry.locked`)と「収集 n / m」(`collected_card_counts()`)は所持数が0かで決める。デッキ編集の在庫の札(`WorkshopStockItem`)は `deck_limit` を分母に渡し、所持1枚の札は1枚入れた時点で暗くなり「1 / 1」を出す(所持0枚は錠前)。CPUデッキの表は `CardOwnership.cap()` を超えないことをテストで見張る。
天井は「レジェンドが出ないまま開けた数が `pity_packs - 1` のとき、その次のパックの最後の枠をレジェンドにする」(40パック目の5枚目)。公開済みのレジェンドが無い間は確定しない。
**保存デッキは枚数上限を超えても読み込みで落とさず**、`CardDeckSave.list_decks()` の各件の `within_limit` を false にして返す(落とすと、読み込み前や通信できない間に所持数が少なく見えて、次の保存で持ち主のデッキが消えるため)。
各件の `shortage` は上限を超えた枚数の合計(`CardDeckSave.shortage()`。`within_limit` は `shortage == 0`)。`CardDeckListScreen` はそれを `CardDeckCase.shortage` へ渡し、札は要約の行に錠前と「n枚不足」を描く。選ぶモードでは不足のある札を暗くし(`CardDeckCase.unavailable`)、押すと `ConfirmModal` で「編集する」を選ばせて `edit_requested` を出す(`deck_picked` は出さない。待たせていた導線は `Main._on_deck_edit_requested` が捨てる)。

**所有はカードごとの所持数で持つ。**`players/{uid}` に次を足す。

| フィールド | 型 | 内容 |
|---|---|---|
| `card_counts` | Dictionary(card_id → int) | 弾のカードの所持数。上限(通常2・レジェンド1)を超えた値は保存しない |
| `sand_dust` | int | 砂粒の残高 |
| `pack_pity` | Dictionary(pack_id → int) | その弾でレジェンドが出ないまま開けたパック数。レジェンドが出たら0に戻す |
| `free_pack_date` | String | 最後に無料パックを開けた日(日本時間、`DailyMissionService.today()`) |

- **既に買ったセットの移行は書き込みで行わず、読むときに導く。**`AccountService.card_count(id)` は
  「保存された所持数」と「そのカードのセットを `owned_card_sets` に持っていれば2」の大きいほうを返す。
  ソロモード限定・プレゼントのカード(どの `PackDefinition` にも含まれないカードセット。10.15節・10.22節)も同じ経路で2枚扱いになるので、それらの仕組みは変えない
- **`AccountService.unlock_card_set(uid, set_id)` は無料で所有させる経路の1本のまま**(ソロモード・プレゼント・はじめの7日の2日目)。
  セットをまるごと買う経路は無い
- **抽選は手元で行う**(サーバーで検証しない方針。GameDesign.md 11章に揃える)。パックの購入は既存の `purchase()` と同じ流儀で、
  `updateTime` を前提条件にした**1回の `commit()` で「砂金の減算・所持数の加算・上限超えの砂粒加算・天井カウンタの更新」を行う**。
  残高を読んでから別に書くと、2つのタブで同時に開けたときに二重に引ける。無料パックは砂金の減算の代わりに `free_pack_date` を更新する
- **生成も1回の `commit()`**(砂粒の減算と所持数の加算)。未公開のカードは生成できない
- **デッキの枚数の上限は `min(2(レジェンドは1), 所持数)`。**デッキ編集の検証と、保存デッキの読み込み時の検査の両方でこの関数を使う
- **CPU戦のデッキ生成・CPUデッキ(`CardCpuDecks`)は、弾のカードを所持状況に関わらず使う**(GameDesign.md 13章)。
  レジェンドの同名1枚は守る。パックに含まれないテーマ(ソロモード限定)のカードは入れない。
  それらが表に入っていないことは `tools/tests/cpu_deck_tests.gd` が確かめる
- **`CardLibrary` はプールを絞らない。**「デッキへ入れられるかどうか」の絞り込みは**呼び出し側**が `AccountService.card_count()` で行う。
  `CardLibrary` 自体にアカウントの状態を持ち込まない
- **デッキ編集(`CardDeckEditorScreen` / `CardDeckShelf`)は、所持0枚のカードをロック表示にし、所持数(1/2)を札に添える。**
  一覧の札(`WorkshopStockItem.locked`)は暗転に錠前を重ねる(30枚に達したときの暗転と区別するため)。
  押すと `ConfirmModal` で「ショップへ」を選ばせ、`shop_requested` を `Main` が受けて `CardShopScreen.open()` でパックのタブを開く。
  この経路で開いたショップの「戻る」はデッキ編集へ帰り(`Main._shop_from_editor`)、編成中のデッキを保ったまま `refresh_ownership()` で反映する
- **砂時計一覧(`AlmanacBook` 等)は、所持0枚をシルエット表示にする**(9章の「未収集はシルエットと『?』で示す」)

**買う前に中身を確認できる場所は、ショップ自身が持つ**(GameDesign.md 21章)。デッキ編集・
砂時計一覧が所持0枚のカードをロック/シルエットで隠す以上、**それ以外のどこかで確認できる
という前提を実装へ持ち込んではいけない**。

| クラス | 責務 |
|---|---|
| `ShopSetPreview`(`scripts/ui/shop_set_preview.gd`) | 弾1つの公開済みカードを見るモーダル。`CardPileViewer` と同じ「暗幕 + `content_panel.tres` の中央パネル + 閉じる」の型を使う |

- **中身は `CardDetailPanel` を横一列に並べて見せる。**`interactive = false` で使い、コスト・総量・
  キーワード・効果・能力の実演までそのまま出す——専用の簡易表示を新しく作らない
- **`ShopDetailPane` はパックを選んでいるときだけ「収録カードを見る」を出し、**`set_preview_requested(id)` で画面側が `ShopSetPreview.open_set()` を開く
- **このプレビューは所持数を一切見ない。**見せる/隠すの判断はデッキ編集・図鑑の側(収集要素の演出)が持ち、
  ショップのプレビューは「開けるかどうかを決めるための確認」という別の役目として並立させる

**ショップのパックと開封・生成のUI**(GameDesign.md 9章「レアリティ」・15章・21章)。

| クラス | 責務 |
|---|---|
| `ShopCatalog`(Kind.PACK) | `items()` は弾を `PACK` として並べ、テーマ(`CARD_SET`)は売らない。`pack_ids()`(公開済みのカードがある弾)・`pack_card_ids()`・`pack_of_set()`(錠前の札からパックへ引く)・`planned_cards()` |
| `ShopPackInfo`(`scripts/ui/shop_pack_info.gd`) | 詳細の確率の表と天井のバー。値は `PackDefinition` をそのまま読む |
| `PackVesselPaint`(`scripts/ui/pack_vessel_paint.gd`) | 封をした砂時計の姿。タイルの包み(`ShopItemArt.pack_cover()`)と開封が共有する |
| `RarityPaint`(`scripts/ui/styles/rarity_paint.gd`) | 菱形の宝石・縁の内線・レジェンドの金の縁と翼と光・カードの裏。`HandCardPaint`・`WorkshopStockItem`・`AlmanacEntry`・開封が呼ぶ |
| `PackOpeningOverlay`(`scripts/ui/pack_opening_overlay.gd`) | 開封の段取り。1280x720 の舞台で組んで画面に合わせて拡大する。抽選と保存は開く前に済んでおり、結果(`open_packs()` の `packs`)と開ける前の所持数・砂粒を受けて見せるだけ |
| `PackCardSlot` / `PackOpeningFx` | 札1枚(裏 → `CardView` の表と下の札)/ 時刻で決まる粒・輪・欠片・レジェンドの演出。`BACK` と `FRONT` の2枚で札を挟み、レジェンドの札だけ `BACK` の上へ移す |
| `CraftModal`(`scripts/ui/craft_modal.gd`) | 砂粒での生成。デッキ編集の所持0枚の札(「ショップのパックへ」も置く)と、図鑑の本の外の「生成する」から開く |

- 開封の「はじめて」「所持 n / 上限」は、開ける前の所持数を札の順に1枚ずつ数え進めて決める(`PackService` は上限超えかどうかだけを返す)
- パックのタブの「所持 n / m」は、弾のカードのうち1枚以上持っている種類の数 / 弾の予定枚数
- ショップのヘッダーは砂粒と砂金の2つの残高を出す(`CurrencyChip.dust`)

**段階公開(GameDesign.md 8章)は `CardSetLibrary` のテーマ定義へ `planned_count`(予定枚数)を足すだけで表す。**
`card_ids` は公開済みのカードだけを持ち、毎日のビルドで1枚ずつ末尾へ足す。

- `CardSetLibrary.planned_count(id)` は `planned_count` が無ければ `card_ids` の枚数を返す。
  `hidden_count(id)`(= 予定 − 公開済み)が0なら、未公開の枠は出ない
- パックの抽選は公開済みの `card_ids` だけを対象にし、レアリティごとの確率は変えずに、そのレアリティの公開済みカードで等分する
- 「?」の枠は `ShopItemArt` がタイル・詳細の両方に描き、`ShopSetPreview` は公開済みの
  `CardDetailPanel` の後ろへ同じ大きさの「?」の札を並べる

##  テーマ「静止の刻」の新しい語彙(GameDesign.md 6章・8章)

5つの語彙を持つ。**いずれも既存の enum・フィールドの末尾に足してあり、既存カードの挙動は変えない**
(11章「enum の並びは保存データ」)。

| 語彙 | 実装 | 場所 |
|---|---|---|
| **静止**(`Keyword.STILL`) | `NAMED` に入れて語として見せる。`CardInstance.tick()` が `has_keyword(STILL)` なら砂を落とさず0を返し、`MatchState.end_turn()` は**実際に落ちたときだけ** `unit_ticked` を出す(落ちていないのに砂が流れる演出を出さない) | `card_enums.gd` / `card_instance.gd` / `match_state.gd` |
| **砂が上へ戻る**(`EffectType.RAISE_SAND`) | `CardInstance.raise_sand(n)`:攻撃力-n / 体力+n。**攻撃力を下限0で止める**(戻せる量は攻撃力まで)。`drop_sand()` の逆向きだが、**負の値を `drop_sand()` へ渡す形にはしない**——砂の移動は名前で区別する既存方針(2.4節)のとおり。実際に動いた量を返す | `card_enums.gd` / `card_instance.gd` / `card_effect_resolver.gd` |
| **反転できない**(`CardData.cannot_flip`) | `cannot_attack` と同じフラグ。`CardInstance.flippable()` が返し、`can_flip()` と `MatchState._can_use_flip_right()` の**両方**がこれを見る(GameDesign.md 6章。反転権は回数・時期の制限だけを無視する)。効果による強制反転(`SWAP_STATS`)は止めない | `card_data.gd` / `card_instance.gd` / `match_state.gd` |
| **攻撃力が体力より多い**(`ConditionScope.ATTACK_OVER_HEALTH`) | `TARGET` と同じく対象の絞り込みとして働く。`condition_total` は使わない(-1のまま)。判定は `CardEffectResolver.eligible_target(unit, effect)`(static)に集約し、`_single_unit()` の絞り込みと CPU(`_strongest_enemy()`)が同じ物差しを使う | `card_enums.gd` / `card_effect_resolver.gd` / `card_cpu_strategy.gd` |
| **自分の攻撃力ぶんの本体ダメージ**(`EffectType.DAMAGE_PLAYER_BY_OWN_ATTACK`) | クロックタワーの落砂。`value` は使わず、発動した駒の `attack` を `damage_player()` へ渡す(落砂は砂が落ちる直前なので落ちる前の値)。攻撃力0なら何もしない。CPUは `_repeating_value()` で `lifetime_of(体力, 初期攻撃力)` 相当を本体打点として見積もる | `card_enums.gd` / `card_effect_resolver.gd` / `card_cpu_strategy.gd` |

- **静止は落砂(`ON_TURN_END`)の発火を止めない。**`end_turn()` は落砂 → `tick()` の順で
  進むため、`tick()` の中で砂を落とさないだけで済む(スプリングの落砂は毎ターン働く)
- **静止の駒を反転すると体力0で砕ける**(攻撃力0のため)。`flip()` の後の死亡判定は既存のまま
  通るため、新しい処理は要らない。反転権で相手の静止の壁を消す使い方はこの経路で成立する
- **`RAISE_SAND` の演出は `play_drop()` の逆向き**(下の部屋から上の部屋へ琥珀の砂が流れる)。
  `MatchState` は `unit_ticked` と別に `unit_raised(side, slot, amount)` を出し、
  `CardMatchEffectStrike.on_unit_raised()` が受けて `CardView.play_raise()` で描く(紋章が
  当たるまでは `_ticks` に `raise: true` で持ち越す)。**被ダメージの飛散・落砂の流れと同じく、
  別のシグナルにして相乗りさせない**(取り違えるとルールを誤解する。GameDesign.md 9章)。
  紋章の型は `DESCEND`(味方へ)/ `DRAIN`(相手へ。攻撃力を抜く払拭に近い)
- **`combat_preview()` は触らない。**砂を上へ戻す効果は戦闘の解決には乗らないため
- **対象選択のUIは条件を満たす駒だけを光らせ、押させる**(五砂の刻のキーも同じ)。
  判定は `CardMatchEffectTarget.can_target()`(static。`eligible_target()` を呼ぶ)に集約し、
  光らせる側(`CardMatchTargets`)と押す側(`CardMatchTouch`)が同じ物差しを使う。
  選べる駒が1体もいなければ対象選択へ入らずそのまま出す(効果は不発。GameDesign.md 6章)。
  解決側の `_single_unit()` は、対象の指定が無い・条件を満たさない場合に条件を満たす中で
  最も生涯ダメージの大きい1体へ向け直す(CPU・オンラインの相手の手もここを通る)
- CPU(`CardCpuStrategy`)は静止の駒を `lifetime_damage()` で評価する(壁としての価値を
  別に見積もる評価は足さない。コントロールの価値は貪欲法では測れず、コンボ系と同じく実測の
  対象外)。攻撃力0の駒は「反転すると損」として自然に反転候補から外れる。`RAISE_SAND` は
  味方なら寿命が伸びる増分(`_best_ally_raise()`)、相手なら抜ける攻撃力ぶんで評価する。
  反転権の候補からは `flippable()` でない駒を外す(選んでも `use_flip_right()` が拒む)
- テーマの登録は `CardSetLibrary` の `still_time` と、9枚の `.tres` の
  `set_id = "still_time"`(10.8.1節)。**購入導線・ロック表示・シルエットは
  五砂の刻で通っている経路をそのまま使う**。イラストはカードごとのシェーダー(10.19節)

##  テーマ「遺砂の刻」の新しい語彙(GameDesign.md 6章・8章)

5つの語彙を持つ。**いずれも既存の enum の末尾に足してあり、既存カードの挙動は変えない**。

| 語彙 | 実装 | 場所 |
|---|---|---|
| **味方の破壊への反応**(`Trigger.ON_ALLY_DEATH`) | `MatchState._destroy_unit()` が余砂の後、同じ側に残る駒へ発火する。**体力0で同時に砕けている駒は除く**(総量+1で息を吹き返さないため)。`trigger_name()` は「常在」を返す(語を作らない) | `card_enums.gd` / `match_state.gd` |
| **墓地を数える**(`EffectType.ADD_TOTAL_PER_GRAVE`) | 墓地の砂時計(トークンを含む・砂術を除く)の数 × value を体力へ足す | `card_effect_resolver.gd` |
| **墓地から手札へ**(`EffectType.RECOVER_FROM_GRAVE`) | 対象 `SELF` は余砂で砕けたそのカード自身(墓地の後ろから探す)。それ以外は hint の `grave_index` | 同上 |
| **墓地から場へ**(`EffectType.REVIVE_FROM_GRAVE`) | hint の `grave_index` を最初の空き枠へ新品の `CardInstance` として出す。`_summon()` と同じく設置効果は解決しない | 同上 |
| **払う駒がいないと撃てない砂術** | `CardEffectResolver.castable()`(static)を `MatchState.can_cast()` が呼ぶ。味方を破壊する砂術は味方が、蘇生は選べる砂時計と空き枠が要る | `card_effect_resolver.gd` / `match_state.gd` |

- **墓地の読み取りは `CardEffectResolver` の static に集約する**(`grave_choices()` / `grave_unit_count()` /
  `best_grave_choice()` / `grave_choice_effect()`)。`MatchState` は公開メソッド数がlintの上限にあるため置かない。
  解決・UI・CPUが同じ物差しを使う
- **選ぶ手は `{"grave_index": i}` として既存の target 辞書に載せる。**`MatchAction` の形は変えないため、
  オンライン・棋譜・再生はそのまま通る。指定が無い・選べない位置を指す場合は、選べる中で最もコストの高い1体
  (同じなら新しいほう)へ向け直す
- **味方を破壊する効果の既定の対象は、最も生涯ダメージの小さい1体**(`_single_unit()`)。払う駒として最も惜しくないもの
- UI:`CardMatchEffectTarget.choose_from_grave()` が、墓地から選ぶ効果のカードを出す/撃つときに
  `CardPileViewer.open_choice()` を開く。選べる砂時計だけを1枚ずつ並べ、押した位置で `MatchAction` を投げる。
  「やめる」・暗幕で閉じると何も出さずに戻る。選べるものが無ければ開かずにそのまま出す(効果は不発)
- CPU:払う駒は `_sacrifice_slot()`(生涯ダメージ最小)、その価値は失う生涯ダメージの負値。蘇生は
  `best_grave_choice()` の総量で、回収はドロー1枚と同じに見る。味方の破壊への反応は `ALLY_DEATH_TIMES` 回ぶん積む
- イラストはカードごとのシェーダー(10.19節)

##  テーマ「反響の刻」(GameDesign.md 8章・21章)

**新しい enum はリピートの `EffectType.RESET_FLIP`・レゾナンスの `Trigger.ON_ENEMY_FLIP`・アンコールの `EffectType.GAIN_FLIP_RIGHT`・クレッシェンドの `EffectType.DAMAGE_PLAYER_PLUS_FLIPS` だけ。**リバーブは既存の `ON_FLIP` × `ALLY_UNIT` × `SWAP_STATS` に、時の裁きと同じ
`ConditionScope.ATTACK_OVER_HEALTH` を載せたもの。対象は `CardEffectData.random_target` で、条件を満たす中から
対局の乱数(`MatchState._rng`。オンライン・リプレイと同じ種・同じ順)でランダムに選ぶ(`CardEffectResolver._random_unit()`)。前提として、効果による反転も `ON_FLIP` を解決するよう
反転の後始末を `MatchState._resolve_flipped()` へ集めた(3.1.2節)。

- ディレイはリバーブのトリガーを `ON_TURN_END` に替えたもの(同じ条件・同じランダム選択)
- リピートは `ON_PLAY` × `ALL_ALLY_UNITS` × `RESET_FLIP`。対象のうち `CardInstance.flipped_this_turn` が立っている駒の印を下ろす。
  印は手の反転(`MatchState.flip()`)だけが付けるため、効果・反転権で返った駒は対象にならない。設置なので1枚につき1回で止まる
- CPU:リピート(`RESET_FLIP` を持つカード)は攻撃と反転を済ませた後にだけ出す(`_choose_play(…, true)` を手番の最後に呼ぶ)。
  価値は反転済みで反転トリガーを持つ味方1体につき `FLIP_TRIGGER_BONUS`
- レゾナンスはリバーブのトリガーを `ON_ENEMY_FLIP` に替えたもの。`MatchState._resolve_flipped()` が持ち主側の `ON_FLIP` の後、
  反対側に残る駒へ発火する(通常の反転・反転権・効果のすべてが通る)。`trigger_name()` は「常在」を返す(語を作らない)。
  向かい合うレゾナンスが互いを返し合っても、返した駒が候補から外れるため止まる。CPUは `ENEMY_FLIP_TIMES` 回ぶん積む
- アンコールは `EffectType.GAIN_FLIP_RIGHT`(対象 `OWN_PLAYER`)。`MatchState.flip_right_remaining` へ直接足し、上限は持たない。
  反転権の札(`FlipRightGauge`)は初期の回数と残りの多い方だけ粒を描く。CPUは総量+1(`ADD_TOTAL`)と同じ値に見る
- 大合唱は `ON_PLAY` × `ALL_ALLY_UNITS` × `SWAP_STATS` に `ATTACK_OVER_HEALTH` を載せたもの。`CardEffectResolver._targets()` は全体対象でも
  `eligible_target()` で絞り、返す直前にもう一度条件を確かめる(先に返した駒の反転トリガーで返った駒を返し直さないため)。
  CPUは条件を満たす駒の寿命の伸びの合計に、反転トリガー持ち1体につき `FLIP_TRIGGER_BONUS` を足す
- クレッシェンドは `ON_PLAY` × `OPPONENT_PLAYER` × `DAMAGE_PLAYER_PLUS_FLIPS`。与えるのは `value` + `MatchState.flips_this_turn[side]`。
  数は `_resolve_flipped()` が持ち主の側へ足し(通常の反転・反転権・効果のすべてが通る)、`_begin_turn()` が両側とも0へ戻す。
  対局中の詳細(`CardMatchDetail`)は `CardEffectResolver.live_rules_text()` で札の「%dダメージ」をいまの値へ置き換えて渡す。
  CPUはリピートと同じく攻撃と反転を済ませた後にだけ撃つ(`_after_flips()`)
- `CardSetLibrary` の `echo_time` は `planned_count = 8`。公開した日に `card_ids` の末尾へ1枚足す
- 連鎖の停止は対象の条件だけで保証する(返した駒は攻撃力≦体力になり候補から外れる)。専用の印や深さの上限は持たない
- CPU:効果で相手の駒を返す砂術(揺さぶりの一手)は、反転権と同じく反転トリガー持ちを対象から外す(`_strongest_enemy()`)
- 検証は `tools/tests/echo_time_tests.gd`

##  テーマ「追砂の刻」(GameDesign.md 8章・21章)

新しい enum はスリングの `EffectTarget.ENEMY_UNIT_OR_PLAYER` と、ボーラの `ConditionScope.HEALTH_AT_MOST`、崩落の `ConditionScope.TOTAL_AT_LEAST`、マーチの `ConditionScope.ENEMY_OUTNUMBERS`。ニブルは `CardEffectData.lowest_health_target` を足した。ブロックは既存の守護と余砂のドローだけで組む。ヴォールトも既存の守護と、被弾の `ALLY_UNIT` × `ADD_TOTAL`(対象は自動で選ぶ。ウェルと同じ)だけで組む。ハイヴは既存の被弾 × `SUMMON`(モート)だけで組む。リリーフは `EffectType.HEAL_PLAYER_PER_ENEMY_UNIT`(`DAMAGE_PLAYER_PER_ENEMY_UNIT` の回復版)を足した。相手の場が空なら紋章を飛ばさず回復もしない。CPUは相手の駒の数 × `value` × `FACE_WEIGHT` で見積もる。

**`ENEMY_UNIT_OR_PLAYER`** は `DAMAGE_UNIT` と組み、本体は枠 -1 で表す(攻撃の `target_slot` と同じ)。

- 解決:`CardEffectResolver._targets()` は指定 `{"side": 相手, "slot": -1}` なら本体、駒の指定ならその駒、指定が無ければ
  `ENEMY_UNIT` と同じ自動選択で駒を選び、駒がいなければ本体を返す。`DAMAGE_UNIT` の分岐は枠 -1 の対象へ `damage_player()` を呼ぶ
- 対局画面:`CardMatchEffectTarget.can_target_face()` が真のカードは、駒がいなくても対象選択へ入り(`has_candidate()`)、
  `CardMatchTargets` が相手の情報帯(`foe_bar.targetable`)も光らせる。器を押すと `CardMatchTouch.on_face_pressed()` が枠 -1 で確定する
- CPU:`_unit_or_face_pick()` が、駒へ与えて減る生涯ダメージ(`_damage_value()`)と本体の値打ち(`value × FACE_WEIGHT`)の大きいほうを選ぶ。初級は本体と駒から等確率
- **`HEALTH_AT_MOST`** は `ATTACK_OVER_HEALTH` と同じく対象の絞り込みで、`condition_total` を体力の上限として読む。判定は `eligible_target()` に足すだけで、
  解決・対局画面の対象選択・CPU(`_strongest_enemy()`)が揃う。**`TOTAL_AT_LEAST`** も同じ経路で、`condition_total` を総量の下限として読む
- **`ENEMY_OUTNUMBERS`** は `SELF` / `ANY_ALLY` と同じく発動の可否を決める条件で、`CardEffectResolver._condition_met()` が相手の駒の数と、この駒を除いた自分の駒の数を比べる(`condition_total` は使わない)。CPUは手札から置く前の盤面で同じ比較を行い、満たさなければ見積もりを0にする。マーチのモート2体は `SUMMON` を2件並べる(砂王の呼び声と同じ)
- 発動条件(`SELF` / `ANY_ALLY` / `ENEMY_OUTNUMBERS`)は `CardEffectResolver.resolve()` がトリガーの発動時に全効果ぶんまとめて判定してから解決する。1件ずつ判定すると、マーチの1体目のモートで数が並び2体目が出なくなるため
- **`lowest_health_target`** は `random_target` と同じく、プレイヤーが選ばない対象の選び方。`CardEffectResolver.lowest_health_slot()`(static)が
  体力最少・同点なら左の枠を返し、`_single_unit()` とCPUの見積もり(`_on_play_value()` の `DAMAGE_UNIT`)が同じ関数を使う
- `CardSetLibrary` の `chase_sand` は `planned_count = 10`。公開した日に `card_ids` の末尾へ1枚足す
- 検証は `tools/tests/chase_sand_tests.gd`

##  テーマ「薙砂の刻」(GameDesign.md 8章・21章)

新しい enum はゲイルの `ConditionScope.ENEMY_COUNT_AT_LEAST` とハウンドの `Trigger.ON_ENEMY_DRAW`。
コロッサスは `CardData.cost_down_per_enemy_unit`、抜け道は `CardData.allies_ignore_guard` を足した。砂礫の雨は既存の `ENEMY_UNIT` × `DAMAGE_UNIT` × `random_target` を3件並べる。

- **`ENEMY_COUNT_AT_LEAST`** は `ENEMY_OUTNUMBERS` と同じく発動の可否を決める条件で、`_condition_met()` が相手の駒の数を `condition_total` と比べる。CPUも置く前の盤面で同じ比較をする
- **`random_target` は手札・CPUから届いた対象の指定より優先する**(`_single_unit()`)。指定を受けると砂礫の雨の3回が同じ駒へ向かうため。
  `_random_unit()` は体力0の駒を候補から外す(砕けるのは砂術の解決の後のため、同じ砂術の次の1回が当たらないように)。
  対局画面の `CardMatchEffectTarget.targeting_effect()` は `random_target` / `lowest_health_target` の効果を対象選択に数えない
- **`allies_ignore_guard`** は `CardInstance.ignores_guard()`(効果を消されていない間だけ真)で読む。`MatchState.ignores_guard(side)` が
  場にその駒がいるかを返し、`attackable_slots()` と `can_attack_player()` は攻撃する側が真なら守護を数えない。
  CPUは守護の駒が相手にいて、自分に攻撃できる駒がいるときだけ価値を持たせる。札の分類は「常在」、実演は守護の後ろの駒を殴る段(`CardEffectPlan.Kind.BYPASS`)
- **`ON_ENEMY_DRAW`** は `MatchState.draw()` が引けた1枚ごとに、引いた側の相手の駒へ発火する。手番の始めの1枚は `_begin_turn()` が
  `draw(side, 1, false)` で呼んで外す。マリガンは `draw()` を通らない。札の分類は「常在」(`CardEnums.trigger_name()`)
- **コストは `MatchState.play_cost(side, card)` で読む**(`card.cost - cost_down_per_enemy_unit × 相手の駒の数`。砂術はさらにセージの分を引く。下限 `MIN_COST`)。
  出せるかの判定・支払い・CPU・手札の宝石(`CardView.play_cost`)・マナの点滅がこれを使う。棚・図鑑・詳細は `card.cost` のまま
- 行数の上限のため、戦闘の予測は `MatchCombatPreview`、CPUの反転権は `CardCpuFlipRight` へ切り出した
- `CardSetLibrary` の `sweep_sand` は段階公開しない
- 検証は `tools/tests/sweep_sand_tests.gd`

##  テーマ「詠砂の刻」(GameDesign.md 8章・21章)

新しい enum はスクライブの `Trigger.ON_OWN_SPELL`、砂占いの `EffectType.TUTOR_SPELL`、アーカイブの `EffectType.RECOVER_SPELL_FROM_GRAVE`、写し詠みの `EffectType.RECAST_SPELL`、グリモアの `EffectType.DAMAGE_PLAYER_PER_GRAVE_SPELL`(`CardEffectResolver.grave_spell_count()` で墓地の砂術を数える)。

- **`ON_OWN_SPELL`** は `MatchState.cast_spell()` が砂術の効果を解決して `_cleanup_dead()` した後、`_fire_own_spell(side)` で
  撃った側の場にいる駒へ発火する(撃った砂術で砕けた駒は反応しない)。札の分類は「常在」(`CardEnums.trigger_name()`)
- CPUは `_repeating_value()` で `OWN_SPELL_TIMES` 回ぶん積む
- **`TUTOR_SPELL`** は `CardEffectResolver._tutor_spell()` が山札の砂術から対局の乱数で選んで手札へ移す。`MatchState.draw()` を通さない
  (相手のドローに反応する効果へ数えないため)。手札が飛んで入る演出のため `cards_drawn` だけは出す。CPUは山札に砂術があればドロー1枚と同じに見る
- 実演は `CardEffectPlan.Kind.OWN_SPELL`。手札の先頭へ対象を取らない砂術(`SPELL_ID` = サンドショット)を足して撃つ
- `CardSetLibrary` の `chant_sand` は `planned_count = 8`。公開した日に `card_ids` の末尾へ1枚足す
- アーカイブの **`EffectType.RECOVER_SPELL_FROM_GRAVE`** は `RECOVER_FROM_GRAVE` と同じ道を通る。違いは選べるものだけで、
  `CardEffectResolver.grave_choices(state, side, spells)` の `spells` を `picks_spell(effect)` から渡す。墓地の一覧の見出しは「墓地の砂術を1枚選ぶ」。
  実演の墓地には `SPELL_ID` の砂術を1枚積む
- ウォーデンは既存の `ON_OWN_SPELL` × `RAISE_SAND`(SELF)の組み合わせで、新しい enum は無い。実演では砂が戻る様子が見えるよう、
  自分の砂を上へ戻す効果を持つ駒を `CardEffectPlan.FALLEN_FOR_RAISE` 粒落とした状態で置く
- 写し詠みの **`EffectType.RECAST_SPELL`** は、`CardEffectResolver.recast_source()`(墓地を後ろから見て、撃ち直す効果を持たない最初の砂術)を
  `CardInstance.new()` して ON_PLAY を同じ hint で `resolve()` する。`MatchState.cast_spell()` を通さないため墓地は動かず、`_fire_own_spell()` も
  写し詠みの1回だけ。`castable()` は撃ち直す砂術の `castable()` を見る
- 対象の選び方は **`CardEffectResolver.acting_card()`**(写し詠みなら撃ち直す砂術、それ以外は札自身)の効果で決める。これを通すのは
  `CardMatchSpellDrag`・`CardMatchSpell.release()`・`SpellForecast.compute()`・`CardCpuSpellSearch.best_cast()`・`CardCpuStrategy` の
  `_spell_cast()` / `_spell_value()` / `_effect_target()`・`CardCpuBeginner`。札の表示とコストは写し詠み自身のまま。
  対局中の文は `live_rules_text()` が `RECAST_NOTE` を添える
- セージは **`CardData.ally_spell_cost_down`** を足した。`CardInstance.spell_cost_down()`(効果を消されると0)を
  `MatchState.play_cost()` が自分の場の駒について足し、砂術のコストから引く(下限 `MIN_COST`)。CPUは手札の砂術の下がる分を
  `_spell_discount_value()` で見る。実演は `CardEffectPlan.Kind.SPELL_DISCOUNT`(下がった後のコストちょうどのマナで `DISCOUNT_SPELL_ID` を撃つ)
- 検証は `tools/tests/chant_sand_tests.gd`

##  テーマ「背水の刻」(GameDesign.md 8章。第2弾)

新しい enum は `ConditionScope.OWN_HP_BELOW_FOE` / `OWN_HP_AT_MOST`、`EffectTarget.DAMAGING_FOE`(パリィ)、
`EffectType.HEAL_PLAYER_HALF_HP_GAP`(リブラ)/ `DAMAGE_RANDOM_UNITS_BY_HP_GAP`(ラストアワー)。
`CardData` へ `cost_down_low_hp` + `cost_down_hp_threshold`(バスティオン)と `still_while_outnumbered`(ホールド)を足した。
背水の陣・レイジ・エンバー・ウィックは既存の効果へ条件を付けるだけで組む。
`CardSetLibrary` の `back_water` は `price = 0`・段階公開なしで、パックとショップには第2弾のパックができるまで並べない。

- **HPの条件**は `ENEMY_OUTNUMBERS` と同じく発動の可否を決める条件で、`CardEffectResolver._condition_met()` が
  `CardBackWaterEffects.hp_condition_met()`(static)へ渡す。`OWN_HP_AT_MOST` は `condition_total`(12)を読み、コードに12を書かない。
  CPU(`_on_play_value()` の入口)と対局画面の対象選択(`CardMatchEffectTarget.has_candidate()`。エンバーはHPが高いと対象を選ばせず出す)が同じ関数を使う
- **`CardBackWaterEffects`**(`scripts/logic/`)はリブラ・ラストアワーの解決と見積もりを持つ。`CardEffectResolver` / `CardCpuStrategy` が1000行の上限に近いため、
  `CardLegendEffects` と同じ作りで切り出した。差は `hp_gap()`(相手のHP - 自分のHP)で、リブラは `(差 + 1) / 2` を `heal_player()` へ、
  ラストアワーは差の回数だけ、砕けていない相手の駒から `MatchState._rng` でランダムに1体選んで `damage_unit()` を1点ずつ当てる(駒がいなくなったら残りは捨てる)
- **`DAMAGING_FOE`**:`MatchState._resolve_unit_combat()` が `_resolve_damaged()` の hint へ `{"damager": 殴ってきた駒}` を載せる。
  `CardEffectResolver._damaging_foe()` がその駒を返し、砕けている・盤面にいなければ空。効果によるダメージ(`damage_unit()`)は hint を運ばないため不発
- **コスト**:`MatchState.play_cost()` が `hp[side] <= cost_down_hp_threshold` のとき `cost_down_low_hp` を引く(コロッサスと同じ経路。手札の緑の数字・CPU・マナの点滅が揃う)
- **ホールドの静止**:相手の駒数 > 自分の駒数(自分を含む)を `MatchState._refresh_held_keywords()` が `CardInstance.held_still` へ書く。
  盤面を変える処理はどれも `_cleanup_dead()` を通るため、そこと `end_turn()` の落砂の前で呼ぶ。`CardInstance.has_keyword()` / `keywords()` が
  `held_still` を静止として返すので、落砂・予測・札の名前の下の語が同じ道で揃う。効果を消されると静止しない。`copy()` は `held_still` も写す
- 実演(`CardEffectPlan`):`OWN_HP_AT_MOST` は実演の自分のHPを `condition_total` にし、`OWN_HP_BELOW_FOE` は基本の盤面(自分14・相手18)で満たす
- 絵・紋章は別の回で足す。それまで `hourglass_art_tests.gd` の `ART_PENDING_SETS` が絵の検証を外す
- 検証は `tools/tests/back_water_tests.gd`

##  テーマ「烈砂の刻」(GameDesign.md 8章。第2弾)

新しい enum は `Trigger.ON_ATTACK`(スパーク)/ `ON_OWN_HP_LOST`(イグニス)、`EffectTarget.OTHER_ALLY_UNITS`(フレア)、
`EffectType.PLAY_RANDOM_FROM_HAND`(スタンピード)。`CardData` へ `quick_while_foe_hp_at_most`(チェイサー。-1 は無し)を足した。
HPを払う札(トーチ・フレア・スタンピード)は既存の `DAMAGE_PLAYER`(対象 `OWN_PLAYER`)で表し、追い風・鬨の声・ブレイズは既存の `GRANT_KEYWORD` / `DROP_SAND` の組み合わせ。
`CardSetLibrary` の `blaze_sand` は `back_water` と同じく `price = 0` で、第2弾のパックができるまで並べない。

- **疾走の判定**:`CardInstance.is_fresh()`(出したターンで、疾走を持たない)が `can_attack()` / `can_flip()` / 出したばかりの沈み表示を決める。
  疾走は `has_keyword(QUICK)` で見るため、あとから与えた疾走(追い風・フレア・スタンピード)と条件を満たしている間の疾走(チェイサー)が、
  最初から持つ疾走(`play_card()` が `summoned_this_turn` を落とす)と同じ道で効く。**与えたターンに殴れるのはこのため**
- **チェイサーの疾走**:`MatchState._refresh_held_keywords()`(ホールドの `_refresh_held_keywords()` を広げたもの)が `CardInstance.held_quick` へ書く。
  盤面が変わる `_cleanup_dead()`・`end_turn()` に加え、**HPが変わる `damage_player()` / `heal_player()` からも呼ぶ**(相手のHPで決まるため)。
  しきい値は `quick_while_foe_hp_at_most`(12)で、コードに書かない。`keywords()` が疾走を返すので札の名前の下の語も揃う。`copy()` は `held_quick` も写す
- **攻撃したとき**:`MatchState.attack()` が戦闘を解決し `_cleanup_dead()` した後に `_fire_attacked()` を呼ぶ。攻撃した駒が盤面にいて砕けていなければ `ON_ATTACK` を発火する
  (相手プレイヤーへの攻撃も同じ。連撃なら1回ごと)
- **HPを失ったとき**:`MatchState.damage_player()` が、HPが0にならなかった減少のたびに `_fire_hp_lost()` で自分側の駒の `ON_OWN_HP_LOST` を発火する。
  戦闘・効果・疲労・払う代償のどれも `damage_player()` を通るため、1回の減少ごとに1回になる。決着した後は働かない
- **`CardBlazeSandEffects`**(`scripts/logic/`)はスタンピードの解決と、CPUの見積もり(スタンピード・疾走を与える効果)を持つ。`CardEffectResolver` が1000行の上限に近いため、
  `CardBackWaterEffects` と同じ作りで切り出した。手札から出せる砂時計(砂術とトークンを除き、札のコストが `condition_total`(2)以下)を `MatchState._rng` でランダムに選び、
  `value`(2)体まで空き枠へ置く。`keyword` を与えてから設置効果を解決し、空き枠か出せる砂時計が尽きたら止める。置く駒は `unit_played` を出さない(復活・召喚と同じ)
- **`OTHER_ALLY_UNITS`**:効果を持つ駒以外の自分の駒すべて(フレア)。`_targets()` が左の枠から並べ、紋章は全体の効果として同時に飛ばす
- CPU:`DAMAGE_PLAYER` の対象が自分なら損として見て、払うと負けるHPなら大きく減点して出さない。`ON_ATTACK` / `ON_OWN_HP_LOST` は `_repeating_value()` が回数の見込みで足す
- 実演(`CardEffectPlan`):`ON_ATTACK` は殴る段、`ON_OWN_HP_LOST` は新しい `Kind.HP_LOST`(相手の駒に本体を殴らせる)、`quick_while_foe_hp_at_most` は相手のHPをしきい値にして出して殴る
- 絵・紋章は別の回で足す。それまで `hourglass_art_tests.gd` の `ART_PENDING_SETS` が絵の検証を外す
- 検証は `tools/tests/blaze_sand_tests.gd`

##  テーマ「早鐘の刻」(GameDesign.md 8章。第2弾)

新しい enum は `EffectType.GAIN_MAX_MANA`(ベル)/ `RAISE_MAX_MANA_TO_CAP`(ドーン)/ `GAIN_MANA`(早回し・前借り)/ `DELAY_MANA`(ボイラー・前借り・サンライズ)、
`ConditionScope.MAX_MANA_FULL`(アラーム)。`CardData` へ `cost_down_full_mana`(カリヨン。0は無し)を足した。
ゴングは既存の `DROP_SAND` を `ALL_ALLY_UNITS` と `ALL_ENEMY_UNITS` に1件ずつ持たせて表す(新しい対象は足さない)。
`CardSetLibrary` の `early_bell` は `price = 0` で、第2弾のパックができるまで並べない。

- **次の手番のマナの減り**:`MatchState.mana_debt`(Side → int)。`_begin_turn()` が回復の後に `max(最大マナ − mana_debt, 0)` で始め、`mana_debt` を0へ戻す。重なれば足す。
  状態は `MatchState` の変数なので、対局の写し(`SpellForecast.fork()`)とオンライン・リプレイ(同じ手を同じ順に流して再現する)にそのまま乗る
- **`CardEarlyBellEffects`**(`scripts/logic/`)がマナを動かす4つの効果の解決・条件(`mana_condition_met()`)・CPUの見積もりを持つ。`CardEffectResolver` が1000行の上限に近いため、
  `CardBlazeSandEffects` と同じ作りで切り出した。最大マナと今のマナは `MatchState.MAX_MANA`(7)で頭打ち、ドーンは上がったぶん × `value`(2)を `damage_player()` で払う
- **カリヨン**:`MatchState.play_cost()` が `cost_down_full_mana` を見る(バスティオンの `cost_down_low_hp` と同じ経路)。条件は最大マナが `MAX_MANA` に届いていること
- **「次 −n」**:`PlayerInfoBar` が `mana_debt` を `show_state()` で受け、マナの溝の右上へ小さな札として描く(0なら出さない)
- CPU:ベルは最大マナの空きぶん、ドーンは上がるぶんの値打ちからHPの代償を引き(払えば負けるなら大きく減点)、前借り・早回しは**増えたマナで新しく出せる手札の砂時計があるときだけ**その札の生涯ダメージを数える。
  次の手番のマナを削る効果は自分なら損、相手なら得として見る。砂術は盤面の差に現れないぶんを `CardCpuSpellSearch.best_cast()` が `spell_bonus()` で足す
- 絵・紋章は別の回で足す。それまで `hourglass_art_tests.gd` の `ART_PENDING_SETS` が絵の検証を外す
- 検証は `tools/tests/early_bell_tests.gd`
