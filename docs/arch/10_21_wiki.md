# 10.21 攻略サイト(GameDesign.md 32章)

ゲームとは別の静的サイト。Cloudflare Pages の別プロジェクト `sunadokei-arena-wiki` に置く
(URL は `https://sunadokei-arena-wiki.pages.dev/`)。pck の置き場(4.6節)と同じ理由で無料・上限なしのため。

| 置き場所 | 中身 |
|---|---|
| `wiki/` | サイトのソース(HTML・CSS・JS)。フレームワークもビルド工程も持たない。`.gdignore` でGodotから外す |
| `tools/build_wiki.py` | `wiki/` を `build/wiki/` へ写し、`functions/data/cards.json` と `functions/data/card_art/*.png`(WebPへ変換)を足す |
| `tools/deploy_wiki.sh` | `build_wiki.py` を回して `npx wrangler pages deploy` する。カードを足したビルドのたびに回す |
| `functions/wiki_stats.js` | 公開用の集計を作る。`index.js` の定期実行 `publishWikiStats` から呼ぶ |
| `wiki/functions/` | Cloudflare Pages Functions(共有リンクの入口)。`build/wiki/` の中から deploy するため、そのまま Pages Functions になる |
| `functions/deck_share.js` | デッキコードの中身(JSON)とデッキ表の画像(PNG)を返す。`index.js` の `deckShare` から呼ぶ |
| `functions/deck_sheet_canvas.js` | デッキ表の画像を描く。共有リンクの埋め込みと Discord `/deck` が同じものを使う |

## 公開用の集計(`public_stats`)

**ログインしていない読み手は Firestore のルール(サインイン必須)を通れない。**訪問者ごとに匿名サインインすると
使われないアカウントが溜まるため、集計だけを誰でも読めるコレクションへ書き出す。

- `publishWikiStats` が**毎日5:00(JST)**に `match_records` を全件読み直して集計し、`public_stats/` へ書く。
  増分にしないのは、記録の `finished_at` が端末の時計で前後しうるため(全件読み直せば取りこぼしが起きない)。
  件数が数万件に近づいたら増分へ切り替える
- `public_stats/wiki_index`: `updated_at` と、版の一覧 `builds`(`{build, version, games}` を新しい順)
- `public_stats/wiki_all`(全期間)と `public_stats/wiki_b{build}`(版ごと)は同じ形:
  `kinds.{ranked|room}` の下に `games`・`decided`(引き分けを除いた局数)・`first_wins`・`turns`(合計)・
  `end.{hp|surrender|timeout|draw}`・`cards.{id}.{g,w}`
- カードの数え方は `MatchRecordService._count_deck()` と同じ(両者のデッキを1回ずつ、同じカードの重複は1回)。
  引き分けは勝ちに数えない(記録の `winner` は引き分けでも `"b"` になるため `end_reason` で見分ける)
- 記録の種別キーはランクマッチが `"random"`(10.9節)のため、`ranked` へ読み替える
- ルール: `public_stats/{doc}` は `allow read: if true; allow write: if false;`(書くのは Admin SDK だけ)

サイトは Firestore の REST(`documents/public_stats/...`)を認証なしで読み、型付きの値(`mapValue` 等)を
`wiki/js/firestore.js` で素の値へ戻す。Firebase の JS SDK はこの段階では読み込まない。

## 共有リンク(GameDesign.md 32章)

**埋め込みのプレビューを出すクローラーはJSを動かさない**ため、静的なページだけでは
リンクごとに違う `og:image` を出せない。Cloudflare Pages Functions でリンクの入口だけを動的にする。

| パス | 返すもの |
|---|---|
| `/d/{code}` | `index.html` に `<base href="/">` と OGP の meta(`og:title` = デッキ名、`og:image` = `/d/{code}.png`)を `HTMLRewriter` で差し込んだもの。人が開けば `app.js` が `location.pathname` を見てデッキのページを出す |
| `/d/{code}.png` | `deckShare` の PNG を中継し、Cloudflare のキャッシュ(`caches.default`)へ1年残す。デッキコードの中身は変わらないため |
| `/d/{code}.json` | `deckShare` の JSON(`{code, name, cards}`、`cards` は `CardDeckCode.to_text()` の形)。デッキのページが読む |

- **`deckcodes` を読むのは Cloud Functions(Admin SDK)だけ。**`deckcodes` のルールはサインイン必須のままにし、
  公開するのは `deckShare` が返す中身だけにする(番号を総当たりで抜かれても、出るのは公開を前提に預けたデッキだけ)
- `deckShare` の URL は `https://us-central1-hourglasspvp.cloudfunctions.net/deckShare?code=…&format=json|png`
- 画像の絵は `deckShare` が攻略サイトの `art/{id}_thumb.webp` を取りに行って描く(`card_art` は
  Cloud Functions へデプロイしない。firebase.json の `ignore`)
- デッキ名は `DeckCodeService.publish()` が `deckcodes/{code}.name` へ預ける。名前の無い古いコードは「デッキ」

## ログインと「ゲームに追加」(GameDesign.md 32章)

- **ログインはゲームと同じ Firebase Authentication を REST で叩く**(`wiki/js/auth.js`)。IDは
  `FirebaseAuth._to_email()` と同じく小文字にして `@hourglass-arena.local` を付ける。API キーは
  `build_wiki.py` が `data/firebase_config.tres` から `data/config.json` へ書き出す(ゲームが pck で配っている公開の値)
- ブラウザに残すのは uid・ID・IDトークン・更新トークンだけ(`localStorage` の `wiki_session`)。パスワードは残さない
- 「ゲームに追加」は `players/{uid}/deck_inbox/` へ `{name, cards, sent_at}` を1件作る。`cards` はデッキコードの
  中身と同じ形。置く前に件数を読み、10件以上なら置かない
- ゲームは `DeckInboxService.receive()` で受け取る。呼ぶのは `AccountSyncService.sync_after_sign_in()` の
  引き終えた直後と、デッキ一覧(`CardDeckListScreen`)を開いたとき。**1件ずつ先に消してから足す**
  (消せないまま足すと、次に受け取ったとき二重になるため)。30枚でないものは消すだけ
- ルール: `players/{uid}/deck_inbox/{entry}` は本人だけが read・create・delete できる
