# 10.21 攻略サイト(GameDesign.md 32章)

ゲームとは別の静的サイト。Cloudflare Pages の別プロジェクト `sunadokei-arena-wiki` に置く
(URL は `https://sunadokei-arena-wiki.pages.dev/`)。pck の置き場(4.6節)と同じ理由で無料・上限なしのため。

| 置き場所 | 中身 |
|---|---|
| `wiki/` | サイトのソース(HTML・CSS・JS)。フレームワークもビルド工程も持たない。`.gdignore` でGodotから外す |
| `tools/build_wiki.py` | `wiki/` を `build/wiki/` へ写し、`functions/data/cards.json` と `functions/data/card_art/*.png`(WebPへ変換)を足す |
| `tools/deploy_wiki.sh` | `build_wiki.py` を回して `npx wrangler pages deploy` する。カードを足したビルドのたびに回す |
| `functions/wiki_stats.js` | 公開用の集計を作る。`index.js` の定期実行 `publishWikiStats` から呼ぶ |
| `wiki/functions/` | Cloudflare Pages Functions(共有リンクの入口)。`build/wiki/` の中から deploy するため、そのまま Pages Functions になる |
| `functions/deck_share.js` | デッキコードの中身(JSON)とデッキ表の画像(PNG)を返す。`index.js` の `deckShare` から呼ぶ |
| `functions/deck_sheet_canvas.js` | デッキ表の画像を描く。共有リンクの埋め込みと Discord `/deck` が同じものを使う |
| `functions/replay_share.js` | リプレイの共有の発行・取り消し(`wikiReplayShare`)と、共有リプレイの中身・画像(`replayShare`) |
| `functions/replay_card_canvas.js` | 共有リプレイの埋め込みの画像を描く。地と色は `deck_sheet_canvas.js` のものを使う |
| `wiki/js/replay.js` | リプレイのページ(自分の対局 `#replay/{match_id}` と共有リンク `/r/{id}`) |
| `scripts/net/replay_launch.gd` | ゲーム側の入口。`?replay` で起動されたら記録を読み、タイトルを飛ばして再生画面へ入る |

## 公開用の集計(`public_stats`)

**ログインしていない読み手は Firestore のルール(サインイン必須)を通れない。**訪問者ごとに匿名サインインすると
使われないアカウントが溜まるため、集計だけを誰でも読めるコレクションへ書き出す。

- `publishWikiStats` が**毎日5:00(JST)**に `match_records` を全件読み直して集計し、`public_stats/` へ書く。
  増分にしないのは、記録の `finished_at` が端末の時計で前後しうるため(全件読み直せば取りこぼしが起きない)。
  件数が数万件に近づいたら増分へ切り替える
- `public_stats/wiki_index`: `updated_at` と、版の一覧 `builds`(`{build, version, games}` を新しい順)
- `public_stats/wiki_all`(全期間)と `public_stats/wiki_b{build}`(版ごと)は同じ形:
  `kinds.{ranked|room}` の下に `games`・`decided`(引き分けを除いた局数)・`first_wins`・`turns`(合計)・
  `end.{hp|surrender|timeout|draw}`・`cards.{id}.{g,w}`
- カードの数え方は `MatchRecordService._count_deck()` と同じ(両者のデッキを1回ずつ、同じカードの重複は1回)。
  引き分けは勝ちに数えない(記録の `winner` は引き分けでも `"b"` になるため `end_reason` で見分ける)
- 記録の種別キーはランクマッチが `"random"`(10.9節)のため、`ranked` へ読み替える
- ルール: `public_stats/{doc}` は `allow read: if true; allow write: if false;`(書くのは Admin SDK だけ)
- `public_stats/wiki_ranking`: `{updated_at, season, rows}`。`publishWikiStats` が同じ時刻に書く(`functions/wiki_ranking.js`)。
  ゲーム内と同じく `players` を `rank_season == 今月のキー(JST)` で絞り `rank_progress_score` 降順に30件
  (複合インデックスはゲームと同じもの)。`rows` の1行は `{name, icon, title, tier, stars, rating}`。
  名前の無い人は「(名無し)」、`rating` の無い人は1000(`CardRankScreen._row_from_fields()` と同じ既定)。uid は書かない
- 段位名(`RankRules.display_name()`)と★の数(`BRACKET_STAR_REQUIREMENT`)はサイトの `wiki/js/ranking.js` が持ち、
  称号の表示名は `build_wiki.py` が `UserProfileLibrary.TITLES` から `data/profile.json` へ書き出す

サイトは Firestore の REST(`documents/public_stats/...`)を認証なしで読み、型付きの値(`mapValue` 等)を
`wiki/js/firestore.js` で素の値へ戻す。Firebase の JS SDK はこの段階では読み込まない。

## 共有リンク(GameDesign.md 32章)

**埋め込みのプレビューを出すクローラーはJSを動かさない**ため、静的なページだけでは
リンクごとに違う `og:image` を出せない。Cloudflare Pages Functions でリンクの入口だけを動的にする。

| パス | 返すもの |
|---|---|
| `/d/{code}` | `index.html` に `<base href="/">` と OGP の meta(`og:title` = デッキ名、`og:image` = `/d/{code}.png`)を `HTMLRewriter` で差し込んだもの。人が開けば `app.js` が `location.pathname` を見てデッキのページを出す |
| `/d/{code}.png` | `deckShare` の PNG を中継し、Cloudflare のキャッシュ(`caches.default`)へ1年残す。デッキコードの中身は変わらないため |
| `/d/{code}.json` | `deckShare` の JSON(`{code, name, cards}`、`cards` は `CardDeckCode.to_text()` の形)。デッキのページが読む |
| `/r/{id}` | `/d/{code}` と同じく `index.html` に OGP を差し込む(`og:title` = 「{共有した人}の対局({勝敗}・{n}手)」、`og:image` = `/r/{id}.png`) |
| `/r/{id}.json` | `replayShare` の JSON。**キャッシュしない**(取り消したらすぐ「見つかりませんでした」にするため) |
| `/r/{id}.png` | 先に JSON で共有が生きているかを確かめてから、`replayShare` の PNG をキャッシュから返す |

- **`deckcodes` を読むのは Cloud Functions(Admin SDK)だけ。**`deckcodes` のルールはサインイン必須のままにし、
  公開するのは `deckShare` が返す中身だけにする(番号を総当たりで抜かれても、出るのは公開を前提に預けたデッキだけ)
- `deckShare` の URL は `https://us-central1-hourglasspvp.cloudfunctions.net/deckShare?code=…&format=json|png`
- 画像の絵は `deckShare` が攻略サイトの `art/{id}_thumb.webp` を取りに行って描く(`card_art` は
  Cloud Functions へデプロイしない。firebase.json の `ignore`)
- デッキ名は `DeckCodeService.publish()` が `deckcodes/{code}.name` へ預ける。名前の無い古いコードは「デッキ」

## ログインと「ゲームに追加」(GameDesign.md 32章)

- **ログインはゲームと同じ Firebase Authentication を REST で叩く**(`wiki/js/auth.js`)。IDは
  `FirebaseAuth._to_email()` と同じく小文字にして `@hourglass-arena.local` を付ける。API キーは
  `build_wiki.py` が `data/firebase_config.tres` から `data/config.json` へ書き出す(ゲームが pck で配っている公開の値)
- ブラウザに残すのは uid・ID・IDトークン・更新トークンだけ(`localStorage` の `wiki_session`)。パスワードは残さない
- 「ゲームに追加」は `players/{uid}/deck_inbox/` へ `{name, cards, sent_at}` を1件作る。`cards` はデッキコードの
  中身と同じ形。置く前に件数を読み、10件以上なら置かない
- ゲームは `DeckInboxService.receive()` で受け取る。呼ぶのは `AccountSyncService.sync_after_sign_in()` の
  引き終えた直後と、デッキ一覧(`CardDeckListScreen`)を開いたとき。**1件ずつ先に消してから足す**
  (消せないまま足すと、次に受け取ったとき二重になるため)。30枚でないものは消すだけ
- ルール: `players/{uid}/deck_inbox/{entry}` は本人だけが read・create・delete できる(Discordのデッキ紹介はFunctionsが管理者権限で置く。10.14節)

## デッキのページのコストの棒グラフ(GameDesign.md 32章)

- `wiki/js/deck.js` が `parseDeckText()` の結果から数えて描く。DOMの棒(`div` の高さを%で)で描き、canvasは使わない
- コストの上限の1本(8+)は `deck.js` の定数で持つ

## デッキを紹介する(GameDesign.md 32章・26章)

- ページは `wiki/js/introduce.js`(`#introduce`)。自分のデッキは `players/{uid}.decks` を REST で読む
- 送信は Cloud Functions `wikiDeckIntro`(onRequest)へ `Authorization: Bearer {IDトークン}` と `{index, comment}` を POST する。
  Functions が `verifyIdToken()` でuidを確かめ、`discord_links` を `uid` の等価フィルタで引いて紹介者のDiscordユーザーidを得る
- 投稿の本体は Discord から紹介したときと同じ関数(`discord_deck_intro.js` の紹介の中身を、interaction に依らない
  `{discordUserId, uid, deck, comment}` を受け取る形へ切り出す)を使う。流れる投稿を2か所に持たないため
- 1分に1回の制限は `deck_intro_cooldowns/{uid}`(`{last_at}`)で数える。Functions だけが読み書きする

## マイページ(GameDesign.md 32章)

- ページは `wiki/js/mypage.js`(`#mypage`)、数え方は DOM を持たない `wiki/js/mypage_stats.js`
- 自分の対局は `match_records` を `player_a == uid` と `player_b == uid` の2本の runQuery で読む(等価フィルタ1つだけのため複合インデックスは要らない)。
  `select` で手順(`actions`)などの重いフィールドを外す。並べ替えはサイトで行う
- 記録の `a` は先手。引き分けは `end_reason == "draw"` で見分ける(`winner` は引き分けでも `"b"` のため)
- 相手の表示名は `players` を `documents:batchGet`(`mask` に `display_name` だけ)でまとめて引く。無ければ「ゲスト」(ゲームの既定と同じ)
- 自分のデッキ別は30枚の中身(並びを無視)で束ね、今の `players/{uid}.decks` に同じ中身があればその名前、無ければコストの高いカード3枚の名前で呼ぶ
- 相手のカード別は、相手のデッキの同じカードの重複を1回として数える(みんなの統計と同じ)
- 期間ごとの推移は日本時間の月で区切る(ランクマッチのシーズンと同じ単位)
- CPU戦は `players/{uid}.stats_kinds` の `"3"`(`CurrencyRules.MatchKind.CPU`)の通算だけを出す

## リプレイの再生(GameDesign.md 32章・12章)

**Cloudflare Pages は1ファイル25MiBまでで wasm が載らないため、ゲームはアプリ版の起動部(GitHub Pages。4.6節)を iframe で開く。**

1. サイトが iframe を `{アプリ版}/?replay=1&build={記録の build}` で開く。開く前に `builds.json`(4.6節)にその版が無ければ
   「この版の対局は再生できません」を出して開かない
2. 起動部は `builds.json` からその版の pck を選び、親へ `{type: "hourglass-replay-ready"}` を送る
3. サイトは送り元(アプリ版のオリジンと、自分の iframe であること)を確かめて `{type: "hourglass-replay", record}` を返す。
   起動部は送り元のホストが攻略サイト(`*.sunadokei-arena-wiki.pages.dev` と手元の localhost)のときだけ受け取り、
   `window.hourglassReplay` へ JSON の文字列で置いてからエンジンを起動する
4. ゲームは `ReplayLaunch.requested()` を見て、`Boot` が読み込みを終えたらタイトルを押されるのを待たずに
   `Main.start_launch_replay()` → `CardMatchScreen.start_replay()` へ入る。通過数(22章)は数えず、戻るボタンを出さない
   (戻る先が無いため)。サインインもしない(記録はサイトが渡すため)

- 渡す記録の形: `{deck_a, deck_b, seed, actions, view: "a"|"b", players: {a|b: {name, icon, title}}}`。
  `view` の側を手前に置く(`my_side`)。JSON の数は小数で届くため、`ReplayLaunch` が整数の値を整数へ戻す
- 自分の対局はサイトがログインしたまま `match_records/{id}` を読んで作る(記録の `player_a`/`player_b` が自分でなければ「見つかりませんでした」)。
  名前・アイコン・称号は `players` を `batchGet` で引く
- デスクトップでは `-- --replay=記録.json` で同じ形の記録を読んで再生する(確かめるため)

## リプレイの共有(GameDesign.md 32章)

- `replay_shares/{id}` = `{match_id, uid, created_at}`。ルールは読み書きとも不可(Functions の Admin SDK だけが触る。一覧で ID を抜かれないため)
- `wikiReplayShare` は IDトークンで本人を確かめ、`match_records/{match_id}` の対局者であるときだけ
  `status`(今の共有ID)・`share`(無ければ作る)・`revoke`(消す)を行う。共有の引き当ては `match_id` と `uid` の等価フィルタ2つ
- ID は英数字10文字を `crypto.randomBytes` から作り、`create()`(既にあれば失敗)で置く。失敗したら引き直す
- `replayShare` は共有した人の今の名前・アイコン・称号を `players/{uid}` から引き、相手を「対戦相手」・既定のアイコン(`sand`)・既定の称号に置き換えて返す。
  対局者の uid は返さない
- 埋め込みの画像のアイコンは `build_wiki.py` が `UserProfileLibrary.ICONS` の絵を `icons/{id}.webp` へ書き出したものを読む
