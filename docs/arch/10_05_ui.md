# 10.5 UI

- `AccountScreen`(`scenes/account_screen.tscn`)。`.tscn` は背景と `ScreenHeader` だけを持ち、
  2枚のパネルはコードで組む(GameDesign.md 14章「アカウント画面のレイアウト」)。

| クラス | 責務 |
|---|---|
| `AccountScreen`(`scripts/ui/account_screen.gd`) | 左カラム(見本・表示名・状態・ボタン)と、保存・登録・ログイン・ログアウト・Discord連携の呼び出し |
| `AccountTablePreview`(`scripts/ui/account_table_preview.gd`) | 対局での見え方の見本。**`PlaymatPaint` のマットの上に本物の `PlayerInfoBar` を置き、右の群が外へ出るよう帯を広く取って切り抜く** |
| `AccountLooksTabs`(`scripts/ui/account_looks_tabs.gd`) | 右カラムの4つのタブ。アイコン・称号・マットの一覧を持ち、選ばれたら通知するだけ(保存は画面側) |
| `EmoteSlotPage`(`scripts/ui/emote_slot_page.gd`) | エモートのタブの中身。4つの枠と所有一覧。入れ替えるたびに自分で保存する |
| `AccountCredentialDialog`(`scripts/ui/account_credential_dialog.gd`) | 登録・ログインの入力ダイアログ。入力を渡すだけで、通信は画面側が行い結果を返す |

- **選んだものは即座に保存する。**選ぶたびに `SAVE_DELAY` 秒の待ちを延ばし、止まったら
  `AccountService.save_profile()` を1回呼ぶ(連打で書き込みを重ねない)。保存中に次が来たら終わってから
  もう1回書く。**戻るときは待ちを打ち切ってすぐ保存する**(待ちの間に画面を離れても消えないように)
- 入口は2つ。`TitleScreen` と `HomeScreen` のヘッダー。`Main` は他の画面と同様に
  `_show_only()` で切り替える
- ホーム画面のヘッダーには設定中のアイコン、表示名と砂金の残高を出す。残高は `AccountService` が
  キャッシュしている値を読むだけにし、画面を開くたびに通信しない

## 10.5.1 表示名に使える文字(GameDesign.md 14章)

`TextGlyphs`(`scripts/logic/text_glyphs.gd`、staticのみ)が、同梱フォントに字形が
あるかどうかだけを答える。**対応する文字の一覧をコードへ持たず、`Font.has_char()` で
フォント自身に問い合わせる。**表を持つと、フォントを差し替えたときに黙って食い違うため。
判定した結果は文字コードごとにキャッシュする。

- `AccountScreen` は入力のたびに `sanitize()` を通し、使えない文字を取り除いて
  1行の注意を出す(GameDesign.md 14章の「入力欄では受け付けない」)
- `AccountService.fetch_display_name()` は、**受け取った他プレイヤーの表示名を
  `TextGlyphs.replace_unsupported()` へ通してから返す**。相手のクライアントが何を
  送ってくるかはこちらで制御できないため、入力側の制限だけでは自分の画面が化ける

**フォントを扱うがロジック層へ置く。**参照するのは `FontFile` リソース1つで、UIの
ノード・レイアウトには一切触れない。ここをUI層に置くと、`AccountService`(net層)が
UI層へ依存することになる。
