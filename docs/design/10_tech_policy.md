# 10. 技術設計方針(毎日アプデ運用のための骨格)

- 砂時計は `Resource`(.tres)としてデータ駆動で管理し、コード変更なしで新規追加できる形にする
- 効果は「トリガー×ターゲット×エフェクト」の組み合わせで表現し、エフェクトの種類ごとにハンドラを用意する
- 既存のエフェクト種別の組み合わせだけで新しい砂時計を作れる状態を維持し、「新効果そのものの追加」と「既存効果の組み合わせによる新駒追加」を分けて運用する
- オンライン対戦はターン制の特性を活かし、非同期(手番ごとにサーバーへ送信→相手に反映)の通信方式を基本とする

## 配信先

- 正規の配信先は unityroom。これに加えて itch.io と PLiCy に載せる(ふりーむ!はブラウザ形式で外部と通信するゲームを掲載しないため対象外)
- itch.io と PLiCy に置くのは起動部(html / js / wasm)だけにし、ゲーム本体(pck)は起動のたびに外から最新版を読む。どの配信先も常に同じ版になり、対戦相手が版違いで分かれない
- 起動部を上げ直すのは Godot 本体を更新したときだけ。起動部と本体の Godot の版が合わないときは起動せず、unityroom で遊ぶよう案内する
- セーブデータとアカウントは配信先ごとに別になる(ブラウザがサイトごとに保存先を分けるため)。引き継ぎは用意しない
- unityroom のランキング送信は unityroom 上で遊んでいるときだけ行う(他の配信先からは送り先が成立しない)
