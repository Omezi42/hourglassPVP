# 31. カードスキン

**特定のカード1枚の見た目(砂時計のイラスト)を、自分だけ別の絵へ差し替えられる品。**
ショップ(21章)で砂金と引き換えに買い切りで解放する。

9章のとおり、砂時計の絵は全種が共通の1枚の色違いであり、固有の絵を1枚ずつ描き起こす
運用は量産に向かないため採らなかった。**スキンはその裏返しで、「量産しない代わりに
1枚ずつ固有の絵を用意する」ための置き場**とする。カードを見分ける役目は引き続き
紋章が担う(9章)ため、スキンで変わるのは砂時計の絵だけで、**紋章・名前・数値・
キーワードの表示は一切変えない**。

## スキンが持つもの

- 対象のカード1枚のid、表示名、そのカードだけの固有イラスト(上向き / 落下中 /
  落ちきりの3状態)。**トークンと砂術は対象にしない**(絵を持たないため)
- 絵は `docs/AssetPromptTemplate.md` の砂時計テンプレートに従って生成し、
  **本体のガラス玉がキャンバス高さの70%を占める制約をそのまま守る**。スキンだけ
  砂時計が大きく・小さく見えると、盤面で駒の大きさが揃わない
- 3状態は必ず「上の砂が多い / 落下中 / 下の砂が多い」と読める形にする。
  絵を差し替えても、**砂の量というこの作品で最も重要な情報チャネル(9章)を潰さない**
- **手札の絵の窓の光だまりの色(9章「手札」)は、スキンごとに1色持つ。**共通の絵の
  色相表から求められないため

## 売り方と価格

- **1品=カード1枚のスキン**とする。コンセプトで揃えた数枚を1つの品(スキンセット)に
  まとめて売ってもよいが、その場合も中身は1枚ずつ独立したスキンとして扱う(ON/OFFは
  1枚ずつ切り替えられる)
- **価格はスキン1枚500砂金を目安とする。**アイコン(100)・エモート(200)より高く、
  プレイマット(1500)より安い。対局中に目に入るのはそのカードを引いて出したときだけ
  であり、常に画面の大半を占めるマットほどは見えないため。**セットは合計より少し
  安くしてよい。**いずれも初期案であり、砂金の入手経路が増えたら見直す
  (「今後足す品ほど高くする」という21章の方針は同じ)
- 品揃えは固定(21章)。**買う前にショップの品目で3状態の絵をそのまま見られる**
  ようにする(見た目が品そのものであり、名前だけでは何を買うのか分からない。
  プレイマットの縮小見本と同じ考え方)
- 一度買ったものは消えない。同じものは2度買えない

## ON/OFF

- **買った時点でONになる。**買ったのに何も変わらない、という状態を作らない
- **切り替えは砂時計図鑑(9章)の右のページで、カード1枚ずつ行う。**そのカードの
  スキンを所有しているときだけ、絵の下に「スキン:ON / OFF」の切り替えを出す。
  所有していないカードには何も出さない(ショップの役目を図鑑が兼ねない。14章の
  「設定する場所に買えないものを混ぜない」と同じ)
- 図鑑の右のページの絵は、**ONのときスキンの絵で表示し、押して裏返す操作もそのまま
  効く**(3状態を持つため)
- **デッキ単位でまとめて切り替える仕組みは持たない。**構築ごとに見た目を変えたい
  場面はあるが、デッキごとにスキンの状態を持つとデッキの保存形式・共有(デッキ表・
  デッキコード)・対局前の受け渡しのすべてへ手を入れることになり、見た目の品1種の
  ために釣り合わない。**アカウントに対して1枚ずつ、が唯一の設定単位**
- 設定はアカウント(14章)に紐づき、別の端末からログインしても引き継がれる

## どこで見えるか

- **ONのスキンは、そのカードの絵を出すすべての場所で使う**:手札・場の駒・
  ドラッグ中のプレビュー・図鑑・デッキ編集の一覧と棚・墓地の中身・デッキ表(9章)・
  デッキ一覧やリプレイ一覧の代表アイコン。**画面ごとに出す/出さないを分けない**
  (分けると「買ったのにここでは元の絵」という不揃いになる)
- **対局では相手にも見える。**表示名・アイコン・称号・プレイマットと同じ経路で
  相手の設定を受け取り、相手の場と手札から出た駒をその絵で描く。見た目の品は
  相手に見えて初めて値打ちになる(プレイマットと同じ)
- **CPUの駒にはスキンを当てない。リプレイと観戦は元の絵で再生する**(棋譜はスキンを
  記録しない。マットと同じ扱い)
- ルール画面(16章)・画面の見かた(20章)・キーワード辞書(17章)の実演と教材の
  盤面は**常に元の絵**を使う。教材の絵がプレイヤーごとに変わると説明と食い違う

## 絵の用意

- スキンの絵は**固有イラストであり、色違いでは作らない**。生成はユーザーが
  `docs/AssetPromptTemplate.md` のテンプレートで行い(`{{MOTIF}}` にそのスキンの
  意匠を入れる)、透過処理までを手作業で済ませたうえで取り込む。1枚ずつクオリティを
  保つことを優先し、**1度に多くを足す運用にはしない**(数枚ずつ)
- **スキンは配布物(pck)を増やす。**基本の絵は1組で済んでいるが(9章)、スキンは1枚
  ごとに3状態の絵がpckへ入る。非可逆(WebP)で取り込んでも1枚あたり数十KBかかる
  ため、Web版の起動待ちを守るには**足す枚数に上限を意識する**(目安として当面は
  合計20枚程度まで。超えるならBGMと同じく実行時に取りに行く方式を検討する)
- 新しいスキンを足したら、Discordの#お知らせへ紹介する(新カードと同じ扱い)
