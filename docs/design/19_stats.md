# 19. 戦績

**勝っても何も残らない状態を避けるための記録**。ランクマッチ(28章)が段位という
「勝つ理由」を別に持つ一方、ルームマッチ・CPU戦を含めた通算の成績を見返せることも
引き続き「勝つ理由」の1つとして残す。

- 記録するのは**対局種別ごとの対局数・勝率・平均手数**、**カード別の勝率**、
  **デッキ別(構築ごと)の勝率**の3つ
- **リプレイから集計しない**。リプレイは直近30件しか残らないため(12章)、
  古い対局が消えるたびに通算の勝率が変わってしまう。終局のたびに1件足す積み上げ方式とし、
  リプレイの保持件数とは切り離す
- **誘導対局(18章)は数えない**。台本どおりに指すだけの対局であり、プレイヤーの成績ではないため
- **アカウントごとに数える**(14章)。ログアウトして別のアカウントで遊んだぶんは混ざらない
- **戦績はFirestoreへ同期し、別端末からログインしても同じ記録を続けて見られる**
  (リプレイ・通貨と同じ扱い)。サーバー側の正当性検証は行わない既存方針のまま、
  クライアントの申告をそのまま信頼する。**通信に失敗した対局の記録は端末へ控えておき、
  次に成功した時点でまとめて反映する**(CPU戦はオフラインでも遊べるため)
- **カード別は「そのカードを入れたデッキで戦った勝率」**であり、そのカードの強さそのもの
  ではない。同じカードを2枚積んでいても1局は1局として数える。**この値でカードの強弱を
  判断してはいけない**(強さの測り方は7章のとおり、含むデッキと含まないデッキを直接
  ぶつける方式による)
- デッキ別は構築を**その内容から作った指紋**で見分ける。1枚でも違えば別の構築として数える。
  9章のデッキコードは番号を預ける仕組みであり、記録のたびに通信することになるため使わない。
  覚えておく構築は多くならないよう上限を設け、超えたら対局数の少ないものから落とす
- **数値は右揃えの列にそろえる**。戦績は数字を見比べる画面であり、「20戦 勝率60.0% 平均9.9手」
  のように1本の文へ流し込むと、名前の長さで桁の位置が行ごとにずれて縦に読み比べられない。
  1つの値しか持たない行も、同じ幅の列へ収める
- **デッキ別は、いま保存しているデッキ・プリセットの名前で出す**。見分けに使う指紋は
  プレイヤーには読めない内部の識別子であり、そのまま画面へ出してはいけない
  (9章の「id順は並びとして使わない」と同じ理由)。名前を引けない構築
  (消したデッキ・受け取った構築)は「いま保存していない構築」として出す
- 表示は専用の画面とし、きろくタブから入る。**対局数が0のうちは、その旨を1行で示す**
