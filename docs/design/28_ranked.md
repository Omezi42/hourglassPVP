# 28. ランクマッチ

**2026-09-15追記。**19章にあった「ランク戦(順位付け)は行わない」という方針を撤回し、
第3のマッチングモードとして追加する。11章のランダムマッチ・ルームコード対戦とは
別のマッチングプールを持ち、フリーマッチ(レート変動なし。中身はランダムマッチと同じ
仕組みを使うが、ランクマッチとはプールを分ける)と対になる。

## 段位構成

| 帯 | 段階 | 昇格条件 |
|---|---|---|
| ブロンズ | 1〜3 | ★2個で昇格 |
| シルバー | 1〜4 | ★3個で昇格 |
| ゴールド | 1〜5 | ★4個で昇格 |
| プラチナ以上 | レート制(1000開始) | 下記の表 |

ブロンズ〜ゴールドは**星取り制**とする。勝利で★+1、敗北で★-1(0未満にはならない)。
既定の★数に達したら次の段位・階級(無ければ次の帯)へ昇格する。ゴールド5から
★4個でプラチナへ上がると、以後は星取りをやめてレート制に切り替わる。

**プラチナへ到達した後は、レートが1000を下回っても星取り制へは戻らない(降格なし)。**
一度プラチナへ上がった実績はシーズン終了まで保持され、下がったレートのまま
プラチナ内に留まり続ける。

## 連勝ボーナス(2026-09-16追記)

**ゴールド以下(星取り制の帯)で3連勝以上しているとき、その回の勝利で得る★が+1される**
(通常の+1に加えて、連勝ボーナスの+1で計+2)。3連勝目・4連勝目・…と、連勝が続く限り
毎勝利で効く。1度でも負けると連勝は0に戻り、ボーナスも外れる。

**プラチナには適用しない。**プラチナは★ではなくレートで進むため、この節はブロンズ〜
ゴールドの間だけを対象とする。連勝の記録そのもの(3連勝したかどうか)はシーズンが
切り替わるとリセットされる(他の段位の値と同じ扱い)。

## プラチナのレート変動

| レート帯 | 勝利 | 敗北 |
|---|---|---|
| 1000〜1099 | +16 | -8 |
| 1100〜1199 | +14 | -10 |
| 1200〜1299 | +12 | -12 |
| 1300〜1399 | +10 | -14 |
| 1400〜1499 | +8 | -16 |
| 1500〜1599 | +6 | -18 |
| 1600以上 | +4 | -20(以降は固定) |

**レートが100上がるごとに勝利側を-2・敗北側を-2(絶対値では+2)ずつ動かし、
1600以上で打ち止めにする。**上位ほど1勝の価値を下げ1敗の重みを上げることで、
実力が拮抗する高レート帯で数値が行き来しにくくする。**この表は初期案であり、
運用しながら調整する。**レートは1000を下回っても(降格しない代わりに)下がり続け、
同じ表の対応するレート帯の値をそのまま使う(1000未満は1000〜1099と同じ +16/-8)。

## シーズン

**1シーズン=1か月。**月初(JST 00:00)に、**全プレイヤーを一律ブロンズ1・★0へ
リセットする**(前シーズンの到達段位に関わらず、全員が同じ位置から再スタートする)。
前シーズンの最高到達段位は月末報酬の判定にのみ使い、新シーズンの開始位置には影響しない。

## 月末報酬・ランキング

- **そのシーズン中に到達した最高段位に応じて、月末(または翌月頭)に砂金を付与する**
  (2026-09-15、ユーザー判断で確定)。**ブロンズ100 / シルバー300 / ゴールド800 /
  プラチナ3000砂金**
- **ゲーム内にランキング画面を新設する。**現在シーズンの参加者を、帯・階級・★・レートを
  貫く単一の順序(進行度)で一覧できるようにする。**プラチナだけに絞らず、ブロンズから
  参加していてもランキングに載る**(2026-09-16、ユーザー判断「プラチナだけじゃなくて
  進行度でもランクに残ったら嬉しそう」)。並び順の合成の仕方は Architecture.md 10.16節
  `RankRules.progress_score()` を参照
- **unityroomのランキング機能との連携(2026-09-15調査済み)。**unityroomのAPIは
  「そのボードへ今回のスコアを送る」だけの一方向の仕組みで、読み出し(ランキングを
  取得する)口は公開されていない。**したがってゲーム内の「ランク」画面
  (ランキング一覧)をunityroom側の値で置き換えることはできず、ゲーム内ランキングを
  主としたまま、unityroom側へはプラチナのレートが動くたびに追加で送る**(そのゲーム
  ページへ来た人が見る、公開された副次的なランキングという位置づけ)。実装は
  `scripts/net/unityroom_ranking_client.gd`。**unityroom側のゲーム管理画面で、
  対応するボードの記録方式を「常に記録」にしておく必要がある**(「ハイスコア」の
  ままだと、シーズンが変わってレートが下がったときに古い最高値が残り続けるため)
- **月初にシーズンが切り替わったプレイヤーへ、モーダルの「表彰式」を1度だけ見せる**
  (2026-09-15、ユーザー判断)。前シーズンの最高到達段位と、それに応じた月末報酬を
  添えて表示する。初めてランクマッチへ触れるプレイヤー(前のシーズンが存在しない)には
  出さない。実装は `CardSeasonCeremonyPanel`(Architecture.md 10.16節)

## 経済(通貨)への影響

ランクマッチの1局ごとの砂金報酬は、当面**ランダムマッチと同額**(勝利30・敗北10。
GameDesign.md 15章)とし、**日曜イベント(15章)の対象にも含める**。段位到達による
月末報酬は、この1局ごとの報酬とは別枠で加算する。

## サーバー側の正当性検証について

**サーバー側での正当性検証を行わない既存方針(11章)により、レートもクライアントの
申告をそのまま信頼する。**意図的なレートの吊り上げ(自己対戦の繰り返し等)への対策は、
15章「不正な稼ぎ方への線引き」と同じ考え方(総手数が少ない対局・同一相手との連戦を
対象外にする等)を流用する想定とし、詳細はArchitecture.mdで詰める。
