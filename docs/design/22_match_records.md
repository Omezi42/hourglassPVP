# 22. 対局の記録と分析

いまバランスの数値は**すべて自己対戦シミュレーションで測っている**(7章)。CPUは1手ごとの
貪欲法であり、**砂術を持て余す**ことが実測で分かっている(`docs/BalanceReport_v5.md` 10.6節)
ように、機械の数字は人の対局とずれる。**人が指した対局を残し、シミュレーションの値と
突き合わせられるようにする。**

## 記録する対象

- **オンライン対戦(ランダムマッチ・ルームマッチ)だけを記録する**。CPU戦は記録しない。
  CPUの癖がそのまま混ざり、「人の対局を測る」という目的と食い違うため。観戦者と
  リプレイの再生も記録しない
- **ルームマッチも記録するが、ランダムマッチとは区別して持つ**。友達対戦は真剣勝負とは
  限らないため、分析のときに外せるようにする

## リプレイとは別に持ち、消さない

対局そのもの(デッキ・種・手順)は既にオンライン対戦の仕組みが持っているが、**それは
リプレイのための置き場であり、アカウントごとに直近30件で消える**(12章)。同じ場所に
「消える」と「消さない」という相反する要件を負わせられないため、**分析用の記録は別に
1件だけ書き、消さない**。中身が重複するが、消えるものと残るものを分けることのほうを採る。

## 記録する中身(要約 + 棋譜)

| 内容 | 理由 |
|---|---|
| ビルドID・バージョン | **カードが変われば混ぜて数えられない**。版をまたいだ集計を防ぐ唯一の手段 |
| 対局の種別(ランダム / ルーム) | 上記のとおり分けて数えるため |
| 勝者・決着の要因・総手数・両者の最終HP | 7章の5指標をそのまま出せる |
| 両者のデッキ30枚のid | カード別・デッキ別の勝率 |
| 山札の種・指した手の並び | **後から再生できる**。「人がどう指したか」はここにしか無い |
| 両者のプレイヤーID | 同じ人どうしの連戦を除いて数えるため。**表示名は記録しない** |

## 誰が書くか

**両者が書きにいき、先着1件だけが通る**。片方が切断していても記録が残り、
二重には数えられない。観戦者は書かない。

**書き込みに失敗しても対局には何も起こさない。**分析のための記録であり、落ちて失われるのは
サンプル1件だけである。**画面にも何も出さない**(裏方の処理の成否をプレイヤーへ見せない。
11章の募集通知と同じ扱い)。

## ゲーム内で見る

全件をクライアントが読むのは重すぎるため、**集計を1つだけ持ち、終局のたびに増分で
更新する**。持つのは総対局数・先手の勝利数・手数の合計・決着の要因ごとの数と、
カードごとの「採用した局数 / そのうち勝った数」。**更新するのは記録を書けた側だけ**とし、
二重に数えないようにする。

戦績画面(19章)へ**「みんなの戦績」**を足し、自分の戦績と切り替えて見られるようにする。
**カード別の勝率はカードの強さそのものではない**という但し書きは、自分の戦績と同じものを
出す(強さの測り方は7章の方式による)。

**集計は版で分けず、通算として貯める。**カードは毎日増えるため版ごとに分けると
画面に出る数字が毎日0に戻る。版ごとの分析は下記の道具が記録そのものを読んで行う。

## Discordで見る

**自動投稿はしない。**1局ごとに流せばうるさく、日次でまとめるにはサーバー側の定期実行が
要るが、この作品はサーバーを持たない(10章)。代わりに**求めたときに記録を読んで集計し、
Discordへ投稿する道具**を用意する。集計の範囲(ビルドID・期間・対局の種別)を指定できる。
